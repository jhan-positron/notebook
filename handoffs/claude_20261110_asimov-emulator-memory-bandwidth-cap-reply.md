## Words used here

- **Asimov**: Positron's chip. Its Arm C1-Nano cores are measured on an emulator, not on silicon.
- **Emulator, image**: the Palladium emulator (GA13) on which Jesse Zhang runs a model of the chip for the user. The image is release a10280100, model `hemi_rtws_tlm`, built from commit 0d9e214eb43b of the GitHub repo Positron-AI-TSMC/asimov (committed 2026-10-28 07:29 UTC).
- **RTL**: the hardware source code of the chip and of the emulator's memory models.
- **System DRAM (SMS)**: the memory of the Arm cores (the application processor, AP), at address 0xC0_0000_0000. **Weight memory (XMS)**: the memory that the datapath reads model weights from.
- **Lane, Goldcrest pair**: one AXI memory interface of the emulator's memory model (AXI is the Arm on-chip bus protocol), and a group of 2 lanes. The model has 18 pairs, which is 36 lanes.
- **Datapath (DP) lanes**: pairs 0 to 15, 32 lanes, the weight memory. **AUX lanes**: pairs 16 and 17, 4 lanes (XMS lanes 32 to 35), the system DRAM.
- **Timing profile**: the DRAM-like settings of a lane. They are 61 lane-clock cycles of read latency (61 ns at the 1 GHz lane clock), 40 cycles of write response latency, and a budget of 39,322 bytes per 1,024 cycles (about 38.4 GB/s) that reads and writes share. Each lane has its own budget.
- **DATAPATH_TIMING, GC_PAIR_INDEX**: the parameter of the lane wrapper that turns the profile on, and the pair number that its condition tests.
- **PR 4492**: https://github.com/Positron-AI-TSMC/asimov/pull/4492, "emu: share Goldcrest AVIP timing with timed host writes", by Thuan Duong. It added the timing profile.
- **Chain load**: one load of the latency test. Its address is the value that the load before it returned. **Flushed**: every line of the buffer is removed from the caches before the timed pass.
- **Prefetchers**: hardware logic that loads data into a cache before the program asks for it.
- **Boot B, boot D, boot F1**: three of Jesse's emulator runs. Boots B and D have the prefetchers off. Boot F1 has the L3 cache and the prefetchers on. Their result folders are results/membench-jibin-006, -008 and -011 in the project folder.
- **Workflow**: the multi-agent tool of Claude Code. **Ultracode**: the `/effort ultracode` mode, which runs a workflow for every substantive task. **Skeptic**: a workflow agent that tries to refute a draft.
- **sw-dev-01**: the lab host that holds Jesse's work folder /home/jzhang/dev/emuMemBenchBox.
- **People**: Jibin Han is the user. Jeremy (Jeremy Conner in the Slack user lookup) asked the question. Jesse Zhang runs the emulator. Thuan Duong wrote the timing model. Bill Baumann reviewed the data earlier.
- **est.**: an estimate, not a measurement.
