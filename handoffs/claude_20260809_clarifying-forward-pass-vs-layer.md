## Timeline (2026-08-09, single Q&A session)

- Clarified the hierarchy: one forward pass runs the entire model (all
  layers once, then logits); a layer does not contain forward passes. What
  colleagues likely meant: each PyTorch layer has its own `forward()`
  method, and each layer's `forward()` runs once per model pass, many times
  per request.
- Explained `lm_head` (the final linear projection from hidden state to
  per-vocabulary-token scores, run once per pass, only for positions that
  requested logits).
- Verified tron's `forward()` at `h/tron/models/model.hpp:1526` is
  model-level, but batched: inputs are `token_jobs` (all live tokens across
  all sessions this step) and listeners (positions wanting logits), so one
  call yields one token per listening session — possibly several tokens,
  possibly zero (a mid-prefill chunk).
- Established the decode mapping: for one session without speculative
  decoding, decode pass k produces generated token k+1 (the first generated
  token comes from the last prefill pass); tron's `forward()` has EAGLE
  (speculative-decoding) arguments that would break the 1:1 mapping if
  active.
- Grounded the terminology in the source: "session" IS tron's term
  (definition at `token_stream_monitor.hpp:390-396`: the state of one token
  generation transaction, from `stream_generate()` until close/cancel);
  "sequence" is NOT a tron serving concept (appears only in attention-math
  comments and the abbreviation `seq_tip`); per the user's instruction the
  final doc uses "session" and "prompt + its completion".
- Corrected the user's "same token" intuition: one batch freely mixes
  prefill and decode tokens from different sessions at different positions;
  what is shared is the weights (each weight tile applied to every row of
  the batch), position is a per-row input (`in_token_positions`,
  `model.hpp:1507-1510`), and attention isolation comes from the token tree
  (each query attends only to its ancestors, `kv_cache.hpp:87`). The user's
  intuition matches static batching, not tron's continuous batching.
- Wrote the reference document
  `/home/jhan/workspace/perf-fluctuation/from-claude/tron-serving-concepts.html`:
  warmup section (11 one-fact sentences, each linked to its proving
  example), a concept-ladder figure (users → sessions → token tree → batch
  → forward pass), five worked examples targeting the session's
  misconceptions, and a glossary table with tron `file:line` anchors
  ("sequence" and "user" present but marked not-a-tron-concept). Light
  background, single theme, inline SVG diagrams.

  term) and "prompt + its completion"; do not introduce "sequence" as a
  tron concept.

  `tokens_generated ≈ decode_forward_count + 1`; verify no background
