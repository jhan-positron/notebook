## Short version

At prompt 1024 tokens, qwen3-4b prefill takes the same time with the AMX attention kernel on the CPU as with attention on the FPGA (every matched pair within -1.9 % to +4.6 %). From prompt 2048 up the FPGA is faster, 1.8 to 1.9x at prompt 8192, while the AMX kernel itself is 2.3x faster than the old AVX kernel on the CPU. The session also moved our CI-harness wrappers to platformd 0.11 (named engines), ran two new campaigns on delphi-3bda (CI harness with three passes per FPGA arm, and runtron with 8 users per engine), and published the report page through nine versions.

## Words used here

- tron: the inference program under test. rinzler: its production server binary (a Debian package, "deb"). runtron: tron's command-line tool that runs one engine with N users in one process.
- AMX: Intel Advanced Matrix Extensions. "canonical AMX deb" (arm name canon) = main 3faba6d0 with the deb preset TRON_AMX_DISPATCH=ON. "nightly deb" (arm base) = tron 2026.09.18-3faba6d0, no AMX kernels, so its CPU attention runs AVX. "VNNI-K" = the PR 4424 build with the VNNI K layout.
- Attention on the FPGA (AoF, FPGA attention): the attention scores are computed on the FPGA card. Controlled by USE_HW_ATTN in /opt/positron/user/config.env (=0 forces CPU attention, unset means FPGA attention). HBM = the FPGA card's own memory. A shard = the card-side copy of 1024 tokens of one request's K/V.
- TTFT: time to first token (the prefill wait). TPS: decode tokens per second per user. Two TTFT definitions exist and must not be compared across harnesses: the CI harness measures a client-side stopwatch per request, and runtron's "Parsing the prompt took" is the batched prefill of all N prompts.
- warm / cold cell: inside a CI-harness pass the later cells reuse the same conversation seeds, so 12 to 54 % of their prompt tokens come from rinzler's prefix cache (warm). The first cell of a driver run, or a single-cell driver run, meets fresh engines (cold).
- platformd: the service that provisions the engines on delphi-3bda. Version 0.11 removed the engine "count" parameter. Every engine must be named (default-0 to default-3) with its own ingress port (3000+N).
- delphi-3bda: the CI machine (2 x Intel Xeon 6, 8 FPGA cards). "our half" = cards 90/93/b9/bc, socket 1. "whole machine" = all 4 tp2 engines behind the Caddy proxy, the nightly's layout. Bill's marker /bill-has-instance-0,2 signals which half Bill may use.
- Workflow: Claude Code's multi-agent orchestration. The session used one to extract data and six to verify pages adversarially.
- Welch t: the t statistic of two means with unequal variances. Values beyond about 3 with n = 3 mean the direction is resolved.

Over all six FPGA passes: 8,506 warnings, 6,851 inside cells, 1,655 in the 30 s gaps (the pre-cell AMX probe's own requests). The recorded sw_fallback_total counter equals the journal count in all 44 recorded pass-cells. Free space at exhaustion is 56.4 MiB of 32 GiB per card (full, not fragmented). Fresh engines have 30.1 to 30.9 GB free per card, so weights and fixed allocations take 3.5 to 4.3 GB (199 to 204 shards). Reading on the page: at 4096 and 5120 both arms scored nearly all new context on the CPU, so the AMX gain there (42 and 37 %) is the CPU-attention AMX gain (49 and 53 %) in another form. Only the 2048 cell is a clean counter-example to the exhaustion explanation, because a degraded shard warns once and stays on the CPU while its prefix-cache node lives.

## Gotchas & decisions

- platformd 0.11 restarts rinzler units that are stopped with systemctl. Any takeover must go through POST /api/inference/down (dut.sh serving-down already did, and lib-guard.sh now does). The 16:36 UTC abort of the runtron campaign was this.
- platformd 0.11 keeps established connections to every engine's ingress port from the host's own addresses (health probes). An idle test that counts established connections must exclude the host's own addresses (127.0.0.1, ::1, and the output of hostname -I).
- Do not pass a regex with backslashes through `awk -v`. awk re-reads the escapes and the pattern silently stops matching. Use index() on a plain string instead. This broke the first launch's switch step.
- Never edit a campaign script while a pass runs. Replace the file atomically (write a temp file, then rename), so the running bash keeps its old inode.
- The auto-mode classifier denies commands that combine a file edit with a launch, and denies ssh launches on 3bda ("Modify Shared Resources"). Split the edit from the launch. If the launch itself is denied, ask jhan to run it with the `!` prefix, as happened at 09:58 PDT on 09-22.
- `sleep N` chained with other commands is blocked. Use the Monitor tool with a filter on status-history.log, or run_in_background.
- Never compare TTFT across harnesses: runtron's batched prefill against the CI client stopwatch differs by 4.3x at tp2 and 2.6x at tp4 through layout alone.
- Do not quote the ci-mimic base 556 ms as the FPGA number at prompt 1024 (loaded client). Use the nightly 528 ms or the 13-night mean 509.5 +/- 7.2 ms.
- A degraded shard (card K/V space exhausted) warns once and stays on the CPU while its prefix-cache node lives. "No new warning in a cell" does not mean "no CPU attention" in that cell.
- The nightly's per-forward prompt chunk is 128 tokens per user (TRON_PER_USER_PROMPT_CHUNK_LIMIT), not 1024. The 1024 is the per-forward capacity across users. A verifier caught a code reader's miscount.
- Page rules kept: plain English, no semicolons in prose (citations may keep them), ASCII only (artifact mojibake trap), light theme, "prompt N" never "ctx N", estimates labelled "est.".
