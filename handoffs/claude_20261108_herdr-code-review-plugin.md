## Words used here

- **herdr**: a terminal workspace manager for AI coding agents. One server process per herdr session owns the panes. A client is the view that a user attaches to it. The binary is /home/jhan/.local/bin/herdr.
- **pane, tab, workspace**: herdr's layout units. A pane is one terminal. An agent pane is a pane that runs Claude Code or Codex.
- **herdr session `claude-agentsrv`**: the named herdr session inside the agentsrv container. It is not a Claude Code session. The same container login starts it with `herdr --session "$(hostname)"`.
- **claude-agentsrv**: the podman container this Claude Code ran in, on the user's Linux dev server agentsrv (same home directory, same files).
- **sw-dev-01**: another dev server of the user. It mounts the same home directory over NFS (a network file system).
- **herdr plugin**: a directory with a manifest file (herdr-plugin.toml) that herdr installs from GitHub with `herdr plugin install owner/repo`. Plugins are community code that herdr does not review or sandbox.
- **marketplace**: herdr.dev/plugins, an automatic index of public GitHub repositories tagged `herdr-plugin`.
- **herdr-reviewr** (plugin id `persiyanov.reviewr`): https://github.com/persiyanov/herdr-reviewr. It shows the agent's diff in a pane, lets a person comment on lines, and sends the comments to the agent's input.
- **herdr-hunk-diff, magnum**: two other review plugins found in the marketplace.
- **live handoff**: herdr's experimental way to replace a running server with a new binary while every pane process keeps running. The commands are `herdr update --handoff` and `herdr server live-handoff`.
- **integration**: a herdr hook for one agent product. It reports the agent's conversation id to herdr, so a restarted server can resume the conversation.
- **prefix**: the user's herdr prefix key, ctrl+q.
- **AskUserQuestion**: the Claude Code tool that shows the user a multiple-choice question.
- **sha256**: a checksum that identifies the exact contents of a file.
- **systemd**: the service manager of most Linux systems. The herdr server here does not run under it.
- **Scratchpad**: the session's temporary folder under /tmp/claude-0. A reboot or a cleanup can clear it.

## Gotchas and decisions

- The user's decision: Claude does not run a herdr handoff, a restart or a plugin install. The user rejected the AskUserQuestion that offered it and asked for a guide to follow.
- A Claude Code session inside a herdr pane is itself one of the panes that a restart or a handoff affects.
- From a shell outside any pane, every herdr command needs `--session claude-agentsrv`. Without it the command looks at the empty default session and reports "not running".
- The binary is shared over NFS. `herdr update` on one machine replaces the file for every machine. A running server keeps its old version until a handoff or a restart.
- `herdr update --handoff` on sw-dev-01 did not hand over the server on agentsrv. The agentsrv server stayed on 0.9.1.
- A plain restart on this machine would have ended every agent process, and herdr could not have resumed the conversations. All integrations were "not installed", session.json had no conversation ids, and pane screen history was off.
- Live handoff conditions that were checked: private protocol 22 on both versions, a pane count below the 64-pane limit of a 0.9.1 sending server, and a server that is not under systemd.
- Known handoff issues that were read: https://github.com/herdrdev/herdr/issues/4972 (panes die under systemd), https://github.com/herdrdev/herdr/issues/5291 (a pane keeps old keyboard flags, fixed with `printf '\033[=0u'` in the pane), https://github.com/herdrdev/herdr/issues/5443 (a 0.8.0 to 0.9.5 handoff where all processes survived) and https://github.com/herdrdev/herdr/issues/3393 (a refused handoff leaves the old server running).
- Key bindings: prefix+r is herdr's resize key. The free prefix letters are a, d, f, i, m, t, u and y. The guide recommends prefix+f for the reviewr toggle.
- AI-driven review is done by Claude Code skills, not by herdr. The session listed `/code-review`, `engineering:code-review`, tron-code-review, Wade-code-review, ben-review and positron-code-review.
