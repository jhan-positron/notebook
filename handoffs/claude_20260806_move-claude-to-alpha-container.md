## Why sshd does not run inside the container

This was the original plan. It is impossible on alpha, proven by
`sshd -ddd` inside the container:

```
debug1: setgroups() failed: Operation not permitted
setgroups: Operation not permitted [preauth]
debug1: Killing privsep child
```

| Check | Value |
|---|---|
| `/proc/self/setgroups` | `deny` |
| `/proc/self/uid_map` | `0 644434775 1` (one uid only) |

You have no subuid ranges in alpha's `/etc/subuid`, so podman maps a
single uid, and the kernel sets `setgroups=deny` on that namespace at
creation time. `sshd` needs `setgroups()` for privilege separation, so
it exits before authentication. No config option avoids this;
`UsePrivilegeSeparation` was removed in OpenSSH 7.5.

**The only alternative fix**: ask whoever administers alpha to add
subuid/subgid ranges for `jhan`, e.g.

```
jhan:1000000:65536
```

in `/etc/subuid` and `/etc/subgid`. With that, sshd could run in the
container and this whole host-sshd workaround becomes unnecessary.

## Security notes before you decide

- The daemon runs as `jhan`, not root. It cannot grant more than your
  own access.
- Authentication is public-key only; `PasswordAuthentication no`,
  `UsePAM no`. It reads your existing `~/.ssh/authorized_keys`
  (3 keys, all labeled `jhan@positron.ai`).
- Any of those keys, used against port 22022, gets a shell **inside the
  container** because of `ForceCommand`. The container mounts your real
  home and `/scratch` read-write, so this is equivalent to your normal
  shell access, not a sandbox.
- alpha is shared. Anyone who can reach alpha on port 22022 reaches this
  daemon and is stopped only by key authentication. Check whether a
  user-run listener is acceptable under your organization's policy.
- `sftp`/`scp` requests are deliberately served from the **host**, not
  the container. `/home/jhan` is the same NFS directory on both sides,
  so transfers are equivalent.

## Make it survive a reboot (optional, do after it works)

Edit `~/.config/systemd/user/claude-dev.service` on alpha and add a
second `ExecStart` line:

```ini
[Service]
Type=oneshot
ExecStart=/home/jhan/claude-container/claude-box start
ExecStart=/usr/sbin/sshd -f /home/jhan/claude-container/sshd/sshd_config
RemainAfterExit=yes
```

Then:

```bash
ssh jhan@alpha 'systemctl --user daemon-reload && systemctl --user restart claude-dev.service'
```

Linger is already enabled for `jhan`, so the unit runs without an
active login session.

---

## How to stop or undo it

Stop the daemon:

```bash
ssh jhan@alpha 'pkill -f "sshd -f /home/jhan/claude-container"'
```

Remove it entirely (the container and normal `claude-box` use are
unaffected):

```bash
ssh jhan@alpha 'rm -rf ~/claude-container/sshd ~/claude-container/enter-container.sh'
```

If you added the `ExecStart` line, remove it and run
`systemctl --user daemon-reload`.
