## Gotchas & decisions

- platformd caches the map: read exactly once at startup, no watcher —
  edits do nothing until restart + reprovision (this staleness bit the
  ab40 run twice).
- NOT a dpkg conffile: local edits to the deployed map are silently
  overwritten by the next tron deb install.
- The tron deb postinst never restarts anything (daemon-reload only).
- Tool-disagreement trap: dev tools (bin/slice) re-parse the YAML fresh
  per call and can disagree with platformd's cached copy.
- No code build needed for map-only changes; shipping is via the
  package, not compilation.
- Verification recipe worth reusing: map mtime vs platformd
  ActiveEnterTimestamp (map newer = stale cache), then
  taskset -pc $(pgrep -x rinzler).
