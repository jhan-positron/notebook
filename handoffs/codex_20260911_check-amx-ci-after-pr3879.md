## Gotchas & decisions

An Intel CI client runner, AMX CPU flags, successful generation or passing standalone kernel tests do not prove that the serving Qwen model dispatched AMX. With AMX compiled in, Qwen's normal FPGA default can allow AMX for eligible early software-attention pages below position 127; forcing `USE_HW_ATTN=0` provides sustained deliberate coverage.

Both switches require fresh server processes. A client-shell export does not automatically reach rinzler through SSH/platformd/systemd. Platformd regenerates instance environment files; the proposed shared override must preserve unrelated contents, ownership and permissions and restore its prior presence/absence. Do not mistake an unchanged model provisioning cache for a server restart.

If using a once-per-model completion marker, the verification request must be the first generation workload after restart; readiness checks must not consume the marker through warmup generation. Bind evidence to the new service invocation/PID, expected model and a cursor captured before the request, for every tested engine. A resettable counter is an alternative.

Optional AMX-versus-AVX measurements must use the same binary/workload with software attention selected in both fresh processes, toggling only the kill switch. Existing FPGA-attention performance thresholds are not that baseline. Related kernel-level CI tracking remains https://github.com/positron-ai/tron/issues/3997.
