## Gotchas & decisions

- Correctness versus speed: the ranged mask decides visibility (correctness); `range_hint` only decides how fast the next range is found. Do not describe the hint as a correctness mechanism.
- Why the AMX path is safe: `is_dense_amx_page` admits a page only when `page.at_offset(page_size - 1) < range.tok_hi`, and the caller's `find_range(page.at_offset(0), *page_end_hint)` guarantees entry 0 is inside the hinted range, so all 64 entries are in one range; the dotter's advance (`kv_idx >= range_hint->tok_hi`) could never fire for that page. `TRON_ASSERT` is compiled in unconditionally, so a `find_range` miss aborts rather than returning a wrong range.
- Ben's sentence "make sure that we shouldn't be handling range_hint in the AMX path as well" is a hedged way of asking "check whether the AMX path also needs to advance the hint". The user first read it the other way; both readings get the same answer.
