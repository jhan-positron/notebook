## Words used here

- **tron**: Positron's inference program (GitHub repo positron-ai/tron). Its software attention path runs on CPU cores.
- **AMX**: Intel Advanced Matrix Extensions. A CPU instruction set with 8 tile registers of 16 rows x 64 bytes. A bf16 operand tile is therefore 16 rows x 32 values.
- **A operand, B operand, C tile**: the two inputs and the fp32 accumulator of one AMX tile multiply.
- **VNNI**: Vector Neural Network Instructions. Here it names the pair-interleaved layout the B operand needs: two consecutive rows of the logical matrix are interleaved into one tile row.
- **Baseline / canonical-K kernel**: the AMX attention kernel in https://github.com/positron-ai/tron/pull/3879. **Mirror / K\* kernel**: the variant that reads a pre-interleaved copy of K, parked as PR 2.
- **the page**: claude-agentsrv:/home/jhan/workspace/intel-AMX/PR3879/baseline-vs-mirror-sketch.html, written in the 2026-09-13 session "AMX baseline vs Mirror sketch". Its section 2, "What the code does, side by side", is an inline SVG lane diagram.

- **Q group, Q_packed, Q_rows**: the 4 query heads of one KV head (4 x 128 bf16), and their packed forms for the baseline (B operand) and mirror (A operand) kernels.
- **K_page, V_page**: one 64-token page of K or V for one KV head. **s_pages**: the per-page score buffer, 4 heads x 64 tokens fp32.
- **P**: exp(score minus running max), the unnormalized softmax weights. **v\*, s\*, m\***: the running attention numerator, denominator, and max per head.

## Gotchas & decisions

- Both of the user's guesses were wrong, and the code says otherwise. A tile register is 16 rows x 64 bytes, so a bf16 operand tile is always 16 x 32 values. Q_packed is not 2 x 128 and a K tile is not 4 x 128. The constant `Q_PACK_ELEMS_2048 = 16 x 128` gives the byte size only, not the layout.
- Never write "v\* fp32". v\* is a bf16 tensor (`btensor_t` resolves to `dmatensor<bf16>`). The update v\* times c plus O is computed in fp32 and stored through `fp32s_to_bf16s`, which truncates toward zero [h/tron/simd/bf16.hpp:53]. P, by contrast, is rounded to nearest even inside the PV kernel. Both the AVX and AMX arms share the v\* truncation.
- The page must stay pure ASCII before publishing (Artifact publishing path decodes as Latin-1, see the 2026-09-13 session). The generator writes symbols as numeric entities for that reason.
- The Workflow journal marks finished agents with `"type":"result"` lines, not `"type":"completed"`. A wait loop keyed on "completed" exits at once with a count of 0.
- Render check used a fallback font wider than the page's IBM Plex Sans, so text that fits in cairosvg fits in the browser.
- Preservation followed the five-step recipe in memory `notebook-preservation-convention.md`. The push was made because the user asked for the repo update explicitly.
