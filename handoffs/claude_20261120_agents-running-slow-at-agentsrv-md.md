## Words used here

- **agentsrv**: a shared Linux development server with 32 CPUs. An admin rule allows each user 8 CPUs, 64 GiB RAM and 8 GiB swap.
- **claude-dev**: the podman container on agentsrv in which the user runs coding agents. Its hostname is **claude-agentsrv**. This Claude Code session ran in it.
- **Agent**: one Claude Code session or one Codex session. **Codex** is the OpenAI Codex command line.
- **Quota**: the CPU time that all processes of one user may use, 800 ms per 100 ms period. When it runs out, the kernel pauses every process of the user until the next period.
- **Stall**: time in which every process of the container that wanted to run had to wait for a CPU. The kernel counts it in the file cpu.pressure, line "full".
- **Pin**: the list of CPUs on which a process may run (its CPU affinity). Child processes inherit it. The command `taskset` sets it.
- **Guard**: the new file /home/jhan/.config/agent-cpu-guard/guard.sh.
- **BASH_ENV**: an environment variable. bash reads the file that it names before each non-interactive command.
- **nproc**: a command that prints how many CPUs the calling process may use.
- **Probe**: a test thread that does 0.3 ms of work and then sleeps 5 ms, again and again. It is not pinned, and it stands for an interactive tool.
- **Probe speed**: the probe's rounds per second, as a share of its speed with no load (192 rounds per second).
- **Burst**: a period of under one second in which many CPUs are busy at once.
- **tmux**: a program that keeps terminal sessions alive. A **tmux client** is one terminal attached to a session.
- **tmux-continuum**: a tmux plugin that saves the window layout through a script in the status line.
- **herdr**: the terminal manager in which the user runs agents today.

- **claude-box**: the launcher script /home/jhan/claude-container/claude-box that creates and enters the container.

## Gotchas and decisions

- Decision by the user at 20:44: detach the 54 idle tmux clients with a plain `tmux detach-client`. The session also offered an option that ends the shells behind the clients. The user did not choose it.
- Answer to the user's question about permanence:
  - The guard is permanent. It consists of files only, and each new command loads it again.
  - Five of the six changed files are on the NFS home.
  - The sixth is the container's Codex config. It is on the host's local disk in /var/tmp/jhan/persist/codex-home. claude-box mounts that folder into every container it creates.
  - The tmux detach is one-time.
- The guard can stop working without an error in three cases:
  - the host name changes,
  - the machine shows fewer than 32 CPUs,
  - a tool stops passing BASH_ENV.
- The rule line "If `nproc` reports 32 ... tell the user" exists for these cases.
- Coverage: the guard pins only what an agent starts through bash. The agents themselves, their built-in file search, herdr and tmux are not pinned. Interactive bash and `sh` do not read BASH_ENV.
- All agent commands together now get 6 CPUs, not 8.
- Three ways to turn the guard off:
  - For one command: `taskset -c 0-31 <command>`.
  - For every session at once: delete the line with the two host names in guard.sh.
  - Completely: take the `env` block out of settings.json and the policy block out of both Codex config files.
- A test harness that must run unpinned needs `taskset -c 0-31 env -u AGENT_CPU_GUARD -u BASH_ENV <command>`. A nested `claude -p` or `codex exec` started from a guarded shell inherits the pin and the marker.
- `os.cpu_count()` still returns 32. Size pools from `nproc` or `len(os.sched_getaffinity(0))`.
- `codex exec --remote unix://SOCKET` accepts only the prompt, resume and output options. Options such as `-C` or `-c` make it fail.
- `pgrep -f PATTERN` matches the searching command line too. Anchor the pattern, for example `'^sleep 13'`.
