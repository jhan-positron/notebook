## Gotchas & decisions

- Decision: AMX code stays uncompiled in every CI configuration until the CI team adds one; the interim substitute is running `exec/p2-verify-after-ci.sh` on delphi-3bda before pushes. The failure class this guards against was demonstrated the same day (`p2-verify-after-ci.round1.txt` records a canonical-build failure caught only by the manual run).
- Decision: verify-run results go to project memory, never into the PR description.
- The verify script builds the NFS-shared checkout as it is at build time, not at launch time — the queued run launched for `298dbad0f` actually validated `3fa11d911`.
- The round generator `exec()`s its data file, so `__file__` inside `round*_data.py` points at the generator's directory; `r5/round5_data.py` carries the workaround comment.
- clang diagnostics carry ANSI color codes; the syntax-check driver (`fixcheck.py`) must strip them or pass `-fno-color-diagnostics`.
- Never size a `thread_local` array by a plugin constant inside a model template: ingest-generated plugins hard-code `max_minibatch_size = 1024`, giving an estimated ~52 MB of static TLS per thread across instantiations (the rejected R1-12 fix; lesson saved to memory).
- The review HTML/MD always describe the tree at generation time; commits made after generation (e.g. the 2026-08-25 evening fixes) are not reflected until the next round.
