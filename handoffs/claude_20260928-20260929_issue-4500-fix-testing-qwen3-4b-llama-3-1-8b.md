## Words used here

- **tron**: Positron's inference program (GitHub repo positron-ai/tron). **runtron** is its command-line tool (one process). **rinzler** is the production server, the one the nightly CI uses.
- **PR 4424**: https://github.com/positron-ai/tron/pull/4424, the draft PR that stores the attention key (K) cache in the VNNI layout. Its head at the time was 30c4ac82cb. **VNNI K** or **vnni** below means that layout and that PR.
- **Issue 4500**: https://github.com/positron-ai/tron/issues/4500, the decode throughput loss of PR 4424 when attention runs on the FPGA card. Root cause (found 2026-09-18/19): the per-token K save, the K gather for the card and the workers' tail scoring each access one token's K row across 64 cache lines instead of 4.
- **The fix** (also "row-major tail block"): a 16-token K block keeps its rows row-major inside its own 4 KiB until all 16 rows are saved. Then the main thread converts the block in place to the VNNI layout.
- **AMX**: Intel Advanced Matrix Extensions, the matrix instruction set the K layout serves.
- **Four binaries measured**: base = the canonical AMX build (main of 2026-09-18, row-major K). vnni = PR 4424 on the same main. fix = vnni plus the fix. nightly = the package installed on the machine (main of 2026-09-28).
- **TPS**: decode tokens per second per user, measured by the nightly's own client over 10 rounds. Step ms = 1000 / TPS.
- **tp2, tp4**: tensor parallel degree (how many FPGA cards one engine uses). **8u** = 8 users per engine. **p1024, p4096** = prompt length in tokens.
- **Paired t**: the paired t statistic over repetitions. The threshold used is 4.30 at n = 3. "n.r." = not resolved (the statistic did not reach the threshold).
- **deb**: the Debian package the nightly installs. The **deb line** is a separate detached worktree that holds the ci-mimic target build (main 3faba6d0fd plus PR 4424 plus the deb preset, commit 29a8a54740) with the fix commits cherry-picked on top.
- **delphi-3bda** (also "3bda"): the CI machine. **Our half** = socket 1 and FPGA cards 90/93/b9/bc. **The lease** = /run/lock/systems-test-ci.lease, held by the nightly CI.
- **The chain**: exec/i4500fix-20260928/chain.sh, a detached script on delphi-3bda that runs steps A to E (build and unit tests, deb build, token smoke, throughput cells, row-major build and tests). (preserved: artifacts/intel-amx/exec/i4500fix-20260928/chain.sh)
- **Smoke**: runtron with one user, temperature 0 and a fixed seed, comparing the generated token rows of two binaries. **fix2** = a second run of the fix binary (the A/A control).
- **Fake device**: the unit tests run without an FPGA card.
- **EAGLE view**: a KV-cache storage view used by speculative decoding. It has its own K layout state entry in the fix.
- **Workflow**: the multi-agent review tool. Readers find issues, refuters try to disprove each one.

## Gotchas and decisions

- Never touch a page's K layout state before a token is relevant. Test books with logical_slot_count() == 0 exist, and k_state_ix asserts on them. This was the second test failure.
- A book type with no x bytes cannot carry EAGLE storage. The EAGLE-view test must use uniform_kv_cache<1, geom, 16>.
- The fix is three states, not two: saved rows and converted blocks are separate bit sets per storage slot. The invariant "block VNNI <=> its 16 bits set" from the first commit was dropped after the first review because a block split across two minibatches raced the readers.
- The in-place transposes in page copies and clears rely on the existing rule that no forward reads a book during tree work (the same reliance the book relocation has). A reviewer suggested a "forward in flight" tripwire assert. It was not added on purpose. The Note in kv_cache.hpp records the reliance instead.
- The concurrent reader of a pending page is the cooperative GOF staging gather, not the attention workers. A pending page is read only after all writer minibatches ticked the latch. The first commit's comments said otherwise and were corrected in 617cb8333f.
- delphi-3bda has no gdb. addr2line over the 1 GB test binary takes about 5 minutes per address, so run it in the background.
- The workflow task output is a wrapper object. The result is under the `result` key.
- Chain design: every step waits for the lease (600 s grace) and for other users (Rhys blocks it, Bill is excluded by the half-split rule). Step D takes idle production serving down through lib-guard and restores it at the end, keyed on a marker file.
- summarize.py's cell-name regex must accept hyphens in model names ([\w-]+). The first version did not.
