### Verdict and top findings

- Issue #4525 captures the request. Two additions would make it self-contained: one sentence naming the problem (bare bf16 pointers carry no layout), and one-line definitions of packed V, native K and PR 4424's blocked K.
- jhan's reading of Ben's reservation is right: the address formula belongs in the view, and storage stays a separate owner. Ben's sketch uses a template parameter shared by storage and view, not a chain. Ben voiced a doubt, not a decision.

- The 9 majors: (F01) the model's V save path is never named, so a stale NaN in the odd partner row could corrupt the weighted sum if `save_v_impl` took the pair-preserving path; the design must say `save_v_impl` keeps calling `page::set_v` implemented with the zeroing append; (2) the revision table calls live main 98bb8cb2 "stale" though it is 79 commits newer than the snapshot; (3) no table maps existing accessors (set_v, get_v, v, v_ptr, v_data, v_base, append_v, scaled_v, k) to keep, rename or remove, and `page::k_tensor` duplicates `page::k`; (4) slices and iteration have no caller at either main revision or in PR 4424; (5) no rule for the 8-lane (AVX512=OFF) build; (6) "placement construction" is under-specified and `std::start_lifetime_as` is not in the pinned libstdc++; (7) the required-CI AMX demand has no owner and issue #3997 already tracks it.
