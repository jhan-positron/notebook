## Words used here

- **TRON**: Positron's inference software, the repository positron-ai/tron. **rinzler** is its server program. **runtron** is its command-line runner.
- **Agent**: an AI coding tool that edits files and runs commands. Here it is Claude Code.
- **Lint rule**: a check that a program runs on source text. It passes or fails without human judgment.
- **AGENTS.md**: a text file in a repository that tells agents how to work there.
- **lefthook**: a tool that runs a list of commands at each `git commit`. TRON's list is the file lefthook.yml.
- **CI**: the automatic checks that run on a server after each push.
- **Nix**: the package tool with which TRON's CI runs the same lint checks (the check `lint-toolchain` in flake.nix).
- **Baseline**: a file that lists the old hits of a new rule. With it the rule fails only on new hits. A **hit** is one place where a rule matches.
- **TLA+**: a language for describing a system as states and steps. **TLC** is its model checker.
- **Model checker**: a program that tries every order of steps. It prints the shortest step list that breaks a rule.
- **Lean**: a proof assistant. A proof checked by Lean holds for every input. `omega` is its procedure for integer arithmetic.
- **Capture slot**: the class `capture_controller` in src/pos/trace_capture.cpp. It lets rinzler record one trace capture at a time. Three threads use it: the FUSE request thread, the capture worker thread and the SIGUSR1 thread.
- **FUSE**: the file-system interface through which rinzler takes commands such as "start a capture".
- **SIGUSR1**: a Unix signal. Sent to rinzler, it starts a capture of 10 seconds.
- **Catch2**: the C++ test framework that TRON uses.
- **Seeded bug**: a bug put into the model on purpose, to see whether the checker finds it.
- **chunk_evenly**: the function in h/tron/models/model.hpp that cuts the token jobs of one forward pass into minibatches.
- **Token job**: one token that a forward pass computes.
- **Minibatch** (also "chunk"): a set of token jobs that are computed together. The cap is 128 token jobs per minibatch for the llama plugin.
- **Group**: the set of token jobs with the same affinity label, for example the tokens of one prompt.
- **Grain**: up to 8 token jobs of one group. chunk_evenly never splits a grain.
- **max_minibatches**: a TRON option that limits the number of minibatches. It is `--max-minibatches` in runtron and `--max-batches` in rinzler. The default is -1, which means no limit.
- **PostToolUse hook**: a Claude Code setting that runs a command after each file edit.
- **Skill**: a file of instructions that Claude Code loads when the user types its name with a slash.
- **Auto-mode classifier**: the permission check of Claude Code that can deny a tool call.
- **The article**: the user quoted it in Chinese and did not paste it. The session traced the quotes to Lauren Tan's talk "All Code Is Slop (Except Mine)" at AI Engineer CODE 2026.
- **claude-agentsrv**: the podman container this Claude Code ran in, on the user's Linux dev server agentsrv (same home directory, same files).

- The four rules:
  - OneCapture: a SIGUSR1 capture never runs beside a FUSE capture.
  - AssertActive: while the worker runs a capture, the slot is not empty.
  - OwnJob: the capture in the slot is the one the worker runs.
  - NeverStuck: the slot can always become empty again.
- One run takes about 0.01 s.
- The trace of seeded bug 1 has three steps:
  1. The FUSE thread starts capture 1.
  2. The worker's `take_start()` returns capture 1.
  3. The FUSE thread stops capture 1 and empties the slot.
- After step 3 the worker holds a capture that the slot no longer has. Its next `TRON_ASSERT(active_)` would fail.
- TRON's unit test at t/t_trace_passes.cpp lines 683 to 699 already covers that order.
