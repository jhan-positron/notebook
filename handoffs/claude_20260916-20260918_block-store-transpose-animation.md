## Words used here

- **tron**: Positron's inference program (GitHub repo positron-ai/tron). **runtron**: its command-line tool.
- **claude-agentsrv**: the podman container this Claude Code ran in (host machine `agentsrv`, called `claude-box` in the user's notes). **delphi-3bda**: the Intel Xeon 6 6962P test machine (DUT = device under test). /home/jhan is NFS and shared by both.
- **AMX**: Intel Advanced Matrix Extensions. **AVX-512**: the 512-bit vector instruction set used by the store code here. **VNNI**: Vector Neural Network Instructions. In this project "VNNI K" means the K cache stored in the pair-interleaved layout the AMX and VNNI kernels read.
- **K, V, KV head**: the key and value vectors of one token in one attention layer. qwen3-4b (the model under test) has 8 KV heads of 128 dimensions per layer.
- **K row**: one token's 128 bf16 values for one KV head, 256 bytes. **dim pair**: two neighbouring dimensions, 4 bytes. **dim step**: 16 dim pairs, 64 bytes, one cache line.
- **bf16**: the 16-bit brain floating point format the K cache uses.
- **page, plane, block**: a KV cache page holds 64 tokens. The plane is one KV head's K storage of one page (16 KiB). A block is 16 consecutive tokens of a page.
- **block store**: remedy (a) of the report. save_k loads 16 token rows, transposes them in registers and writes each 64-byte line whole (`k_vnni::store_block`).
- **shared block save**: remedy (b) of the report. The report calls it "striping". The main thread cuts the pass's token list into units, opens a window, and the idle main helpers claim units from one atomic counter (`save_k_helper`, `k_store_window`).
- **per-token scatter**: the store of the earlier binary: 4 scatter instructions per token row (`k_vnni::scatter_row`).
- **prefill, decode, pass, item**: prefill processes the prompt in passes of up to 1024 token items. Decode generates one token per user per pass.
- **tp2, tp4**: the model split over two or four FPGA cards (tensor parallelism).
- **main thread, main helpers, attention workers**: the three thread classes of the generated qwen plugin.
- **Save K**: the Perfetto trace span of `save_k_impl`, the K store of one layer.
- **L1D**: the level-1 data cache, 48 KiB per core on delphi-3bda. **DRAM**: main memory. **cache line**: 64 bytes.
- **the report**: status/store-remedies-report.html, "VNNIed K in place: the K store, measured and shortened", generated by exec/vnnik2-20260915/gen_report.py.
- **artifact**: a page published to claude.ai through the Artifact tool. Each has a fixed URL and numbered versions.
- **Workflow**: the multi-agent verification tool. Each round fans out reviewer lenses and checks every finding with two skeptic agents.
- **ground truth**: a small C++ program that runs the real tron function on mock data and dumps the result. The pages' tables are generated from it.
- **nix**: the package manager whose profile used to provide tron's compiler on claude-agentsrv.
- **PR 4424**: https://github.com/positron-ai/tron/pull/4424, the VNNI K pull request (branch `jhan-amx-vnniK`).

## Gotchas & decisions

- The four dim steps of a K row are one contiguous 256-byte row. Figure 3.1a of the report stacks them only for width. The block store reads that one row in four loads at four different times (steps 6, 39, 72 and 105 of the 132-step animation).
- Store order is the program order of the two loops in `store_block` (dim step outer, pair row inner). A final-state check cannot observe order, so the page states it from the code, not from the ground truth.
- `g++` 11 on claude-agentsrv has no `__bf16`. `exec/block-store-animation/shim/common/numerics/bf16.hpp` replaces tron's bf16 header for the ground-truth build. Rerun `build-gt.sh` if `k_vnni.hpp` changes.
- `~/.nix-profile` on claude-agentsrv points to a missing target, so `~/.nix-profile/bin/nix` no longer runs. Recorded in memory `claude-box-tron-build-env.md`.
- No node, deno or browser exists on claude-agentsrv or in delphi-3bda's default profile. JavaScript can only be checked by static reading, bracket balance and a Python replica of the simulation.
- The Artifact tool wraps the file in its own `<!doctype html>` skeleton. The pages carry their own skeleton too. The `html.parser` check therefore reports `unclosed: ['html', 'body']`. That is expected.
- Every generator patch in this session is a Python script that asserts each search string occurs exactly once. A string that spans two Python literals fails the assertion and nothing is written. Check the failing string, then rerun the whole patch.
- The report generator `exec/vnnik2-20260915/gen_report.py` writes to the checked-in report path by default. Regenerating it changes only the "Generated" timestamp plus whatever was edited.
- Wording rules the reviews enforced: define cell, panel line, plane line, item versus token. Never write "arm" for a binary configuration (the user's rule of 2026-09-15, memory `vnni-k-terminology`). Say "shared block save", not "striped block store". Label every cache-behaviour statement as measured, model or hypothesis.
- A fixed-width "overview" strip must be computed from cell width plus gaps plus padding plus borders. Round 1 asked for 64 cells that fit in 1000 px, and round 2 found the result was 1014 px. A fluid flex strip fixed it.
- The measured spans come from commit 9928cb2849, whose window used 16-item blocks and two join counters. The page animates the head protocol (page-block units, one counter). For the mock pass both cut rules give the same 64 units.
- The unit cut rule starts a new unit on every change of the KV flag, the page or the block. A token without KV work in the middle of a block splits that block into three units.
