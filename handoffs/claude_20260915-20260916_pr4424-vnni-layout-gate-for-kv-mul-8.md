- **reader** or **qk_group**: the AVX-512 routine that scores tokens from the VNNI plane. **dotter**: the per-token AVX-512 loop over row-major K. **scatter store**: the per-token K store of a lone token into 64 cache lines.

Reading of the traces: the scatter store of a lone decode token adds about 0.7 ms to 0.8 ms per step on the main thread. The reader is faster than the dotter per worker at every prompt length. At prompt 1024 the two cancel. At prompt 8192 attention dominates the step and the reader's gain sets it. In prefill the block save plus the reader cut each pass by 50 ms to 400 ms, and pass count times that cut equals the TTFT gains (8 passes at 1024, 64 passes at 8192). The prompt-2048 loss is real (3 repetitions) but its traces do not explain it: attention per worker is 1.0 ms faster and the store 0.8 ms slower, yet the step is 2.3 ms slower. The report states this as an open hypothesis (attention and expert kernels balanced at that length, so the serial store lands on the critical path).

## Gotchas & decisions

- The 2026-09-15 one-run loss compared the VNNI binary against the old base binary 544ca05c7a, not against `main`. This campaign used `main` c7844ca2ce as base and added the headoff arm (PR head with the layout off) so that the PR's code and the layout are separated. headoff equals base in speed and tokens in every cell.
- The nightly held the lease until 13:18 UTC, later than the 11:30 to 13:20 UTC window seen on earlier days. The chain must poll the lease itself. Two rinzler units were still running after the lease cleared, and the guard stopped them after the 10-minute idle check.
- GUARD_TAKEOVER_LAST (the epoch of our last rinzler stop) is a plain shell variable in lib-guard.sh. A child script that sources lib-guard.sh starts with 0 and would bypass the 6-hour rule. Export it in the parent and hand it back from the child through a file (takeover.last).
- Do not edit a running bash script (bash re-reads by byte offset). The review fixes were applied while only chain.sh was running and before campaign.sh, trace.sh and build.sh had started.
- Background `sleep` waiters get killed by the container's low-memory rule when swap is full. Use the Monitor tool (30-minute expiry, re-arm) instead. Perfetto trace_processor daemons started by analyze.py stay alive after the script exits unless `tp.close()` is called.
- The Monitor command must use absolute paths. A `cd` inside it printed a directory listing as the first event.
- The campaign monitors report every status line unless filtered. The second monitor was replaced by one that reports phase changes, smoke results, failures and completion only.
- Trace overhead: traced TTFT was within the run-to-run spread of untraced runs (5.226 s traced against 5.262 s untraced at tp2 prompt 1024).
- Decision: the pre-registered rule (paired t below -2 for a loss) was written in PLAN.md before the runs. The report text is generated from the data, so the Short version changes wording with the outcome (loss, gain, or not resolved).
- The dataviz palette validator needs node, which claude-agentsrv lacks. The chart colors are the reference palette's validated pair (blue #2a78d6, orange #eb6834, gray #8a8987) and every value is labeled as text.
- The page published as an artifact needs the `<!doctype html>`, `<html>`, `<head>` and `<body>` wrapper stripped. The generator writes a second copy for that.
