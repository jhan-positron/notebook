## Current state

The completed report concludes that **a single persistent swizzled CPU K is technically viable**, with a storage-interface migration and native pagewise AVX readers. FPGA transfers already use a separate GOF shuffle buffer, so direct layout-aware reads can feed the existing hardware format. The mirror’s rationale is migration scope and performance risk, rather than an ISA or FPGA requirement for canonical CPU K.

The design selects immutable encoding per physical slot before first write; replaces contiguous-row assumptions with explicit store/read/copy/staging interfaces; preserves conversion and completion publication; dispatches by encoding before choosing AMX/AVX; masks memory loads and transformed scores; migrates append/defrag/overlap/EAGLE operations; and keeps a process-start canonical rollback. Direct GOF packing is preferred, with bounded unpacking useful as a test oracle or deterministic reference fallback.

Removing the external mirror saves one third of the allocated three-plane KV payload for mirrored slots. It saves ordinary RAM and leaves the existing two-plane hugepage capacity unchanged. The production single-K path was **designed, not implemented**. The standalone proof does not link Tron, and full builds, AMX execution, FPGA DMA, integrated accuracy and production performance were not validated.

## Gotchas & decisions

- Bill’s older layout orders token blocks before dimension blocks; the reviewed mirror reverses those outer axes. For K[0][32], the BF16 offsets are 512 and 2048 respectively. Porting the older simple stride formula directly would address the wrong values.
- A token’s successive dimension pairs within a panel are **64 bytes** apart, correcting the review comment’s 32-byte claim. A token touches 64 swizzled cache lines versus four canonical lines; locality and false sharing still need measurement.
- Swizzled load masking must avoid inactive or concurrently written columns. Output masking alone is insufficient, and a negative-infinity sentinel must remain effective after softcap.
- Layout preserves K bits but changes summation order. The local BF16 and FP32/FMA paths were not bitwise equal to the canonical transcription; BF16 subnormal semantics also differ from ordinary FMA. Repeatability and reference-output compatibility are separate contracts.
- Bill’s historical performance figures concern an older mirrored implementation and were not independently reproduced. They do not establish a single-K speedup. The PDF source-access limitation from the first answer was resolved by the user’s supplied file.
