## Short version

The user asked why the 120-thread memory throughput on CRB (the Arm reference server) fell with the new test loops. The session measured that only read really fell (about 300 GB/s against about 468 GB/s, 36 % lower): the load-only loop lets each core work on 36 to 40 cache lines at one time instead of 18 to 22, and the rule inside the core behind this is not established. The reboots of a firmware throttle test showed a second fault: CRB started with 10 of its 12 memory modules in 5 of 12 boots at 8000 MT/s, and after the session set the memory speed to 7200 MT/s, 6 of 6 reboots gave 12 modules.

## Words used here

- **CRB**: the Arm Phoenix Reference Server. It has 128 Neoverse V3AE cores. Its address is 192.168.2.45 and its Linux hostname is `ubuntu`. It is a shared machine, and only CPUs 0 to 119 may be used.
- **Mesh 0, mesh 1**: the two halves of the chip (two CMN S3 meshes, Arm's on-chip interconnect). CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **64+56, 120 threads, whole chip**: 64 threads on CPUs 0 to 63 plus 56 threads on CPUs 64 to 119. Each thread reads its own 256 MiB buffer from DRAM. Other layouts are written the same way, for example 64+32.
- **Kernel, loop**: the inner loop of the memory benchmark. It is not the Linux kernel.
- **Old read loop (`oldread`)**: portable C. One pass has 4 `ldp q` loads and 8 vector adds per 128 B. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **New load-only loop (`asmread`, and the new C read)**: 8 `ldp q` loads per 256 B and nothing else.
- **`read_nopN`**: the load-only loop plus N `nop` (do-nothing instructions) per 256 B. **`read_1pl`**: one load per 64 B line. **`read_daddK`, `read_iadd16`**: the load-only loop plus vector adds that use, or do not use, the loaded data. **`rand_nop0`, `rand_nop96`, `rand_nop256`**: the same loads in a scrambled block order.
- **Window, window depth**: the out-of-order window is the list of instructions that a core has fetched and not yet finished. Window depth is the number of 64 B cache lines that the loads in the window cover.
- **robsize**: the one-thread test this session wrote to measure the window (two cache-missing loads with N filler instructions between them).
- **bwx11, bwx12, bwx13**: versions of the benchmark runner program. bwx11 existed before this session. bwx12 (bwx11 plus 26 loops) and bwx13 (bwx12 plus the 3 scrambled-order loops) were built in this session.
- **Common stop, whole-pass stop**: two stop rules. With a common stop all threads stop at the same time. With the whole-pass stop of bench/bandwidth.c each thread finishes the buffer pass it is in.
- **GB/s**: 1e9 bytes per second, summed over all threads.
- **Busy level (CBusy)**: a number from 0 to 3 that each response of the interconnect carries back to a core. Level 3 means that the sender's queue is nearly full.
- **TXREQ, "CPU TXREQ Throttle"**: TXREQ is Arm's name for the outstanding memory requests of a core. The firmware has a setting group with this name. It lets a core lower its request limit when it sees busy level 3.
- **MPAM**: a memory-partitioning feature of the chip. It is off on CRB.
- **uefisettings**: the tool from the Arm welcome kit that reads and writes firmware settings from Linux. It needs root.
- **Arm welcome kit**: Arm's support files for CRB in /home/jhan/workspace/vendor-resources/ARM/agi-cpu-welcome-kit (12 GB, documents for firmware 0.9.0).
- **DIMM, module**: one memory module of 32 GiB. CRB has 12 slots, 6 per half. The slot names are `DIMM_CP0_0` to `DIMM_CP0_5` and `DIMM_CP1_0` to `DIMM_CP1_5`.
- **MT/s**: million transfers per second, the unit of memory speed. **"DIMM Frequency"**: the firmware setting for it.
- **Training**: the step at power-on where the firmware tunes the signal timing of each memory module.
- **Error record**: a message that the firmware passes to Linux when hardware reports an error. Linux prints it in the kernel log with the tag `[Hardware Error]`.
- **BMC**: the management controller on the board. **EVT0, EVT1**: board revisions. CRB is EVT0.
- **RUNNING marker**: the file /tmp/positron-perf.RUNNING on CRB. Another user creates it during timed runs. Every command of this session stopped when it existed.
- **Jeremy**: a colleague who runs timed blocks on CRB and announces them in the Slack channel #phoenix-crb.
- **Load average**: the mean number of running or waiting tasks over 1 minute, as Linux reports it.
- **Workflow**: the multi-agent tool of Claude Code. **Ultracode**: the `/effort ultracode` mode, which runs a workflow for every substantive task.
- **FINDINGS.md**: the facts sheet of this investigation. The two report pages take their numbers from it.
