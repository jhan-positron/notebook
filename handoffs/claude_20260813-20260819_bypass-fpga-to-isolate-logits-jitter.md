## 1. Objective

Find the cause of TRON (Positron FPGA inference) decode-TPS fluctuation on qwen-3-4b tp4. The session's entry point: a verification hack — bypass the FPGA during `fill_logits_buffer` (hold the RX driver a constant time, return garbage logits) so that, if jitter collapses, the FPGA's wcls/logits processing is proven to be the cause. The session then ran a chain of exclusion experiments as each hypothesis fell, ending with a burst-resolved DDR/HBM peak-bandwidth test.

Final state of the exclusion ledger (all measured, all reported): wcls pipeline ruled out (bypass), CPU frequency/power/throttling ruled out (lowered_freq), ingestion path ruled out (peer's Mixtral A/B), host DRAM bandwidth ruled out (average and burst-resolved), FPGA compute + HBM ruled out (constant chip work per token, burst-resolved). Standing suspect: per-engine-bring-up host thread-handoff latency (worker join, RX-to-scheduler wcls delivery, listener notify — they slow together as a per-draw level shift).

### 4.1 wcls FPGA-bypass A/B (delphi-3c51, 2026-08-13 night; 16 draws/arm, ~65.5k tokens/arm; numbers independently recomputed twice, exact agreement)

| metric | control (knob off) | bypass (2.5 ms hold) |
|---|---|---|
| TPS range | 164.6–173.0 | 117.3–121.2 (slower by design) |
| TPS CV across draws | 1.32% | 0.80% (rescaled to control mean: ~1.14%) |
| within-draw token period F3→F3 p90−p10 | 1559 µs | 1538 µs (−1%) |
| forward pass (intra-pass span) p90−p10 | 1437 µs | 1456 µs (unchanged) |
| transfer [open→F1] p90−p10 | 398 µs | 397 µs |
| logits [F1→F3] (pinned stage) p90−p10 | 373 µs | 154 µs (−59%) |
| corr(F1F3, TPS) | −0.86 | −0.06 |
| inter-pass window share of per-token variance | 29.4% | 19.2% |
| total per-token variance | 410,112 µs² (sd 640.4 µs) | 374,299 µs² (sd 611.8 µs) = −8.7% variance, −4.5% sd |

Verdict: pinning the wcls stage left the period spread at 99% of control — the wcls pipeline is ruled out as the fluctuation cause. The bypass removed ~40% of the window's own variance (a real but minor cause, ~12% of total). Two variance pools clarified: within-run per-token wobble is span-dominated (57–68% pre-bypass), while the fast4→slow4 draw-speed difference is window-dominated (64–66%) — both true simultaneously; report 01's remembered 74.7% is the cross-draw row.

### 4.4 DRAM bandwidth ceiling (delphi-3bda, 2026-08-16, `3bda-drambw-tp4-20260816T195258Z`, 16/16)

- Measured ceiling (28 membw readers, quiesced, same IMC instrument): ≈220 GB/s reads per socket.
- Decode: mean 11.5–14.4% of ceiling; busiest single second of any draw 30.4%. ~8× headroom at mean, ~3× at worst second.
- corr(TPS, bandwidth) = +0.57; corr(TPS, peak-second utilization) = +0.74 — demand-limited, not supply-limited.
- Side findings: IMC `cas_count` under-reports bytes by exactly ×2.01 on this platform (DDR5 sub-channel CAS at 64 B scale; ratios immune); turbostat RAMWatt flat ~57.5 W regardless of TPS (useless as a discriminator).

### 4.5 FPGA status — fpgastat arm A and arm B (delphi-3bda, 2026-08-16/17)

Arm A (`fpgastat-20260817T013917Z`, 16/16 but regime-perturbed — TPS halved to 87–92 by the tracer-core collision; trust only qualitative claims): HBM read duty (pchan 0) 6.5–6.9%; matmul engine busy 1.4% of cycles; stalls ~1.1% (virtually all weight-fetch; result-path zero); activation command queue empty in 1.000 of snapshots; correlations demand-following (+0.96).

Arm B (`fpgastat-armB-20260817T114401Z`, fence-flip capture, 16 fence draws + 3 controls, 19/19, fence draws 157.4–171.8 tok/s, CV 2.43%):
- Chip work counters single-valued to the cycle across all 65,504 token×device samples: [F1→F3] = exactly 47,520 HBM-read + 11,880 matmul cycles every token; rest-of-cycle = 253,440 + 63,360. Slowest-decile tokens carry identical chip work to fastest-decile.
- Only wall time varies: rest-of-cycle wall corr −0.98 with draw TPS. Chip ~80% idle even inside the window; result FIFO peaks 1188/4096.
- The user's discrepancy resolved: in the window the chip streams one fixed job (lm-head weight slice, ~97 MB/device est., matches fp8 lm-head to 0.2%) then idles; the CPU's waits are for host-side delivery and logits-buffer writing, not chip compute. Both sides idle at the same time is real.
- Measured instrumentation cost from matched controls: 4.1% (172.5 → 165.5 tok/s).
- HBM duty at production speed: ~19% in [F1→F3], ~12.6% rest-of-cycle, 13.5% exposure-weighted; weight-memory stall ≈20% of engine time in the window (~132 µs/token, constant ±0.8 µs).

### 4.6 Window-waits mining (report 05; arm B data, no machine time)

Fast4 (170.1 tok/s) vs slow4 (160.3), +360 µs/token delta:
- Serial budget: [open→F1] +112 µs (31%), [F1→listeners-notified] +159 µs (44%), [notify→end] +23 µs (7%), 36-layer span +65 µs (18%). Window carries 82% of the draw-level delta.
- The three growing waits: `fill_logits_buffer` +147 µs (corr TPS −0.70), `listeners_notified` +110 µs (−0.64), `workers_done` join +70 µs (−0.79). Inside fill, the growth is entirely the wcls block-arrival tail (489 µs fastest draw → 897 µs slowest; post-arrival processing constant ~30 µs).
- Chip turnaround constant: tx-dispatch→rx-completion median 19.9–20.2 µs, p99 73–84 µs, every draw; slow−fast +0.0 µs.
- Level shift, not contention events: within a draw the three waits are pairwise uncorrelated (≤0.14) token-to-token; every token in a slow draw pays a near-constant surcharge set once per engine bring-up. 77% of within-draw period variance remains the span (separate pool).

### 4.7 Peak/burst DDR + HBM (delphi-3bda, 2026-08-19, `peakbw-20260819T221215Z`, 16 window-mode draws + 3 controls, 19/19, TPS 159.8–180.1)

- H1 DDR at 10 ms windows: decode windows peak at 28–30% of the same-counter calibrated ceiling (p99), max 32–42%, all on the one active socket (socket 1 ≤0.5%). Only near/above-100% windows are a deterministic end-of-run teardown burst (~1.3 GB in one window, present in fast/slow/control alike).
- H2 memory-controller queue pressure: traffic-weighted RPQ residency per read 11.0–11.2 units in every draw (slow4−fast4 = +0.3%, bar 1.6%) — does not fire. Decode's residency is 2.15× the saturation reference: latency-class scattered reads, invariant across draws.
- H0 CPU memory-bound share: fires numerically (25.9% fast4 → 30.2% slow4, corr −0.78) but confounded — most plausibly the load signature of extra waiting (report 05 level shift). Tiebreaker = the placement/wakeup campaign's per-core breakdown.
- H3 HBM at ~278 µs windows (97% coverage, ~86k windows/draw): read duty p99 45.93–45.97% in every draw, max 52.8–55.3%, zero windows ≥90%, no burst spans two consecutive windows; fine-window totals reproduce arm B's per-token constants at ratio 1.000.
- Bonus: `id_dat` register = 0x0105080016062026 → bitfile 01.05.08.00 dated 2026-06-16 — report 04's tracer-ABI question settled (deployed bitfile predates the RTL-HEAD tracer word; missing `compute_phase`/`act_*` bits are ABI lag, not bugs).

## 8. Gotchas & decisions

- **Build traps (tron worktrees on alpha)**: `config/models.local.yaml` is gitignored — a diff-port misses it and the build then fails ingesting gated HuggingFace models. The Fence-1 tag-7601 hand-edit lives in the GENERATED plugin header (gen/src/tron/h/tron/plugins/qwen_3_4b_instruct_2507.hpp) and is WIPED by any plugin regeneration — always re-verify after builds (archived copy: trace-sync-points/data/fpgause-gen-plugin-4ceaca1a.hpp.gz). Build in the `nix develop` shell (missing ccache/cargo otherwise); build with `ninja -C gen runtron`.
- **New main's RUNPATH is `$ORIGIN`-relative**: install dirs on /scratch must carry `libversion.so` AND `libfuse3.so.4` in lib/; verify with strict ldd from the DUT under a scrubbed environment.
- **3bda host facts**: `rdmsr`/`wrmsr` not installed — read MSRs via /dev/cpu/N/msr (harnesses do this now). No RAPL perf PMU on this kernel — power via /sys/class/powercap (`RAPLCAP=1`) or turbostat. No standalone perfetto binary — parse-test configs against tracebox (v57.2). No working RPQ-inserts IMC encoding on Granite Rapids (event 0x10 dead, 0x20 is the write queue).
- **TRON pins TX driver threads to cores 3/4/5/6** (work_queue 24, worker 25, RX 147–150): any pinned helper (tracer) on those cores halves TPS. Use TRACER_CORE=16. This also re-attributed arm A's halving — it was never perfetto category overhead.
- **`pgrep -x runtron` misses runtron** (it renames its threads) — match the full command line; also beware `-f` substring self-matches.
- **Campaign hygiene now standard**: smoke barrier (TPS ≥ 160 + token sha `66af1d58…` + kvwait liveness) — it saved two campaigns; host-wide lock /var/tmp/jhan/3bda-campaign.lock; pre-launch guard (no runtron AND no campaign root younger than 3 min); matched control draws in-campaign; CI-lease check (peakbw harness); safe stop = `kill -TERM $(cat $ROOT/harness.pid)`, never SIGKILL.
- **Statistics conventions** (report 03 R.5): CV needs rescaling when an intervention moves the mean (variance/sd do not — translation-invariant). Two distinct variance pools: within-run per-token wobble (span-dominated) vs draw-to-draw speed (window-dominated); quoting a share change as a jitter change is a trap (the denominator moves too). Utilization SHARES mislead when the window timer varies — use absolute cycles (the denominator trap fired in real arm B data).
- **IMC `cas_count` bytes are ×2.01 under-reported** on this platform; same-counter ratios are immune.
- **Terminology (user-adopted)**: "intra-pass span" = layers 0–35; "inter-pass window" = [open→F1→F3→end]; "rest-of-cycle" = [F3→next F1] (NOT the span — it also contains [open→F1] and [F3→end]); token cycle = span + window. Write intra-/inter- in full (misread hazard).
