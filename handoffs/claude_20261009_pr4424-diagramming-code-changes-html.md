## Gotchas and decisions

- The journal.jsonl of a workflow never writes a "completed" record. A wait loop that greps for one never ends. Rely on the task notification instead.
- The task output file of a workflow is a wrapper object with `logs` and `result` keys. The `result` of the drawing workflow is keyed per page (`perKey`), the legend workflow's is a list.
- Workflow agents and Claude edited the same generator files in parallel. Twice a patch by Claude failed because an agent had already changed the text (check_page.py at 12:39, and the legend forms at 15:17). Put a new figure in its own module while a workflow is running, as base_k_vnni_b1a.py was.
- spec_builder.py resolves a base figure that is missing from base_<key>.py by importing base_<key>_<name>.py. That is how B1a is wired in.
- A figure module may expose `fig()` (one figure) or `figs()` (a list). spec_builder.py joins the list.
- check_page.py accepts a box citation only if the cited head line contains an identifier token of the box label. A citation with prose in it ("63-65 (PAIR_2, DWORD_BYTES_4); 87-90 (...)") fails. Cite bare line ranges.
