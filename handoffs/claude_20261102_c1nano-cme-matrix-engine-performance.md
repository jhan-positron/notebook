## Words used here

- **Asimov**: Positron's Arm-based chip under development. It runs today on a Cadence Palladium emulator, not silicon.
- **C1-Nano**: the Arm CPU core on Asimov (Arm code name Nevis). Two cores per cluster.
- **DSU**: Arm DynamIQ Shared Unit, the cluster block holding the two cores, their shared L3 and the CME (Arm code name Pilatus).
- **CME**: Compute Matrix Engine, Positron's name for the Arm C1-SME2 unit (Arm code name Griffin). One per DSU, shared by the DSU's two cores. It executes Arm SME instructions.
- **SME, SME2**: Arm's Scalable Matrix Extension instruction sets. **Streaming mode**: the CPU state entered with SMSTART and left with SMSTOP, in which SME and vector instructions execute on the CME instead of the core.
- **SVL**: streaming vector length, 512 bits (64 B) on this CME.
- **Half matmul**: the CME build option (FULL_MATMUL FALSE in the RTL config) that executes one outer product every other cycle.
- **FMOPA, BFMOPA, SMOPA, UMOPA**: outer-product instructions (FP32, BF16, int8 inputs). **MAC**: one multiply-accumulate. **ZA**: the CME's accumulator tile storage.
- **LD1B, ST1B, LD1D, LASTB, DUP, RPRFM, PRFM**: instructions used by the new kernels: vector loads and stores, extract the last active element into a scalar register, broadcast a scalar into a vector, the streaming-mode prefetch hint, the normal prefetch hint (a no-op in streaming mode).
- **cache-mem-perf**: the user's Asimov latency and bandwidth suite (latency.c, bandwidth.c, cmncount.c, run scripts), folder cache-mem-perf of GitHub repo https://github.com/jhan-positron/asimov. Working copy: /home/jhan/workspace/titan/cache-perf/asimov. Clone: /home/jhan/workspace/ai-runs/asimov-repo.
- **Phases A, B, D, E, C, F**: sections of the suite. A is DRAM latency, B is OCM latency, D is one-core bandwidth, E is multi-core bandwidth, C is SPM (last), F is the new CME rows.
- **Run 1, run 2, control run, run 3**: emulator runs of the suite by Jesse Zhang. Results folders membench-jibin-001 (2026-10-31), -002 (run 2) and -003 (control run, run 2 code on run 1 firmware), both received 2026-11-02. Run 3 is the run requested in this session.
- **OCM**: on-chip memory, five 256 KiB regions in the mesh home nodes. **SLC**: system level cache (3.75 MiB unlocked). **SPM**: scratchpad memory. **CMN**: Arm Coherent Mesh Network. **cmncount**: the suite's helper that reads mesh counters around one command.
- **Chase**: a dependent-load latency walk over a chain of pointers. **Dense chain**: every 64 B line of the buffer is a chain member. **Sparse chain** (`latency --sparse`, new): chain c's members are line 8c + 4 of every 4 KiB page, one member per page per chain.
- **Refills per load**: cache refill events (L1, L2, L3) divided by the loads of a timed pass. A value of 1.00 means every load missed that level once.
- **perf_cov** (new): per-row counter coverage, running time divided by enabled time, 1.0 when the counter group was not multiplexed.
- **CME PMU events**: raw core-PMU event codes 0x3246 CME_CYCLES, 0x327D CME_L1D_CACHE_REFILL_INNER, 0x327E CME_L1D_CACHE_REFILL_OUTER.
- **Chip time**: emulated time on the chip. One chip second takes about 2,779 s of wall time on the Palladium. **Launch cost**: the per-process start-up allowance in the chip-time estimate (14 ms from run 1 in the tool, 3 to 5 ms per command in Jesse's run 2 README).
- **est_chip_time.py** (new): the estimator that reads the `--dry-run` command list of a run script.
- **CRB**: the Arm development board at 192.168.2.45 (Neoverse V3AE cores, no SME). Used here for builds and host-side checks only. Lock file /tmp/positron-perf.RUNNING.
- **QEMU user mode**: qemu-aarch64 running an aarch64 binary on the x86 host. Version 11.1.3 has SME2, versions 8.2 and 10.0 do not.
- **Palladium, GA13, Spokane**: Cadence emulators. GA13 is the Cadence cloud site (hosts ga13pd01 and ga13pd02, 18 boards each) where Jesse runs. Spokane is the local 4-board machine (driver host palladium-94a4, queue database /ice/infra/asimov-emu/queue.sqlite3 on sw-dev-01).
- **hemi_rtws_tlm**: the 4-board emulator image of one hemisphere (five DSUs).
- **SCP, TF-A, PPU**: System Control Processor firmware (GitHub positron-ai/asimov-scp-firmware), Trusted Firmware-A, power policy unit. The SCP must set the CME PPU to dynamic mode before a core's first streaming instruction, or that core stalls with no rescue path.
- **asimov-bench**: GitHub positron-ai/asimov-bench, the pre-silicon benchmark repo. Boots M2, M3 and M4 are its 2026-10-12 emulator runs. dpa/stress is its counter-based stress test.
- **codex**: the OpenAI Codex agent that reviewed CME-plan.md and wrote codex-review-CME-plan.md in rounds.

## Gotchas and decisions

- User rules of this session: do not use the emulator (GA13 or Spokane), write and check the code with the available resources. Jacob's AGENTS.md adds: builds under /scratch/$USER/agent-builds, no emulation launch without the user's yes, verify other agents' claims against primary sources.
- The SCP must arm the CME PPU in dynamic mode before the first streaming instruction, or the core stalls with no rescue path [firmware_boot_spec.md, CME PPU section]. The arming function entered the SCP at commit 32658a4c (2026-07-06) and is present in both scp-v0.34.0 and scp-v0.48.0.
- Firmware per run: run 2 used SCP 0.48.0-nopcie.1 (e361a83) and TF-A 0.35.0. Run 1 and the control run used scp-v0.34.0 and TF-A 0.24.0. The first draft to Jesse had this wrong and quoted run 1's 1.237 s as run 2's chip time (run 2 measured 1.630 s).
- Streaming mode rules used by the kernels: no system call inside a streaming span, a signal survives but contaminates the timing, no Advanced SIMD, the first SMSTART of a thread traps once, save d8 to d15 and FPCR around the span. PRFM and PRFB are no-ops in streaming mode, only RPRFM (at most 1,024 B) is executed [C1-SME2 TRM section 6.3].
- The CME path is CME L1 (64 KB, 4-way) to DSU L3 to the mesh. The core's L2 is not on it. The 0x327D and 0x327E refill counters say inner (inside the cluster) or outer, demand and prefetch alike. OCM against SLC against DRAM is not separated by any per-walk counter: cmncount spans the whole command.
- A sparse timing is the whole-call time of a 64-hop walk divided by 64. The empty bracket (27.9 ns on the CRB) and the cme-call rows bound what a short pass carries. Nothing is subtracted.
- perf_event ioctl RESET does not reset time_enabled and time_running, so coverage is a per-row delta. Counter groups must be zeroed at open (the first perf_cov_test had indeterminate stack state).
- QEMU 8.2 and 10.0 user mode lack the SME2 hwcap. Debian's qemu-user 11.1.3 works with `-cpu max,sme-default-vector-length=64`. The qemu-user-static package is a metapackage, fetch qemu-user.
- `python3 -I` ignores PYTHONPATH, so pypdf in the scratchpad pylib needs sys.path.insert.
- The CRB has no SME: it serves builds, refusal checks and core-side runs only. Its V3AE prefetcher makes sparse chains five times slower than dense ones, which says nothing about the C1-Nano.
