Words used here:

- TLB (translation lookaside buffer): the core's cache of virtual-to-physical address translations. DTLB is the data TLB; STLB is the shared second-level TLB.
- page walk: the hardware procedure that reads the page tables in RAM when the TLB has no entry.
- page fault (#PF): the CPU exception raised when the page walk fails or the access is not allowed; the operating system handles it.

## The answer

Question 1: page fault versus TLB miss.

- TLB miss: the TLB has no entry. On x86 the hardware page walker reads the page tables through the cache hierarchy and fills the TLB. The operating system is not involved; the only cost is walk latency.
- Page fault: the walk fails or is not allowed to complete, the CPU raises #PF, and the operating system runs. The user's definition (page table lacks the entry) is the main case but incomplete. A fault is raised when the reached entry's present bit is clear (no mapping, or swapped out), when the access violates permissions (write to read-only, user access to kernel page, execute on a no-execute page), or when reserved bits are set.
- A page fault is always preceded by a TLB miss; most TLB misses end in a successful walk without a fault.
- Linux distinguishes minor faults (fixable without disk I/O, such as first touch or copy-on-write) from major faults (disk I/O needed). tron's hugepage pool is mapped with MAP_POPULATE, so it takes neither after startup.

Question 2: page size in the TLB entry.

- Yes. The size decides how many address bits form the tag and how many are page offset (12 bits for 4 KB, 21 for 2 MB, 30 for 1 GB). The size comes from where the walk stopped: a leaf PTE means 4 KB, a PS bit in the PDE means 2 MB, a PS bit in the PDPTE means 1 GB.
- Two hardware styles, both present on the Xeon 6962P per the CPUID data on the page: separate arrays per size with the size implied by the array (L1 load DTLB: 96 entries for 4 KB, 32 for 2 MB/4 MB, 8 for 1 GB; all probed in parallel, at most one hits), and mixed arrays with a size field per entry (the 16-entry store TLB accepts any size; each STLB array accepts two sizes, 4 KB + 2 MB/4 MB or 4 KB + 1 GB).
- Software view: one 1 GB hugepage translation occupies one TLB entry covering 1 GiB, which is why the page's reach table multiplies entries by page size.
