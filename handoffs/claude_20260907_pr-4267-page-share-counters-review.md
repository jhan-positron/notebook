## Gotchas & decisions

- User directive: "I hate to see same var names, especially in same file." Do not reuse an identifier for two things in one file, even across scopes. This is why the totals struct was dropped for `total_` prefixes.
- User directive: PR description edits by Claude are additions only; changing existing wording needs the user's approval first.
- User directive: "Do not change anything before confirming with me" when checking the user's own edits; work on copies.
- The auto-mode classifier blocks `git push --force-with-lease` even as a single plain command. A force-push always needs the user to run it with the `!` prefix. Regular fast-forward pushes work.
- Renaming a member of the per-call struct to the same name as a namespace-level atomic makes `flush()` add the member to itself (name hiding) and fails to compile; reproduced with g++.
- tron writes integer zero tests as `== 0` (44 cases vs 6 bare `!x`); tron has no clang-tidy, only clang-format via lefthook with `-Werror`, so a trailing space blocks a commit.
- tron constexpr constants are lower snake_case (260) with few ALL_CAPS exceptions (27); the user chose `HISTOGRAM_SLOTS_7` knowingly.
- `n_visible` counted query tokens, not K tokens; the requested `n_k_visible` would have been wrong. Final name `relevant_query_tokens`.
- The exit-time stderr report is the only way the counters leave the process; the counters are not in the FUSE stats tree, so platformd cannot see them. Registering them is a possible follow-up (this became Wade's FUSE question on 2026-09-09).
- split-verify3.sh has an advisory pre-CI hold (no start between 01:40 and 03:45 UTC); it was overridden with `PRECI_HOLD_FROM=345` after the lease check showed CI was not holding the machine.
