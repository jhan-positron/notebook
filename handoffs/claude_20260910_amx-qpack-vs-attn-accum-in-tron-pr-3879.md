## Gotchas & decisions

- Decision: `std::vector` member sized on first use (option B) over Ben's `std::array` (option A). Reason: the array is resident in every `attn_accum` for every model, AMX-eligible or not; the vector costs 24 bytes wherever the AMX path never runs. The earlier defence of the `thread_local` ("per (token, kv_head)", "ownership unchanged") was a scope choice, not a technical obstacle; the report says so plainly.
- `resize()` zero-fills new slots, and the packer relies on that (it writes only the 4 live columns of each slot; see the `pack_q_group_128x4` contract in `h/tron/kernels/amx_attn_iface.hpp`). Do not replace `resize` with a non-initializing growth.
- The user rejected comment text that is hard to read on first pass. Phrases like "one 4096-byte slot per token of the minibatch" and "Scratch of one apply_page_range call (one kv_head)" had to be rewritten as full sentences. The user's own shorter comment was used, with "as they are stored" added because "cannot read a token's 4 query heads" alone says the kernel cannot read them at all.
- On claude-agentsrv `lefthook` is not on PATH, so git commit hooks print "Can't find lefthook in PATH" and do not run.
- `sleep N; ssh ...` in one foreground command is blocked by the harness; use a background `until ... done` loop and read its output file.
- cairosvg rejects duplicate SVG attributes; the figure generator hit this once (`class` given twice) and was fixed.
- `node` is not available in the container, so the dataviz palette validator could not run; the two colors used are the documented adjacent pair of the default validated palette.
- delphi-3bda was under load from Bill's process during this session; runs used the script's fixed CPU set and finished normally.
