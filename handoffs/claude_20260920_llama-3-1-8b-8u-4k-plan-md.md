## Gotchas and decisions

- **"8 users" is ambiguous.** The harness config named 8 users is 2 users per engine (4 engines). The best cells are 32 users in total, 8 per engine. Every page and message states users per engine.
- **No prompt above 4096 can be measured** with the deployed llama-8b tokenizer file (it truncates). The user's "8k prompt" cell does not exist.
- **Prefill is derived, not measured.** Every prefill tok/s figure, in CI and on the page, is prompt tokens over TTFT. TTFT includes queue waiting, so absolute rates are not comparable across user counts. Within one cell both arms saw the same queue, so the gain is fair.
- **Cached prefixes in the Saturday cells.** Every Saturday cell except 2 users x 1024 reused prompts whose beginning an earlier cell of the same seed had sent. rinzler's prefix cache served 15 to 37 % of their tokens. The cached share differs between arms by up to 3.8 points per cell because rinzler serves a prefix only when Caddy routes the request to the engine that holds it.
- **One-config campaigns need a different stop rule.** The Saturday "two zero-completion runs stop the campaign" rule counts every failed pass when there is one config. campaign.sh now counts only runs that never reached the benchmark.
- **dut.sh OUT is hard-coded** to /var/tmp/jhan/canon-ci-20260918. The plan text said it follows NAME. Harmless here because the debs live there.
- **Pages are ASCII only** because the artifact publisher mangles non-ASCII bytes. Each generator asserts this.
- **The Monitor tool expires after 30 minutes.** The session re-armed it four times.
- **Write tool refuses to overwrite an unread file.** The stale Saturday gen_report.py copy had to be removed before writing the new one.
- **Verification pattern that worked.** Each page part went through a Workflow with independent finder lenses (numbers recomputed from the source files, completeness, plain English) and one refuter per finding.
