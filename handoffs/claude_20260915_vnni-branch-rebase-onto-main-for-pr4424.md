## Words used here

- **tron**: Positron's inference program (GitHub repo positron-ai/tron). **runtron**: its command-line tool.
- **AMX**: Intel Advanced Matrix Extensions, the tile matrix-multiply instructions of the Xeon 6 CPU.
- **VNNI**: Vector Neural Network Instructions. Here it names the pair-interleaved K layout that the AMX tile multiply reads as its right operand.
- **VNNI-K**: the branch `jhan-amx-vnniK`. It stores the K cache (the saved key vectors of past tokens) of 128-dimension heads in the VNNI layout.
- **TRON_K_VNNI**: the CMake option (default OFF) that turns the VNNI-K layout on. It requires **TRON_AMX_DISPATCH**, the CMake option from PR 3879 that compiles the AMX attention kernels.
- **PR 3879**: https://github.com/positron-ai/tron/pull/3879, branch `jhan-amx-p0`, AMX software attention. Merged into `main` on 2026-09-15 as merge commit 3fd5edaa66.
- **PR 4424**: https://github.com/positron-ai/tron/pull/4424, the VNNI-K pull request (draft).
- **Issue 4444**: https://github.com/positron-ai/tron/issues/4444, created in this session.
- **rebase**: replaying the branch commits on a new base commit. `git rebase --onto` names the new base and the old base.
- **range-diff**: `git range-diff`, which compares two series of commits patch by patch.
- **worktree**: a git checkout that shares one `.git` directory. The tron repo `.git` is at /home/jhan/workspace/tron on NFS and is shared by claude-agentsrv and delphi-3bda.
- **kv_mul**: the number of query heads that share one KV head. The AMX kernel serves head size 128 with kv_mul 4 only.
- **row view**: the accessor that returns one token's K values as a contiguous row. A VNNI slot does not have one.
- **dotter**: the per-token AVX-512 dot-product loop of the software attention before PR 3879. **qk_group**: the new AVX-512 reader that scores 64 tokens at once from the VNNI plane.
- **kill switch**: the environment variable `TRON_AMX_DISABLE=1`, which turns the AMX kernels off at run time.
- **TTFT**: time to first token (prefill latency). **TPS**: decode tokens per second per user.
- **CI**: continuous integration. On `main` the default lane is the "GCP Nix" workflow. The "CMake and CTest" workflow (`cmake-single-platform.yml`) is a legacy lane that runs by hand or from `publish-deb.yml`. Only the legacy lane compiles the two AMX options.

## Gotchas & decisions

- Decision: rebase with `--onto origin/main 544ca05c7a`, not a merge. The old base 544ca05c7a is a merge commit of `main` into `jhan-amx-p0` that is not an ancestor of `main`, so `git rebase origin/main` alone would replay the wrong range.
- The eight K row-view overloads on `main` (two-argument whole-page views were new) all need the `!k_vnni::layout_on<head_size>` constraint. A rebase that compiles can still miss new callers on `main`. Check `main`'s new callers and new sibling overloads of every function the branch constrains. Recorded in memory git-rebase-traps.md.
- `git rebase` strips lines that start with `#` from commit messages. None of the 17 messages had such lines this time (author, date and message were byte-identical by range-diff).
- The CI lint job runs clang-format-19 through bin/ci/run-lint-checks.sh and the Nix check `lint-toolchain`, not through a workflow step. A grep for "clang-format" under .github/ misses it. Limit is 88 columns (.clang-format `ColumnLimit: 88`).
- The GitHub REST PATCH of a PR body stores the text with LF line endings even when the payload carries CRLF. Compare bodies after normalizing line endings. Always re-fetch the live body before a PATCH, because the user edits the description in parallel (the Status section was removed by the user during this session).
- The auto-mode permission classifier blocks `git push --force-with-lease` for Claude in this project. In this session the push went through at 19:00 PT after the user asked to check an error, so the classifier is not absolute. Prepare the command for the user first.
- For root in the container, `~` is /root. Give the user absolute paths under /home/jhan.
- Fact found during the Notion page check: the AMX gate never tests whether hardware (FPGA) attention is on. Under hardware attention the scheduler still hands software the queries below the engagement point (position 127 by default), the causal tail past the K and V already in FPGA memory, and every query of a sliding-window layer. A dense page in one of those pairs takes the AMX path even with USE_HW_ATTN unset [h/tron/models/self_attention.hpp:1220-1221, 1236-1239, 1535-1551, h/tron/scheduler/full.hpp:1936-1965]. Also: USE_HW_ATTN=N starts hardware attention at N rounded up to a 128-position page end, never below 127.
- Fact: with TRON_K_VNNI on, TRON_AMX_DISABLE=1 runs the VNNI reader qk_group, not the row-major dotter. The row-major dotter loop is not compiled for VNNI slots [h/tron/models/kv_cache.hpp:706-712]. The kill switch is therefore not a rollback to the row-major binary's numerics.
- No default CI lane compiles TRON_K_VNNI or TRON_AMX_DISPATCH. Only the legacy CMake workflow does, and it also serves as the test gate of publish-deb.yml.
