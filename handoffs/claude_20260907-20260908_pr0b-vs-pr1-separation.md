Which instrument reacts to the release-ordered load (tron's nix clang 19.1.7 with libstdc++ 14.3, tron's flags, on delphi-3bda; the same held for Ubuntu clang 19 with libstdc++ 12, the CI runners' pairing):

| Guard | Result |
|---|---|
| Compiler warnings, tron's set and `-Weverything`, at -O0 and -O3 | silent |
| clang-tidy 19, all checks | silent |
| ThreadSanitizer, UndefinedBehaviorSanitizer | silent |
| Machine code, wrong line vs fixed line, real header | identical (1114 assembly lines) |
| `-D_GLIBCXX_ASSERTIONS` | aborts at the load, exit 134 (SIGABRT); fixed line passes |
| Host g++ 11.4, -O1 or higher, with `-Wsystem-headers` | warns `-Winvalid-memory-model`; hidden without that flag (system header) |

Why warnings stay silent: libstdc++ passes the order as a function parameter, so clang's constant-expression check never sees it, and clang lowers the invalid order to monotonic (relaxed). Both orders produce the same load instruction on x86-64.

- Why "Skip benchmarks" on #4265 and #4267: tron's README.ci.md labels table says to add it to every PR unless directed otherwise; it suppresses only the `benchmark` and `benchmark-report` jobs, takes effect on the next pull-request event (so it must be on before the push), and does not cancel a run in progress (#3879 got a benchmark run because the force-push landed before the label was re-applied). - Codex P2 on #4267 was right with two corrections: the fallback build (artifact-miss path) is rare, fires only after the 3-day artifact expiry combined with a forced rerun or a bundle/NFS/ldd failure, and an instrumented run is identifiable because the binary prints four `[page-share]` lines to stderr; worse than codex wrote, the nightly golden baseline (benchmark-golden.yml) always builds clean, so after merge every golden comparison would have been instrumented-vs-clean. Production `deb` packaging carries no flag.
- Because `log_kv_footprint` is always-inline (`TRON(inline)`), a test target compiled with `DEFINES _GLIBCXX_ASSERTIONS` gets its own checked copy while the rest of tron builds unchanged; the macro works with `-DNDEBUG -O3` and does not change data layouts, so the object links against the existing libtron.a. The test's header comment says it must move if the function ever leaves the header.
