## Findings (by source reading, each cited to file:line in the report)

- The proposal's premise is already mostly true: the app side runs exactly
  one pinned thread per app core (app_cores - 1 pool workers;
  h/tron/threading.hpp:762-828, 863-873), and no thread is created inside a
  forward pass.
- Places where two tron threads share a physical core:
  - The TX/RX driver pair per FPGA on SMT siblings (TX submits DMA work to
    the FPGA, RX completes it) — deliberate (src/pos/worker.cpp:2323-2329);
    RX also runs model callbacks (RoPE-K, KV-cache page writes), so merging
    TX+RX would put that work inline with launches.
  - The rinzler front-end core (rinzler = tron's production serving daemon):
    the unpinned work_queue coordinator shares a hardware thread with 8
    drogon (HTTP framework) IO threads, while the app core reserved for
    "Main" sits idle because a temporary init thread consumed it
    (src/pos/driver.cpp:410, src/rinzler.cpp:3699-3703).
  - TBB (Intel Threading Building Blocks) workers on HT peers of app cores —
    init-only in FPGA serving.
  - Low-duty monitoring threads on core 0 and its SMT sibling.
- Neither stated goal of the proposal (determinism, fewer concurrency bugs)
  is served by thread topology: every documented output-nondeterminism
  source (Note [Paying for Determinism] in the tron source) is a cross-core
  partition effect the proposal keeps, and every recorded concurrency bug
  examined was between threads on different cores.
- Verdict by reading, per proposal variant: A (merge TX/RX) — measure first;
  a naive merge deadlocks and the freed sibling is unused by any config.
  B (static thread creation, remove TBB) — recommended hygiene; the one past
  measured win from reducing concurrency was removing TBB's task_group in
  2024 (+50% Mixtral prompt throughput, a hang removed). C (independent
  per-core pipelines) — not viable for decode: estimated (est.) >=3x
  attention serialization at 8 users.
- Follow-up finding: production rinzler hard-codes pay_for_determinism =
  false with no override (src/rinzler.cpp:2009); only runtron (tron's
  test-run wrapper) exposes the flag.
