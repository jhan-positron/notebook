## What the new page contains

- Section "Which Threads Run Which Functions (Software Attention)" after
  Thread Families:
  - Selection logic: software attention is the default for handwritten
    plugins (USE_HW_ATTN unset falls back to force_hw_attn, which
    handwritten plugins do not define; src/tron/models/hw_attn_config.cpp:10-31).
  - App-pool split: main thread + n_main_helpers helper tasks +
    n_attn_workers attention workers (always the last pool workers). Pinned
    split formula (N*2)/7 with examples Genoa96 full 40/102 and 6962P full
    31/80, plus the token-count clamp caveat (a 4-user decode gets 4
    helpers, not 40).
  - Function-to-thread matrix: token embedding (main thread); RMSNorm,
    SiLU-times-mul, residuals (main + helpers); RoPE-on-Q and the
    softmax-attention kernel (attention workers); RoPE-on-K and save_k/
    save_v KV-cache writes (FPGA RX-worker callbacks); all weight matmuls —
    wq/wk/wv, wo, w1/w2/w3, wcls (the final vocabulary projection / LM
    head) — on the FPGA; logits top-k and sampling (app-pool listener
    tasks).
  - A per-layer stage-order strip (schematic, captioned not-to-scale — no
    timing measurements exist for it), a "three traps" callout, the die-A
    placement story, and a glossary.
- Intel Xeon 6962P (YAML key granite_rapids_6962p) everywhere Genoa96
  appears: slice map (8 slices x 14 app cores = 112, no helper_cores key),
  comparison table, the die-A sibling-id pinning trick (main thread on die
  B; attention lands on die-A SMT siblings 151-158/223-230 because they are
  the highest core ids), and the Maximum Thread Counts table extended to 4
  columns (6962P full: 111 workers, subtotal 128; -i 1,2: 55, subtotal 64).

## Gotchas & decisions

- The ~54 ns / ~63 ns L3 latency figures and the +1.5% decode figure on the
  page come only from a YAML comment in config/resource-map.yaml (labeled as
  such on the page); they were not re-measured.
- The pinned (N*2)/7 helper/attention split holds only when the minibatch
  has at least that many tokens; small decodes are clamped to the user
  count.

  attention" (not "sw-attention"); the final projection is called "LM head".
