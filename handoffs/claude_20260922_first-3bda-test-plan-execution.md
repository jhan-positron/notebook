## Gotchas & decisions

- **Source under test.** The branch had no commit when the plan appeared, so the working tree was snapshotted into a commit with a temporary `GIT_INDEX_FILE`, `write-tree`, `commit-tree` and `update-ref`. Step D ran the snapshot, Step E the final commit 682064f8fb after the peer removed a hot-path assert. The peer's later commits (c2efd73ff6, c3c368d298) changed only tests, comments and an 8-lane-only function, verified by `git diff --name-only`.
- **Branch rebased later.** On 2026-09-23 the peer rebased the branch onto main 996f58ec82 and pushed the old tip as `origin/jhan-kv-typed-tensors-pre-rebase-20260923` (source: memory note issue4525-implementation.md read in the next session). The shas in this handoff are pre-rebase shas. The PR body of https://github.com/positron-ai/tron/pull/4557 cites "pre-rebase tip c3c368d298 passed the machine test on delphi-3bda".
- **Short-sha fetch.** `git fetch <repo> <short sha>` fails with "couldn't find remote ref". build2.sh passes full shas and skips the fetch when the object exists.
- **pgrep self-match.** A `pgrep -f` pattern in an ssh `bash -c` command matched the launcher itself. chain.sh was killed by hand, and chain3.sh finds the Step C build group through the make process instead.
- **NFS stale file handle.** Editing smoke.sh (sed -i, then mv) while a 3bda process ran it killed that process at its next read. Rule: fix bugs in a copy with a new name (build2.sh, chain2/3/4.sh pattern). The memory note records this.
- **ssh and nohup.** `ssh host 'nohup ... &'` hangs unless the job gets `</dev/null`. `ssh -n` breaks `bash -s < file`.
- **cd listing hook on 3bda.** `cd` prints a directory listing (bashrc hook) that floods tool output. Avoid cd in remote commands.
- **Socket pinning.** The chain driver was pinned by hand with `taskset -pc 72-143,216-287` at about 14:19 PDT. Before that, runtron's main thread ran on socket-0 cpus during model load in 9 of the 14 Step D runs. All 36 Step E runs stayed on socket 1.
- **Serving takedown by hand.** Done at 14:13 PDT from claude-agentsrv with `exec/q4b-fpga-20260921/dut.sh serving-down` (platformd API), not by the chain's lib-guard takeover. Serving was restored through the same API twice (15:30 and 15:49 PDT).
- **Deviations from the plan.** Step D used runtron's built-in prompt of the requested length, not a forced text token file (the A/A control was identical). tp2 runs used `--instance 2,4` on cards 90 and 93, not the plan's `--instance 1,2`.
- **Review workflow findings** applied before Step D: the summarize.py header regex and the `I4525_FUNCTIONS_ONLY` sourcing bug in smoke.sh. Report review corrections: 682064f8fb is the last production-code commit, not the branch head, and t_rinzler was never a host target.
