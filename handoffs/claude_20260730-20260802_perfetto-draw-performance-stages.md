## Gotchas & decisions

- `trace_processor -q` emits one blank line per DDL statement before
  the CSV header — `csv.DictReader` silently grabs a blank header
  (header at line ~20). Cost real debugging time twice.
- ab49 ftrace starts ~577 ms after track_event: early cycles have
  spans but no sched rows — `wq_slices = 0` reads like "off-CPU" but
  means "no data". Filter `wq_slices > 0`. Per-CPU ftrace ring buffers
  also start at different times (offsets 0-1800 ms) — raw on-CPU sums
  are floors, not duty cycles.
- Kit configs differ: ab57 = 25 s, write_into_file+DISCARD (data-loss
  warning applies), categories driver/scheduler/gen, **no kernel
  data**; ab49 = 10 s, RAM buffer, driver/scheduler **+ linux.ftrace
  sched_switch** — do not generalize one kit's config to another
  (Claude did, twice, and corrected it). ab49 config is kit-level
  (`m6_10s.cfg`), not per-draw.
- tron thread names: space-padded 3-char CPU field (`"  3/0-TX-10"`)
  — leading-digit globs silently drop most threads; comm truncated at
  15 chars. Name prefix `N/` = pinned CPU N (verified exact).
- All tron compute threads spin (mwaitx) — a fully-green CPU row is
  the *normal idle state*; on-CPU tells you nothing about useful work.
  ~50 spinning workers swamp whole-box symbol histograms.
- Enabling the `model` trace category perturbs the measured code path
  by +335 µs/cycle — fine for structure, invalid for timing.
- 3bda machine etiquette: talos nightly 04:25-11:20 UTC is hands-off
  (one small violation occurred and was self-reported); daytime GitHub
  CI window is reclaimable but the runner was found inactive; load
  ~125-134 is normal idle (rinzler spin threads).
- Draws cannot be re-captured: each engine launch is a new lottery
  ticket — a re-run is a new draw, not a copy.
- gpt-oss per-layer code is generated/unrolled under `gen/` — line
  numbers there are build products; cite library files for stability.
