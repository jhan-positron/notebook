## Gotchas & decisions

- **Keep `int` for the mask constant.** `_mm512_set1_epi32(int)` takes `int`. An `unsigned` constant compiles under the repo flags but warns under `-Wsign-conversion`.
- **Keep the names `VIEW_ALIGNED_TRUE` and `as_view`.** `VIEW_ALIGNED_TRUE` follows main's parameter name plus value, like `VIEW_DMA_FALSE`. Alternatives (`VIEW_CHUNK_ALIGNED_TRUE`, `VIEW_SIMD_ALIGNED_TRUE`, `VIEW_ALIGNED_LOADS_TRUE`) each promise the wrong thing. `as_view` is what `dmatensor.hpp` already uses.
- **"aligned" for a view** means the caller promises every chunk the view loads or stores starts at a multiple of the chunk width (32 bytes for bf16 at 16 lanes). The view then uses aligned vector instructions. Nothing checks the address except `slice()`.
- **The whitespace check** is `git diff --check`, run by the CI Lint job over the whole tree, by the lefthook pre-commit hook over `origin/main..HEAD`, and by `make lint`. It is not a Claude feature.
- **Commits used `--no-verify`** because the hook calls a lefthook binary under `/nix/store/` that does not exist on claude-agentsrv. `git diff --check`, clang-format 19.1.7 (`uvx --from clang-format==19.1.7`), an ASCII check and an 88-column check were run by hand instead. The Note checker (`lint-notes`) was not run; it needs GHC, and no Note block or reference was added.
- **Named constants in AMX intrinsics** compile only with clang. GCC's `_tile_loadd` and `_tile_dpbf16ps` are macros that paste the tile number into inline assembly.
- **`construct_kv_blocks()` is new code**, not a refactor. On main the two allocators returned raw bytes and readers cast them. The placement new satisfies the C++ object-lifetime rule for member calls on `v_vnni_tensor`, emits no instructions, and the `static_assert`s block a future non-trivial block type. The design review asked for both.
- **3bda use during a busy period.** The single-file compile ran with two rinzler processes active, pinned to 2 cpus at low priority. No serving was taken down.
