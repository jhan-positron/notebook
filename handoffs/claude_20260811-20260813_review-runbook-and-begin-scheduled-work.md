FPGA tracer (`--tracer-core N`): FPGA DMA-writes a state snapshot every ~10 µs to a host mailbox (`src/pos/device.cpp:288–300`); a host thread on core N (`src/pos/metrics.cpp:124–153`) emits perfetto counter tracks — `rmem_depth`, `rmem_bp`, `inprog_pause` on category `driver` (enabled in the template); more on `driver-detail` (disabled). The dice wrapper `bin/runtron:82` forbids the flag, so it needs a bare run — exactly the campaign-harness setup. No code change; best direct fit for the ~800 µs question (high `rmem_depth`/`rmem_bp` = host consume behind; empty RMEM + `wmem_bp` = wcls matmul starved on weights). Adds a 10 µs-cadence polling thread — smoke against the bare band first.

## Gotchas & decisions

- Full-rate ungated tracing at `-u 1` wedges runtron if SIGUSR1's 10 s timed window (ending in `TrackEvent::Flush()`) overlaps the external capture: per-thread trace writers stall and every thread blocks on the shared memory buffer. Fix (in the r2/r3 harness copy): send SIGUSR1 early during model load, gated on the `pos_startup() completed` log line — earlier would kill the process because the handler installs only at the end of `pos_startup()`. Prior full captures survived only because they ran at `-u 4` (~7× lower event rate).
- Full-rate ungated tracing costs ~32% decode throughput (122.2 tok/s smoke vs bare 170–190 band) and widens the lottery spread (16.8% vs 8.0% gated/bare) — do not compare traced TPS against bare TPS, and treat fast-vs-slow selections made under full tracing with care.
- The gated binary's traces are ~60 MB/draw, not single-digit MB as the runbook predicted (wcls dispatch burst ~240 slices/window); the 100 MB leak threshold still held.
- Token hash `66af1d58…93c4` is the numerics-invariance check: every instrumented build (gate, marker) reproduced it bit-identically across all draws.
- The stock installed binary `tron-perfetto-install-20260809` (sha `17da8295…`) predates Mike's `"data ready"` marker; only builds patched on 12804a812 have it. The peer session later made "fence 1"/"fence 3" + "data ready" owner-mandated defaults for every perfetto build.
- The shared project memory file is edited by concurrent sessions (3c51 session updated it twice during the campaign); append via shell instead of read-modify-write to avoid racing.
- The dice wrapper `bin/runtron:82` forbids `--tracer-core`; the flag needs a bare `gen/runtron` invocation (the campaign harness already does this).
- Campaign-machine discipline on delphi-3bda: check `/run/lock/systems-test-ci.lease`, use `campaign_guard_acquire` from `~/workspace/intel-AMX/exec/lib-guard.sh`, and let the harness restore + verify trio serving after every campaign (this session did all three).
