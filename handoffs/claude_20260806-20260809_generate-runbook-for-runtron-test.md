## Gotchas & decisions

- **`pgrep/pkill -x runtron` never matches a live engine** (runtron renames its main thread) — match the full binary path with `pgrep -f`. The v3 harness handles this internally; the warning in the runbook is for manual shell checks and was deliberately kept verbatim (user decision).
- **The Perfetto config MUST have `write_into_file: true`** (+ 2 s flush): without it, this workload (~20 MB/s of events) cannot drain a 2 GiB buffer through the consumer socket inside the client's fixed 60 s post-capture timeout; the trace truncates to driver-only slices and smoke fails. This was campaign attempt 1's failure.
- **RING_BUFFER is the canonical fill policy** (user decision 2026-08-06); complete RING_BUFFER traces are ~3.5x larger than the earlier DISCARD ones (~977 MB vs ~277 MB for 120b).
- **Nightly 02:45 UTC `ci-runner-stop` timer on delphi-3bda restarts rinzler** and kills in-flight draws ("no log directory" / "running inference processes" failures). Keep campaigns clear of 02:45 UTC. Also: most per-draw failures never write a journal line — monitor `results.csv`, not just `journal.log`.
- **Both harnesses generate the Perfetto config from `~/workspace/common/perfetto.cfg-template` at launch** — the template is the single place to change capture settings; a config-parse preflight catches template syntax errors (e.g. the missing-space `RING_BUFFER}` form the parser rejects) before the machine is mutated.
- **The harness's per-draw `kill -USR1` to runtron** exists to start runtron's tracing session (producer registration); as a side effect it arms `malloc_tracing_enabled` for exactly 10 s (runtron-internal timer, `src/pos/perf.cpp`), so the `sys` malloc counter covers only the first ~10 s of each 25 s window. Frees are not traced; the counter is a sampled rate (every 25th allocation, value mod 1000), not events.
- **driver-detail costs ~15% throughput during capture** — within-campaign comparisons stay valid (uniform overhead), but tok/s is not comparable across campaigns with different category sets.
- **User renamed `results/draw_18` -> `draw_18-slowest` and `draw_19` -> `draw_19-fastest`** in the 0306Z campaign; this breaks the paths recorded in `results.csv`, `analysis/selection.env`, and `report.html`, and `perfetto-5cat-report-v3.py` would fail if re-run on that root (it looks up `results/draw_NN` literally).
- **matmul and gen categories never emit** in this workload (campaign-wide, both models) — the harness treats them as soft observations; only scheduler and model are hard-required. `hwattention` is a real, team-default category the old allowlist never captured; `sys` is tron-defined (not a Perfetto built-in), instrumented via `TRACE_COUNTER` only.
- **alpha claude-box container limits**: fuse-overlayfs rejects group-chown (worked around with Nix `sandbox = true`); seccomp EPERMs `fchmodat2` (fatal for nix-store rsync 3.4.1; fix requires relaunching the container — see tron-build-fail-alpha.md). `/` and `/var/tmp` are ephemeral; keep durable work on `/home/jhan` or `/scratch`.
- The 719.1/742.1 W numbers appearing early in the transcript are from **synthetic turbostat fixtures** used to test the v3 report parser — not measurements.
