## Gotchas & decisions

- **Runtime version log lines are unreliable identity**: the same
  executable self-reported `29924aa8-...-dirty` in ab54 and
  `0b6cb141-...-dirty` in ab60g; executable SHA-256 is the only
  trustworthy artifact identity. `runtron-FROZEN.sha256` contains the
  relative path `gen/runtron`, so `sha256sum -c` works only from the
  tree root.
- **IRQ window denominator trap**: ab54 `smi_irq/notes.txt` snapshot
  window (20.16 s) vs benchmark ttlt (49.19 s) -- using ttlt gives a
  2.44x exposure error. IRQs/token is mechanically coupled to
  throughput; descriptive only.
- **Gen-length confound**: all rolling arms `-l 4096`, all tight
  controls `-l 1024`; `chain60.sh` had a 1024 fallback (GEN_LEN
  passthrough fix added but no `arms.txt` line uses it -- hazard still
  live).
- **`--instance i,N` is not co-residency** -- N is the card-slice
  count; but ab53 did run 20 simultaneous A+B pairs (`0,2` + `1,2`),
  each wrapper printing "Instances: 1" -- a sweep blind spot.
- **Orchestrator watchdog hazard**: orchestrator54.sh:698 /
  orchestrator58.sh:1279 hard-cleanup kills runtron and leaves the
  serving trio down with `RESTORE_NEEDED`.
- **Rule duplication failure mode**: the same rule stated in 3 runbook
  sections; an edit reaching only 2 of 3 created a stale contradiction
  Codex caught in the last round.
- **Runbook must not widen signed consensus rules**: twice a runbook
  clause quietly carved an exception into FINAL_CONSENSUS (Gate 1.5
  ambiguity rule, Gate 4 matched-AMD requirement); both reverted --
  changing a signed rule requires a re-signed consensus.
- `/proc/stat` hardirq jiffies column is a structural zero on this
  kernel config -- check `/proc/interrupts` instead.
