## Words used here

- **Asimov**: Positron's chip. It runs on an emulator that Jesse Zhang operates. The page calls Jesse "the operator".
- **C1-Nano, cluster**: the Arm core of the chip, and a group of two cores that share an L2 cache (128 KiB), an L3 cache (256 KiB) and one port on the mesh. Each core has an L1 data cache of 32 KiB. The tests use CPUs 2 to 9, which are four clusters.
- **Mesh, home node, SLC, OCM**: the on-chip network, the five mesh devices that hold shared memory, the system-level cache (1 MiB per home node), and the on-chip memory (five regions of 256 KiB, one per home node).
- **DRAM model**: the emulator's memory behind the home nodes. It has no configured delay. It is not silicon timing. **DRAM-backed**: a buffer that lies in memory which this model backs.
- **Boot**: one power-on of the emulated chip with one firmware set. The page uses six boots:
  - **Boot F1**: results/membench-jibin-011, L3 on, prefetchers on. The main boot.
  - **Boot E**: results/membench-jibin-010, the same firmware state, another command set.
  - **Boot B**: results/membench-jibin-006, prefetchers off, the L3 holds no data.
  - **Boot C**: results/membench-jibin-007, prefetchers on, the L3 holds no data, OCM mapped with one translation per 64 KiB.
  - **Boot D**: results/membench-jibin-008, as boot B plus the 64 KiB OCM mapping.
  - **Boot R3**: results/membench-jibin-004, prefetchers on, the L3 holds no data. Earlier handoffs call it run 3.
- **"L3 on", "the L3 holds no data"**: the two L3 states. In the second one the L3 only tracks which core has a line.
- **Prefetcher**: hardware logic that loads data into a cache before the program asks for it.
- **Latency test, chain load**: the test walks a list of pointers, one per 64-byte line. Each load reads the address of the next load. The number is ns per load.
- **Bandwidth test**: the test reads, writes or copies a whole buffer in address order. A rate is a loop throughput (bytes over elapsed time).
- **Rep, best row**: one timed measurement, and the row that the test program marks as best.
- **Hit set**: the group of counter events of boot E that count L2 hits, L3 reads and L3 hits. The page calls these events exploratory.
- **The old generator**: gen_perf.py with gen_perf_core.py. Until this session it wrote asimov-c1nano-perf.html.
- **The new generator**: gen_c1nano_perf.py with the package c1nano_page/. **Data layer**: c1nano_page/data.py. **Self-test**: `python3 -m c1nano_page.data`, 434 checks at the end. **Guard**: a check in c1nano_page/refs.py that stops the build when a cited line of common.h no longer holds the expected text.
- **SPEC.md, fact sheets, critic**: the specification the session wrote for the builders, the research notes of the first workflow, and the agent that checked the notes against the raw files. critic.md is binding for the builders.
- **codex**: the OpenAI coding agent that the user runs in parallel as a reviewer. It writes to codex-review-asimov-c1nano-perf.md.
