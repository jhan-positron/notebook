## Current state

The design follows save completion, groups of four tokens, upload preparation, transfer submission, completion polling, and the hardware-ready prefix observed by later attention plans. It separates direct upload delay from extra CPU attention caused by data arriving late. [root-cause-tracing.html, sections 2–7]

The Friday per-user interval reconstruction is mean(1000/request_TPS), not 1000/mean(TPS). It gives 0.817009 ms/token added for TP4 and 0.282979 ms/token for TP2. Those are client intervals, not engine-forward costs. The design flags build and workload differences in that historical comparison. It uses matched layout-on/off builds for the proposed causal test. [Design: measured-loss table and controls]

Insufficient data: no matched trace in the reviewed evidence assigns the regression to a stage. A controlled intervention must reduce the suspected delay and restore untraced decode speed before a root-cause claim. [Design: acceptance criteria]

## Open items / next steps

## Gotchas & decisions

TRON_AMX_DISABLE does not restore row-major key storage. Count actual upload groups and token-window boundaries. Cache-line address counts are not measured cache misses. The current attention launch need not wait for current-token uploads, so correlate each upload with later plans.
