### What one run of the deployed task does

```
minute 17 -> cloud run -> save check_pr.py, verify hash -> REST check
   -> others acted in the window?  yes -> one push    no -> silent
```

- `RESULT: ALERT`: one push of at most 180 characters and a final message with one bullet per item.
- `RESULT: FETCH FAILED`, or a hash that does not match after two saves: one push "PR 5022 watch: check failed".
- A merge conflict is reported once a day, in the run of 17:17 UTC (09:17 PST).

What a fresh session would otherwise rediscover:

- The session first told the user, from the documentation, that a cloud run has no built-in alert. The first test run showed a PushNotification tool. Start one short test run and read its log before asking the user to choose between workarounds.
- A cloud session reaches an attached private repository through `gh api repos/...` without a token. GraphQL is blocked, so `gh pr`, resolved threads, reactions and the review decision are not available there.
- A cloud run keeps no state. The deployed design needs none, because each run reports the window that ends at the latest minute 17. If a run is skipped, that hour is not reported later. `watch_pr.py` still shows it.
- The constant `MINUTE` in `cloud/check_pr.py` must equal the minute of the cron expression.
- The cloud agent types the embedded script again when it saves it. The prompt therefore contains the SHA-256 of the script, and the run checks its copy.
- A task created without a connector list gets every connector of the account. Send `clear_mcp_connections: true` for none.
- Each create, update and start answer of RemoteTrigger repeats the prompt four times (24 to 31 KB here). `list_runs` and `get_run_log` are small.
- Documented limits: no schedule tighter than hourly, and 100 scheduled runs per hour per account.
- An inline comment of a pending review keeps its draft time as `created_at` and gets the publication time as `updated_at`. Isaac's 26 comments were created at 04:22 UTC and published at 15:42:07 UTC on 2026-10-23. The cloud script uses the later of the two times.
- cursor[bot] rewrites its summary comment at every push. The cloud check marks that edit QUIET and does not alert.
- `python3 -m py_compile` left a `__pycache__` folder in the project folder. Run the scripts with `python3 -B`.
- Web sources say that Slack raises no alert for a user's own messages and that Gmail likely raises none for self-sent mail. This was not tested.
- The prompt of the cloud task names the PR number, the repository and the user's GitHub login. It holds no email address and no token.
