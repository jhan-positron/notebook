## Words used here

- **Owner, repository**: the only two levels of a GitHub address, `github.com/<owner>/<repo>`. The owner is a user account or an organization.
- **Organization**: a shared GitHub account that owns repositories.
- **Topic**: a label attached to a repository. `topic:<word>` filters a repository list.
- **Submodule**: a pointer from one git repository to one specific commit of another repository.
- **Parent repository**: the repository that holds the folder layout. Here it is jhan-positron/ai-proj.
- **Level 1, level 2, level 3**: the user's layout. Level 1 is ai-proj. Level 2 holds the single projects plus common tooling and a library. Level 3 holds the real code repositories.
- **arm-crb**: the first level-2 project directory. The name refers to the user's work on an Arm reference server. This session put no code in it.
- **.gitkeep**: an empty placeholder file. Git does not track empty directories, so this file keeps a directory in the repository.
- **gh**: the GitHub command-line tool.
- **No-reply address**: an address that GitHub gives each account. A commit with it is linked to the account, and the person's real address stays private.
- **claude-agentsrv**: the podman container this Claude Code ran in, on the user's Linux dev server agentsrv (same home directory, same files).

- The user's decisions: everything stays under the user account jhan-positron and not under a new organization, the local clone is directly at /home/jhan/workspace/ai-proj, and the first project directory is arm-crb.
- Three choices came from the session, and the final message listed them for the user:
  - The repository is private.
  - The folder is directly under /home/jhan/workspace. The user's standing rule reserves that level for folders the user creates. The session read message 4 as the user naming this location.
  - The commit author is `jhan` with the account's GitHub no-reply address, set for this repository only. The address is not recorded here.
- A new repository on this machine needs a local identity before its first commit, because no global one exists.
- `gh repo create --source <dir> --remote origin --push` creates the repository, adds the remote and pushes in one step.
- A submodule has a cost. The parent records one commit per submodule and shows that commit until someone updates the pointer. Dependabot (GitHub's update bot) can open those update pull requests through its `gitsubmodule` setting.
- A simpler option that the session named: keep only a README with links and a clone script in the parent. The clickable folder view on GitHub is then lost.
- If level 3 does not need separate repositories, one repository with plain directories gives real folders and needs no maintenance. The later commits use this layout.
