- **T1 to T5**: the PR's timers. T1 = wall time of one forward, T2 = busy time of one attention job, T3 = job wall time, T4 = layer period, T5 = join wait time (leaf key `join_wait_cycles`).
- **Forward**: one pass of the model over the current batch. **Forward class**: `decode_like` (every token job has a listener) or `prompt_or_mixed` (some do not). **Token job**: one token of one user in one forward. **Listener**: the consumer the scheduler registers for a token job's output.
- **Join**: the step where an attention worker waits for the other workers' partial results. The hardware join (`stream_hw_joins`) runs when the FPGA is used. The software join is the polling loop in `run_joins` under `USE_HW_ATTN=0`.
- **Pool worker / attention worker**: tron has one pool of worker threads per model. The attention workers of a forward are the last `n_attn_workers` pool workers. The **split** is how many pool workers do attention in a forward.
- **FUSE leaves**: the stats files that runtron and rinzler expose under `stats/.../attention/`. **Exit report**: the stderr summary printed at the end of a runtron run.
- **Workflow**: the multi-agent verification tool. Readers collect evidence, refuters try to disprove claims, a critic looks for gaps.
- **respond-Wade-comments.html**: the page this session wrote, in the project folder. Its generator is `gen_wade.py`.

## What the page says (as reported in chat)

Every factual claim in Wade's five comments holds against the code at 1430736b2a. Four have small fixes that keep every leaf name and the off-state contract. The fifth (one class per forward) was deliberate, and Wade is right that it hides decode work in serving. No code sketch on the page was compiled.

| Id | Wade's point | Recommendation on the page |
|---|---|---|
| W1 | T5 never times the software join poll (self_attention.hpp:1131) | Time the stretches of consecutive failed polls in `run_joins` into the same accumulator (no rdtsc when off). Not Wade's per-head clock, which double counts. Reword Note, README, PR body. |
| W2 | Two writers of the per-forward record (full.hpp:2093) | One `forward_scope` object at the top of `model::state::forward`. full.hpp leaves the PR. |
| W3 | One class per forward hides decode work in serving (model.hpp:1746) | Now: a README sentence plus `listener_jobs` and `kv_only_jobs` per forward class. The per-token-job split as a follow-up PR. The user's call. |
| W4 | Silent range guards (attn_stats.hpp:382) | Asserts everywhere, delete the dead `note_token_path`, one assert per call instead of per visit, `begin_forward` in four test fixtures, keep a fork-based negative test. |
| W5 | Rows keyed by attention worker although sized by the pool (self_attention.hpp:498) | Key rows by pool worker, record `n_attn_workers` min and max per class, move T3 and T4 into a per-layer struct. |

Two findings the checks turned up:

- The per-job split of W3 cannot live in the W2 scope constructor. The listener map is built later inside `run_forward`, so it is a second call site either way.
- The 8-user decode split is Insufficient data. Every 8-user run reads 20 attention workers, while the code reading predicts at least 23. The W5 leaf would record it.

Measured values quoted on the page come from the earlier runs, not from this session: T5 read 0 in all 6 CPU-attention rows of attnstats-20260924b, and active_workers read 26 in the 1-user runs and 20 in the 8-user runs [exec/results/attnstats-20260925-fpga and -warm exit-reports.txt].
