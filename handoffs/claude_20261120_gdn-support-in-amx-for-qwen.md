## Words used here

- **tron**: Positron's inference program. FPGA cards do the large matrix multiplies, and the host CPU does attention and GDN. **runtron**: its command-line tool. **rinzler**: its server binary.
- **GDN (GatedDeltaNet)**: a recurrent layer type that keeps a memory matrix of fixed size (the **state S**, 128 x 128 FP32 values per value head). Qwen3.5 uses it in 3 of every 4 layers.
- **Qwen3.5 4B**: the model under study. 32 layers: 24 GDN layers and 8 full-attention layers. Its tron name is `ingested-qwen-3.5-4b-tp4`. **tp4**: one engine on four FPGA cards.
- **Pull request 3696**: https://github.com/positron-ai/tron/pull/3696, "Register Qwen3.5 4B", head commit 72e1191804. The model is not on tron's main branch. It lives in this open pull request and the open pull requests under it.
- **AMX**: Intel's matrix instructions. A **tile** is an AMX register of 16 rows x 64 bytes. **Tile product**: the instruction TDPBF16PS, which multiplies bf16 values and adds the products into FP32.
- **AVX-512**: Intel's 512-bit vector instructions. **FMA**: one fused multiply-add instruction.
- **bf16**, **FP32**: the 16-bit and the 32-bit floating-point formats.
- **delphi-3b35**: the user's default test server (2 x Intel Xeon 6962P). **Our half**: socket 1, FPGA cards 90:00.0, 93:00.0, b9:00.0 and bc:00.0, application CPUs 96-143 and 223-230, selected by `SYSTEM_CONFIG="--instance 1,2"`. **delphi-3bda**: the earlier test server, the source of older AMX numbers.
- **TTFT**: time to first token, in seconds. With 8 users it is the slowest user's time. **Decode speed**: generated tokens per second per user.
- **Prefill**: processing of the prompt. **Decode**: generation of tokens after the prompt. **Pass**: one forward computation through all 32 layers. **Decode step**: one pass that produces one token per user.
- **Cell**: one combination of user count and prompt length, for example 8 users with prompt 1,024. **Arm**: one setting of a cell. The **on** arm allows AMX, and the **off** arm sets the kill switch `TRON_AMX_DISABLE=1`.
- **Attention statistics**: the counters and timers that `TRON_ATTN_STATS=1` turns on. **Attention busy time**: the time the attention workers spend on attention jobs, without their waits for input. **T3**: the wall time of the attention jobs on one worker, waits included. **K token**: one context token that an attention kernel reads.
- **Trace**: a Perfetto recording made by runtron (`--trace-gen`, `--trace-passes`). The trace slice named `GatedDeltaNet` covers the GDN host work of one layer on one thread. **GDN wall**: the time from the first GDN thread's start to the last one's end.
- **Core clock**: the frequency a CPU core runs at. **Clock probe**: the small program this session wrote to read the core clock under AVX-512 and AMX loops.
- **Part 0, Part A, Part B**: the three proposed changes. Part 0 is a new loop order for GDN prefill without AMX. Part A is an AMX kernel for GDN prefill. Part B is an AMX attention kernel for 256-wide heads.
- **L1 cache**: the 48 KiB cache nearest to a core.

### The design, as published at 11:38

- **Part 0** (no AMX, same result bits): a chain path for GDN prefill. The recurrence walks the state in halves of 64 columns (32 KiB), which stay in the 48 KiB L1 cache. Est. GDN step: 2.6 to 3.5 us against 6.4 us today.
- **Part A** (AMX, rare output bits differ): a block kernel that takes 32 tokens at once. It splits the FP32 state into 3 bf16 pieces and uses 18.5 tile products per value head per token. Est. cost: 972 to 1,286 core cycles per value head per token.
- **Part B** (AMX): attention kernels for heads of 256 values with 4 query heads per KV head.
- **GDN decode**: no AMX. One token fills 1 or 2 of the 16 rows of a tile.
- **A finding outside AMX**: spreading the GDN work items over all 56 threads would cut the GDN wall with 8 users to about 3/8 (est.). It needs a scheduler change.
- **Plan of 6 tasks**: (1) stand-alone benchmark of the Part 0 loop order, (2) Part 0 in tron, (3) stand-alone AMX block kernel, (4) stand-alone 256 x 4 attention kernel, (5) Part B in tron, (6) Part A in tron after the owners of the GDN code accept the change in result bits.
