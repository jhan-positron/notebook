## Gotchas and decisions

- Read #phoenix-crb before every login on the CRB, and check /tmp/positron-perf.RUNNING as the first command of every login. Do not log in during an announced block. Use CPUs 0 to 119 only and never pin anything to CPUs 126 or 127.
- A file copy with scp is a login that cannot check the marker first. Run 1 used scp. handoff.md therefore sends and fetches files inside an ssh call that checks first.
- One ssh call slipped into a local command at 19:12 UTC and opened a login by mistake. Keep ssh out of commands that are meant to be local.
- The dev machine cannot build bandwidth.c any more. Every build and every objdump check runs on the CRB.
- A C loop that does not use its loaded values loses its loads: gcc 14.2.0 deleted every load of such a loop. The barrier keeps them. It guarantees that the values are loaded, not which instructions load them.
- The barrier does not guarantee the order of loads and stores in `k_copy`. The order "8 `ldp`, then 8 `stp`" is an observation with gcc 14.2.0. A copy loop without the barrier alternated loads and stores.
- The three repetitions of one process use the same buffer, so they are not independent samples.
- The benchmark stops on whole passes. With 256 MiB per thread and 0.5 s, a repetition holds 2 to about 10 passes per thread, so totals move in steps.
- Rates of `read`, `write` and `copy` from before 2026-11-13 cannot be compared with rates from after it.
- Both result page generators hold typed text for their run. Check and rewrite that text before a page of a new run is used.
