- AMX B-operand rule (doc 01 §5.1): no AMX instruction on the 6962P rearranges data — loads are strided memcpys and `TDPBF16PS` reads B positionally, silently wrong on flat input. Layout must be produced in memory (pre-interleaved store, maintained mirror copy, or reformulation so the flat matrix is the A operand).
- AMX/AVX-512 coexistence (doc 01 §1.1): concurrent on one core by design; the one hard collision is port 5 (second AVX-512 FMA closes while TDP* run, peak 2→1 FMA/cycle; 100-300-instruction AVX blocks can lose up to 20% to reopen churn — Intel's countermeasure is a `TILEZERO` in the block); the frequency license (~8% single-core) taxes all code on the core.
- HTML convention: pure ASCII + numeric entities + meta charset (entities do not work inside `<style>` blocks — ASCII-fy those); validate tag balance with an HTMLParser script after every edit.
- English: banned words unless quoting code/spec: convoy, refund, "in disguise", swept, "young positions". "mirror" must NOT be renamed to "Bill's PR" (rename would misattribute our numbers; lineage note instead: formulation from PR #2934, implementation and numbers ours).
- Kill-switch A/B validity depends on the clean-binary check: dispatch-off overhead is ~zero, but the kill-switch OFF arm ran up to 3% off true clean in some cells — final headline numbers are vs the clean binary.
- Tile stores always write all 16 configured rows — output buffers must be 16 rows even for 4-row results (a 4x128 buffer overruns).
- `_tile_stored` requires literal tile-register immediates (no loops/ternaries over tile numbers).
- arch_prctl(ARCH_REQ_XCOMP_PERM) is per-PROCESS (Sol wrongly claimed per-thread; corrected from kernel xstate docs).
- T1 traps: 21-token canned prompts never fill a 64-token page (hollow pass); without USE_HW_ATTN=0 both arms are bit-identical because attention runs on the FPGA. extract_logits: GPTQ path needs optimum (use unquantized Qwen3-4B-Instruct-2507); `--max-tokens` truncates the input.
