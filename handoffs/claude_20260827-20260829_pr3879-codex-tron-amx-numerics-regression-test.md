## Objective

Verify a bug that codex (an OpenAI coding agent reviewing the same PR) reported
in tron (Positron's model-serving/inference runtime) PR
https://github.com/positron-ai/tron/pull/3879: the AMX (Intel Advanced Matrix

## Gotchas & decisions

- Gate, do not convert: converting Q to bf16 before packing would introduce a
  third numerics difference the executor contract does not cover (measured
  above); the fix therefore excludes non-bf16 executors from AMX dispatch.
- Codex's original regression test demonstrates the bug but does not pin the
  fix (it reinterpret_casts Q itself, so it stays red under any correct fix);
  it was replaced, not kept.
- On the claude-agentsrv container, run Catch2 tests with
  `env -u SYSTEM_CONFIG` — the container's `SYSTEM_CONFIG=--instance 1,2`
  aborts them (saved to session memory).
- Build tron only inside `nix develop`: one `cmake --build gen` outside it
  deleted `gen/CMakeCache.txt` and forced a reconfigure.
- On delphi-3bda, apport writes a ~3.9 GB core per crash even with
  `ulimit -c 0` (the kernel core-pipe handler ignores the limit); crashing
  negative controls therefore take minutes and leave files in /var/crash.
- `exec/p3-q-scalar-gate.sh`'s first verdict logic had a false positive
  (matched its own annotation); fixed during the session.
