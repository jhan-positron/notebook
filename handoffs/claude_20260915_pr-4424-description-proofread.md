## Gotchas & decisions

- The base AMX kernel puts the K page (64 tokens x 128 dimensions, as stored) on the left of the tile multiply and the packed queries on the right. So the scores come out transposed, `S^T = K * Q^T`, and an AVX-512 register transpose writes the 4 query columns as score rows. `Q^T * K` does not conform (inner sizes 4 and 64).
- The sharing gate is `k_store_shared = n_workers > 1 && n_workers <= 128 && items > 16` [h/tron/models/model.hpp:2806-2813]. Only generated plugins pass n_workers greater than 1. Handwritten plugins (llama.hpp, mock.hpp) and the default pass 1. The three-thread case of t_llama_unit does share [h/tron/models/model.hpp:2753-2754].
- The runtime's split heuristic decides the helper count once per pass. The plugin calls it [ingest/src/TronCpp.hs:1239; h/tron/models/model.hpp:1939-1983]. Do not write "the generated plugin decides the helper count".
- A partial block gets masked stores, not whole 64-byte lines. Only a full 16-token block writes whole lines.
- The code has no decode rule. A plain decode step (one token per user) gives runs of one token. Speculative decoding could give longer runs. Do not write "every decode step keeps the scatter" as a code fact.
- The PR description's Words table sits below the Short version. A Short version has to define its own terms or stay to three sentences that need none.
- The 4 "vnnik2" campaign arms: vnni0 = unchanged VNNI store, a = 16-token block store, b = striping over the idle main helpers, ab = both (the shipped shared block save).
