## Gotchas & decisions

- Three STALE COMMENTS in tron source (annotated in the doc):
  kv_cache.hpp claims kv_saves_==2 "fires gof_rodeo" (false — dispatch
  fires from gof::save_count==8); a scheduler comment references page.hi
  (no such field; offset_bound); the "~1 MB data + 16 kB vout" page
  comment is a fossil (pages own zero bytes; real range 2-21 MiB).
- n_kv_heads is the trap: model cards advertise QUERY heads; the KV
  cache is sized exclusively by n_kv_heads (sizing off a model card
  overestimates 4x for Llama-3-8B).
- The FPGA/host split is inverted from intuition: card gets n_heads+gqa,
  never n_kv_heads; host lays out memory with n_kv_heads.
- Number collisions: five different 8s and four different 128s in play;
  three unrelated things named "page" (64-token software page, 128-token
  POS_PER_PAGE hw page, hwkv channel page).
- HW eligibility is a whitelist, not <=128 (head_size 96 would be
  rejected).
- Browser-pane screenshots are impossible when the pane isn't composited
  on the user's end — recurred all session.
