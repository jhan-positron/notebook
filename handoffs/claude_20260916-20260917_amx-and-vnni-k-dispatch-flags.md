## Words used here

- **tron**: Positron's inference program (GitHub repo positron-ai/tron). **runtron**: its command-line tool. **rinzler**: the inference server process.

- **AMX**: Intel Advanced Matrix Extensions. **VNNI**: Vector Neural Network Instructions. **VNNI K layout**: the pair-interleaved storage order of the K cache for heads of 128 dimensions, introduced by PR 4424.
- **PR 3879**: https://github.com/positron-ai/tron/pull/3879, the AMX software-attention kernel, merged to main. **PR 4424**: https://github.com/positron-ai/tron/pull/4424, branch `jhan-amx-vnniK`, "VNNI K: store the K cache of 128-dimension heads in the AMX VNNI layout, with a shared block save". **Issue 4444**: https://github.com/positron-ai/tron/issues/4444, tracks that the kill switch on a VNNI binary is not a rollback to row-major numerics.
- **TRON_AMX_DISPATCH**, **TRON_K_VNNI**: CMake options, default OFF, that compile the AMX kernels and the VNNI K layout. TRON_K_VNNI requires TRON_AMX_DISPATCH. **TRON_AMX_DISABLE**: environment variable, the run-time kill switch read by the probe `available()`. **USE_HW_ATTN**: environment variable that selects hardware (FPGA) attention. Unset means on for ingested models only.
- **kv_mul**: query heads per KV head. **128 x 4**: head size 128 and kv_mul 4, the only shape the AMX kernel dispatches for.
- **dense page**: a (query, page) pair that passes `is_dense_amx_page`: full 64-token page, begin 0, query visible, whole page inside one visible range, first token inside the sliding window. Only dense pages run the AMX kernels.
- **KV slot**: one kind of persistent K/V storage in the cache, fixed at compile time by its KV geometry and retention rule. The K layout gate reads the slot's head size.
- **SW_REQUIRED / HW_AVAILABLE**: the scheduler's marks on each (query, token range) pair. SW_REQUIRED pairs go to the CPU, HW_AVAILABLE pairs to the FPGA. **engagement point**: the first sequence position the FPGA may serve (127 by default).
- **staging**: the copy of K and V rows from the CPU cache into FPGA memory. Under the VNNI layout it rebuilds each K row with 4 gathers (`page::get_k_row`).
- **block save**: PR 4424's K store. A run of 2 to 16 consecutive tokens landing in one 16-token block is transposed in registers and stored as full or masked 64-byte lines. A run of 1 token uses 4 scatter instructions.
- **tile registers**: the 8 AMX tile registers, numbered 0 to 7, named as immediates in `_tile_loadd` and `_tile_dpbf16ps`.
- **clang-format**: the formatter the repo's lint job runs (clang-format-19 from the nix dev shell). **lefthook**: the repo's pre-commit hook runner.
- **CI lease**: /run/lock/systems-test-ci.lease on delphi-3bda, held by the nightly CI while it runs. **campaign flock**: /var/tmp/jhan/3bda-campaign.lock, the host-wide mutex every campaign of ours takes.
- **Workflow**: the multi-agent tool of this Claude Code (ultracode effort), used here for read-only verification with one verifier and two refuters per claim.
- **Notion**: the team wiki. The parent page "AMX and VNNI options (PR 3879, PR 4424)" is https://app.notion.com/p/3ddd132d3cfd81ec8b97f46aec9ebbe9.

- The 128 x 4 shape test is folded in at compile time per model plugin and executor: head size and kv_mul are template constants of the plugin, and only bf16 executors pass. No code compares a loaded model's shape at run time. The run-time decisions are the probe (once per process) and the dense predicate (per query and page).
- Under `USE_HW_ATTN=1` nothing changes at compile time. The value 1 rounds up to engagement point 127, the same as unset. The difference from unset is that hardware attention is on for every eligible model, not only ingested ones.
