## Words used here

- tron: the Positron inference engine repository (positron-ai/tron).
- KV cache: the saved key (K) and value (V) vectors that attention reads. One `kv_block` holds K followed by V for one head and one 64-token page.
- packed V: V stored pair-interleaved (two tokens per 32-bit lane, the VNNI B-operand layout) in the 16-lane (AVX-512) build only. The 8-lane (AVX2) build keeps row-major V.
- AMX: Intel Advanced Matrix Extensions, the tile instructions used by the attention kernels in `src/tron/kernels/amx_attn.cpp`.
- 16-lane / 8-lane: builds with `TRON_CHUNK_SIZE` 16 (AVX-512) or 8 (AVX2).
- delphi-3bda (3bda): the Intel Xeon 6 CI machine with AMX. Our half is socket 1 (CPUs 72-143 and 216-287). The nightly CI holds `/run/lock/systems-test-ci.lease` while it runs.
- claude-agentsrv: this container (the user's docs call it "claude-box"). It has no nix shell, so every compile ran on 3bda.
- Step C/D/E/F: the steps of the 3bda test plan. C = host test suite, D = token-identity A/B, E = performance A/B, F = instruction comparison by objdump.
- TPS / TTFT: tokens per second and time to first token, the two performance metrics of Step E.
- peer session: a second Claude session named `issue4525-40` (handoff `claude_20260922_first-3bda-test-plan-execution.md`) that executed the plan's Steps C-F on 3bda while this session stayed off the machine.

## Gotchas & decisions

- The design page is at `issue4525/status/design-new-tensor-type.html`. The request said `status/status/`; that path does not exist.
- Rebase: main's PRs 4455 and 4456 replaced the reclaimable arena with chunks. The branch's `construct_kv_blocks` hook point vanished. The rebase ports the placement-new to `allocate_retained_storage` and once per chunk in `allocate_reclaimable_chunk`. The `git-rebase-traps` memory warns that `git rebase` strips `#`-leading message lines; the messages were diffed before and after and were identical.
- The bounds assert `TRON_ASSERT_LT(token, Rows)` in `v_vnni_access::pair_base` was removed from the bulk route in commit 2 because `TRON_ASSERT` is active in release builds (h/common/assert.hpp undefines NDEBUG) and main never had that check on the hot path. Two of three refuters preferred keeping it; the plan records both views. Element accessors keep their asserts.
- clang-19 at -O0 flushes a bf16 denormal (0x0001) to zero through a plain struct copy even with DAZ/FTZ off. Do not use denormal special values in Debug-tree tests; the test uses negative zero instead.
- A non-dependent `requires` expression with an invalid body is a hard compile error, not `false`. Contract probes must be variable templates.
- Catch2 splits a test name on commas. Run a single case whose name has commas with `\,` in the filter; the unescaped run matched nothing (exit 2).
- `cmake --build gen ... -- -k 0`: the ninja keep-going flag must come after `--`. With it before `--`, the build never ran (BUILD1 EXIT 1 with no compile).
- `lefthook` is not on PATH in the worktree, so commits used `--no-verify`. clang-format was run on 3bda instead and the formatted files pulled back with rsync.
- Sync to the 3bda tree with `rsync -rlc` and never `--delete` (a dry run showed it would delete `bin/__pycache__` and more).
