## Gotchas & decisions

- Start time decided the shape of the run. The agent started at 21:09 UTC, past the plan's 20:30 UTC deadline for a full Saturday run, so it split the work into a Saturday check-only run and a detached Sunday run of the six passes (plan section 2, Sunday fallback, decided under plan 2a).
- `NOT_BEFORE` must never fall inside the nightly's possible window (03:30 to 13:20 UTC). An absent lease file reads as free, so a wake-up at 05:00 UTC would have started the passes during the nightly. The Sunday run woke at 13:00 UTC and then waited for the lease.
- `verify-env` must expect platformd's configured engine count, not a fixed 4. After the Sunday nightly the saved layout is the soak phase's 2 tp4 engines. The review's two high findings caught this before the run.
- The qwen tokenizer adds no BOS token. The harness's `prune_convo` drops the first token of every part, so every part loses its first character(s). The nightly runs the same code for this model, so nothing was changed in the harness. The server-counted prompt tokens are below `prompt_length` by 47 to 302 tokens (cell means). The plan's check-cell band of 8192 to 8400 would have failed every request. The band was set to [prompt_length - 800, prompt_length + 400] from the offline measurement. It still catches a silent truncation (the llama case read 4096 of 8192).
- config.env is read only at engine start. Write or clear it, then `serving-down`, then start. Every restore path clears it before any `serving-up`.
- The permission classifier refused `sudo systemd-run --on-calendar=...` on delphi-3bda ("Unauthorized Persistence"). The dead-man timer for config.env therefore does not exist. The manual command is in `RUNBOOK.md`. The classifier also refused an inline `python - <<EOF` heredoc executed inside the systems_test checkout; the same code ran when saved as a file in the scratchpad.
- Bash runs a TERM trap only after the current foreground command ends. A `sleep 1800` in the marker loop would have deferred `kill -TERM` by 30 min. The driver uses `nap() { sleep "$1" & wait $!; }`.
- `rc=$?` after `if cmd; then ...; fi` reads the if-statement's status. Capture rc first.
- The check-only run and the Sunday run share one results directory. `campaign.sh` renames the previous run's end-state files to `prev-<time>-<name>` at start. `launch.sh` refuses to start while another `campaign.sh` process is alive.
- Never edit a campaign script while it runs (bash reads the file incrementally from NFS). Compare md5 sums on both hosts before launching (`launch.sh` does this for 11 files).
- A `Monitor tail -F` worked on `exec/logs/q4b-swattn-20260919.log` here because `campaign.sh` writes that file on claude-agentsrv itself. A tail on a file written on delphi-3bda over NFS delivers nothing (RUNBOOK; the plan's section 8).
- The detached Sunday run survived the end of the Claude session (the session resumed at 00:22 PDT and found pid 2400417 alive). `launch.sh` uses `setsid nohup`.
- The `.orig/` copies of the llama driver were kept so the review could work from unified diffs. They are duplicates of `exec/l8b-levers-20260919/` files.
- The report page is pure ASCII (the artifact publisher mangles non-ASCII bytes; memory `artifact-utf8-mojibake-trap.md`). Render check: extract each inline SVG, rasterise with cairosvg, look at the PNGs. Two label overlaps were found and fixed this way before publishing.
