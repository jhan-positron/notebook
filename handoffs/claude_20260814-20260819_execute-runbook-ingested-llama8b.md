## Gotchas & decisions

- Fresh-worktree trace copy does not skip the export: ninja re-runs the gated
  torch-export because the stamp edge has no `.ninja_log` entry (mtimes alone
  do not make it clean). Fix: stage the model's config/tokenizer files under
  /opt/positron/weights/huggingface/<org>/<model>/ — `build-model.py` prefers
  that local path and the `--meta-device` export needs only config.json. No
  HF token needed.
- Campaign collision mode: two sessions' preflights can both pass inside the
  ~60 s traffic-gate window, then kill each other at smoke. Guard before
  launching: no runtron process on 3bda, no campaign root younger than 3 min
  (either /scratch/jhan/perf-fluctuation/deep-dive or pfgate-3bda), peer roots
  show `finished-epoch.txt` + RESTORED, and take the host-wide flock
  `/var/tmp/jhan/3bda-campaign.lock` (protocol agreed with the peer 08-17).
- runtron pins TX driver threads to cores 3/4/5/6 (work_queue 24, worker 25,
  RX 147–150 for tp4 instance 0); pinning any helper/instrument thread onto
  those cores halves TPS (peer finding, 08-17). Hazard for CAPTURE=perf runs —
  the harness's perf CPU list includes core 3. CAPTURE=none is safe.
- Raw IMC cas_count counters under-scale by exactly x2.01 on 3bda (DDR5
  sub-channel) — relevant only if reading IMC counters raw (peer finding).
- The Notion matrix's verdict rule (TIGHT <= 0.8% CV; ROLLS >= 2.5% CV or
  >= 5% range) differs from the runbook screen rule (>= 1.0% CV or >= 3%
  range). llama-8b tp4 qualifies as ROLLS in the matrix via the range
  criterion (5.8% >= 5%), not the CV criterion. ingested Mixtral tp4 is
  labeled MILD (user's preferred term) because it sits between the bands.
- Notion page edits must re-fetch first: the user edits the page concurrently
  (a "Note" column appeared mid-session and broke an update anchor).
- Stats caveat carried in the reports: at n=20 the CV estimate has ~±16 %
  relative error.
