## Short version

After the 2026-10-03 change to how herdr is entered, new panes showed a bare `$` prompt and Tab inserted a tab character. The cause was that the herdr server inside the container had no SHELL variable and fell back to /bin/sh, which is dash on the container image. The fix sets a default shell in the herdr config (applied live with a config reload, no restart) and passes SHELL=/bin/bash on the three podman lines that enter or create the container.

- **herdr**: the terminal workspace manager at ~/.local/bin/herdr (version 0.9.1). It runs a server per session and opens shell panes. **Pane**: one terminal inside a herdr tab. **Session**: one herdr server, here named `claude-agentsrv`.
- **dash**: the Debian Almquist shell, what /bin/sh is on the container image. It has no line editor, so Tab inserts a tab and the prompt is a bare `$`.
- **claude-dev**: the podman container that Claude Code runs in. **claude-box**: the script ~/claude-container/claude-box that creates and enters it (~/bin/claude-box is a symlink to it).

## Gotchas and decisions

- Never restart the `claude-agentsrv` herdr server to apply a config change. Its panes hold live claude sessions, including the one doing the fix. `server reload-config` applies `default_shell` to new panes without a restart.
- podman exec passes no host environment, and bash sets SHELL as a shell variable without exporting it (`env -i bash -lic 'env | grep SHELL'` prints nothing). So any program started through `podman exec ... bash -lic` sees no SHELL.
- The old setup never showed this, because the pane server ran on the host from an ssh login where sshd sets SHELL (see the memory note herdr-agentsrv-topology-2026-10-03.md).
- To diagnose again: `readlink /proc/<pane-shell-pid>/exe` (dash or bash) and whether the herdr server has SHELL in /proc/<pid>/environ.
- The fix was tested on a throwaway server first, then applied to the live one, with an unfocused temporary tab so the user's view did not change.
