## Words used here

- **Asimov**: Positron's chip. One hemisphere has 10 C1-Nano CPUs in 5 clusters of 2, an Arm CMN S3 mesh and 5 home nodes.
- **Emulator**: the Cadence Palladium machine that runs the Asimov design. Jesse Zhang operates it and runs our code. We never log in. One second of chip time takes about 2,779 s of wall time, and a guard kills a script after 12 chip seconds.
- **Chip time**: time as the emulated chip sees it.
- **Mesh, crosspoint, step**: the chip's interconnect is a grid of 6 x 6 crosspoints (switches). A message moves from one crosspoint to a neighbour at a time. One such move is a step. Every CPU-to-node distance on this mesh is 1, 3 or 5 steps.
- **Home node**: one of five cache nodes on the mesh, node ids 88, 160, 216, 288 and 344. Each holds a 1 MiB slice of the system-level cache (**SLC**).
- **OCM**: on-chip memory, 256 KiB per home node, reached through `/dev/ocm`. OCM region n belongs to exactly one home node.
- **DRAM-backed line**: a 64-byte line of normal memory. A hash of its address selects its home node, so before this test no program could pick lines by node.
- **Run 8**: this test, the mesh latency map. **Run 7**: the L3-mode follow-up (`run_l3.sh`) that an earlier session wrote. Its request was never sent.
- **meshmap**: the new C program of run 8. **run_map.sh**: the new script that runs it (phase M of the test suite).
- **Cell, kind**: a cell is one CPU, one home node and one kind of row. The kinds are `ocm-flush` (OCM lines, flushed first), `slc` (DRAM-backed lines held in one node's slice), `dram-flush` (the same lines flushed first, so each load goes to DRAM), `ocm-evict` (OCM lines with the `slc` recipe, as a control) and `idle` (an empty timed bracket).
- **Classification**: the step in which meshmap finds each line's home node. It flushes and loads one line 64 times and reads which node's counter rose.
- **Mesh counters**: the hardware counters of the mesh, the Linux device `arm_cmn_0`. The event `hns_pocq_reqs_recvd_all` counts the requests one home node received. **Read floor**: the counts that one empty read adds to each node's counter.
- **Evictor**: loads of other lines that push the chain lines out of the CPU's own caches before a timed pass.
- **Rehearsal**: one short meshmap command on CPU 2 (about 0.06 s est. of chip time), asked for before the full run.
- **Boot B, F1, F2**: firmware states of earlier runs. B: the L3 holds no data, prefetchers off. F2: L3 in use, prefetchers off. F1: L3 in use, prefetchers on.
- **cache-mem-perf**: the user's test suite, folder `cache-mem-perf` of https://github.com/jhan-positron/asimov. **The clone**: /home/jhan/workspace/ai-runs/asimov-repo. **The project folder**: /home/jhan/workspace/titan/cache-perf/asimov, which holds a working copy of the sources, the report pages and the message drafts.
- **CRB**: the Arm reference board at 192.168.2.45 (user jhan). Used here for aarch64 build checks only, never with sudo.
- **codex**: the OpenAI coding agent the user runs in parallel as the reviewer.
- **Self-test**: `./meshmap --selftest`, a set of checks inside the program. **Stand-in**: a plain file or fake counter values used where the host has no `/dev/ocm` and no mesh counters.
- **Workflow**: the multi-agent tool of Claude Code. **Ultracode**: the `/effort ultracode` mode, one workflow per substantive task.
