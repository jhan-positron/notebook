## Words used here

- **Asimov**: Positron's Arm-based chip under development. It runs today on a Cadence Palladium emulator, not silicon.
- **C1-Nano**: the Arm CPU core on Asimov (Arm code name Nevis). Two cores per cluster.
- **DSU**: Arm DynamIQ Shared Unit, the cluster block holding the two cores, their shared L3 and the CME (Arm code name Pilatus).
- **CME**: Compute Matrix Engine, Positron's name for the Arm C1-SME2 unit (Arm code name Griffin). One per DSU, shared by the DSU's two cores. It executes Arm SME instructions. It has its own 64 KiB 4-way L1 data cache, its own TLB and its own hardware prefetcher. Its path to memory is CME L1, then the DSU L3, then the mesh. The core's L1 and L2 are not on it.
- **SME, SME2**: Arm's Scalable Matrix Extension instruction sets. **Streaming mode**: the CPU state entered with SMSTART and left with SMSTOP, in which SME and vector instructions execute on the CME instead of the core.
- **SVL**: streaming vector length, 512 bits (64 B) on this CME.
- **Half matmul**: the CME build option (FULL_MATMUL FALSE in the RTL config) that executes one outer product every other cycle.
- **FMOPA, BFMOPA, SMOPA, UMOPA**: outer-product instructions (FP32, BF16, int8 inputs). **MAC**: one multiply-accumulate. **ZA**: the CME's accumulator tile storage.
- **LD1B, ST1B, LD1D, LASTB, DUP, RPRFM, PRFM**: instructions used by the new kernels: vector loads and stores, extract the last active element into a scalar register, broadcast a scalar into a vector, the streaming-mode prefetch hint, the normal prefetch hint (a no-op in streaming mode).
- **cache-mem-perf**: the user's Asimov latency and bandwidth suite (latency.c, bandwidth.c, cmncount.c, run scripts), folder cache-mem-perf of GitHub repo https://github.com/jhan-positron/asimov. - **OCM**: on-chip memory, five 256 KiB regions in the mesh home nodes, 4 of the 16 ways of each home node's 1 MiB SRAM locked by firmware. **SLC**: system level cache, the other 12 ways (3.75 MiB unlocked in all). The SLC and the OCM are the same SRAM. **SPM**: scratchpad memory. **CMN**: Arm Coherent Mesh Network. **cmncount**: the suite's helper that reads mesh counters around one command. **Home node (HN-S)**: the mesh node that owns an address. Node ids 88, 160, 216, 288 and 344 are OCM0 to OCM4.
- **Crosspoint, step**: one mesh switch, and one move between two crosspoints. A route's distance is the number of steps, 1, 3 or 5 here. The user does not want the word "hop" on the pages (2026-11-05).
- **Chase, chain**: a dependent-load latency walk over a chain of pointers, written on the pages as "the latency test" and "chain load". **Dense chain**: every 64 B line of the buffer is a chain member. **Sparse chain** (`--sparse`): chain c's members are line 8c + 4 of every 4 KiB page, one member per page per chain. **Vary chain** (`--sparse-vary`, new in run 4): one member per page with the line changing from page to page by a hash. **Sequential chain** (`--seq`, new in run 4): the lines in address order, the stimulus that validates the prefetch counters. **Repeat, fresh, flushed**: the three timing modes of latency.c (one chain walked repeatedly, a never-walked chain walked once, every line cleaned and invalidated with DC CIVAC before one pass).
- **Refills per load**: cache refill events (L1, L2, L3) divided by the loads of a timed pass. A value of 1.00 means every load filled one line at that level. A fill can be a demand miss or a prefetch.
- **perf_cov**: per-row counter coverage, running time divided by enabled time, 1.0 when the counter group was not multiplexed.
- **Counter sets** (`--events`): the run 3 set is cycles plus 0x03 L1D_CACHE_REFILL, 0x17 L2D_CACHE_REFILL and 0xA2 L3D_CACHE_REFILL_RD. The **prefetch set** (run 4) adds 0x81BC L1D_CACHE_REFILL_HWPRF, 0x81BD L2D_CACHE_REFILL_HWPRF and 0x0111 IMP_L2D_CACHE_REFILL_L1DHWPRF. The **TLB set** adds 0x05 L1D_TLB_REFILL, 0x2D L2D_TLB_REFILL and 0x34 DTLB_WALK. The **hit set** (`--events l3`, run 5) adds 0x81C5 L2D_CACHE_HIT_RD, 0xA0 L3D_CACHE_RD and 0x81C6 L3D_CACHE_HIT_RD. The **walk set** (run 5b) adds 0x34, 0x8188 DTLB_WALK_BLOCK and 0x818A DTLB_WALK_PAGE. The **CME set** is cycles, 0x3246 CME_CYCLES, 0x327D CME_L1D_CACHE_REFILL_INNER, 0x327E CME_L1D_CACHE_REFILL_OUTER, 0x3280 CME_L1D_CACHE_REFILL_RD, 0x32B2 (refills by the CME prefetcher) and 0x3281 (store refills, must read 0). The **cme-l3 set** (run 6, exploratory) is 0x328E CME_L3D_CACHE_HIT, 0x328F CME_L3D_CACHE_MISS and 0x3290 CME_L3D_CACHE_REFILL.
- **cme-roundtrip, cme-call**: the two CME controls with no memory access. cme-roundtrip moves a value into a vector register and back (DUP then LASTB) 65,536 times inside one streaming span. cme-call does one such round trip per call, 64 calls, so it carries the register save, SMSTART, SMSTOP and restore of a whole call. On the CME brief and the full CME page the roundtrip row is called the "round-trip baseline" (the user's choice, 2026-11-06).
- **Per-call cost**: the fixed time a CME kernel call pays beyond its bytes, the intercept of a line fitted through two bandwidth rows (time per pass against bytes). **Looped form**: one kernel call per pass. **Single-call form** (`--asm-passes`): all passes of a rep inside one assembly call. The user chose these two names on 2026-11-05.
- **Bracket, span**: the caller's elapsed time around a kernel call, and (run 6) the time between two counter reads inside streaming mode, just after SMSTART and just before SMSTOP. Bracket minus span is the "instrumented outside-span interval". **`--no-fold`**: the read kernel without its end-of-call fold (the matched control for the fold). **`--dsb-st`**: a write kernel with DSB ST before SMSTOP, so each call waits for its stores to complete.
- **Snoop-filter-only mode (SFONLY)**: the DSU L3 state in which the slice neither looks up nor allocates data. IMP_CLUSTERPWRSTAT_EL1 reads 0x0 in it and 0x70 in **cluster operating mode 7** (all slices, full L3 RAM). On runs 1 to 3 and boots A to D the L3 of CPUs 2 to 9 was in SFONLY, because the stock SCP stages mode 7 for cluster 0 only. Boot E's rebuilt SCP stages it for all clusters.
- **Contiguous hint (cont=64/64)**: the /dev/ocm mapping form of boots C and D, groups of 16 page-table entries of 4 KiB marked as one 64 KiB translation. `cont=0/64` on boot E means plain 4 KiB pages.
- **IMP_CPUECTLR_EL1 bit 48 (ALLPFDIS), IMP_CMECFG_EL1 bit 28 (PF_DISABLE)**: the core and CME prefetcher-off bits. **TF-A 0.35.0-pfoff.1 (5a9e2a8)**: Jesse's Trusted Firmware-A rebuild with a power-on hook that sets them on CPUs 2 to 9 (boots B and D). **SCP 0.48.0-nopcie.1 (e361a83)**: the System Control Processor firmware of runs 2 to 4. **SCP 0.48.0-nopcie-l3.1**: Jesse's rebuild that turns the L3 on (boot E).
- **CME PMU events** (older wording): raw core-PMU event codes 0x3246 CME_CYCLES, 0x327D CME_L1D_CACHE_REFILL_INNER, 0x327E CME_L1D_CACHE_REFILL_OUTER.
- **Chip time**: emulated time on the chip. One chip second takes about 2,779 s of wall time on the Palladium. **Launch cost**: the per-process start-up allowance in the chip-time estimate (14 ms per launch in est_chip_time.py, 3 to 10 ms per command in Jesse's READMEs).
