## Short version

The session replayed the nightly's perf phase on the whole of delphi-3bda through platformd, Caddy and the nightly's own client code, once with the nightly's package (base) and once with a package that merges PR #4424 and turns AMX plus VNNI-K on in the deb preset (target). Base matched the same-day nightly within 1.6 % TPS on 11 of 12 configs, and target cost qwen-3-4b 5.0 % (tp2) and 11.0 % (tp4) with FPGA attention while giving llama-3.1-8b only +0.8 %. A follow-up campaign on llama-3.1-8b with rinzler and the CI harness showed the AMX gain grows with users per engine (+0.2 % at 2, +3.9 % at 4, +12.9 % at 8), and the qwen loss was filed as issue #4500.

## Gotchas & decisions

- Client host saturation: the container shared its 32 CPUs with other containers at 0 % idle. TPS means are robust (the capture window uses server token counts), TTFT and slowest-user values are not. Renicing cannot help across containers. Record PSI and load in every snapshot.
- Bash: `${VAR:+x}` expands when VAR is set to "0". Test `[ "$SMOKE" = 1 ]` explicitly.
- A remote `flock ... -c "exec sleep 50000"` holder survives when the local ssh is killed. Capture the remote pid and kill it in the cleanup trap.
- asyncssh: the harness's test_performance creates its own event loop. Do not touch dut.conn before it (read versions through a plain ssh subprocess).
- apt install or remove never restarts engines. platformd re-execs them on the next provisioning. After a package restore the running engines still execute the old (deleted-inode) binary until platformd restarts them. Check `/proc/<pid>/exe` sha, and restart through platformd.
- The deb version 2026.09.18-<sha8>-<branch> sorts above the nightly's, so the restore needs `apt-get install --allow-downgrades tron=<version>`.
- talos stub must be first on PYTHONPATH. `LOCAL=1` with the real talos still writes the CI database.
- The harness's provision dedupe means config 4 (70b tp2 @4u) reuses config 3's engines: 11 platformd reconfigurations per pass, not 12.
- perf.py references `use_case` before assignment when the first config fails to provision, so the whole phase aborts with no results. Later configs get a zero row labelled with the previous config's name.
- Never edit a running bash script. Editing the Python driver mid-campaign without `py_compile` cost one target arm (missing `import re`).
- Fidelity rule: `|z| > 3` against the 13 nights and at least 1 % off the 13-night mean and at least 1 % off the same-day nightly. The third condition was added after the data to absorb a day effect. Say so in the report, do not call it pre-registered.
- Chart bands must use one reference point. Centre the 13-night band relative to the same-day nightly when the dots are "base vs nightly", and express the half-width in the axis unit.
- The nightly's static thresholds: enabling the target package would flip qwen-3-4b tp4 to FAIL (133.44 vs 135 TPS) and leave llama-8b failing as it does every night.
- `TRON_K_VNNI` is compile-time. A kill-switch comparison on one binary measures the AMX kernel alone and leaves the layout in both arms. Comparing the off arm with the nightly's 13-night mean gives the layout's own effect.
- `USE_HW_ATTN` unset means FPGA attention on for ingested models and off for the hand-written plugins. `USE_HW_ATTN=0` turns it off everywhere (a no-op for llama-8b). `USE_HW_ATTN=N` above 0 turns it on for every eligible model.
- qwen-3-4b's AMX probe count (13.7 billion) is small because FPGA attention keeps only the first 127 positions of each query and the newest tokens on the CPU.
- Monitor pitfalls: `tail -F` on the NFS copy of a log written from delphi-3bda sees no appends (tail over ssh on the machine instead), and a trailing `cut` block-buffers (use `stdbuf -oL`).
- The classifier refused writes of scripts that install packages on the shared machine until the user added `Write(//home/jhan/workspace/intel-AMX/exec/ci-mimic-20260918/*)` and `Bash(ssh delphi-3bda:*)` rules. It also refused a ssh key probe to the positron account ("Credential Exploration").
- Bill's marker: `exec/bill-share.sh take` refuses when Bill is active. Every failure path of campaign.sh released the marker, so it had to be re-taken before each relaunch.
