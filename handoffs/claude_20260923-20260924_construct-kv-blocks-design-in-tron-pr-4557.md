## Short version

PR 4557 (typed KV-cache tensors) started the `kv_block` object lifetimes with a placement-new pass named `construct_kv_blocks`, and this session replaced that pass with a design where the DMA allocation call itself creates the objects (draft PR 4587, two commits). Unit tests, machine-code comparison and runtron correctness and performance tests on delphi-3bda showed no regression for PR 4557 or PR 4587, after a 64-byte function-alignment test showed that the only flagged difference (about 1 percent on the AVX fallback path) came from code placement. On the user's instruction, PR 4587 was folded into PR 4557 by fast-forward, and PR 4557 is ready for review at head c73e7fb2f9 with all CI checks green.

## Words used here

- **tron**: the inference program, repository https://github.com/positron-ai/tron.
- **KV cache**: the store of attention keys (K) and values (V) for past tokens. `book` owns the storage, `page` is the per-64-token view, and `kv_block` holds K and V of one KV head for one page.
- **DMA pool**: tron's own allocator for device-visible memory (`dma_allocate_aligned`). It returns raw bytes.
- **placement new**: the C++ form `::new (address) T[n]`. It creates objects at an address without allocating memory.
- **implicit object creation**: a C++20 rule. A call of any function named `operator new[]` creates the objects the program then uses in the returned memory (standard draft N4950, section [intro.object], paragraph 13).
- **std::launder**: a standard function that turns an address into a pointer to the object that lives there.
- **A2-min**: the chosen design. A tagged global `operator new[]` wraps `dma_allocate_aligned`, and the three accessor casts use `std::launder`.
- **K1**: a second, separable commit. `kv_block::k` becomes a plain `bf16` array with the same bytes.
- **C2**: the design of draft PR 4584 (jhan plus Codex). Arenas become `bf16` arrays and `kv_block` disappears.
- **runtron**: the tron benchmark and serving binary used for the machine tests.
- **TPS**: decode tokens per second per user. **TTFT**: time to first token, in seconds (prefill time).
- **AMX**: Intel Advanced Matrix Extensions, the fast attention path on the CPU. **AVX path** or **kill switch**: the same binary run with `TRON_AMX_DISABLE=1`, which falls back to AVX vector code.
- **band**: the no-regression rule from the 2026-09-22 test of PR 4557. A difference is inside the band when it is at most twice the larger standard deviation, or at most 0.4 TPS per user or 0.15 s TTFT, whichever is larger.
- **our half of delphi-3bda**: CPU socket 1 and FPGA cards 90:00.0 and 93:00.0, the half not used by Bill.
- **lcheck**: a clang 19 syntax-only checker built in this session on claude-box, because claude-box has no nix and no clang.

- **The two CI failures on PR 4557 were issue 4593**, not the PR: `t_generate_host_2-fast` (about 35 GB of memory) is killed on runners andoria-02 and andoria-14 when it lands in memory slots 0 to 3, and the runner service then stops. Signature in the log: "The runner has received a shutdown signal" 2 to 3 s before the test is reported failed. Remedy: `gh run rerun <run> --failed`. Use `gh run view <run> --job <job> --log`, because `gh api .../logs` returned empty files.
- **The AVX-path performance flag is code placement.** The removed allocation code shifted nearly all attention functions to a different offset within a 64-byte line. A small AVX-path difference in either direction can appear after any unrelated code change. Test it with `-falign-functions=64` on both sides before blaming a change.
