## The answer (as given in chat)

The header uses the FUSE stats layer for all publishing: 4 calls (is_initialized, get_file_handle, make_file, set_read_callback) in 37 lines [h/tron/models/attn_stats.hpp:721-757 at cbf1bb6c0c]. The PR changes no fuse_* source. The other 700 lines are the store, which the FUSE layer does not provide.

| Need | FUSE layer | attn_stats.hpp |
|---|---|---|
| mount, tree, live read by `cat` / `pho` | yes | calls it (37 lines) |
| one value per file, text on read | yes | JSON text per leaf |
| add or increment | no: `set_value` replaces the value | rows with load-add-store (92 + 203 lines) |
| sums over workers or layers | no | 64 lines |
| timers | no (only a file mtime) | T1 to T5 |
| per-model-state lifetime | no: files are never removed | weak_ptr, takeover by the next state |
| counting with no tree at all | no: `make_file` asserts an initialized tree | yes (unit tests run without one) |

Why the counters cannot live in the FUSE files:

- A leaf stores the caller's value and never derives from the old one. `set_value` takes a writer guard, reads the wall clock, copies the variant and swaps buffers [src/system/fuse_sysfs.cpp:898-925]. The file handle offers only `set_value`, `get_value` and callback setters [h/system/fuse_sysfs.hpp:348-357].
- The per-visit hook runs millions of times per second. The exit report of the final test run counted 10,865,664 decode visits in about 3.2 s. One `set_value` per visit is impossible at that rate.
- `get_value` takes no writer guard [src/system/fuse_sysfs.cpp:933-956]. A leaf shared by several workers and updated by get-then-set would lose updates. One file per value would be 42,938 files for qwen-3-4b tp2 (2 classes x 27 workers x 36 layers x 22 fields, plus FPGA and forward counters). The PR registers 131 leaves with the switch on and 5 with it off.
- The tree is one process-wide singleton [h/system/fuse_stats.hpp:36-48]. A rinzler process can host several models, so rows must belong to the model state [h/tron/models/self_attention.hpp:475].

Precedent: all 11 publisher families in the tree keep their values in program memory or read hardware, and hand the tree a read callback. The whole tree has 2 production `set_value` callers (tensor-loading progress, h/tron/models/model.hpp:1017 and :1035) and 38 read-callback sites. The layer's own design document recommends this shape [doc/fuse_stats_design.md:114]. The closest precedent is the MoE expert stats [h/tron/models/expert_stats.hpp:156-196].

One reason was REFUTED by the workflow and must not be used: "the stderr summary exists because runtron unmounts before the state dies". runtron unmounts at main return, after every batch's state was destroyed [src/runtron.cpp:485, :520, :527]. The summary exists because the rows die with the model state at batch end and the leaves then read `{}` [h/tron/models/attn_stats.hpp:736-738]. Only rinzler unmounts before its states die [src/rinzler.cpp:4806].

A ready-to-paste paragraph for the Note in attn_stats.hpp and for the PR body is in the chat answer and in the memory note.
