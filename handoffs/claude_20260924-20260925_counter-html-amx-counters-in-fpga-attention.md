- **TRON_ATTN_STATS**: the environment variable that turns the PR 4596 counters on. **TRON_AMX_DISABLE**: the kill switch that forces the AVX path instead of AMX.
- **AoF, FPGA attention**: attention scored on the FPGA card. runtron uses it when `USE_HW_ATTN` is unset.
- **AVX path, AMX path**: the two CPU software kernels. The AVX dotter scores any token range. The AMX kernel scores only a dense page.
- **Dense page**: a 64-token KV page whose whole live range the CPU must score through one mask range. Only dense pages take AMX.
- **Visit**: one apply_page_tok call (one page, one query group, one layer, one KV head). The counters count visits.
- **Ready page, pending page**: pages written in earlier forwards versus the page written in this forward. The counters keep them apart.
- **GOF**: a group of four tokens, the unit copied to the card's memory by DMA.
- **Engagement point**: sequence position 127. A query below it is scored fully on the CPU.
- **Boundary L**: the last key position the card scores for a query, taken at plan time from the DMA progress in whole GOFs.
- **State 1 to 8, 5b, 5c**: the cases in which AMX runs under FPGA attention, as numbered on the page (Table 2). The list is in the Results section below.
- **Workflow**: the multi-agent verification tool (readers, refuters, a synthesizer, a critic).
- **delphi-3bda**: the shared CI machine. The campaigns ran on its half assigned to the user, behind the nightly CI lease.
- **Campaign**: one run of exec/attnstats-20260924/campaign.sh on delphi-3bda over a list of cells. A **cell** is one model, user count and prompt length. An **arm** is one binary plus environment, here `headon2` (stats on) and `headkill2` (stats on plus the kill switch).
- **Exit report**: the stderr summary that the PR 4596 binary prints at exit with every counter. The campaign collects them in exit-reports.txt.
- **agentsrv**: the user's Linux dev server where Claude Code ran (called `claude-agentsrv` or `claude-box` in earlier handoffs).

The states that give AMX work under FPGA attention (Table 2 of the page, all code-verified in tron main 0a51385e95):

1. Query below the engagement point (page 0 is dense from position 64). Measured exact.
2. First shard not yet engaged (fewer than 32 landed GOFs, earliest offload at position 128). Measured exact.
3. Copy lag of a whole page (possible up to about 25 GOFs per card, never observed).
4. Degraded shard after HBM exhaustion (its 1,024 tokens and everything after). Not observed (0 warnings).
5. Prefix-cache branch inside a shard. Measured, 3.0 to 3.6 %.
5b. A hole in the copied prefix (whole request on software attention, no warning). Not tested.
5c. A request that repeats a cached answer at temperature 0. Not reproducible with runtron (its iterations diverged).
6. Prefill copy lag. Measured at prompt 8192, 0.6 %.
7. Layers or models that are not card candidates. Excluded for qwen-3-4b (all 36 layers used the card).
8. Hit at the shard end followed by a branch. The page's zero was refuted (about 4 all-CPU forwards).

The 2026-09-17 measurement (501 M AMX-busy cycles under FPGA attention, 57 % of the CPU-attention count) is still unexplained. States 1, 2, 5 and 6 give a few percent at most. The candidates left are 5c and 5b. The test for 5c is rinzler at temperature 0 with the counters on.
