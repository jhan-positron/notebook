## Gotchas & decisions

- Any name-based kill of `sleep` inside the old container (`pkill sleep`, `pkill -f sleep`, `kill -- -1`) stopped the whole container and every session in it. Review and test agents use `sleep` in shell experiments routinely.
- The podman 5.8.4 file events log records `died` with the exit code but no `stop` event for `podman stop`; `kill -TERM 1`, `kill -TERM 2`, `podman stop` and `pkill -x sleep` all look identical (143). Only transcript timing identified the culprit.
- `podman inspect` is unreliable for a past death: its `ExitCode` read 0 while the events log said 143, and `StartedAt` (10:48) was later than `FinishedAt` (00:19) after the restart.
- tmux-continuum autosaves only while a client is attached; save times bound when the server was last alive, not when it died. Only ssh, vim, less and tail are auto-restarted by resurrect; Claude and Codex must be resumed by hand (`claude --resume <id>`, `codex resume`).
- Bash tool outputs of Claude sessions persist under `/tmp/claude-0/<project>/<session>/tasks/*.output` inside the container and survive the container's death; they gave millisecond timing.
- `podman events --since 7d` is rejected by this podman ("unable to interpret time value"); use an absolute timestamp.
