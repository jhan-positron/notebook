## Words used here

- **Asimov, emulator**: Positron's chip and the Cadence Palladium machine that runs its design. Jesse Zhang operates the emulator and runs our code. One second of chip time takes about 2,780 s of wall time.
- **Mesh, crosspoint, step**: the chip's interconnect is a grid of 6 x 6 crosspoints (switches), written (x,y). One move to a neighbour crosspoint is a step. **X step, Y step**: a step along x or along y.
- **Home node**: one of five cache nodes on the mesh, ids 88 at (1,3), 160 at (2,4), 216 at (3,3), 288 at (4,4) and 344 at (5,3). Each holds a 1 MiB slice of the system-level cache.
- **Cluster**: two CPUs that share one L2 and one L3 cache. CPUs 0-1 sit at (1,2), 2-3 at (2,3), 4-5 at (3,2), 6-7 at (4,3), 8-9 at (5,2). CPUs 0 and 1 run the kernel.
- **OCM**: on-chip memory, 256 KiB per home node.
- **Run 8**: the mesh latency map test. Its program is **meshmap** and its script is **run_map.sh**, commit 3b12e4f of https://github.com/jhan-positron/asimov (folder cache-mem-perf), written by the session of `claude_20261110_notion-scratch-page-instructions.md`.
- **Kinds** of row in meshmap:
  - `ocm-flush`: OCM lines of a node, flushed first.
  - `ocm-evict`: OCM lines pushed out of the CPU's caches by loads of other lines (the **evictor**).
  - `slc`: DRAM-backed lines held in a node's cache slice, with the same recipe as `ocm-evict`.
  - `dram-flush`: the same DRAM-backed lines, flushed first, so each load goes to memory.
  - **Flushed kinds** are the first and the last. **Evicted kinds** are the middle two.
- **Cell**: one CPU, one home node, one kind. A cell has 7 timed **passes** of 2,048 dependent loads. **Best**: the smallest ns per load of a cell's 7 passes.
- **Rehearsal** (the pages call it the trial run): one short meshmap command on CPU 2, run before the full run.
- **Boot 1, 2, 3**: the three firmware states of the full run. Boot 1: the L3 holds no data, prefetchers off. Boot 2: L3 in use, prefetchers off. Boot 3: L3 in use, prefetchers on. These states hold for CPUs 2 to 9 only.
- **membench-jibin-013 to -016**: Jesse's result folders. 013 is the rehearsal, 014 to 016 are boots 1 to 3.
- **Lab share**: /home/jzhang/dev/emuMemBenchBox/results/jibin/ on **sw-dev-01** (the shared Linux dev server), where Jesse puts each run's folder.
- **Share**: the core counter `l3d_refill_rd` per load, read as the share of loads that left the cluster.
- **mc_reqs**: a mesh counter column, the requests a home node sends on to memory, per load.
- **Control rows**: four rows of the older program `latency` on the same boot, to compare with meshmap's `ocm-flush` cells.
- **SBSX, memory bridge**: the mesh device that passes a request on to the memory model. **Three-leg path**: CPU to home node, home node to a memory bridge, memory bridge straight back to the CPU.
- **Hash**: the rule that maps the address of a DRAM-backed line to its home node (Arm CMN S3 manual 107858, section 2.4.5.3).
- **rms**: root mean square of a fit's errors.
- **`--kernel-cpus`**: the run_map.sh option that also measures from CPU 0.
- **Review loop**: the file-based loop of the user's inter-agent-review-loop skill, between a worker agent and a reviewer agent. **Digest**: the SHA-256 of the reviewed file.

- **est.**: an estimate, not a measurement. **Insufficient data**: no measurement answers the question.
