- The change widens the timing gate in emu/hemi_tlm/agents/goldcrest_ew_fullconn_avip.sv from `GC_PAIR_INDEX < 16` to `< 18` at two places. The pull request had 4 files, 24 additions and 17 deletions, state OPEN, head 13418eb7c3ae5e828b4feea571497c7895c89f4b.
- The AUX lanes then load the datapath reset profile: 61-cycle reads (61 ns at the 1 GHz lane clock), 40-cycle write responses, a bandwidth budget of 38.4 GB/s per lane, and 63 outstanding transactions.

Findings for the user's use case:

| # | Severity | Finding |
|---|---|---|
| 1 | medium | Nothing verifies the change. The testbenches set the lane parameter directly, the passing simulation job does not embed the lanes, `sys2gc` checks data only, and a Linux boot prints nothing about lanes 32 to 35. |
| 2 | medium | No run-time control and no switch back. The host timing settings loop over 32 lanes only. A comparison of timed against untimed needs one image from before the merge and one from after. |
| 3 | medium | The model is a constant for a read from an already-open row: 40 ns of link plus 21 ns. A random read on real DRAM would cost about 79 to 97 ns of memory delay (est., from a public timing set, not from the actual part). |
| 4 | medium | The 38.4 GB/s budget is per lane and is shared by reads and writes, so the cores see 153.6 GB/s in total. The pull request text does not say "per lane". |
| 5 | medium | Whether the profile fits the cores' DRAM is not established. Insufficient data: the board memory specification would settle it. |
