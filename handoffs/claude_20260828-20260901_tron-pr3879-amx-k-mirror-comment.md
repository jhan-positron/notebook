Words used here: tron = Positron's model-serving (inference) runtime.
AMX = Intel Advanced Matrix Extensions, the CPU matrix-multiply instructions
the new attention kernel uses. AVX = the older 512-bit vector instructions
that the existing attention code (the "dotter" fallback) uses. PR #3879 =
https://github.com/positron-ai/tron/pull/3879, the pull request that adds the
AMX attention path. K mirror = a second copy of the K cache in the tile
layout the AMX kernels need ("arena-mirror" build, `TRON_AMX_K_MIRROR`);
"canonical" = the AMX kernel that reads K as stored (no mirror); "kill
switch" = the same binary run with `TRON_AMX_DISABLE=1`, which falls back to
the AVX dotter. delphi-3bda = the AMX-capable test machine (two Xeon 6962P
CPUs). 1u / 8u = one or eight requests decoding at the same time. A "unit"
= one query token's 4 query heads against one 64-token KV page of one KV
head. "prompt N" (formerly written "ctx N") = a prompt of N tokens; every
run then generates 256 tokens. Sol = the GPT-5.6 reviewer model reached
through PAL (a model bridge script).

Perf-stat round 3 (2026-09-01, phase-locked at decode token 400, 4 of 54
windows excluded for mid-window run end): the AVX arm takes 2x the L1 and
demand-L3 misses and 3.3x the L2 misses of either AMX arm; mirror pays about

at 1u); 99.999% of misses served locally; mirror 72.7 M 4K walks per window
vs canonical 0.11 M; clocks 3.53-3.55 vs 3.74 GHz.

at prompts 2048 and 8192 (765 windows per cell). Conclusion: the base-page
arena costs nothing in wall time; no allocation change is warranted.

## Gotchas & decisions

- NFS attribute cache: a file patched from the container may be read stale
  by delphi-3bda for tens of seconds; grep the content on 3bda before
  building.
- runtron's `RUNPATH` begins with `$ORIGIN` entries: binaries must be run
  from `gen/` (rename in place); copies elsewhere fail with rc=127.
- `kernel.perf_event_paranoid` is 4 on delphi-3bda; the user gave standing
  approval (2026-09-01) to set it to 0 for counter rounds provided every run
  restores 4 with read-back and logs all three transitions.
- Granite Rapids exposes no `AMX_OPS_RETIRED` and no `CORE_POWER.LVL*`
  license events; AMX occupancy comes from `EXE.AMX_BUSY` (0xb7/0x02, from
  Intel's GNR perfmon JSON). With the NMI watchdog on, at most 3
  general-purpose events per counter group.
- A decode window is F3 to F3 with exactly one 7602 record; without that
  filter prefill passes leak into the medians.
- A dTLB counter is not a stall counter: the mirror's 4K-page walks were
  large in count and free in wall time (THP experiment).
- The same-binary kill switch is 2-5 points slower than a clean AVX build;
  never mix the two denominators.
- "ctx" in our scripts and pages meant prompt length; the user chose the
  word "prompt" for all new documents (memory `prompt-not-ctx.md`).
- When a real measurement is planned, publish no derived interim numbers.
- Drain the queue until the window guard says stop; ask only at genuine
  gates (the user twice found the machine idle because Claude stopped to
  ask).
- Two failure detectors lied (`ok` marker on a refused `perf stat`; `ok` on
  a clock-truncated run) before their signatures were added; check marker
  semantics when writing a new campaign script.
- User preference from 08-28 stands: header comments say why in plain words,
  not what the code does.
