## Gotchas & decisions

- Trace timing is compromised in all 20 traces: every trace carries
  Perfetto's `config_write_into_file_discard` data-loss warning
  (`write_into_file` combined with a DISCARD buffer is explicitly
  discouraged by Perfetto), all 20 draws flag
  `invalid_or_incomplete_durations_present` (77 negative-duration slices in
  the fast trace, 105 in the slow), and sibling kernels show mean-duration
  deltas of five orders of magnitude in opposite directions. Only
  `metrics.json` throughput is trusted.
- Two of the five requested categories emit zero slices: `matmul` and
  `gen`. The matmul work is instrumented under other categories (`MoE
  matmul` under `model`; `Prepare/Launch hardware matmul job` under
  `driver`). Effectively three live categories: `scheduler`, `model`,
  `driver`. Prior campaigns had the same gap.
- Harness bug affecting all inherited harnesses: runtron (tron's test-run
  wrapper binary) renames its main thread (`/proc/<pid>/comm` reads
  ` 24/0-Main`), so `pgrep -x runtron` / `pkill -x runtron` never match it;
  the inherited kill/preflight logic silently never killed a stuck engine.
  The 5cat harness also matches on the full binary path.
- Never edit a bash script file that is currently executing from NFS: bash
  reads scripts incrementally, the edit replaces the inode, and the process
  dies mid-script without running its EXIT trap (no cleanup/restore). Run
  campaigns from a `chmod 555` versioned copy.
