## Timeline (2026-08-26, Pacific)

- 12:26-12:30 — Question: "is the K in the mirror not transposed?" Answer
  from source: the mirror plane IS Kᵀ in VNNI layout (VNNI = the
  pair-interleaved operand layout the AMX TDPBF16PS instruction requires
  for its B operand); "no transposing store" refers to the score tile S,
  not K. Canonical orientation produces Sᵀ and pays an AVX-512 transpose
  per page per decode step; mirror produces S directly and pays the
  transpose once per stored K row. A verification script (vnni_check.py)
  emulated TDPBF16PS on the real index formulas; all four asserts passed.
- 12:45 — Confirmed save_k write-through: the mirror scatter runs in
  save_k_impl on the RX worker (the per-device thread that runs completion
  callbacks), immediately after the canonical K store, same loop iteration
  (h/tron/models/model.hpp:2752-2814 in the tron-amx checkout). Complete
  list of mirror write sites: save_k, copy_storage_slot (page moves), and
  fill_random (tests only).
- 13:05 — Wording help: plain replacements for "funnel" and an
  explanation of "null-checks" (all mirror consumers test the plane
  pointer for nullptr; the QK reader falls back to the AVX dotter loop,
  the three writers skip the write).
- 13:24 — Reviewed the user's rewritten PR-description bullet. One real
  misunderstanding: there is no runtime-failure path in the kernels; a
  partially filled last page (< 64 tokens) is a dispatch-eligibility rule
  of TRON_AMX_DISPATCH, evaluated before the mirror pointer is fetched,
  not a mirror failure. One half-right claim: only the reader falls back
  to AVX; writers skip. Terminology fixes (RX worker, head dimension 128,

  heap is built from 1 GB hugepages because the FPGA needs pinned,
  physically contiguous memory for DMA; the TLB gain is a side effect).
- 15:36-17:47 — Hugepage/TLB deep dive with live measurements on

## Gotchas & decisions

- "No transposing store" in the PR text means the score tile S, not K —
  the mirror plane is exactly Kᵀ in VNNI layout. Misreading this was the
  session's starting question.
- There is no runtime-failure fallback in the mirror kernels; the only
  null source is the arena not being allocated. Partial-page cases are a
  TRON_AMX_DISPATCH eligibility rule, common to both kernel orientations.
- On null mirror pointer, the reader falls back to the AVX dotter loop
  (not to the canonical AMX kernel — that call is compiled out under
  TRON_AMX_K_MIRROR); the three writers skip the write.
- In tron, "hugepage memory" and "DMA memory" name the same pool (the pos
  heap); the mirror arena deliberately lives outside it (operator new,
  4 KB pages) so it costs no KV page capacity.
- hugetlbfs allocations never fall back to smaller pages; a short pool is
  a loud startup failure, not a silent slowdown.
