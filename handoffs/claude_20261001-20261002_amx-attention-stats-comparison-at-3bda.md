## Words used here

- **tron**: Positron's inference program (GitHub repo positron-ai/tron). **runtron**: its command-line tool, one process per run. **main dd0f942c75**: the commit built and measured.
- **PR 4596**: https://github.com/positron-ai/tron/pull/4596, the attention path stats (env var TRON_ATTN_STATS). Merged into main before this campaign (main 9c88327931 already contained attn_stats.hpp at 441e81178b).
- **Exit report**: the `[attn-stats]` lines runtron prints to stderr at exit when TRON_ATTN_STATS=1 (7 lines per model: a header, then per class a totals line, a forwards line and a per-layer line). **FUSE leaves**: the same counters as files while the process runs, snapshotted per run into leaves/<run>/.
- **AMX, AVX**: two CPU instruction sets. The AMX kernel scores whole dense 64-token KV pages. The AVX loop (the "dotter") scores every other key the CPU must score. **FPGA attention (AoF)**: the FPGA card scores the keys already copied to it; the CPU scores the 1 to 4 newest keys and some layers.
- **amxon**: TRON_AMX_DISABLE unset, kernel available. **amxoff**: TRON_AMX_DISABLE=1, the kill switch, same binary. **Arm**: one of these two. **Cell**: one model, prompt length and attention mode; each cell ran both arms.
- **attn=cpu**: USE_HW_ATTN=0, software attention. **attn=fpga**: USE_HW_ATTN unset, the model default (FPGA attention for the generated plugins gpt-oss and qwen3, CPU attention for llama).
- **Fitting shape**: head size 128 and 4 query heads per KV head, the only geometry the kernel is compiled for (h/tron/kernels/amx_attn_iface.hpp:148-150 at main). llama-3.1-8b and qwen3-4b fit. gpt-oss-120b (head size 64, 8 query heads per KV head) does not.
- **K tokens**: keys scored, counted once per KV head for the software paths. The report scales the FPGA count by 8 KV heads to the same unit. **Visit**: one (token job, KV head, page) scoring step. **decode_like / prompt_or_mixed**: the two forward classes of the stats (generation steps vs prompt chunks).
- **TPS**: generated tokens per second per user (runtron 'average tok/s', mean over 8 users). **TTFT**: prompt parsing time in seconds, mean over users.
- **T1, T2 (busy), T4, T5 (join wait)**: the stats timers: forward wall, attention job busy, layer period on worker 0, time waiting in the join.
- **Kill-switch identity**: avx_full_page(amxoff) = amx_visits(amxon) + avx_full_page(amxon), and AVX K tokens (amxoff) = AMX + AVX K tokens (amxon). It holds when both arms scored the same positions.

Other verified findings in the report:

- The kill-switch identity holds in all 12 class rows, so the two arms scored the same positions.
- Under FPGA attention, qwen's card scores exactly the K tokens the kernel scored under CPU attention in prefill (1,056,964,608), and 2.5 % more in decode (the partial pending page down to the last complete 4-token group).
- gpt-oss keeps 299,520 full-page AVX visits per decode run in its sliding-window layers. A kernel for head size 64 and 8 query heads per KV head could take at most those: 5.1 % of its decode K tokens, 14.7 % in prefill.
- llama at prompt 1024 absorbs about two thirds of the extra attention time off the forward's critical path (two attention jobs per worker per layer); qwen (one minibatch) passes it through 1:1. Code-supported hypothesis, not a direct measurement.
- The only cross-arm counter difference outside the identity: gpt-oss prefill empty visits 16,218 vs 16,362, and 4 to 11 % more attention jobs in the llama kill-switch runs (a worker-split effect, not more work).

- The cross-avx512 preset is gone from main (2026-09-30, 8d64eeed81). Old CONF strings that name it fail to configure. Use `--preset native`.
