## Measured model numbers (from the Notion sub-pages, script-verified)

| Model | Total params | Active params/token | Checkpoint bytes | Dominant group |
|---|---|---|---|---|
| gpt-oss-120b | 116,829,156,672 | 5,132,852,352 | 65,248,815,744 | experts, 114,661,785,600 weights stored MXFP4 at 4.25 bits/weight = 93.5% of bytes |
| qwen2.5-32b | 32,763,876,352 | (dense; all) | 65,527,752,704 (= params x 2, all BF16) | FFN (W_ff1/W_ff3/W_ff2) = 83% of bytes |

MXFP4 = a 4-bit micro-scaling float format: 4-bit E2M1 values plus one
shared scale byte per 32-weight block, hence 4.25 bits per weight.
Totals match each checkpoint's `metadata.total_size` exactly (asserted by
the generator script on 2026-08-23).

## Gotchas & decisions

- head_dim is stored in `config.json` for some models (gpt-oss-120b:
  `"head_dim": 64`, not derivable there) and derived for others
  (Llama-3-8B, Qwen2.5-32B: hidden_size / num_attention_heads). The
  explainer initially claimed it was stored for Llama-3-8B; corrected.
- "3 = current sequence length" was off by one against real decode; the
  page now says "number of past tokens in the cache" and names the
  simplification.
- Orientation convention: safetensors stores Linear weights as out x in;
  the pages display the math view (rows = input = hidden size) with the
  storage caveat stated once. Byte counts are identical either way.
- The session's title on disk stays "kv-head-vs-query-head token axis
  dimensions" even though most of the work went beyond section 1.
