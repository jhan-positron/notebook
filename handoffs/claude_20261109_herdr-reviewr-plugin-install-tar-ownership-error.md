## Words used here

- **herdr**: a terminal workspace manager for AI coding agents. One server process per herdr session owns the panes (terminals). The user's herdr session in this container is named `claude-agentsrv`.
- **herdr-reviewr**, or **reviewr** (plugin id `persiyanov.reviewr`): a herdr plugin from https://github.com/persiyanov/herdr-reviewr. It shows an agent's diff in a pane and sends a person's line comments to the agent.

- **Build command**: a command that a plugin's manifest tells herdr to run during install. For reviewr it is `bash herdr/install.sh`, which downloads a release archive and unpacks it with tar.
- **User namespace**: a kernel feature that remaps user ids inside a container. **uid_map**: the file /proc/self/uid_map that lists the mapped ids.
- **TAR_OPTIONS**: an environment variable that GNU tar reads as extra command-line options. **--no-same-owner**: the tar option that leaves an extracted file owned by the user who extracts it.
- **Live handoff**: herdr's way to replace a running server with a new binary while the pane processes keep running.
- **Integration**: a herdr hook for one agent product (Claude Code or Codex). It reports the agent's conversation id to herdr, so a restarted server can resume the conversation.
- **Auto mode classifier**: the Claude Code permission check that can refuse a command. It refused one command in this session.
- **Prefix**: the user's herdr prefix key, ctrl+q.
- **tmux**: a terminal multiplexer, a program that keeps several terminals running inside one server process. The user also runs agents under it.
- **sha256**: a checksum that identifies the exact contents of a file.
- **Container overlay**: the container's own file system layer. /tmp is on it, and the home directory is not.
- **claude-agentsrv**: the podman container this Claude Code ran in, on the user's Linux dev server agentsrv (same home directory, same files). **sw-dev-01**: another dev server that mounts the same home directory over NFS (a network file system).
- **Scratchpad**: the session's temporary folder under /tmp/claude-0. A reboot or a cleanup can clear it.

## Gotchas and decisions

- In this container any chown to an id other than 0 fails with "Invalid argument". Every installer that unpacks an archive as root needs `--no-same-owner`. The memory note says that the sw-dev-01 container is set up the same way. The session did not test that.
- herdr build commands inherit the caller's environment. That is why `TAR_OPTIONS` in front of `herdr plugin install` reaches tar.
- On success herdr prints only two lines ("Installed ..." and "Config: ..."). The script's own `reviewr:` lines appear only when the build fails.
- A failed install leaves nothing behind. herdr removes the checkout, so a retry is safe.
- `herdr plugin action list --plugin <id>` prints an empty list for an unknown id, not an error. The id must be spelled `persiyanov.reviewr`.
- `herdr plugin action invoke` acts on the workspace that has focus in the herdr window, not on the shell that typed the command. In a folder that is not a git repository it exits with status 1, and `herdr plugin log list` shows "reviewr: no repo to review".
- Claude Code's auto mode classifier refuses `herdr integration install claude`, because that command edits Claude Code's own settings file. The user must run it from a plain shell.
- The 0.9.1 server log has no line for the panes that the user closed between 2026-11-08 and the handoff. That log is not a record of pane closes.
