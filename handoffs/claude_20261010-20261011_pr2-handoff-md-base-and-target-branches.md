## Gotchas and decisions

- runtron deletes the intermediates log path before opening it, so a named pipe there becomes a 20 GB file and the probe hangs. Use a plain file and filter afterwards.
- A free run that diverges once differs everywhere after that step. Only a forced run (same token list fed to both binaries) makes per-step score comparison meaningful.
- The greedy sampler takes the lower token id on an exact tie, so an exact tie in one binary and a one-step lead in the other produce different tokens from the same rule.
- Count near ties in bf16 steps at each step's own magnitude. The count within 0.25 score units (17) is not the count within 2 bf16 steps (12). The wrong count reached the PR body and the posted comment before it was fixed.
- Correctness across intended arithmetic changes (AMX vs AVX, core count) is "within a documented band of a reference, with equal quality", not "the same token". Bit identity is a valid test only for the identity case.
- The user's mapping "base is PR1, new is PR2, head is main" was wrong. base is main, head is PR-1, new is PR-2.
