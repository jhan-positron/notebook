## Gotchas and decisions

- Call the host phoenix-crb in every document (memory feedback note). Define it once per document.
- Claude's access to the host is the positron-perf account, read-only. Every root change was made by the user from `jhan`, and Claude verified afterwards. Keep that split.
- Every ssh login sends two broadcast IPIs to every core, measured. Reading the CPPC feedback counters sends interrupts to the target CPU. Never log in or read per-CPU sysfs files of CPUs 120 to 127 during a counted run.
- The double taskset in Jeremy's launch line (`taskset -c 120-125 taskset -c 120-125,127 ...`) exists because a taskset whose new mask excludes the current CPU is migrated to any CPU of the mask, isolated ones included. Fork and wake-up balancing never pick isolated CPUs, so the inner set may include 126 and 127 once the outer call has landed the launcher on 120 to 125.
- On this kernel `nohz_full=` is refused, and the flag `isolcpus=nohz` drops the whole isolcpus setting. The stock 6.8.0-147-generic kernel is installed but has never booted on the board and lacks the vendor GIC quirk: never pick it.
- `systemctl disable --now netperf.service` did not stop the running netserver (a SysV-style unit). `systemctl stop` did.
- PID 1 runs on CPUs 0-119 because of the CPUAffinity drop-in, not 0-125. A check written for 0-125 was wrong and was fixed by the as-built checkers.
- The word "void" is the SDK's own verdict name. In messages say "did not count" first, then the term.
- codex's report and the plan agree on the kernel fact. The difference is what follows: the latency judge needs only a pinned pass thread, so counted runs work on the current kernel.
