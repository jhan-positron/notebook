The four-line comparison now on every page (the user's pattern, 2026-10-16):

- PR 4956 changes how one K row is stored (scattered into the VNNI plane instead of written as a row) and how the CPU reads it (the AVX-512 reader instead of the row-major dotter).
- PR 4957 changes who scores a full page (the AMX tile kernel reads the VNNI plane as its B operand) and how the queries are packed for it.
- PR 4958 changes how a run of tokens is written (a 16-token block at once, transposed in registers) and which threads write it (the idle helpers share the store).
- PR 4959 changes what a run shorter than a block saves (row-major rows) and when that block turns VNNI (at the end of the pass that completes it, or never under hardware attention). It also turns the option on in the deb package.

The "run" answer given at 10:23, as a table of what each PR does with a run of n tokens:

| Run length n | PR 4958 | PR 4959 |
|---|---|---|
| 16 (fills the block) | VNNI block save: transpose, 64 whole-line stores | unchanged |
| 2 to 15 | VNNI block save with a present mask: masked line stores into all 64 lines | row-major rows: 4 whole lines per token |
| 1 (decode) | scatter: 4 bytes into each of the token's 64 lines | the same row-major path as 2 to 15 |
| block afterwards | always VNNI, complete or not | row-major until all 16 rows are saved, then converted in place at the forward end |
