Daily benchmark email

Short version: The monitor checks Slack daily at 7:00 a.m. Pacific time and emails jhan@positron.ai. Every email includes “This email was sent by Codex.” The container and its cron daemon must stay running.

What it checks

7:00 a.m. Pacific → Read Slack → Compare metrics → Send email
  • Slack channel: ci-cd-notifications (C06S8PNDBQA).
  • Platform and machine: GRANITE_RAPIDS_72_RINZLER, DUT: delphi-3bda.
  • Benchmark: llama-3.1-8b-instruct-good-tp2 @32u per machine (AMX benchmark).
  • Use the latest matching report posted that day. Its Nightly Report date must also match.
  • Send AMX CI/CD perf regressed when TPS (generated tokens per second) is below 32.3 tokens/s or prefill (input processing throughput) is below 353 tokens/s. Equality passes.
  • Otherwise send AMX CI/CD perf normal. The email body shows the measured decode and prefill rates, each expected range, and PASS or BELOW MINIMUM for each metric. The expected ranges are at least 32.3 tokens/s for decode and at least 353 tokens/s for prefill. There are no upper limits.
  • The displayed minimums come from the same constants used to classify the email. These are the email monitor's thresholds. The nightly report has its own thresholds. The email preserves the entire original Slack line below the comparison, then adds the Codex attribution and report date.
  • Missing or invalid result data produces AMX CI/CD perf unavailable. Connection or process failures are recorded in the logs and may prevent email delivery.

Schedule and process

Supercronic reads schedule.cron. The cron expression is 0 7 * * * with CRON_TZ=America/Los_Angeles. This handles daylight saving time without changing the cron entry. Supercronic v0.2.49 was installed from the official release and its SHA-256 digest was verified.

The monitor uses the existing Codex login and connected Slack and Gmail plugins. It reads configuration from /home/jhan/codex-home-claude-agentsrv. Keep those connections authorized.

The scheduler is detached from the terminal. This container has no service manager, so restart the scheduler after a container restart:

/bin/sh /home/jhan/workspace/random/amx-ci-monitor/start-cron.sh

The startup script holds a lock to prevent duplicate scheduler processes. Each monitor run also holds a lock. A daily email receipt prevents repeat delivery. Before sending, Codex checks Sent mail for an identical message to cover an interrupted previous run.

Inspect or run manually

# Read and classify today's report without sending email:
/bin/sh /home/jhan/workspace/random/amx-ci-monitor/run.sh --dry-run

# Run now; an existing daily receipt prevents another email:
/bin/sh /home/jhan/workspace/random/amx-ci-monitor/run.sh

# Verify threshold and source-validation rules:
cd /home/jhan/workspace/random/amx-ci-monitor
python3 -m unittest -v test_check.py

Files under logs/ contain fetched reports, outgoing email bodies, and Gmail delivery receipts. logs/scheduler.log records cron launches, monitor output, and errors.

To pause the task, comment out the executable line in schedule.cron, then send SIGUSR2 to this monitor's Supercronic process to reload the schedule.
