Capture on Android

Fast: simple mode

adb shell perfetto --time 10s --buffer 64mb \
  --app com.example.app \
  --out /data/misc/perfetto-traces/app.perfetto-trace \
  sched/sched_switch sched/sched_waking am wm gfx view

adb pull /data/misc/perfetto-traces/app.perfetto-trace

--app enables app ATrace events. Names such as am and wm are Android-version-dependent ATrace categories.

Repeatable: config mode

adb push config.pbtx /data/local/tmp/config.pbtx
adb shell perfetto --txt \
  --config /data/local/tmp/config.pbtx \
  --out /data/misc/perfetto-traces/trace.perfetto-trace
adb pull /data/misc/perfetto-traces/trace.perfetto-trace

Minimal config.pbtx

duration_ms: 10000
buffers { size_kb: 65536 fill_policy: RING_BUFFER }

data_sources { config {
  name: "linux.ftrace"
  ftrace_config {
    ftrace_events: "sched/sched_switch"
    ftrace_events: "sched/sched_waking"
    ftrace_events: "power/cpu_frequency"
    ftrace_events: "power/cpu_idle"
    atrace_apps: "com.example.app"
    atrace_categories: "am"
    atrace_categories: "wm"
  }
} }

data_sources { config {
  name: "linux.process_stats"
  process_stats_config {
    scan_all_processes_on_start: true
    proc_stats_poll_ms: 1000
  }
} }
Buffer rule: RING_BUFFER keeps the newest data; DISCARD keeps the oldest data and stops accepting writes when full.

Explore safely

Longest app slices

INCLUDE PERFETTO MODULE slices.with_context;
INCLUDE PERFETTO MODULE time.conversion;

SELECT
  process_name,
  thread_name,
  name,
  ROUND(time_to_ms(dur), 3) AS dur_ms
FROM thread_slice
WHERE process_name = 'com.example.app'
  AND dur > time_from_ms(1)
ORDER BY dur DESC
LIMIT 50;

SQL Â· CPU scheduling

CPU time by thread

INCLUDE PERFETTO MODULE sched.with_context;
INCLUDE PERFETTO MODULE time.conversion;

SELECT
  process_name,
  thread_name,
  ROUND(time_to_ms(SUM(dur)), 2) AS cpu_ms
FROM sched_with_thread_process
WHERE process_name = 'com.example.app'
GROUP BY process_name, thread_name
ORDER BY cpu_ms DESC;

Runnable or blocked time

INCLUDE PERFETTO MODULE time.conversion;

SELECT
  t.name AS thread_name,
  s.state,
  s.io_wait,
  ROUND(time_to_ms(SUM(s.dur)), 2) AS total_ms
FROM thread_state AS s
JOIN thread AS t USING (utid)
WHERE t.name = 'RenderThread'
GROUP BY t.name, s.state, s.io_wait
ORDER BY total_ms DESC;

SQL Â· counters and quality

CPU frequency / idle events

SELECT c.ts, t.cpu, t.name, c.value
FROM counter AS c
JOIN cpu_counter_track AS t ON c.track_id = t.id
WHERE t.name IN ('cpufreq', 'cpuidle')
ORDER BY c.ts;

cpuidle = 4294967295 means the CPU returned to the not-idle state.

Check trace data loss

SELECT *
FROM stats
WHERE severity = 'data_loss'
  AND value != 0;

Non-empty result: fix capture quality before trusting timing conclusions.

Diagnosis checklist

Slow wall timeMeasure the exact area; compare slice duration with CPU-running time.
CPU-boundLong sched time; inspect hottest threads and stack samples.
Scheduler delayLarge thread_state time in runnable state R.
I/O or lock waitBlocked states, io_wait, blocked_function, Binder or mutex slices.
Frequency limitCompare active CPU intervals with cpufreq and cpuidle.
Missing evidenceData source was not captured, buffer wrapped, or events were lost.
Rule: the timeline suggests a cause; SQL measures it. If the required track or table is absent, record again with that data source enabled.
