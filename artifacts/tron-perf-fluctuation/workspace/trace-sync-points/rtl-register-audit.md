# llm_fpga host-observability register audit (2026-08-17)

## Source of truth
- SystemRDL CSR map: `registers/fsm_csr.rdl` (all regs); field detail in
  `registers/fsm_cmd.rdl`; driver-facing merged JSON (BAR + absolute addr):
  `registers/fsm_csr.json` (generated by `registers/gen_json.py`).
- Central status fan-in: `rtl/mm_fsm/mm_fsm_top.sv:118-245`.
- Everything is BAR2 except HBM thermal (BAR4).

## Clocks (drive all cycle counters)
- `clk_mm` = **550.0 MHz** (mmfsm_metrics_* counters) — `archer_top.sv:429`,
  PLL `ip/agilex7/common/core_iopll_1.ip:1122-1124`. (A "560 MHz" comment at
  archer_top.sv:130 is stale.)
- `clk_hbm` = **368.75 MHz** (hbm_metrics) — `archer_top.sv:430`.
- `clk_dma` = **400 MHz** (tracer pacing, CSR access).
- All metric counters are 32-bit and **saturate** (do not wrap) when the
  timer hits 0xFFFF_FFFE: max window 7.81 s (mm) / 11.65 s (hbm). Keep
  capture windows <= ~5 s.

## fpga_use metrics semantics (the block tron reads)
- `hbm_metrics.read` increments once per AXI R-channel **beat** (512-bit =
  64 B payload + 8 B shared-exponent user data), on **initiator/pseudo-channel
  0 ONLY** (`archer_top.sv:2559-2560`). `read/timer` = pchan-0 read duty in
  [0,1]. There is NO aggregate or per-channel-selectable HBM counter.
- mm-FSM counters (`rtl/mm_fsm/mm_fsm_metrics.sv:105-121`):
  `mm_fsm_in_prog` = productive cycles (valid accumulate into the array);
  `mm_fsm_bp` = total stall cycles while an activation in flight;
  `mm_rmem_bp` = stalled on results-FIFO above threshold;
  `mm_wmem_bp` = stalled with RMEM healthy => starved of weights from HBM.
  rmem_bp/wmem_bp are not gated on activ_inprog, so their sum can slightly
  exceed fsm_bp — treat fsm_bp as total, the pair as approximate split.
- SEQUENCING GOTCHA: `metrics_start` does NOT self-clear despite the RDL
  comment (`rtl/rdl/fsm_csr.sv:819-841`); a fresh 0->1 edge is needed per
  capture. tron's start (clear-pulse then start=1) / stop (start=0, done
  pulse) sequence produces the edge correctly. Read result registers only
  AFTER metrics_done (plain 2FF CDC, safe only on hold registers).

## The FPGA tracer (device->host DMA status push)
- Not a register: chip writes a 64-bit sample to host memory at
  `tracer_addr` (CSR 0x200028) every `(delay+1) x 2.5 ns`
  (`tracer_config` 0x200020; delay=400_000 => 1 kHz; tron default period
  10 us). Samples silently dropped on interconnect backpressure
  (`archer_top.sv:2214`). Reading the mailbox is host-DRAM only — zero MMIO,
  zero side effects; poll as fast as desired.
- ABI (`archer_top.sv:2165-2179`): [15:0] rmem_depth (LOWER 4K FIFO);
  [16] mm_results_accum; [18] fetcher0_read_done; [19] fetcher16_read_done;
  [20] activ_inprog; [21] activ_pending; [22] inprog_pause;
  [23] rmem_rdy_legacy (1 = room); [25:24] wmem_loaded_untouched;
  [27:26] wmem_loaded; **[29:28] compute_phase (0=idle, 1=matmul,
  2=attention K, 3=attention V)** — compute_phase was missing from tron's
  decoder (added 2026-08-17 in tron-fpgause).
- CAVEAT: tracer rmem_depth reports the lower 4K FIFO, but backpressure is
  decided on the UPPER 1K CDC FIFO (`mm_fsm_activation_top.sv:95`,
  threshold 870/1024). Read `rmem_ctrl` 0x700400 for the real one.

## Not-yet-read registers, ranked for fast-vs-slow comparison
Tier 1 (highest value):
1. tracer with full decode incl. compute_phase (see above).
2. `rmem_ctrl` 0x700400: upper_rmem_q_depth[47:32] (the FIFO that actually
   gates backpressure) + lower depth + threshold.
3. `cb_stat` 0x700280: aq_depth/aq_empty (activation cmd queue, 1024 deep) +
   wq_depth/wq_empty — **aq_empty during a draw = host is command-starving
   the FPGA; the cleanest "FPGA slow vs host not feeding it" discriminator.**
4. `activ_mgr_dbg_2` 0x100210: r_mem_pause_cnt[63:48] (saturating EVENT
   count of RMEM pauses, clearable via sticky_clr[0]) + sticky/live stall
   reasons (sticky_rmbp/oowbp/cfgbp) + live compute_phase/pause bits.
Tier 2 (cheap per-draw deltas):
5. `cmd_cnt` 0x702000: matmul/attn0/attn1/unknown command counters.
6. **HBM thermal (BAR4 0x0C_0000_0100 north / 0x1C_0000_0100 south)**:
   temprd[7:0] degC, temp[30:28] refresh band, cattrip[31]. A refresh-band
   step = direct bandwidth loss; the most likely PHYSICAL slow-draw cause
   currently unmeasured.
7. `weights_mgr_debug_0/1` 0x100100/0x100108: fetch pipeline state, per-
   fetcher done bitmap (all 32), free-running fetch req/done counters
   (deltas = fetch throughput + in-flight).
8. `wim_debug`/`rim_debug` 0x380000/0x380010 (x2 stacks): host->HBM and
   host<-HBM burst counters (KV/weight upload traffic invisible to
   hbm_metrics) + FIFO pressure + AXI error stickies.
Tier 3 (assert-zero health per draw): `rmem_debug` 0x100300 (per-FIFO
under/overflow), attn_fsm_stat[63:62] credit/depth errors, smax 0x702008
over/underflow, WIM/RIM slverr/decerr stickies, `hbm_debug_0` 0x3000f8 cal
state, `id_dat` 0x000000 (bitstream version — pin per campaign).
Tier 4: all 32 `fetcher_debug_0/1[n]` (0x300100/0x300200 + 8n) — straggler
pseudo-channel detection; `trans_stat` 0x702100/0x702110 min-latency
high-water marks.
Also: `attn_fsm_stat` 0x7002a8 stall taxonomy (emem_starve, aux, accum,
seq_short + error stickies). SDM mailbox 0x300-0x350 gives FPGA die temp and
core voltage (side-effectful FIFO — needs mutual exclusion).
Write-only A/B knobs: `fetch_disable` 0x3000f0 (per-fetcher kill bits +
read-delay injection). No event FIFOs / timestamped trace buffers exist;
the tracer stream is the only time-series mechanism.

## HBM topology and ceiling
- 2 HBM2E stacks x 8 channels x 2 pseudo-channels = **32 pchans**, 1 GB each
  = 32 GB/card; 32 fetchers, 1 pchan per fetcher; fetchers 0-15 north,
  16-31 south.
- Fabric-side per-pchan ceiling: 64 B x 368.75 MHz = **23.60 GB/s** payload
  (26.55 GB/s incl. shared-exponent user bytes).
- Card aggregate: **755.2 GB/s payload** (849.6 incl. shexp) — IF all 32
  pchans are symmetric (hbm_metrics sees only pchan 0; cross-check via the
  per-fetcher registers). Device-side HBM rate is not derivable from this
  repo (compiled IP).
- Sanity identity between the two metric clocks:
  hbm_timer/368.75e6 ~= fsm_timer/550.0e6 for the same window.

## Torn-read caveat
Several 64-bit debug buses cross clock domains via plain 2FF sync without
gray coding (`mm_fsm_top.sv:354-362` and WIM/RIM/smax paths): occasional
torn multi-bit values are possible — use deltas over many samples and drop
non-monotonic readings on free-running counters. No register in the map is
clear-on-read (only two benign rd_swacc strobes).
