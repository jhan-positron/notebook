Where the per-launch decode loss lives: a thread-complete view of the inter-fwd-pass window

perf-fluctuation deep dive · delphi-3bda · drill-down series, gated-perfetto step 0 · 2026-08-12 12:03–12:28 UTC campaign (pfgate-tp4-20260812T120255Z, 20/20 draws ok + smoke)

What was measured

Every tron trace event was put behind a runtime gate that is open only inside the inter-fwd-pass window during decode: it opens when the last layer’s attention finishes (layer 35 barrier) and closes when the next step’s first attention job starts (layer 0 entry). One capture therefore contains ~3700–3890 dense event clusters (“windows”, one per generated token that fits the 25 s capture) separated by silent forward passes, on all threads: the work_queue coordinator, the pool worker that runs the logits job, and the TX/RX driver threads of all four cards. Mike’s “data ready” instant marker (activations ready at each hardware launch, on the TX thread) rides inside the window.

Numerics unchanged, workload unperturbed: all 21 runs (smoke + 20 draws) produced bit-identical token sequences (sha256 66af1d58…93c4, the qwen-tp4 reference), decode TPS stayed in the bare band (170.5–185.3, campaign CV 2.60%, worst-vs-best gap 8.0% — the launch lottery rolled normally).

A1′ = window start → listener job start; B′ = listener job (logits stream wait + consume + callback); C′ = listener end → next step’s first dispatch.

Reading the slow window left to right: the lm-head (wcls) dispatch burst itself pauses ~200µs between chunk completions (card-side); the logits stream wait/consume doubles to 667µs; after the callback there is a 239µs stretch where nothing runs; then the next-step preparation executes ×3–5 slower than the same code in quick windows (compute_forward_args 43→186µs in the two windows shown; pooled medians 35→117µs) with another idle stretch before the first dispatch. Every station stretches together — including pure host compute that never touches the cards.

Disagreements to note. (1) This capture attributes 96.7% of the step difference to the inter-fwd-pass window vs kvprobe7’s 68.3% — the perfetto window additionally contains the layer-35 post-attention MLP and the full dispatch tail, the campaigns’ spreads differ, and the TSC accounting carried a 10.1% reconciliation residual; the derived forward-pass remainder here is flat (+13.6µs), so the earlier “in-attention +17%” share does not replicate in this view. (2) Absolute segment values run larger here for the same reason (wider window edges). The new information perfetto adds: the co-stretch of pure host compute inside stalled windows, and the small true all-idle share (12.3%).

Measured answers to the runbook’s §5.4 question

“In slow windows, where does the wall time between the wcls dispatch and data-ready / fill completion sit — in a named span on some thread (which?), or in unattributed gaps?”

  • Mostly in named spans, split between waiting and slowed-down work. Of the +402µs/step fast4→slow4 window growth: 47.2% named wait spans (the logits stream wait inside fill_logits_buffer is the single largest, +181µs, corr −0.86; TX act_ready/slot waits +381µs summed over 4 TX threads), 40.4% named host work spans that simply run slower (e.g. compute_forward_args, host-only, ×3.3–4.7 in stalled windows; construct_minibatches ×12), and only 12.3% true all-idle.
  • The lm-head input chain also stretches: window start → last wcls data ready goes 247→396µs (corr −0.77), with visible ~200µs pauses between chunk completions in stalled windows (card/DMA side of the stream).
  • The stall is a window-wide state, not one component: every station (card stream, TX waits, host prep) stretches together in a stalled window while waiting_for_logits stays fixed (~185→194µs, corr −0.27) and whole-package core frequency is flat across draws (turbostat Bzy_MHz 3751–3778, 5 s cadence — too coarse for per-window transients).
  • All-idle gaps concentrate at two seams: after the listener callback ends (before the coordinator’s next get_work) and between attention-plan assembly and the first hardware dispatch of the next step.

Next collection targets

1 · Per-window CPU-speed transient (prime suspect for the co-stretch). Pure host compute runs ×3–5 slower inside stalled windows while 5 s turbostat shows nothing. Stamp aperf/mperf (or cycles + ref-cycles) around the window on the coordinator and listener threads to test “cores ramp down during the near-idle inter-fwd-pass and wake slowly — more often in slow launches”.
2 · Stall inter-arrival forensics (cheap, data already on disk). Within each draw, test whether stalled windows are periodic (external poller?), bursty, or memoryless; compare the rate constant against the launch TPS. Every per-window duration for all 20 draws is already in analysis/out/draw_*/draw_*.gaps.csv.
3 · Card-side chunk pauses. The wcls burst shows ~200µs pauses between chunk completions in stalled windows. Scope the existing per-block stream-arrival stamp idea (step-4 target from the TSC series) to stalled windows only, or pull card telemetry for the same windows.
4 · Chunk-size A/B under wall-clock. The harness’s TRON_MAX_LOGITS_CHUNK_SIZE arm is present but was disabled this run; re-enable on alternating draws to test whether smaller logits chunks shrink B′ in stalled windows.
5 · Replicate the mixture finding on delphi-3c51 (Bill’s machine, same shared /scratch tooling): does its narrower spread (CV 0.85%) come with a lower stalled-window rate, same stall profile?

Glossary and traceability

inter-fwd-pass windowthe once-per-token end-of-step path: last layer’s attention ends → lm-head (wcls) matmul → streamed logits consumed → token picked → next step’s first dispatch. “Window” on this page always means one such occurrence, recovered as a dense cluster of trace events separated by >1.5 ms silences.
draw / launch lotteryone benchmark process start; the same binary and input lands at a per-launch decode speed that persists for the whole run.
wcls / lm-headthe final vocabulary-projection matmul (151k vocabulary) whose streamed output are the logits.
gatean atomic flag checked inside tron’s perfetto emission macros; trace events are dropped at the source while it is closed. Open/close sites: layer-35 attention barrier / layer-0 attention entry (decode batches only), defensive close on parse batches.
corrPearson correlation coefficient of a per-draw quantity vs the draw’s decode TPS across the 20 draws; −1 = longer exactly when slower.
span / instanta named begin/end interval (span) or single timestamped marker (instant) emitted by tron’s TRACE_EVENT macros on the thread that executes it.
