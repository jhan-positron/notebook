Are gap lengths evenly distributed?

No — even less so than the slow draw. CV 87% with three sharply separated regimes: a near-zero cluster under 200 µs (39% of passes), a mid cluster at 600–800 µs, and a distinct slow band at 1,300–1,600 µs (~20%). No drift over the window (first half 635 µs, second half 621 µs) — the regimes interleave throughout rather than evolving.

This is where the fast draw differs most: 871 gaps (55%) are bridged end-to-end by an in-flight rx collecting results (draw_18: 33%), and moe_blend/attention work spans hundreds more — device-side work overlaps the host-side turnaround far more deeply here.

Verdict: as in draw_18, the interval is not idle time — it contains the pass epilogue, the scheduler’s get_work, and (more than in the slow draw) overlapped device activity. The definition measures host-side turnaround, and the same boundary adjustment applies if pure idle is wanted.

Are O1a lengths evenly distributed?

No — bimodal, but with a stronger fast mode than the slow draw. CV 128%; 78% of passes sit in the 50–150 µs mode (draw_18: 59%), with the slow regime thinner and spread to ~1,500 µs. The slow regime grows over the window (138 µs first half → 225 µs second half).

Same structural finding as draw_18: measured from compute_forward_args end to forward start the interval is negligible (median 0.4 µs, p99 10.4 µs) — O1a is the duration of compute_forward_args itself, and the fast draw simply keeps that function in its fast mode more often.

The fast draw does not merely shrink the gap — it changes regime: three times as many near-zero gaps and two-thirds more gaps bridged end-to-end by in-flight rx collecting results, i.e. markedly deeper overlap of device receive with the host-side turnaround. Its compute_forward_args (≈ O1a) also stays in the fast mode far more often (78% vs 59%). Both point the throughput difference at host-side turnaround efficiency and pipelining depth, not at device compute or clocks.

Memory allocation and deallocation events

malloc/free are not in the capture. Three checks, run against both draws’ traces:

  • Slice-name sweep for malloc, free, alloc, mmap/munmap, heap, hugepage, delete, mem: the only match is the application-level Free scratchpads slice — no libc/allocator-level events exist.
  • heapprofd (heap_profile_allocation): 0 rows — the native heap-profiling data source was not enabled in this capture (the config enables only the five track_event categories: scheduler, model, matmul, driver, gen).
  • Counter tracks: none — no process/system memory counters (process_stats/sys_stats were not configured).

Free scratchpads is runtron’s own scratchpad-buffer release, running on a dedicated worker thread (draw_18-slowest: 32,434 occurrences — the count scales with pass count, one batch per forward pass region). To capture true malloc/free, a future campaign would add the android.heapprofd data source (native heap profiling with sampled callstacks) or process_stats counters to the Perfetto config — neither is part of the current five-category template.

SQL used for this check
SELECT s.name AS slice_name, COUNT(*) AS n, CAST(AVG(s.dur) AS INT) AS mean_ns FROM slice s WHERE LOWER(s.name) LIKE '%malloc%' OR LOWER(s.name) LIKE '%free%' OR LOWER(s.name) LIKE '%alloc%' OR LOWER(s.name) LIKE '%mmap%' OR LOWER(s.name) LIKE '%munmap%' OR LOWER(s.name) LIKE '%heap%' OR LOWER(s.name) LIKE '%hugepage%' OR LOWER(s.name) LIKE '%delete%' OR LOWER(s.name) LIKE '%mem%' GROUP BY s.name ORDER BY n DESC LIMIT 40;
SELECT COUNT(*) AS heapprofd_allocations FROM heap_profile_allocation;
SELECT t.name AS counter_track, COUNT(*) AS samples FROM counter c JOIN counter_track t ON c.track_id = t.id GROUP BY t.name ORDER BY samples DESC LIMIT 20;

SELECT s.category, th.name AS thread_name, COUNT(*) AS n, CAST(AVG(s.dur) AS INT) AS mean_ns, CAST(SUM(s.dur)/1e6 AS INT) AS total_ms FROM slice s JOIN thread_track tt ON s.track_id = tt.id JOIN thread th ON th.utid = tt.utid WHERE s.name = 'Free scratchpads' GROUP BY s.category, th.name ORDER BY n DESC LIMIT 10;

SQL queries used

Identical scripts to the draw_18 analysis, run against this draw’s trace (gap extraction via windowed running-maximum over the merged RX-end/CFA event stream; validation classifies every slice start/end against gap boundaries; gap-extract2.sql is the boundary-corrected ends pass).

gap-extract.sql
-- rx-collect slice ends (gap start candidates)
CREATE PERFETTO TABLE rx_ends AS
SELECT s.ts + s.dur AS t
FROM slice s JOIN thread_track tt ON s.track_id = tt.id JOIN thread th ON th.utid = tt.utid
WHERE s.name LIKE 'rx collecting result%' AND th.name LIKE '%RX-%' AND s.dur >= 0;

-- compute_forward_args on the work_queue thread (gap end = its start)
CREATE PERFETTO TABLE cfa AS
SELECT s.id AS sid, s.ts, s.dur, ROW_NUMBER() OVER (ORDER BY s.ts) AS idx
FROM slice s JOIN thread_track tt ON s.track_id = tt.id JOIN thread th ON th.utid = tt.utid
WHERE s.name = 'compute_forward_args' AND th.name LIKE '24/%work_queue%';

CREATE PERFETTO TABLE fwd AS
SELECT s.id AS sid, s.ts, s.dur FROM slice s WHERE s.name = 'forward';

-- for each cfa, the latest rx-collect end at or before it
CREATE PERFETTO TABLE ev AS
SELECT t, 0 AS kind, NULL AS idx FROM rx_ends
UNION ALL
SELECT ts AS t, 1 AS kind, idx FROM cfa;

CREATE PERFETTO TABLE gaps AS
SELECT idx, last_rx AS gap_start, t AS gap_end, t - last_rx AS gap_ns
FROM (SELECT t, kind, idx, MAX(CASE WHEN kind = 0 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_rx FROM ev)
WHERE kind = 1 AND last_rx IS NOT NULL;

-- O1a: cfa start -> next forward start
CREATE PERFETTO TABLE o1a AS
SELECT c.idx, c.ts AS cfa_ts, c.dur AS cfa_dur, (SELECT MIN(f.ts) FROM fwd f WHERE f.ts >= c.ts) AS fwd_ts
FROM cfa c;

-- validation: slice starts / ends falling strictly inside any gap
CREATE PERFETTO TABLE sev AS
SELECT gap_end AS t, 0 AS kind, NULL AS nm, NULL AS gs FROM gaps
UNION ALL
SELECT gap_start AS t, 1 AS kind, NULL, gap_start FROM gaps
UNION ALL
SELECT s.ts AS t, 2 AS kind, s.name, NULL FROM slice s;

CREATE PERFETTO TABLE starts_state AS
SELECT t, kind, nm,
  MAX(CASE WHEN kind = 1 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_open,
  MAX(CASE WHEN kind = 0 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_close
FROM sev;

CREATE PERFETTO TABLE v_starts AS
SELECT nm, COUNT(*) AS n, COUNT(DISTINCT last_open) AS gaps_hit
FROM starts_state
WHERE kind = 2 AND last_open IS NOT NULL AND (last_close IS NULL OR last_open > last_close)
GROUP BY nm;

CREATE PERFETTO TABLE eev AS
SELECT gap_end AS t, 0 AS kind, NULL AS nm FROM gaps
UNION ALL
SELECT gap_start AS t, 1 AS kind, NULL FROM gaps
UNION ALL
SELECT s.ts + s.dur AS t, 2 AS kind, s.name FROM slice s WHERE s.dur > 0;

CREATE PERFETTO TABLE ends_state AS
SELECT t, kind, nm,
  MAX(CASE WHEN kind = 1 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_open,
  MAX(CASE WHEN kind = 0 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_close
FROM eev;

CREATE PERFETTO TABLE v_ends AS
SELECT nm, COUNT(*) AS n, COUNT(DISTINCT last_open) AS gaps_hit
FROM ends_state
WHERE kind = 2 AND last_open IS NOT NULL AND (last_close IS NULL OR last_open > last_close)
GROUP BY nm;

-- slices that fully enclose a gap (start before, end after)
CREATE PERFETTO TABLE v_span AS
SELECT s.name AS nm, COUNT(*) AS n, COUNT(DISTINCT g.idx) AS gaps_hit
FROM slice s JOIN gaps g ON s.ts < g.gap_start AND s.ts + s.dur > g.gap_end
WHERE s.dur >= (SELECT MIN(gap_ns) FROM gaps)
GROUP BY s.name;

SELECT 'meta_fwd_thread' AS kind, COUNT(*) AS a, 0 AS b, 0 AS c, 0 AS d, th.name AS nm
FROM fwd f JOIN slice s ON s.id = f.sid JOIN thread_track tt ON s.track_id = tt.id JOIN thread th ON th.utid = tt.utid GROUP BY th.name
UNION ALL
SELECT 'meta_rx_name', COUNT(*), 0, 0, 0, s.name FROM slice s WHERE s.name LIKE 'rx collecting result%' GROUP BY s.name
UNION ALL
SELECT 'gap', idx, gap_start, gap_end, gap_ns, '' FROM gaps
UNION ALL
SELECT 'o1a', idx, cfa_ts, fwd_ts, cfa_dur, '' FROM o1a WHERE fwd_ts IS NOT NULL
UNION ALL
SELECT 'v_start', n, gaps_hit, 0, 0, nm FROM v_starts
UNION ALL
SELECT 'v_end', n, gaps_hit, 0, 0, nm FROM v_ends
UNION ALL
SELECT 'v_span', n, gaps_hit, 0, 0, nm FROM v_span;

FROM slice s JOIN thread_track tt ON s.track_id = tt.id JOIN thread th ON th.utid = tt.utid
WHERE s.name = 'compute_forward_args' AND th.name LIKE '24/%work_queue%';

CREATE PERFETTO TABLE ev AS
SELECT t, 0 AS kind, NULL AS idx FROM rx_ends
UNION ALL
SELECT ts AS t, 1 AS kind, idx FROM cfa;

CREATE PERFETTO TABLE gaps AS
SELECT idx, last_rx AS gap_start, t AS gap_end, t - last_rx AS gap_ns
FROM (SELECT t, kind, idx, MAX(CASE WHEN kind = 0 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_rx FROM ev)
WHERE kind = 1 AND last_rx IS NOT NULL;

-- ends stream with boundary-correct ordering: at t==gap_start a slice END sorts
-- BEFORE the gap-open event, so the defining slice is excluded; at t==gap_end
-- the close sorts first, excluding ends at exactly cfa start.
CREATE PERFETTO TABLE eev AS
SELECT gap_end AS t, 0 AS kind, NULL AS nm FROM gaps
UNION ALL
SELECT s.ts + s.dur AS t, 1 AS kind, s.name FROM slice s WHERE s.dur > 0
UNION ALL
SELECT gap_start AS t, 2 AS kind, NULL FROM gaps;

CREATE PERFETTO TABLE ends_state AS
SELECT t, kind, nm,
  MAX(CASE WHEN kind = 2 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_open,
  MAX(CASE WHEN kind = 0 THEN t END) OVER (ORDER BY t, kind ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS last_close
FROM eev;

SELECT nm, COUNT(*) AS n, COUNT(DISTINCT last_open) AS gaps_hit
FROM ends_state
WHERE kind = 1 AND last_open IS NOT NULL AND (last_close IS NULL OR last_open > last_close)
GROUP BY nm ORDER BY n DESC;
