gpt-oss-120b: parameters → bytes

How the published config.json numbers of openai/gpt-oss-120b turn into the 65,248,815,744-byte checkpoint (65.25 GB). Matrix names follow the ASIMOV dataflow diagram (the Scratch page): WE, WQ, WK, WV, WO, Gate (expert selection), Wff1/Wff3 (the FF13 pair into SwiGLU), Wff2 (FF2), WE+1.

head_dim = 64 — one width shared by query heads AND KV heads
head_dim is the width of every head’s vector, not a query-head-only number: each of the 64 query heads makes a 1×64 q, and each of the 8 KV heads makes a 1×64 k and a 1×64 v. q and k must match because the score q·k is a dot product; v uses the same width by convention. Unlike Qwen2.5-32B (where head_dim is derived), here it IS a stored config key, and it cannot be derived: hidden_size / num_attention_heads = 2,880 / 64 = 45 ≠ 64 — the query output (4,096) is deliberately wider than the hidden size. It sizes WQ as 2,880×(64×64) and WK/WV as 2,880×(8×64).

K-Cache and V-Cache from the diagram are runtime DRAM state, not weights — they do not appear in the checkpoint. The diagram’s QK-Norm blocks apply only to models that have them (Qwen3-style); gpt-oss has none. The 64 “sinks” per layer are one learned attention-sink logit per query head.

Shape convention: rows = input dimension (math view, x·W, matching the kv-head-vs-query-head page). The checkpoint stores every weight transposed (out×in): q_proj.weight is (4,096, 2,880) in the safetensors file. Parameter and byte counts are identical either way. WE is an index lookup — one row per token id — and is kept as 201,088×2,880; WE+1 is stored as (201,088, 2,880) like every other weight.

3 · The three calculations that matter

Experts (93.5% of all bytes). Each expert has the SwiGLU pair Wff1, Wff3 stored fused as one FF13 matrix of 2,880×5,760 — the two 2,880×2,880 matrices interleaved along the 5,760-wide output axis (even columns Wff1, odd columns Wff3) — plus the FF2 down-projection Wff2 of 2,880×2,880:

36 layers × 128 experts × (2,880×5,760 [FF13] + 2,880×2,880 [FF2])
  = 36 × 128 × 24,883,200
  = 114,661,785,600 weights            ← this term is the “120b” in the model name
stored in MXFP4 at 4.25 bits = 0.53125 B/weight:
  114,661,785,600 × 0.53125          = 60,914,073,600 B
  + expert biases in BF16: 36 × 128 × (5,760+2,880) × 2 B =     79,626,240 B
  = 60,993,699,840 B  (60.99 GB)

Attention (BF16, all 36 layers). Widths come from the head counts: q width = 64 heads × 64 = 4,096; k/v width = 8 KV heads × 64 = 512 (GQA: 8 query heads share each KV head).

per layer:  W_Q 2,880×4,096 + W_K 2,880×512 + W_V 2,880×512 + W_O 4,096×2,880
            = 26,542,080 weights
            + biases (4,096+512+512+2,880) + 64 sinks = 8,064
× 36 layers = 955,805,184 params × 2 B = 1,911,610,368 B  (1.91 GB)

Embeddings (BF16, untied).

W_E   201,088 × 2,880 = 579,133,440
W_E+1 201,088 × 2,880 = 579,133,440

Remainder: Gate (expert selection) 36×(128×2,880 + 128) = 13,275,648 params (26,551,296 B) and RMS norms 73×2,880 = 210,240 params (420,480 B).

4 · Why 4.25 bits: the MXFP4 block

Block widths drawn to scale (16 : 1). The contracted dimension 2,880 = 90 blocks of 32, which is why the stored block tensors have shape (128, rows, 90, 16) in uint8.

5 · Byte budget by tensor group (65.25 GB total)

Bars to scale, zero-based, GB = 10⁹ bytes. Color = storage format. Expert bars include their BF16 biases; the attention bar includes the biases and the sinks. Gate and norms are drawn to scale — at this scale they are invisible, which is the point.

Verification against the real checkpoint (measured 2026-08-23)
Sum of all rows above = 65,248,815,744 bytes. The published model.safetensors.index.json reports metadata.total_size = 65,248,815,744 bytes — an exact match, and the per-tensor byte sum read from all 15 shard headers (HTTP range reads) agrees exactly as well. 65,248,815,744 B = 65.25 GB = 60.77 GiB.

Glossary (plain words)

MXFP4
A 4-bit floating-point storage format. Weights are stored in groups of 32; each weight keeps a 4-bit value and the group shares one 8-bit scale factor, so the average cost is 4.25 bits per weight. Only the expert matrices use it here.
BF16
16-bit floating point, 2 bytes per number. Used for everything the quantizer excluded: attention, Gate, embeddings, biases, norms.
MoE / expert
Each layer has 128 separate feed-forward networks (experts). The Gate picks 4 of them per token, so most expert weights are idle for any one token — but all of them must stay resident in memory.
FF13 / FF2
Diagram names for the feed-forward matrices: FF1 and FF3 both read the latent and feed SwiGLU (gpt-oss stores them fused, interleaved as one FF13 tensor of doubled width 5,760); FF2 projects the SwiGLU output back to width 2,880.
GQA
Grouped-query attention: 64 query heads share 8 KV heads, so WK/WV are 8× narrower than WQ.
Attention sink
One learned scalar per query head added to the softmax denominator, letting a head attend to nothing.
