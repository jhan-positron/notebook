Humanfia: the projects, features, and workflows

Humanfia is a family of projects built around Humanize. Humanize is the runtime you install and run as hmz. humanize1 is an optional package of workflows that Humanize runs. [Humanize] [humanize1]

The components are installed at different levels. Installing Humanize gives you its built-in flows. You add other flow packages as needed. The research projects have their own repositories and task setups.

How to choose for a normal working day

  • “Explain this repository.” Use chat or your usual agent session.
  • “Develop a cache-layout design.” Start with humanize1:gen-idea, inspect the draft, then plan the chosen direction.
  • “Adapt these existing PRs and check the result.” Start with rlar and the specific acceptance conditions in this guide.
  • “Find opportunities for higher TPS and lower TTFT.” Draft candidate investigations first. Use a bounded experiment loop once the baseline and measurement process are available.
  • “Automate this recurring integration procedure.” Write a custom flow, or use aot to draft one after the procedure is settled.

For this guide, the practical starting set is Humanize plus rlar. Add humanize1 when you need design work. Use the other packages when their specific coordination rules solve an observed problem in your process.

3. Understand effort, defaults, and budgets

QuestionAnswer
Does Humanize choose the effort for this task?You set it per role. The flow cannot change that agent’s effort during the run.
Must I also change each CLI’s global settings?For a run with explicit effort bindings, set the choice in Humanize. It passes the setting to the selected CLI.
What does auto mean?Humanize omits the effort setting. The CLI’s default applies. This does not ask Humanize to tune effort to task difficulty.
Does high mean the same thing for both agents?Each backend interprets its own effort word. Equal names do not imply equal reasoning time, cost, or quality.
Can every model use every effort?No. Choose from the selected model’s menu. Humanize rejects an unsupported backend effort before starting a run.
What happens when I change the model?The interface keeps a supported effort. Otherwise, it selects the new model’s highest effort. Check before saving.

These behaviors are documented in Humanize’s effort guide. My proposed starting point is high for both roles. The caller and worker-ordering checks justify deliberate review. Consider a supported higher reviewer setting, such as xhigh, if the first review leaves a difficult question unresolved. This is an engineering recommendation, not a measured model comparison.

A run budget controls the whole loop. Effort controls an agent’s reasoning setting. The default budget behavior lets the active turn finish after the limit is reached, so a 2h budget can exceed two hours of elapsed time. A budget stop can return exit status zero even when work remains. [Budgets and exit status]
