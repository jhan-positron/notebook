qwen2.5-32b: parameters → bytes

How the published config.json numbers of Qwen/Qwen2.5-32B turn into the 65,527,752,704-byte checkpoint (65.53 GB). One rule covers the whole model: every tensor is BF16, so bytes = parameters × 2, exactly. Matrix names follow the ASIMOV dataflow diagram (the Scratch page): WE, WQ, WK, WV, WO, Wff1 (FF1), Wff3 (FF3), Wff2 (FF2), WE+1.

head_dim = 128 — one width shared by query heads AND KV heads
head_dim is the width of every head’s vector, not a query-head-only number: each of the 40 query heads makes a 1×128 q, and each of the 8 KV heads makes a 1×128 k and a 1×128 v. q and k must match because the score q·k is a dot product; v uses the same width by convention. It is not a stored key in this config — it is derived as hidden_size / num_attention_heads = 5,120 / 40 = 128 (the divisor is the query-head count; KV heads reuse the same width). It sizes WQ as 5,120×(40×128) and WK/WV as 5,120×(8×128).

Shape convention: rows = input dimension (math view, x·W, matching the kv-head-vs-query-head page). The checkpoint stores every weight transposed (out×in): k_proj.weight is (1,024, 5,120) in the safetensors file. Parameter and byte counts are identical either way. WE is an index lookup — one row per token id — and is kept as 152,064×5,120; WE+1 is stored as (152,064, 5,120) like every other weight.

3 · The three calculations that matter

Feed-forward (83% of all bytes). A dense SwiGLU MLP in every layer: Wff1 and Wff3 both map 5,120 → 27,648 into SwiGLU, Wff2 maps 27,648 → 5,120 back. Three matrices of the same size:

64 layers × 3 matrices × (5,120 × 27,648)
  (W_ff1, W_ff3: 5,120 → 27,648; W_ff2: 27,648 → 5,120 — same element count)
  = 64 × 3 × 141,557,760
  = 27,179,089,920 params × 2 B = 54,358,179,840 B  (54.36 GB)

Attention (12% of all bytes). Widths from the head counts: q width = 40 heads × 128 = 5,120; k/v width = 8 KV heads × 128 = 1,024 (GQA: 5 query heads share each KV head).

per layer:  W_Q 5,120×5,120 + W_K 5,120×1,024 + W_V 5,120×1,024 + W_O 5,120×5,120
            = 62,914,560 weights
            + biases on q,k,v: 5,120 + 1,024 + 1,024 = 7,168   (W_O has no bias)
× 64 layers = 4,026,990,592 params × 2 B = 8,053,981,184 B  (8.05 GB)

Embeddings (untied).

W_E   152,064 × 5,120 = 778,567,680
W_E+1 152,064 × 5,120 = 778,567,680
= 1,557,135,360 params × 2 B = 3,114,270,720 B  (3.11 GB)

Remainder: RMS norms (64×2 + 1) × 5,120 = 660,480 params (1,320,960 B).

4 · Byte budget by tensor group (65.53 GB total)

Bars to scale, zero-based, GB = 10⁹ bytes. Single storage format (BF16), so one hue. Norms are drawn to scale — invisible at this scale.

Verification against the real checkpoint (measured 2026-08-23)
Sum of all rows above = 32,763,876,352 params × 2 B = 65,527,752,704 bytes. The published model.safetensors.index.json reports metadata.total_size = 65,527,752,704 bytes — an exact match, and the per-tensor byte sum read from all 17 shard headers (HTTP range reads) agrees exactly as well. 65,527,752,704 B = 65.53 GB = 61.03 GiB.
The “32B” in the name
Exact parameter count: 32,763,876,352 ≈ 32.76B. Because every tensor is BF16, the checkpoint is exactly twice that in bytes — the entire parameters→bytes mapping is the single factor “×2”. Contrast with gpt-oss-120b, where the answer depends on which matrix contains the weight (MXFP4 experts at 4.25 bits vs BF16 attention and embeddings).

Glossary (plain words)

BF16
16-bit floating point, 2 bytes per number. This checkpoint stores every tensor in it.
Dense (vs MoE)
One feed-forward network per layer that every token uses. No experts, so no Gate matrix.
FF1 / FF3 / FF2
Diagram names for the SwiGLU feed-forward matrices: FF1 and FF3 both read the latent (their outputs multiply inside SwiGLU); FF2 projects the result back down.
GQA
Grouped-query attention: 40 query heads share 8 KV heads, so WK/WV are 5× narrower than WQ.

Sources: huggingface.co/Qwen/Qwen2.5-32B — config.json and model.safetensors.index.json + shard headers, accessed 2026-08-23. All “bytes” are stored checkpoint bytes; runtime memory adds KV cache and activations. GB = 10⁹ bytes, GiB = 2³⁰ bytes.
