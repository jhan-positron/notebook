From reconstructable GOF staging to batched prompt attention

Start with PR 2906: a GOF's two host DMA staging buffers become disposable cache, rebuilt from durable KV pages and pinned only while DMA reads them. PR 3385 builds on that lifecycle to let many prompt queries share one hardware-resident K/V prefix—without duplicate transfers, causal overshoot, capacity overflow, or premature staging eviction.

Executive summary

One lineage, two ownership problems

PR 2906 solves memory lifetime: formatted GOF staging is reconstructable, so completion may evict it after the final DMA reader leaves. PR 3385 solves submission and execution ownership: concurrent paths reserve each shard/GOF/layer exactly once, then prompt Qs share resident K/V while carrying distinct causal boundaries. The two mechanisms meet at xfer_gof, but they protect different facts.

The central bridge: first reserve the right to submit one GOF/layer, then prepare and pin the ephemeral staging that descriptors will read. Once submitted, commit both promises and let completion independently mark HBM progress and release the final staging reader.
Semantic coverage

Short queries and per-query causal tails remain software work, so no token range is dropped or counted twice.

Capacity

EMEM determines shards per subpass and activations per inner loop; the metadata ring limits the logical batch.

Lifetime

PR 2906 pins reconstructable staging; PR 3385 also owns metadata slots and multi-subpass result buffers.

Concurrency

GOF DMA uses sparse per-layer bitsets, contiguous prefixes, and rollback-safe reservations.

Section 1

Background: the machine this PR is changing

The smoothest entry is the lifecycle introduced by PR 2906. It explains what a GOF is, which KV copies are durable, and why asynchronous DMA needs an explicit owner. From there, PR 3385's planner, metadata, subpasses, and sparse completion accounting become extensions of a familiar transfer pipeline.

PR 2906 foundation: staging is a cache, not the data

A GOF (“group of four”) owns two hardware-formatted host buffers: one K block and one V block, each 8 KiB. Before PR 2906 those buffers stayed allocated for the GOF's lifetime. PR 2906 recognizes that they are merely a swizzled DMA view. The durable host KV pages—the code calls them “the books”—remain available for reconstruction, and the FPGA has its durable HBM copy after a successful transfer. Evicting staging therefore does not forget tokens or change GOF identity.

That observation turns staging into a five-state lifecycle. The staging_busy atomic gate serializes the free-versus-prepare handoff. While holding it, prepare_for_dma() reacquires missing buffers, rebuilds K/V position tables, repopulates from the books if needed, and increments dma_inflight before exposing the buffers to a submitter.

The PR 2906 invariant: a descriptor may read staging only while its in-flight credit exists. An uncommitted inflight_guard rolls a pre-submit credit back; after submission, dma_tracker::push() is noexcept and the tracker owns completion. The tracker pops before decrementing, then calls free_staging_if_idle() outside its mutex.
Shutdown is not completion. dma_tracker::clear() may abandon queue entries and drop their shared pointers, but it deliberately neither decrements dma_inflight nor frees staging. Only observed hardware completion proves the buffers are safe to reclaim.

Attention in three quantities

For one query vector Q, attention scores every eligible cached key K, normalizes the scores, and uses the resulting probabilities to blend cached values V. During prompt parsing there are many Q vectors in one forward pass. Causality means query at position 2,047 may see keys through 2,047, while the next query may see one more key.

s = QKᵀ

Score the query against every visible key. The visible prefix may differ per query.

p = softmax(s)

Normalize scores. Tron's partial result carries a max and a sum so disjoint ranges can be merged safely.

o = pV

Blend values into the output vector. Hardware and software partials meet in the join phase.

Why splitting works: a partial attention accumulator contains the weighted value sum plus the softmax maximum and sum. join_page_ranges can merge two disjoint context ranges as though they had been processed together. The PR reuses this property for multiple hardware subpasses as well as the established hardware/software join.

The hardware cache has four useful scales

Tron's token tree stores ordinary software KV pages, while a second, hardware-formatted representation is progressively DMA'd into FPGA HBM. The names below recur throughout the patch.

K and V use different HBM layouts. K is token-major. V is transposed and striped across pseudochannels; for the common 32-fetcher layout, moving one GOF produces four K transfer specifications plus 32 V specifications. That descriptor fan-out explains why reducing producer-lock acquisitions matters.

The existing end-to-end path

The bridge: two guards, two different promises

PR 3385 does not replace PR 2906's staging guard. It adds a reservation in front of it because live rodeo dispatch and shard backfill may race to submit the same layer. The reservation answers “who may submit?”; the original guard answers “how long is the source memory safe to read?” Conflating them would either allow duplicate HBM writes or free staging under live descriptors.

The Stage 2 limitation

Before PR 3385

  • A hardware pass had one shared causal boundary.
  • prepare_hwattn_cmds asserted B == 1.
  • Any scheduler entry with more than one query was folded wholesale from HW back to SW.
  • One pass meant one physical command and one result block per Q.

After PR 3385

  • Every hw_query carries its own last readable token position.
  • Compatible prompt queries share K/V loads in batches up to the device cap.
  • Only the short-query case and each query's uncovered causal tail return to SW.
  • One logical pass may join up to four EMEM-safe physical subpasses.
Section 2

Intuition: separate what can be shared from what cannot

The K/V prefix is expensive but shareable. The Q vector and its causal end position are cheap but query-specific. The PR reorganizes the request around that distinction, then introduces two capacity boundaries: how much context one physical subpass can hold, and how many Qs its inner loop can process at once.

Toy example: four queries, four shards, two subpasses

Take a 64-head model with 1,024-token shards. EMEM can hold two such shards for one Q, while compound splitting lets an ingested model form a four-shard logical pass. Suppose four prompt queries have consecutive causal ends. The planner may batch the Qs because they share the same shards, have the same number of physical subpasses, and their boundaries are equal or increase by one.

Two meanings of “batch size” now coexist. activ_cnt = B is the logical number of Qs in the request. activ2proc is the EMEM-safe divisor processed together inside one physical command. For B = 12 and an EMEM cap of 2, hardware may loop in groups of 2 without splitting the logical Q batch.

The causal boundary stays per query

An hw_plan_entry captures the HBM-resident boundary seen during tree descent. Rechecking DMA later would race with new completions and could move the boundary beyond the scheduler's mask transition. The planner therefore freezes that boundary and assigns each query min(query_position, resident_boundary).

Explore the two EMEM limits

EMEM capacity explorer

Adjust a physical subcommand's shape. The helper ignores head dimension for EMEM—it matters to activation memory, not the E-value store.

16 128-token pages
2 raw Q cap = ⌊1024 / (pages × heads)⌋
2 activ2proc, largest Q-count divisor ≤ cap
4 complete shards per physical subpass

This shape is runnable. A 12-Q logical batch loops in six groups of two. 

PAGEcnt = ceil(local_sequence_tokens / 128)
raw_q_cap = floor(1024 / (PAGEcnt × attention_heads))
activ2proc = largest divisor of B that is ≤ raw_q_cap

max_shards_for_one_Q =
  min(floor(1024 / attention_heads) × 128 / shard_tokens,
      4096 / shard_tokens)

The first formula limits Q parallelism inside a subpass. The second limits context per subpass. If even one complete shard does not fit—more than 128 heads for today's 1,024-token shard—the model is gated to software before scheduler masks can claim any hardware range.

Out-of-order facts, in-order progress

DMA completions can arrive out of layer order. A scalar “largest layer seen” is unsafe: if layer 2 finishes before layer 1, advertising progress through layer 2 would let consumers read a hole. The new bitset records exact facts, while dma_done exposes only the contiguous prefix.

Section 3

Code: follow one prompt batch through the stack

The cleanest reading order is the runtime order: decide whether hardware may own a range, build a safe logical plan, lower it into hardware commands, recover and join the results, and keep the HBM KV prefix fed without duplicate or out-of-order DMA claims.

00

PR 2906 baseline: make GOF staging reconstructable

PR 2906 · hwattention.hpp · gof.{hpp,cpp} · dma_tracker.{hpp,cpp} · model.hpp

Begin here because PR 3385 inherits this machinery essentially unchanged. In Git history, PR 2906 produces the h/tron/gof.hpp blob that PR 3385 starts from; PR 3385 only adds tracing inside prepare_for_dma(). The staging gate, pointer rebuild, in-flight credit, tracker pin, and completion-driven eviction are the established contract—not new Stage 3 behavior. 

// PR 2906: all steps happen under the per-GOF staging gate.
lock_staging();
finally unlock([this] { unlock_staging(); });

if (!k.is_allocated()) k.reacquire_buffer();
if (!v.is_allocated()) v.reacquire_buffer();
if (!populated) populate(...);     // rebuild from durable host KV pages

dma_inflight.fetch_add(1);
return inflight_guard{this};        // rolls back unless submission commits

The counter and the gate solve different races. The counter tells eviction how many submitted DMAs may still read staging. The atomic CAS/wait gate makes the zero-to-one handoff indivisible: either free wins first and a later prepare rebuilds, or prepare wins first and free rechecks a nonzero count. The final implementation does not use a std::mutex for staging. 

auto guard = g->prepare_for_dma(...);
auto last = sh->xfer_gof(*g, gof_index, layer);
guard.commit();                     // descriptors now own the reader credit

tracker.push(device,
    pending_xfer{last, sh, gof_index, layer, g}); // pins GOF, noexcept

// Completion: pop before decrement; free outside tracker.mu.
if (pinned && pinned->dma_inflight.fetch_sub(1) == 1)
    to_free = pinned;
// ...release tracker.mu...
if (to_free) to_free->free_staging_if_idle();
No lock inversion: prepare releases staging_busy before tracker push takes dma_tracker::mu; completion releases dma_tracker::mu before the free path takes the staging gate. The two are never nested.

PR 2906's tests verify pointer-table rebuilding, rollback versus commit, last-reader eviction, abandon semantics, real FPGA free/reacquire DMA round trips, 1,000-cycle allocation balance, tracker pin lifetime, and multi-target fanout. That evidence is the safety floor under every PR 3385 GOF transfer.

01

Admit the model, then partition each query

model.hpp · full.hpp · common.hpp · hw_attn_config.{hpp,cpp}

use_hw_attn_for_this_model() becomes the single admission gate. It combines model shape, EMEM's ability to hold one full shard, the generated model's default, and the process-wide USE_HW_ATTN override. This is more than configuration hygiene: it prevents the scheduler from marking ranges HW-only when the planner would later produce an empty plan. 

if (max_shards_for_emem(n_heads, head_size, shard_tokens) == 0)
    return false;                   // force complete SW fallback

return fwd_hw_attn_enabled(model_forces_hw_attn());
// USE_HW_ATTN, if set, overrides the model default.

The scheduler no longer treats “more than one query” as automatic software work. Instead it performs two targeted reconciliations:

  1. Queries below position 127 have their bits moved from HW to SW in every affected range.
  2. For multi-query entries, a finalized range is split immediately after the resident boundary; only the later causal tail is moved to SW.
Safety property: the HW/SW masks are a partition of work. Incorrect gating could produce a silent “neither path computes this token” gap; incorrect tail handling could double-count or violate causality.
02

Turn resident-shard snapshots into compatible Q batches

model.hpp · common.hpp · self_attention.hpp

Two small data-model changes unlock the new plan. hw_query gains a per-Q boundary. hw_pass gains the number of physical subpasses whose results must be joined. 

struct hw_query {
    token_job_id job_ix;
    size_t last_hw_token_pos;       // absolute, inclusive
};

struct hw_pass {
    PosDevice* dev;
    vector<shard const*> shards;
    vector<hw_query> queries;
    size_t physical_subpasses = 1;
    // scratchpad, length, and max boundary omitted
};

construct_hw_plan now works in three passes over its input: 

1. For each scheduler entry:
   freeze resident_boundary
   create (job, min(query_position, resident_boundary))
   group identical (device, shard-vector) seeds

2. For each seed:
   sort and deduplicate jobs, keeping the furthest safe boundary
   sort by boundary

3. Form a batch while:
   Q count stays below maximum_hwattn_batch_size
   boundaries are equal or exactly sequential
   every Q needs the same physical-subpass count

The final condition is subtle. A shorter Q must not be carried into a later subcommand whose first shard begins beyond that Q's extent. Grouping only queries with equal subpass counts makes every metadata word valid for every emitted subcommand.

Device-local positions are concatenated, not subtracted. Shards assigned to one FPGA may be non-contiguous in absolute token space. If that device owns 1,024-token shards beginning at global positions 0 and 2,048, global position 2,600 becomes local index 1024 + (2600 − 2048) = 1576. The new relative_hw_tok_ix() walks the shard list to compute this correctly.

Generated “ingested” models enable compound splitting by default. A logical pass may contain up to four shards even when EMEM only permits one or two shards physically; the worker then emits two to four subpasses. Other models can opt in with TRON_HWATTN_COMPOUND_SPLIT.

prepare_hwattn_cmds removes the old B == 1 assertion. It computes the largest Q boundary to determine how many shared K/V shards are needed, splits those shards by EMEM capacity, writes per-Q/per-subpass metadata, and emits one AC0/AC1 pair for every physical subpass.

The metadata ring becomes an explicit lifetime

The device has 128 host metadata slots. Preparing several requests before launching them used to leave room for accidental overwrite. Each slot now carries an atomic prepared owner, encoded as request_id + 1 so zero remains “free.” Prepare claims every slot; tx_launch releases them after launch has consumed the prepared descriptors.

Reviewer caveat: this proves one pass fits, not that every prepared pass fits cumulatively. prepare_hw_attention prepares all passes before launch releases any metadata owners, and a long-context Q can appear in more than one same-device shard-chunk pass. The final diff does not assert Σ(queries_in_pass × physical_subpasses) ≤ 128 per device. Atomic owners turn an over-budget plan into a loud assertion instead of silent corruption, but the global capacity argument still depends on topology or planner constraints not established by the per-pass static assertion.

Weight-load reuse becomes capability-driven

HW-attention WLR is now automatic on known-good bitfiles: project 01 at version 05.08 or later; project 03 at 05.08 or later and dated 2026-05-18 or later. HWATTN_WLR=0/1 still forces the choice. Reuse is limited to a single physical subpass (num_acmds == 2), avoiding a compound-command mismatch.

04

Land and join every partial without stale completion

self_attention.hpp · common.hpp · driver.cpp

A raw landing buffer is enlarged from one hardware result to four. The streaming layer learns result_blocks_per_activation, so each Q receives its complete sequence of subpass blocks. Unpack decodes block zero directly into the pass accumulator, decodes later blocks into a temporary accumulator, and merges them with join_page_ranges. 

decode(raw + 0 × hw_result_size, pass_accumulator);

for each later subpass:
    decode(raw + subpass × hw_result_size, temporary_accumulator);
    join_page_ranges(pass_accumulator, temporary_accumulator);

Completion changes from atomic<bool> to a per-layer generation atomic<uint64_t>. A callback for layer L stores L + 1; the joiner waits until the slot reaches that generation. A stale true from the previous layer can no longer release a join onto results that have not arrived.

Why no reset? Resetting a boolean at the next layer can race with the RX callback and erase a completion. A monotonic generation needs no cross-thread reset and makes old state visibly old.

This scheme still relies on the device queue preserving layer order for a reused pass slot: a later generation would satisfy an older >= expected wait.

05

Make GOF DMA exact, rollback-safe, and cheaper to submit

shard.hpp · gof.{hpp,cpp} · dma_tracker.cpp · hwattention.hpp · driver.cpp

PR 2906 supplied only scalar start/done watermarks. PR 3385 strengthens that existing transfer lifecycle: each of a shard's 256 GOFs now records exact “started” and “done” layer bits for up to 256 layers. The frequently polled gof_dma_state keeps only two compact atomic prefixes and a pointer; the larger bitsets and their start lock live in a cold per-shard side table. That keeps count_complete_gofs() cache-dense and avoids false sharing between DMA writers and scheduler pollers. 

auto reservation = shard.try_reserve_gof_dma(gof_index, layer);
if (!reservation) return;           // duplicate or already complete

auto staging_guard = gof.prepare_for_dma(...);
auto final_descriptor = shard.xfer_gof(...);
reservation.commit();               // keep the exact started fact
staging_guard.commit();             // tracker now owes the reader decrement
tracker.push(device,
    pending_xfer{final_descriptor, shard_ptr, gof_index, layer, gof_ptr});

Completion performs the two independent obligations in the opposite direction: mark_gof_dma_done(gof, layer) records HBM progress, then the inherited PR 2906 path pops the tracker entry, decrements dma_inflight, and may evict the host staging pair. “Layer is resident” and “source memory is reclaimable” happen at the same completion event but remain distinct state.

Layers that never use hardware are premarked started and done when the shard is constructed. Without that step, a perfectly valid SW-only layer would create a permanent hole and stop every later contiguous prefix.

xfer_gof no longer calls a lock-taking transfer routine once per K/V block. prep_xfer first materializes all descriptor arguments—commonly 4 K blocks and 32 V blocks—and xfer_n_blocks validates them, takes the queue's producer mutex once, writes the full descriptor sequence, and publishes one final tail. Completion of that final descriptor implies completion of everything preceding it. The post-submit mark_gof_dma_started() call is idempotent bookkeeping for direct-call compatibility; duplicate prevention comes from try_reserve_gof_dma() before submission.

06

Generate the right launch order and roll out deliberately

LoopyTron.hs · Tron.hs · TronCpp.hs · TronTron.hs · TraceSidecar.hs · model.hpp

The ingest IR gains four conditional statements: MaybePrepareEarlyHwAttention, MaybeLaunchEarlyHwAttention, and their late counterparts. Codegen emits both routes around save_k/save_v; runtime batch size selects exactly one route.

Large batch · B ≥ 16 by default

Prepare HW attention
Launch HW attention
Save current K
Save current V

Overlaps HW work with current K/V persistence. Hardware only reads the already-resident prefix.

Small batch · B < 16 by default

Save current K
Save current V
Prepare HW attention
Launch HW attention

Keeps the established late-launch ordering when overlap is unlikely to repay its setup cost.

TRON_HWATTN_EARLY_LAUNCH_MIN_B changes the threshold. Generated model structs set force_hw_attn = true, so ingested models default on when eligible; USE_HW_ATTN=0 remains a global emergency off switch, while USE_HW_ATTN=1 can enable other eligible models.

Reviewer checklist: the invariants worth tracing

No ownership gap

If a model or query cannot run in HW, its mask must remain in SW from scheduler through join.

No causal overshoot

Each metadata word must derive from that Q's frozen boundary, translated into the current device-local subpass.

No capacity overshoot

Shard count, activ2proc, logical B, metadata words, command arrays, and result landing size each have a separate bound.

No stale lifetime

Prepared metadata cannot be overwritten before launch; old completion state cannot release a later layer.

No DMA hole

Public progress is the contiguous prefix of exact bits, not the numerically largest completed layer.

No duplicate submission

Backfill and live dispatch must contend on the same reservation and commit only after descriptors are published.

No premature eviction

Every submitted target owns a PR 2906 in-flight credit until its tracker completion is popped.
