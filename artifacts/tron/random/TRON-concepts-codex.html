Computation · visibility · storage · scheduling

How the five
concepts fit together.

TRON is a hardware inference system. Inference runs a trained model to produce an output. This page follows token work through a large language model (LLM).

Short version

A minibatch groups token work for execution. Attention uses a visibility rule, such as a sliding window, to choose the keys and values (K/V) each query may use. KV cache pages store those keys and values across execution steps.

Words used here
  • Token: one model input unit.
  • Request: one generation task.
  • Layer: a repeated model stage.
  • Query (Q): the vector asking for information at one token position.
  • Mask: marks which query–key pairs may contribute.
  • Token job: work for one token in a sequence.
  • Forward pass: evaluates the model for selected token jobs.
  • Scheduler: selects sequence work to run.

TRON’s grouping and visibility objects support these distinctions. [T1] [T2] [T3]

These strips describe lifetimes, not durations. Once Q is ready, TRON can process pages whose K/V is complete. Pending-page work waits for its new K and V. The partial results are then combined. [T6]

Why group work into minibatches? Different resources can overlap.

TRON uses minibatches to overlap accelerator work with central processing unit (CPU) attention. M0 and M1 below name two minibatches. The accelerator computes vectors for M1 while the CPU attends for M0. [T6]

05 / Check your intuition

Predict the change before revealing it.

Make pages larger.

Keep queries 8–11 and a 6-token window. Change page capacity from 4 to 8 tokens. Does query 11 see more K/V?

Reveal answer

No. Query 11 still sees positions 6–11: 6 keys. The group still needs positions 3–11: 9 keys. They now span 2 pages instead of 3 pages. The attention rule stayed fixed.

Look at the group’s final query.

In the default example, query 11 needs positions 6–11. Can the whole group discard positions 3–5 before attention?

Reveal answer

No. Earlier queries in the same group still need them. Query 8 needs position 3. The group must keep every position needed by any of its unfinished queries.

Add another request.

Put one token from request B beside three tokens from request A. Does B gain access to A’s K/V?

Reveal answer

No. The group has 4 token jobs from 2 requests. Sequence-specific visibility remains separate. Sharing an execution group does not add cross-request attention.

Scope and simplifications
  • The interactive matrix shows one sequence and one attention operation at one layer.
  • Logical page arithmetic assumes a contiguous sequence in this toy layout. TRON separates token IDs from sequence positions. The mock keeps old K/V resident. It does not simulate TRON’s allocation, eviction, prefix sharing, or hardware transfers.
  • Each token slot represents the K/V associated with that token. Vector dimensions and the arrangement of attention heads are omitted.
  • A mask can be more general than one continuous interval. The example uses ordinary causal visibility plus an optional sliding window.
  • Full causal attention means all preceding positions plus the current one in the illustrated sequence. It does not mean unlimited model context.
  • Decode examples assume one new token per active sequence per step. They omit speculative decoding and branching generation.
  • Animation speed is chosen for reading. It is not measured TRON performance.
