7. Terms in this request

Phoenix CRB
The team’s Arm reference server. The supplied messages do not expand the letters “CRB.”
CPU ID / core
A CPU ID is Linux’s number for a runnable processor. On the inspected host, each requested CPU has its own reported core.
Runtime / pass thread
The runtime coordinates SDK execution. “Pass thread” is Jeremy’s runtime term; its exact function and placement controls need his confirmation.
Housekeeping CPUs
CPUs left to run operating-system maintenance and background work. The proposed group is 0–119.
Governor / CPUFreq
The governor selects a processor-performance policy. CPUFreq is the Linux subsystem that applies it.
Pinning / affinity
Restricting a thread or interrupt to a specified set of CPUs.
Tick / nohz_full
A tick is a periodic scheduler interrupt. Full-tick suppression can stop it during eligible single-task execution.
RCU callbacks
Deferred kernel work associated with read-copy-update synchronization. Offloading moves that work to kernel threads.
IRQ / managed IRQ
An interrupt request signals an event that needs handling. The kernel controls the routing of managed interrupts.
Root / sudo
Root is the administrator account on Phoenix. Sudo can run authorized commands with another account’s privileges. The test account remains unprivileged.
Asimov / LSF
Asimov names the accelerator cards in the original request. LSF names the shared batch-worker system Jeremy says is too noisy for these runs.
Latency measures
Per-step overhead measures host coordination. Inter-token latency is the gap between output tokens. First-token latency is the initial response delay. Reader wake-up latency measures resuming a waiting reader.
