So the SLC lines that one core has read are taken to be stored on the core's own mesh. Counters support this for CPU 0. For the other cores only the latency supports it. Home lines and proxy lines use the same 64 slices. One mesh has 64 slices of 1 MiB each. That is 64 MiB. The SLC misses of one buffer start at that size.

  • Shared storage. Arm states that home lines and proxy lines share the storage of each slice [CMN S3 TRM, section 2.1.1.4 page 55].
  • Limits. Software with access to the mesh configuration registers can cap the share of each kind with an occupancy limit. Each limit is a 7-bit field. Its value after reset is the largest value [CMN S3 TRM, section 4.5 pages 335 to 336, and register cmn_hns_lbt_cfg_ctl on pages 1038 to 1039]. The limits of CRB were not read.
  • Demand. In the measured 32 MiB buffer, half of the lines are homed on each mesh. The same is expected for any buffer that consists of complete pairs of lines, each pair aligned to 128 bytes of physical address (not measured). So for one core about half of its lines are home lines, and half are expected to be proxy lines. The demand on each crosspoint is then about equal for the two kinds. The run did not count the lines of each kind in a slice.
  • Measured and inferred. Measured: the SLC misses of one buffer start at 64 MiB (section "Effective capacity is 64 MiB for one buffer"). Inferred: this size is the capacity of the 64 slices of one mesh. Also inferred: neither limit was below about one half of a slice (0.5 MiB, est.) for this workload.
