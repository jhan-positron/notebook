Protocol Agents that communicate over a CML_SMP may have to be uniquely identiﬁed. These
protocol agents can be either a Requesting Agent (RA), Home Agent (HA) or a Subordinate Agent
(SA). A requesting agent can either be a caching agent or a non-caching agent. A caching agent
is the one that sends coherent traﬃc and can cache the line in its local cache. These agents must
have a unique ID so they can be tracked in the remote Snoop Filter (SF). In CMN S3(AE) with
hierarchical home LCN, each coherency domain is considered as a caching agent that requires
unique ID. CXL Type1 devices can be attached to CMN S3(AE) and each CXL Type1 device is
considered as a caching agent. CMN S3(AE) is compliant to CXL3.0 and supports multiple caching
agents behind a CXL.cache port. A non-caching agent can be an RN-I or RN-D. Non-coherent
traﬃc from RN-Fs bypasses LCN and is directly sent to CCGs, hence RN-F for non-coherent
traﬃc is considered as non-caching agent. Each of these Requesting Agents, are assigned a unique
Requesting Agent ID (RAID). Further, the CML_SMP protocol messages are routed using ID-based
routing. CMN S3(AE) supports direct connect mode for CHI C2C Host to Device connections. In
CHI C2C, requests are routed based on address and all other message types are routed based on
ID. Refer to the CHI C2C speciﬁcation for more details.
On a given CMN mesh, unique LDIDs are assigned per device type (RN-F, RN-I, RN-D etc.) by
default and they sequentially range from zero to n-1, where n is the number of devices per device
type. RN-F LDIDs can be further overridden by programming por_mxp_p[0-3]_ldid_override
register at the MXP device port where a given RN-F is connected. Refer to Identifying clusters and
individual devices in clustered mode for more details on this LDID override.
Multiple LCN slices together form a coherency domain. Each coherency domain is treated as a
single caching agent and all LCN slices belonging to the same coherency domain are assigned the
same LDID. This LDID must be programmed in HN-S’s lcn_ldid ﬁeld of cmn_hns_lbt_cfg_ctl reg.
There can be multiple coherency domains on a given chip and are expected to be assigned unique
LDID in the range zero to m-1, where m is the total number of coherency domains on the chip.
cmn_hns_rn_cluster* programming is needed in LCN slices to mark valid_lid* = 0 for all local RN-Fs
which are not in this LCN’s coherency domain.

the protocol messages. CMN multi-chip Gateway (CCG) maps between C2C or CML_SMP ID
space (RAID and HAID) and on-chip ID space (LDID).

8.4.9.5 Assign LDIDs to remote caching agents
Use this procedure to assign a unique LDID for each remote caching agent (RN-F) that can send
requests to HNs (HN-F, HN-I, HN-D, and HN-P).
About this task
This task is part of the requirements to enable communication between local and remote agents.
For the full list of requirements, see Program CML system to enable CML_SMP communication.
HN-Fs use the LDID of remote caching agents for SF tracking. LDID assignment is not required for
non-caching RAs, for which snooping is not required.
Procedure
1.
Program unique LDIDs for each remote caching agent in the
por_ccg_ha_rnf_exp_raid_to_ldid_reg<X> register that is present in each HA. The LDID values
for remote RN-Fs must be greater than those values that are used by the local RN-F nodes,
unless you override local RN-F LDIDs by using the por_ccg_ra_rnf_ldid_to_ovrd_ldid_reg_0-127
register.
2.
Set the ldid<X>_rnf bit, which marks the remote agent as a caching agent, and set the
respective valid bit.
3.
Set the ldid<X>_cxl bit, which marks the remote agent as a cxl agent, and set the respective
valid bit.
4.
Program the HA NodeID at the LDID index of each remote caching agent in
cmn_hns_rn_cluster<X>_physid_reg<Y> register in the HN-F. Set the appropriate attributes for
remote bit, LCN bypass, CPA enable, and CPA group information for each LDID. Set the srctype
for remote caching agents to “CHI-G”, since they are represented by the HA. For CXL Type 1
device, set lcn_bypass_dis to ‘1’.
For a CXL Type 1 device, set corresponding CCG HA logical ID bit in
cms_hns_cxg_ha_smp_exclusion_list and cmn_hns_cxg_ha_metadata_exclusion_list
to ‘1’ .
For CCG HA on IOHUB chiplet which is connected to compute chiplet, set
corresponding CCG HA logical ID bit in cmn_hns_cxg_ha_snp_throttle_disable_list to
‘1’.

8.4.9.6 Program HA RN SAM in CCG
Use this procedure to program the RN SAM in each CCG.
About this task
RN SAM is used to route the incoming request to respective Home Nodes. If hierarchical home is
not enabled on a given chip, then the CCG target ID is programmed for address range belonging
to remote Home Nodes. Currently this is only allowed on specialized IO/Memory chip in a
heterogeneous system conﬁguration.
For more information about RN SAM programming, see RN SAM and HN-F SAM programming.
8.4.9.7 Program RA RN SAM in CCG
Use this procedure to program the RA RN SAM in each CML_SMP CCG.
About this task
In Hierarchical caching system, RA RN SAM is used to route the incoming CML_SMP snoop
request to the respective Local Coherency Nodes (LCNs). For more information about RA RN SAM
programming, see RN SAM and HN-F SAM programming
