<li><b>Slice occupancy limits.</b> The 64 MiB a core sees is explained as one mesh's 64 slices holding both home lines and proxy lines. The limit on each kind's share of a slice (CMN S3 TRM, capacity partitioning, pages 335 to 336, register cmn_hns_lbt_cfg_ctl on pages 1038 to 1039) was not read. Reading it needs the mesh configuration registers, which sit in the Root security space, not perf. Root on Linux may not be enough.</li><li><b>Home hash and proxy map.</b> The hash rule fits one buffer of 16 chunks. PA bits 37 and higher were not tested, and other choices of the bits 21 to 36 fit as well. The proxy crosspoints are fitted from the latency of one run. They were not read from the mesh registers. Which node id stores a line was not measured. Whether a line can be in its home slice and in a proxy slice at once was not measured. Tests: a second buffer with other physical pages, homelat from CPUs 120 to 127, and a read of the node id table of each mesh [CMN S3 TRM, Figure 4-2 page 327].</li>
