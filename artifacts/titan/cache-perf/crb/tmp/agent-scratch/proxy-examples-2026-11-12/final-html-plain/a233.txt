<p class="take"><b>So the SLC lines that one core has read are stored on the core's own mesh. Home lines and proxy lines use the same 64 slices. This explains why the SLC misses of one buffer start at 64 MiB: one mesh has 64 slices of 1 MiB.</b></p><ul><li><b>Shared storage.</b> Arm states that home lines and proxy lines share the storage of each slice [CMN S3 TRM, section 2.1.1.4 page 55].</li><li><b>Limits.</b> Software with access to the mesh configuration registers can cap the share of each kind with an occupancy limit. Each limit is a 7-bit field. Its value after reset is the largest value [CMN S3 TRM, section 4.5 pages 335 to 336, and register cmn_hns_lbt_cfg_ctl on pages 1038 to 1039]. The limits of CRB were not read.</li><li><b>Demand.</b> Half of the lines of a buffer are home lines and half are proxy lines. So the demand on each crosspoint is about equal for the two kinds. The run did not count the lines of each kind in a slice.</li><li><b>Measured and inferred.</b> Measured: the SLC misses of one buffer start at 64 MiB (section "Effective capacity is 64 MiB for one buffer"). Inferred: neither limit was below about one half of a slice (0.5 MiB, est.) for this workload.</li></ul>
