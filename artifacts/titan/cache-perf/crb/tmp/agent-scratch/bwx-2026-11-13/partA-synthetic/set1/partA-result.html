Words used here

  • CRB: the Arm Phoenix Reference Server (128 cores, AArch64). All measurements ran there.
  • Part A, screening: the first part of the plan. It uses the existing benchmark programs. It can show where to look next. It decides no hypothesis.
  • Observed in screening: the wording for every result of Part A. It means: seen in this run, without a control.
  • Kernel: one timed loop of the benchmark bandwidth.c. It is not the Linux kernel.
  • Old read, old write: the C kernels before 2026-11-13, from the program bw_old.
  • New read, new write: the C kernels since 2026-11-13, from the program bw_new.
  • asm read, asm write: the kernels written in assembly, here always from bw_new.
  • Process, launch: one start of the benchmark program. The tag of a launch is its name in the run script.
  • Repetition, interval: one timed period inside a process. Its shortest length is set by the option --min-ms.
  • Pass: one sweep of a thread over its whole buffer. A thread runs whole passes until the interval is over.
  • Rate: bytes moved per second, in GB/s (1 GB = 109 bytes).
  • Total: the rate of a repetition as the benchmark prints it: the bytes of all threads divided by the longest time of a thread.
  • Thread rate: the bytes of one thread divided by its own time. The benchmark prints it with 2 decimals.
  • Sum of thread rates: the thread rates of one mesh added. It is not the same number as the total.
  • Median: the middle value of a sorted list.
  • Mesh 0, mesh 1: the two halves of the chip. CPUs 0 to 63 are on mesh 0. CPUs 64 to 127 are on mesh 1, and we use 64 to 119.
  • a+b threads: a threads on mesh 0 (CPUs 0 to a-1) and b threads on mesh 1 (CPUs 64 to 64+b-1).
  • q: the thread rate at the 10th percentile divided by the thread rate at the 90th percentile, in one repetition. A percentile here is the value at that position of the sorted thread rates.
  • Split, uniform, between: the provisional pattern labels of a repetition: q below 0.65, q above 0.85, or neither.
  • Low, high, changing: the provisional level labels of an interval with one thread at 8 MiB: below 69 GB/s, above 70.5 GB/s, or neither.
  • 2 MiB pages, --no-thp: Linux can back memory with pages of 2 MiB instead of 4 KiB (transparent huge pages, THP). With --no-thp the benchmark asks for 4 KiB pages.
  • Load: the Linux 1-minute load average: the average count of tasks that run or wait to run.
  • Runnable tasks: the count of tasks that can run at one moment (4th field of /proc/loadavg).
  • Waited: the time the script waited for at most 2 runnable tasks before a launch, 20 s at most.
  • H2, H3a, H7a, H7b, H8, H9a, H9b, H11, Q2a, B4, B7, B8: labels of hypotheses, questions and later steps in the plan [Ref1].
  • SVE: the scalable vector instruction set of AArch64.
  • est.: an estimate, not a measurement.

Distribution of q over all repetitions with many threads

q is the rate of the thread at the 10th percentile divided by the rate of the thread at the 90th percentile, in one repetition. The provisional rule of the handoff calls a repetition split if q is below 0.65, uniform if q is above 0.85, and between otherwise [Ref2]. The handoff asks to look at the distribution first. If q does not fall into two groups, the labels are not used [Ref2].

One dot is one repetition. Dots are moved a little up or down so that equal values stay visible. The grey band is the range that the rule calls "between". Each row is labelled with its lowest and highest q.

Observed in screening: the 116 values of q fall into two groups. 48 values lie from 0.49 to 0.59, and 68 values lie from 0.96 to 1.00. No value lies between 0.59 and 0.96. The lower group is below 0.65 and the upper group is above 0.85. So this page uses the labels split and uniform.

How "two groups" is tested here is a choice of the analysis script, because the handoff gives no test [Ref5]: largest distance between neighbouring q values divides them; two groups if each side has at least 2 values, the distance is at least 0.10 and larger than the width of each group; labels are used only if also the lower group is below 0.65 and the upper group above 0.85.

Limits of this page

  • Part A has no control with two copies of one loop. So no difference on this page is compared with the difference between two equal loops.
  • An old kernel and an asm kernel come from two programs (bw_old and bw_new) [Ref2].
  • The limits for the pattern (0.65 and 0.85) and for the level (69 and 70.5 GB/s) are provisional [Ref2].
  • Thread rates are printed with 2 decimals. So the sum of 64 thread rates can differ from the exact sum by up to 0.32 GB/s (64 x 0.005 GB/s).
  • The pass count is an average over the threads. The programs do not print the passes of each thread [Ref2].
  • All threads start an interval together, and each thread stops after a whole pass. Part A does not change this timing method.
  • The page state of the buffers and the physical pages were not recorded.
  • The chart colours were not checked with the palette checker of the chart rules, because the program it needs (Node.js) is not on the development machine. Every chart also uses position, shape or a text label.
