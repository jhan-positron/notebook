# `r0.sh` explained, line by line

- Source file: `w120-2026-11-15/r0.sh` in the code repo `/home/jhan/workspace/ai-proj/arm-crb/code` (Bash script, 25 lines, 1864 bytes).
- sha256 of the source when this page was built: `cbf28ef4157b59c65877236ca1f6db1198fdb5910ea97df1f917e211445076f5`.

## Short version: purpose

`r0.sh` is round 0 of the 120-thread investigation. It starts the runner `bwx11` two times with 120 threads (64 on mesh 0, 56 on mesh 1), and each process times 12 read kernels in 2 rounds with a common stop after 6 s and with six core counters. The second process runs the eight kernel variants in the reverse order.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Mesh 0, mesh 1**: the two halves of the chip. CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **Marker file**: the file `/tmp/positron-perf.RUNNING` on CRB. It exists while another user runs a performance test. Our scripts stop when it exists.
- **Load average**: the number of tasks that are runnable or wait for disk input and output, averaged by Linux over the last 1, 5 and 15 minutes (file `/proc/loadavg`). The fourth field of the file gives the tasks that are runnable now and the number of all tasks.
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **Counter, counter event**: a hardware counter of the core counts events such as cycles, instructions or cache misses. Linux reads it through the `perf` interface.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **Old read kernel**: portable C code with 16 running sums. Each load is followed by an add. Its name is `read` in the binary `bw_old` and `oldread` in the runners.
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Round, position**: a runner repeats its sequence of kernels. Each repeat is a round, counted from 0. The position is the place of a kernel in the sequence, counted from 0.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **Rate**: bytes divided by time, in GB/s.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Result folder**: the folder that one run of a test script writes on CRB, under `~/cache-perf/results/`. Its name ends with the start time in UTC.
- **sha256**: a checksum. Two files with the same sha256 have the same content.
- **Exit status**: the number that a process returns when it ends. 0 means success.
- **UTC**: Coordinated Universal Time.
- **`read_nop32`, `read_nop64`, `read_nop96`, `read_nop128`**: the `asmread` loop with 32, 64, 96 or 128 `nop` instructions after the 8 loads of each 256 B. A `nop` is an instruction that does nothing.
- **`read_1pl`**: a read kernel with one load per 64 B line: four loads of 16 B per 256 B.
- **`read_pf256`, `read_pf2048`**: the `asmread` loop plus four software prefetch instructions per 256 B. They ask for the lines that lie 256 B or 2048 B ahead.
- **`read_sparse`**: a load-only loop that handles 128 B per pass: 4 `ldp q` loads and 9 `nop` instructions.

## Main flow

1. Set the marker path and the fixed path of the runner `bwx11` (lines 5 to 6).
2. Stop when the marker file exists, or when the binary does not have the expected sha256 (lines 7 to 8).
3. Create the result folder, set the counter events and write `env.txt` (lines 9 to 11).
4. Define the function `run`. It checks the marker file, waits until the machine is quiet, starts one process, waits for its end and then pauses 15 s (lines 12 to 21).
5. Set the shared arguments: 120 threads on the CPUs 0 to 119, 256 MiB per thread, common stop, 6000 ms, 2 rounds, six counters (line 22).
6. Run process `p1` with the 12 kernels (line 23).
7. Run process `p2` with the eight variants in the reverse order (line 24).
8. Print a summary with every interval row of both processes (line 25).

## Behavior a reader must know

- The script times nothing. The runner times each interval and computes the rates. By the runner source, the total rate of an `I` row is the bytes of all threads divided by the longest time of a thread.
- The wait of line 14 tests the number of runnable tasks at that moment. It does not test the load average. So the second process can start while the load average is still high from the first one.
- The path and the sha256 of the binary are fixed in the script. It takes no argument and reads no spec file.
- The marker file is checked three times: at the start, before each process, and once per second while a process runs. Each check ends the script with exit status 3. The last one also ends the running process.
- Other exit statuses: 2 when the sha256 of the binary differs. The exit status of the binary is written to `launches.txt` and is not tested.
- The script runs no command as root.
- This script does not call `hw.sh`. It makes no hardware record.

### Function `run`: start one process and wait for its end (lines 12 to 21)

| Line | Source | Explanation |
|---:|---|---|
| 12 | `run() { tag=$1; shift` | Starts the function `run`. It starts one process, waits for its end and writes its record. The first argument is the tag and goes to `tag`. `shift` then removes it. So the arguments that remain are the arguments of the binary. |
| 13 | `  [ -e $M ] && { echo "marker: stop"; exit 3; }` | Marker check 2 of 3, before each process. When the marker file exists, the script prints `marker: stop` and ends with exit status 3. |
| 14 | `  for i in $(seq 30); do r=$(cut -d' ' -f4 /proc/loadavg \| cut -d/ -f1); [ "$r" -le 2 ] && break; sleep 1; done` | Waits until at most 2 tasks are runnable, with at most 30 tries. `cut -d' ' -f4 /proc/loadavg` takes the fourth field, for example `1/1019`. `cut -d/ -f1` keeps the number before the slash. This is the number of tasks that are runnable now [Ref1]. When the number is 2 or less, the loop ends. If not, the script sleeps 1 s and tests again. After 30 tries (about 30 s) the loop ends too, and the script goes on without a message. |
| 15 | `  echo "launch $tag utc $(date -u +%T) load $(cat /proc/loadavg) users $(who \| wc -l) args $*" >> $out/launches.txt` | Appends one `launch` line to `launches.txt`: the tag, the UTC time (hours, minutes, seconds), the content of `/proc/loadavg`, the number of logins and the arguments. `$*` stands for all arguments with one space between them. | 16 | `  taskset -c 0-119 $BW "$@" > $out/$tag.csv 2>> $out/stderr.txt &` | Starts the binary in the background (`&`). The script goes on immediately. `taskset -c 0-119` allows the new process to run on the CPUs 0 to 119 only. Then `taskset` replaces itself with the binary in the same process. So the process id of line 17 is the process id of the binary. `"$@"` gives each argument of `run` to the binary as one word. The standard output of the binary goes to the file `TAG.csv` in the result folder. Error messages are appended to `stderr.txt`. The line names no input. For a command that a script starts in the background, `bash` then uses `/dev/null`, an empty input. `r0.sh` pins no thread. The runner pins each thread to one CPU of its `--cpus` argument (function `worker` of `bwx11.c`). |
| 17 | `  pid=$!` | `pid`: the process id of the process that line 16 started. |
| 18 | `  while kill -0 $pid 2>/dev/null; do [ -e $M ] && { kill $pid; echo "marker: killed"; exit 3; }; sleep 1; done` | Waits for the process and watches the marker file. `kill -0 $pid` sends no signal. It only tests whether the process still exists. The loop runs as long as it exists. Marker check 3 of 3, once per second: when the marker file exists, `kill $pid` sends the termination signal to the process. The script then prints `marker: killed` and ends with exit status 3. It writes no `rc` line in that case. If the marker file does not exist, `sleep 1` waits 1 s. So `r0.sh` sees the end of the binary up to about 1 s late. |
| 19 | `  wait $pid; echo "rc $? $tag utc $(date -u +%T)" >> $out/launches.txt` | `wait $pid` returns the exit status of the binary. The time in this line can be about 1 s later than the real end of the process (line 18). |

### The two processes and the summary (lines 22 to 25)

| Line | Source | Explanation |
|---:|---|---|
| 22 | `C="--threads 120 --cpus 0-63,64-119 --bytes 256M --stop common --start common --min-ms 6000 --rounds 2 --count --pmu-type 11 --events $EV"` | `C`: the arguments that both processes share. `--threads 120 --cpus 0-63,64-119`: 120 threads, and thread number i is pinned to entry i of the CPU list. So 64 threads run on mesh 0 and 56 on mesh 1. `--bytes 256M`: each thread has its own buffer of 256 MiB. `--stop common`: all threads of an interval stop at one common time. `--start common`: every thread starts its reading at the start of its buffer. `--min-ms 6000`: the common stop time is 6000 ms after the common start time. `--rounds 2`: the kernel sequence runs two times. `--count --pmu-type 11 --events $EV`: each thread counts the events of line 10 during each interval. 11 is the type number of the counter device, which the runner gives to Linux with each counter request. |
| 23 | `run p1 $C --seq oldread,asmread,read_nop32,read_nop64,read_nop96,read_nop128,read_1pl,read_pf256,read_pf2048,read_sparse,asmread,oldread` | First process, tag `p1`: calls `run` with the shared arguments and the kernel sequence. `$C` has no quotes. So the shell splits it at the spaces into single arguments. `--seq` names 12 kernels: `oldread`, `asmread`, then eight variants (`read_nop32`, `read_nop64`, `read_nop96`, `read_nop128`, `read_1pl`, `read_pf256`, `read_pf2048`, `read_sparse`), then `asmread` and `oldread` a second time. With 2 rounds the process times 24 intervals. |
| 24 | `run p2 $C --seq oldread,asmread,read_sparse,read_pf2048,read_pf256,read_1pl,read_nop128,read_nop96,read_nop64,read_nop32,asmread,oldread` | Second process, tag `p2`: the same arguments and the same 12 kernels. The eight variants in the middle stand in the reverse order. So a kernel that runs early in `p1` runs late in `p2`. |
| 25 | `echo "done $out"; cat $out/launches.txt; wc -c $out/stderr.txt; grep -h '^I,' $out/p1.csv $out/p2.csv` | Prints a summary to the standard output: `done` and the path of the result folder, then the whole `launches.txt`, then the size of `stderr.txt` in bytes with its path (`wc -c`), then every line of `p1.csv` and `p2.csv` that starts with `I,`. `grep -h` prints these lines without the file name. An `I` line is the row of one interval: round, position, kernel, bytes per thread, number of threads, bytes of all threads, the longest time of a thread in seconds, and the total rate in GB/s. The exit status of `r0.sh` is the status of `grep`. It does not depend on the exit status of the binary. |
