## Short version: purpose

`r8.spec` is a spec file for the script `rx.sh`: 5 lines of the form `tag|arguments`, one runner process per line. Every process reads with the old read kernel, with `asmread` and with padded kernels, and counts in each core how many answers arrive with each busy level. The five lines differ in the thread layout: 64 plus 56, 64 plus 32, mesh 0 alone, mesh 1 alone, and one thread.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Mesh 0, mesh 1**: the two halves of the chip. CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **Counter, counter event**: a hardware counter of the core counts events such as cycles, instructions or cache misses. Linux reads it through the `perf` interface.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **Old read kernel**: portable C code with 16 running sums. Each load is followed by an add. Its name is `read` in the binary `bw_old` and `oldread` in the runners.
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Round, position**: a runner repeats its sequence of kernels. Each repeat is a round, counted from 0. The position is the place of a kernel in the sequence, counted from 0.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Spec file**: a text file that the script `rx.sh` reads as its input. Each line has the form `tag|arguments of the binary` and gives one process.
- **Result folder**: the folder that one run of a test script writes on CRB, under `~/cache-perf/results/`. Its name ends with the start time in UTC.
- **Part L**: one `bwx12` process with the kernel sequence `oldread`, `asmread`, `read_nop96`, `read_nop256`, `read_1pl`.
- **Tag**: the name of a process. The script `rx.sh` writes the output of the process to the file `TAG.csv`.
- **Layout**: the number of threads on mesh 0 and on mesh 1. "64 plus 56" means 64 threads on mesh 0 and 56 threads on mesh 1.
- **`read_nop96`, `read_nop256`**: the `asmread` loop with 96 or 256 `nop` instructions after the 8 loads of each 256 B. A `nop` is an instruction that does nothing.
- **`read_1pl`**: a read kernel with one load per 64 B line: four loads of 16 B per 256 B.
- **Busy level**: a number from 0 to 3 that the mesh sends to a core with each answer. 3 means most busy. This definition comes from the notes of the ASCT cross-check in the same repo.
- **`cbusy0` to `cbusy3`**: the names that this file gives to the event codes `0x198` to `0x19b`. The analysis script `an8.py` reads them as the answers with the busy level 0 to 3.
- **`cbusy_mt`**: the name that this file gives to the event code `0x19c`. No file of this folder says what it counts, and `an8.py` does not read it.

## Main flow

1. Read one line as one process. The text before the first `|` is the tag. The rest of the line holds the arguments of the runner, as the function `main` of `bwx12.c` reads them (line 1).
2. `--threads` and `--cpus` give the number of threads and the CPU of each thread. The four digits of a tag repeat the layout: `a6432` means 64 threads on mesh 0 and 32 on mesh 1 (lines 1 to 4). The tag `a0001` of line 5 does not follow this rule: its one thread runs on CPU 2, which is on mesh 0.
3. `--bytes` gives the size of the buffer that each thread owns and reads. `256M` means 256 MiB.
4. `--stop common` and `--min-ms` give the timing of an interval. The main thread sets one start time and one stop time for all threads. Each thread reads its buffer in chunks of 2 MiB, reads the clock after each chunk and stops at the first clock reading at or after the stop time.
5. `--start common` makes each thread begin at the first byte of its buffer.
6. `--seq` gives the kernels: one timed interval per kernel, in the order of the list. `--rounds` gives the number of times that the whole sequence runs.
7. `--count`, `--pmu-type` and `--events` turn on the core counters. Each thread counts the six named events during each interval. An event is written `name=code`. The runner uses the name as the head of a column and gives the code and the number of `--pmu-type` to Linux.

## Behavior a reader must know

- The file holds no command. The script `rx.sh` starts one process per line, in the order of the file, and limits each process to the CPUs 0 to 119.
- line 1 is equal to the one line of the file `like.spec` in the folder `w120-7200-2026-11-17`. That line is part L of the rerun.
- The codes `0x198` to `0x19c` are not in the table of the common Arm events [Ref3]. So this page takes their meaning from the names and from `an8.py` only.
- The launch record of the result folder `w120-R8-20261117T020549Z` holds 5 launch lines with the tags and the arguments of this file. Its `env.txt` names the binary `bwx12` [Ref1].
- Four result folders of the test `2026-11-17-firmware-and-dimm` hold the same 5 launch lines: `w120-X1d10-20261117T034916Z`, `w120-X2d12-20261117T040922Z`, `w120-BASEd10-20261117T041738Z` and `w120-w120-F72d12-20261117T200231Z` [Ref2].
