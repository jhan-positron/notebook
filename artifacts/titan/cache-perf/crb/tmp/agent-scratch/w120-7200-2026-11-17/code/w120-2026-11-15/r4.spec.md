## Short version: purpose

`r4.spec` is a spec file for the script `rg.sh`: 8 lines, and each line gives one group of processes that run at the same time. In each group two latency probes, on CPU 2 and on CPU 66, time loads that miss the caches. In the first group the machine is idle, in six groups runner processes read on the other 118 CPUs at the same time, and in the last group they read on the other 63 CPUs of mesh 0 only.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Mesh 0, mesh 1**: the two halves of the chip. CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Spec file**: a text file that the script `rx.sh` reads as its input. Each line has the form `tag|arguments of the binary` and gives one process. This file has the form of the script `rg.sh`: each line gives one group of processes.
- **Result folder**: the folder that one run of a test script writes on CRB, under `~/cache-perf/results/`. Its name ends with the start time in UTC.
- **Group**: the processes of one line. The script `rg.sh` starts them one after the other and waits until all of them have ended.
- **Item**: one process of a group, in the form `tag=arguments`. The items of a line are separated by ` ;; `. The script writes the output of an item to the file `GROUP.TAG.csv`.
- **`read_nop96`, `read_nop256`**: the `asmread` loop with 96 or 256 `nop` instructions after the 8 loads of each 256 B. A `nop` is an instruction that does nothing.
- **`read_1pl`**: a read kernel with one load per 64 B line: four loads of 16 B per 256 B.
- **`robsize`**: the window test program of the folder `robsize`. Its loop does two independent loads that miss the caches, and N filler instructions after each load. It prints the time per loop pass in ns.
- **Latency probe**: one `robsize` process that runs while the other CPUs read. Its time per pass shows how long a load that misses the caches takes on that CPU.
- **Window**: the out-of-order window of a core: the instructions that the core holds between fetch and retirement.
- **Filler, N**: a filler is an instruction between the two loads that does not depend on them. N is the number of fillers after each load.
- **Pointer chain**: a buffer of pointers that form one random cycle. Each load of a pointer gives the address of the next load, and each such load misses the caches. `robsize` builds two chains, one for each of its two loads.

## Main flow

1. Read one line as one group. The text before the first `|` is the group name. The rest holds the items, with ` ;; ` between them (line 1).
2. Read one item as one process. The text before the first `=` is the tag of the item. The rest holds the arguments.
3. Arguments that start with `@` are a full command: the path of the program `robsize` and its options, as the function `main` of `robsize.c` reads them. These are the items `probe2` and `probe66` (line 1).
4. All other arguments are arguments of the runner, as the function `main` of `bwx12.c` reads them. These are the items `m0` (mesh 0) and `m1` (mesh 1) (line 2).
5. `--threads` and `--cpus` give the number of threads and the CPU of each thread. The CPU lists leave out CPU 2 and CPU 66, which the probes use.
6. `--bytes` gives the size of the buffer that each thread owns and reads. `256M` means 256 MiB.
7. `--stop common` and `--min-ms` give the timing of the one interval of a runner process. The main thread of the process sets one start time and one stop time for its threads. Each thread reads its buffer in chunks of 2 MiB, reads the clock after each chunk and stops at the first clock reading at or after the stop time. `--start common` makes each thread begin at the first byte of its buffer.
8. `--seq` names the kernel, and `--rounds 1` runs it for one interval.

## Behavior a reader must know

- The file holds no command of its own. The script `rg.sh` starts the processes of a line one after the other, in the order of the line, and limits each one to the CPUs 0 to 119.
- The checksum check of `rg.sh` covers the runner binary only. It does not cover the program `robsize` that the `@` items name.
- A probe does not measure at once. By `robsize.c` it first builds two pointer chains of 1024 MiB each, which is the default size, and then times its loops. Nothing in this file or in `rg.sh` ties the timed loops of a probe to the timed interval of the runner processes. The interval of 60 s is the only thing that makes them overlap.
- A probe line times two values of N only. `robsize` then prints its two data rows and, in place of a step position, two comment lines that say that there are too few points.
- The launch record of the result folder `w120-R4-20261115T200016Z` holds 8 launch lines with the group names and the items of this file. Its `env.txt` names the binary `bwx12` [Ref1].
