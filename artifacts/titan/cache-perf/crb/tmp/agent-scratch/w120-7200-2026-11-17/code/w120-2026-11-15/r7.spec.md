## Short version: purpose

`r7.spec` is a spec file for the script `rg.sh`: 13 lines, and each line gives one group of processes of the runner `bwx13` that run at the same time. The groups use the three kernels `rand_nop0`, `rand_nop96` and `rand_nop256`, which read the same bytes as `asmread` in a scrambled order. Eleven groups have one process on mesh 0 and one on mesh 1, and two groups have a process on mesh 0 only.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Mesh 0, mesh 1**: the two halves of the chip. CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Spec file**: a text file that the script `rx.sh` reads as its input. Each line has the form `tag|arguments of the binary` and gives one process. This file has the form of the script `rg.sh`: each line gives one group of processes.
- **Result folder**: the folder that one run of a test script writes on CRB, under `~/cache-perf/results/`. Its name ends with the start time in UTC.
- **Group**: the processes of one line. The script `rg.sh` starts them one after the other and waits until all of them have ended.
- **Item**: one process of a group, in the form `tag=arguments`. The items of a line are separated by ` ;; `. The script writes the output of an item to the file `GROUP.TAG.csv`.
- **`read_nop256`**: the `asmread` loop with 256 `nop` instructions after the 8 loads of each 256 B. A `nop` is an instruction that does nothing.
- **Address order**: the kernel reads its buffer from the lowest address to the highest, one 256 B block after the next. `asmread` and `read_nop256` do this.
- **`rand_nop0`, `rand_nop96`, `rand_nop256`**: three kernels that only the runner `bwx13` has. Each reads every 256 B block of its range once, with the 8 `ldp q` loads of `asmread`, but it visits the blocks in a scrambled order. After the 8 loads of a block stand 0, 96 or 256 `nop` instructions.
- **Scrambled order**: with nb blocks in one call and nb a power of two, step i reads the block with the number i times (2 i + 1), modulo nb. With the common stop one call covers one chunk of 2 MiB, which is 8192 blocks. So the order is scrambled inside a chunk, and the chunks follow in address order.

## Main flow

1. Read one line as one group. The text before the first `|` is the group name. The rest holds the items, with ` ;; ` between them (line 1).
2. Read one item as one process. The text before the first `=` is the tag of the item: `m0` for the process on mesh 0, `m1` for the process on mesh 1. The rest holds the arguments of the runner, as the function `main` of `bwx13.c` reads them.
3. `--threads` and `--cpus` give the number of threads and the CPU of each thread.
4. `--bytes` gives the size of the buffer that each thread owns and reads. `256M` means 256 MiB.
5. `--stop common` and `--min-ms` give the timing of the one interval of a process. The main thread of the process sets one start time and one stop time for its threads. Each thread reads its buffer in chunks of 2 MiB, reads the clock after each chunk and stops at the first clock reading at or after the stop time.
6. `--start common` makes each thread begin at the first byte of its buffer.
7. `--seq` names the kernel, and `--rounds 1` runs it for one interval.

## Behavior a reader must know

- The file holds no command. The script `rg.sh` starts the processes of a line one after the other and limits each one to the CPUs 0 to 119.
- The file needs the runner `bwx13`: the runner `bwx12` has no `rand` kernel and ends with an error for an unknown kernel name.
- The common stop holds inside one process only. Each of the two processes sets its own start time and stop time. So the two intervals of a group overlap, but they do not begin at the same moment.
- The launch record of the result folder `w120-R7-20261115T205946Z` holds 13 launch lines with the group names and the items of this file. Its `env.txt` names the binary `bwx13` [Ref1].
