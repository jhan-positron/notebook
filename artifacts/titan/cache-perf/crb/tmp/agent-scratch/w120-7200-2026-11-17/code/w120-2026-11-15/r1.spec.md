## Short version: purpose

`r1.spec` is a spec file of the 120-thread investigation: 7 lines of the form `tag|arguments`, one runner process per line. The lines run the kernel variants that the runner `bwx12` adds: read kernels with `nop` padding, with vector adds and with fewer loads, and padded write and copy kernels. Four processes use 120 threads on both meshes, one uses 56 plus 56 threads and two run write kernels on 64 threads.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Mesh 0, mesh 1**: the two halves of the chip. CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **Counter, counter event**: a hardware counter of the core counts events such as cycles, instructions or cache misses. Linux reads it through the `perf` interface.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **Old read kernel**: portable C code with 16 running sums. Each load is followed by an add. Its name is `read` in the binary `bw_old` and `oldread` in the runners.
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Round, position**: a runner repeats its sequence of kernels. Each repeat is a round, counted from 0. The position is the place of a kernel in the sequence, counted from 0.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Spec file**: a text file that the script `rx.sh` reads as its input. Each line has the form `tag|arguments of the binary` and gives one process.
- **Result folder**: the folder that one run of a test script writes on CRB, under `~/cache-perf/results/`. Its name ends with the start time in UTC.
- **Tag**: the name of a process. The script `rx.sh` writes the output of the process to the file `TAG.csv`.
- **Layout**: the number of threads on mesh 0 and on mesh 1. "64 plus 56" means 64 threads on mesh 0 and 56 threads on mesh 1.
- **`read_nop48` to `read_nop256`**: the `asmread` loop with that many `nop` instructions after the 8 loads of each 256 B. A `nop` is an instruction that does nothing.
- **`read_dadd2`, `read_dadd4`, `read_dadd8`, `read_dadd16`**: the `asmread` loop with 2, 4, 8 or 16 vector adds after the 8 loads. Each add takes a register that the loads of the same pass filled.
- **`read_iadd16`**: the `asmread` loop with 16 vector adds that take no loaded register. It is the control of `read_dadd16`.
- **`read_sparse`**: a load-only loop that handles 128 B per pass: 4 `ldp q` loads and 9 `nop` instructions.
- **`read_sp24` to `read_sp56`**: the `read_sparse` loop with 24, 32, 40, 48 or 56 `nop` instructions in place of 9.
- **`read_1pl`**: a read kernel with one load per 64 B line: four loads of 16 B per 256 B.
- **`read_1pl_nop96`**: the `read_1pl` loop with 96 `nop` instructions after the four loads.
- **`oldwrite`, `oldcopy`**: the write kernel and the copy kernel of the old benchmark source `bandwidth.orig.c`: plain C loops over 8-byte elements.
- **`write`, `copy`**: the new C write kernel and the new C copy kernel. Per 256 B they do 16 stores of 16 B, and `copy` does 16 loads of 16 B before them.
- **`asmwrite`**: a hand-written store loop with 8 `stp q` stores per 256 B. `stp q` is the Arm instruction that stores two 16-byte vector registers.
- **`asmcopy`**: a hand-written copy loop with 8 `ldp q` loads and 8 `stp q` stores per 256 B.
- **`write_nop32` to `write_nop256`**: the `asmwrite` loop with that many `nop` instructions after the 8 stores.
- **`copy_nop96`, `copy_nop192`**: the `asmcopy` loop with that many `nop` instructions after the 8 stores.

## Main flow

1. Read one line as one process. The text before the first `|` is the tag. The rest of the line holds the arguments of the runner, as the function `main` of `bwx12.c` reads them (line 1).
2. `--threads` and `--cpus` give the number of threads and the CPU of each thread. The digits of a tag such as `p5r5656` repeat the layout (lines 5 to 7).
3. `--bytes` gives the size of the buffer that each thread owns. `256M` means 256 MiB.
4. `--stop common` and `--min-ms` give the timing of an interval. The main thread sets one start time and one stop time for all threads. Each thread works through its buffer in chunks of 2 MiB, reads the clock after each chunk and stops at the first clock reading at or after the stop time.
5. `--start common` makes each thread begin at the first byte of its buffer.
6. `--seq` gives the kernels: one timed interval per kernel, in the order of the list. `--rounds` gives the number of times that the whole sequence runs.
7. `--count`, `--pmu-type` and `--events` turn on the core counters (lines 1 to 2). Each thread counts the named events during each interval. An event is written `name=code`. The runner uses the name as the head of a column and gives the code and the number of `--pmu-type` to Linux.

## Behavior a reader must know

- The file holds no command. It has the form that the script `rx.sh` reads: `rx.sh` starts one process per line, in the order of the file, and limits each process to the CPUs 0 to 119.
- The launch record of the result folder `w120-R1-20261115T185140Z` holds 7 launch lines with the tags and the arguments of this file. Its `env.txt` names the binary `bwx12` [Ref1].
- By the runner source, the runner times each interval itself. Before each interval every thread runs the kernel once over its whole buffer without timing.
- By the runner source, a read or write kernel counts the bytes of its one buffer. A copy kernel counts the bytes that it reads plus the bytes that it writes. The runner prints for each thread its bytes and its own time, and for each interval the bytes of all threads divided by the longest time of a thread.
