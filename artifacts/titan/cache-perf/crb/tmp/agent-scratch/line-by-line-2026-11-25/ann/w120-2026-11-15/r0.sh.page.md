## Short version: purpose

`r0.sh` is round 0 of the 120-thread investigation. It starts the runner `bwx11` two times with 120 threads (64 on mesh 0, 56 on mesh 1), and each process times 12 read kernels in 2 rounds with a common stop after 6 s and with six core counters. The second process runs the eight kernel variants in the reverse order.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Mesh 0, mesh 1**: the two halves of the chip. CPUs 0 to 63 sit on mesh 0. CPUs 64 to 127 sit on mesh 1.
- **Marker file**: the file `/tmp/positron-perf.RUNNING` on CRB. It exists while another user runs a performance test. Our scripts stop when it exists.
- **Load average**: the number of tasks that are runnable or wait for disk input and output, averaged by Linux over the last 1, 5 and 15 minutes (file `/proc/loadavg`). The fourth field of the file gives the tasks that are runnable now and the number of all tasks.
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **Counter, counter event**: a hardware counter of the core counts events such as cycles, instructions or cache misses. Linux reads it through the `perf` interface.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **Old read kernel**: portable C code with 16 running sums. Each load is followed by an add. Its name is `read` in the binary `bw_old` and `oldread` in the runners.
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Round, position**: a runner repeats its sequence of kernels. Each repeat is a round, counted from 0. The position is the place of a kernel in the sequence, counted from 0.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **Rate**: bytes divided by time, in GB/s.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Result folder**: the folder that one run of a test script writes on CRB, under `~/cache-perf/results/`. Its name ends with the start time in UTC.
- **sha256**: a checksum. Two files with the same sha256 have the same content.
- **Exit status**: the number that a process returns when it ends. 0 means success.
- **UTC**: Coordinated Universal Time.
- **`read_nop32`, `read_nop64`, `read_nop96`, `read_nop128`**: the `asmread` loop with 32, 64, 96 or 128 `nop` instructions after the 8 loads of each 256 B. A `nop` is an instruction that does nothing.
- **`read_1pl`**: a read kernel with one load per 64 B line: four loads of 16 B per 256 B.
- **`read_pf256`, `read_pf2048`**: the `asmread` loop plus four software prefetch instructions per 256 B. They ask for the lines that lie 256 B or 2048 B ahead.
- **`read_sparse`**: a load-only loop that handles 128 B per pass: 4 `ldp q` loads and 9 `nop` instructions.

## Main flow

1. Set the marker path and the fixed path of the runner `bwx11` ({L5-6}).
2. Stop when the marker file exists, or when the binary does not have the expected sha256 ({L7-8}).
3. Create the result folder, set the counter events and write `env.txt` ({L9-11}).
4. Define the function `run`. It checks the marker file, waits until the machine is quiet, starts one process, waits for its end and then pauses 15 s ({L12-21}).
5. Set the shared arguments: 120 threads on the CPUs 0 to 119, 256 MiB per thread, common stop, 6000 ms, 2 rounds, six counters ({L22}).
6. Run process `p1` with the 12 kernels ({L23}).
7. Run process `p2` with the eight variants in the reverse order ({L24}).
8. Print a summary with every interval row of both processes ({L25}).

## Behavior a reader must know

- The script times nothing. The runner times each interval and computes the rates. By the runner source, the total rate of an `I` row is the bytes of all threads divided by the longest time of a thread.
- The wait of {L14} tests the number of runnable tasks at that moment. It does not test the load average. So the second process can start while the load average is still high from the first one.
- The path and the sha256 of the binary are fixed in the script. It takes no argument and reads no spec file.
- The marker file is checked three times: at the start, before each process, and once per second while a process runs. Each check ends the script with exit status 3. The last one also ends the running process.
- Other exit statuses: 2 when the sha256 of the binary differs. The exit status of the binary is written to `launches.txt` and is not tested.
- The script runs no command as root.
- This script does not call `hw.sh`. It makes no hardware record.
