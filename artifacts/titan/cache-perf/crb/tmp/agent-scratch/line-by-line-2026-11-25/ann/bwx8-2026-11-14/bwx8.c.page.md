## Short version: purpose

`bwx8.c` is the source of `bwx8`, the version of the runner that the investigation into the small gain of the new read kernel at a buffer of 8 MiB used in its rounds 1 and 2 [Ref8]. It is the first runner `bwx.c` plus a second mode, the trial mode: one pinned worker thread runs the trials of a plan file, and each trial is a list of timed windows with only clock reads and, when the plan asks for it, counter readings between them. The interval mode of `bwx.c` stays as it is: it times a sequence of kernels in one process and prints the bytes and the times as csv rows.

## Words used here

- **CRB**: the Arm reference server under test. It has 128 CPUs.
- **Kernel**: the inner loop of a benchmark that reads, writes or copies memory. On this page "kernel" means this loop. The operating system kernel is always written "Linux kernel".
- **Read kernel**: the kernel that reads memory.
- **Old read kernel**: portable C code with 16 running sums. Each load is followed by an add. Its name is `read` in the binary `bw_old` and `oldread` in the runners.
- **New read kernel**: NEON intrinsics (C functions that map to Arm vector instructions), loads only. Its name is `read` in the binary `bw_new` and in the runners.
- **`asmread`**: a hand-written load-only loop. It has the same 8 `ldp q` loads per 256 B as the new read kernel. `ldp q` is the Arm instruction that loads two 16-byte vector registers.
- **`bandwidth.c`, `bw_old`, `bw_new`**: the benchmark and its two binaries of 2026-11-13. `bw_old` was built from the old source (`bandwidth.orig.c`), `bw_new` from the new source (`bandwidth.c`).
- **Runner**: a benchmark program that times a sequence of kernels in one process and prints one row per thread. The versions are named `bwx`, `bwx8`, `bwx10`, `bwx11`, `bwx12` and `bwx13`.
- **Process**: one start of a benchmark binary.
- **Interval**: one timed measurement inside a process.
- **Round, position**: a runner repeats its sequence of kernels. Each repeat is a round, counted from 0. The position is the place of a kernel in the sequence, counted from 0.
- **Whole-pass stop**: the stop rule of `bandwidth.c`: after the minimum time each thread finishes the pass over its buffer that it is in. The threads stop at different times.
- **Common stop**: a stop rule of the runners: all threads have one common deadline. Each thread ends its interval at its first clock read at or after that deadline.
- **Rate**: bytes divided by time, in GB/s.
- **GB, MiB**: GB = 1e9 bytes. MiB = 1048576 bytes (2 to the power of 20).
- **Self-test**: a program that checks what the kernels do to memory, without timing.
- **Machine-code listing**: the instructions that the compiler produced for a function, as text (output of the tool `objdump`).
- **Pinned**: a thread that is pinned to a CPU may run on that CPU only.
- **First touch**: the first write of a thread to its new buffer. Linux assigns the memory pages at that moment. The benchmarks do it before any timing.
- **Transparent huge pages (thp)**: memory pages of 2 MiB that Linux can use for a buffer in place of its smaller standard pages.
- **Counter, counter event**: a hardware counter of the core counts events such as cycles, instructions or cache misses. Linux reads it through the `perf` interface.
- **sha256**: a checksum. Two files with the same sha256 have the same content.
- **Exit status**: the number that a process returns when it ends. 0 means success.
- **Marker file**: the file `/tmp/positron-perf.RUNNING` on CRB. It exists while another user runs a performance test. Our scripts stop when it exists.
- **Window record**: the structure `struct win` of one window: its kernel, its range and its requested duration, and after the run its byte count and its two clock times.
- **Stop rules of the runner**: `--stop pass` selects the whole-pass stop. `--stop common` selects the common stop.
- **Interval mode, trial mode**: the two modes of the program. The interval mode (option `--seq`) runs the number of threads that `--threads` gives and times one interval per round and kernel of the sequence. The trial mode (option `--trial`) runs one worker thread through the trials of a plan file.
- **Kernel table, `kernels[]`**: the array of {L821-831}. Each entry holds the name of a kernel (the word used in `--seq`), its type (`T_READ`, `T_WRITE`, `T_COPY` or `T_OLDREAD`) and a pointer to its function. In this version it has 21 entries.
- **`cfg`**: the structure that holds the settings from the arguments: thread count, CPU list, buffer size, kernel sequence, rounds, stop rule and counter settings ({L180-198}).
- **CPU list of `--cpus`**: the CPUs that the option `--cpus` names, in the order of its text. Thread `i` is pinned to entry `i` of the list. When the process has more threads than the list has entries, the list is used again from its start.
- **Allowed CPU set**: the set of CPUs on which Linux may run a thread.
- **Worker, main thread**: a worker is one benchmark thread (function `worker`). The main thread runs `main`: it starts the workers, sets the start time of each interval and prints all rows.
- **Barrier**: a POSIX thread barrier (`pthread_barrier_wait`). A thread that calls it blocks until all workers and the main thread have called it. Then all of them continue.
- **Warm-up pass**: one call of the kernel of the coming interval over its whole range, before the start of that interval. It is not timed.
- **Chunk**: a piece of 2 MiB of a buffer (`CHUNK_BYTES`), or the whole range of a `--seq` entry when that is smaller. With `--stop common` the worker calls the kernel on one chunk and then reads the clock.
- **Common start, lead**: with `--stop common` the main thread sets the start time of an interval to its clock reading plus 2 ms (`LEAD_NS`, the lead). Every worker waits for this time in a loop that only reads the clock.
- **Deadline**: the common start time plus the `--min-ms` value. A worker stops at its first clock read at or after the deadline.
- **`gen`**: an atomic counter of intervals. The main thread adds 1 after it has stored the start time and the deadline of the next interval. A worker waits until `gen` equals its own interval count plus 1.
- **Late flag**: the word `late` in the last column of a T row. It marks a thread whose start clock read was more than 100 us after the common start time.
- **us**: microsecond. 1 us is 1000 ns.
- **`sink`**: a volatile variable on the stack of each worker. `call` stores there the sum that an old read kernel returns. So the compiler cannot remove the adds of the old read kernel.
- **I, T, P, C rows**: the row kinds of the interval mode: one I row per interval, one T row per thread and interval, one P row per buffer and page-state reading, and with `--count` one C row per thread and interval with counter values.
- **Page state**: two values of a buffer from the Linux file `/proc/self/smaps`: the size of its mapping and the part of it on 2 MiB pages, both in kB of 1024 bytes.
- **PMU, PMU type, event code**: PMU means performance monitoring unit, the hardware event counters of a core. The value of `--pmu-type` and the code of an event of `--events` go into the fields `type` and `config` of the structure `perf_event_attr`. The two fields tell Linux which event to count.
- **Counter group, group leader**: the counters that one thread opens form a group. The first one is the leader. One `read` of the leader returns the values of all counters of the group.
- **Enabled time, running time**: two times of a counter group, in ns: how long the counters were enabled, and how long they really counted.
- **File descriptor**: the number that Linux returns when a program opens a file or a counter.
- **AArch64, NEON**: AArch64 is the 64-bit Arm instruction set. NEON is the vector part of it: 32 registers of 16 bytes, written `v0` to `v31`, or `q0` to `q31` when an instruction uses all 16 bytes, or `d0` to `d31` for the low 8 bytes.
- **`ldp`, `stp`, `nop`**: AArch64 instructions. `ldp` loads two registers from memory, and `stp` stores two. With `q` registers each of them moves 32 B. `nop` does nothing.
- **Loop pass**: one run of the loop body of a kernel. It is not a pass over the whole buffer.
- **64 B line**: a block of 64 bytes of memory, a cache line. The source comments count memory in such lines.
- **Clobber list**: the last list of a gcc `__asm__` statement. It names the registers and the other state that the assembly text changes.
- **Save of `d8` to `d15`**: the Arm calling rules say that a function must keep the registers `d8` to `d15` for its caller. A kernel whose clobber list names `v8` to `v15` stores them on the stack once at its start and loads them back once at its end.
- **`PLACE`, pad, loop offset**: `PLACE(name)` is a macro that stands before each kernel. It adds unused bytes, the pad. The kernel then starts at a chosen address modulo 64. The aim is a fixed loop offset: the address of the first instruction of the loop modulo 64.
- **`LOOP`, `HEAD`, `PAD`**: the values of the loop placement. `LOOP` is the planned loop offset of a kernel. `HEAD` is the number of bytes of code between the start of the function and the start of its loop. `PAD` is the number of zero bytes that `PLACE` adds. The macro `PADOF` computes it as `LOOP` minus `HEAD`, modulo 64.
- **Stand-in**: a plain C loop that replaces a NEON kernel or an assembly kernel when the file is compiled for a machine that is not AArch64. The rates of such a build mean nothing.
- **Development machine**: the machine on which the program was written and tested before the build on CRB. The stand-in kernels exist for it.
- **A/A copy**: the same kernel source under a second name, for example `asmread2`.
- **`handoff.md`**: the specification of the first runner `bwx`. The comments cite its sections B.4 to B.8 [Ref4].
- **Build record**: the files that the build script `build8.sh` wrote on CRB. `build.txt` holds the compiler, the flags and the sha256 values [Ref2]. `listing.txt` holds the machine-code listing of every kernel [Ref1].
- **Plan file, trial, window (trial mode)**: the plan file lists the trials of one process. A trial is a list of windows. A window runs one kernel on one range of the buffer for a fixed time.
- **Phase, target window (trial mode)**: a trial has up to four phases, in this order: previous activity (1 window), prefix (4 windows), predecessor (1 window) and target. A target window is a window of the last phase.
- **Timed sequence (trial mode)**: the run of all windows of one trial, done by the function `timed_sequence`.
- **Counter state (trial mode)**: the field `count` of a plan line: `closed` (no counter group is open), `open` (the group is open and is not read during the trial) or `read` (the group is read at the boundaries of the target windows).
- **Record block (trial mode)**: one memory block that holds the records of all trials: the trial records, the window records, the counter readings, the bins and, with `--trace`, the event log.
- **Bin, trace (trial mode)**: a bin is a part of a target window with a requested length of 10 ms. The trace (`--trace`) is a log of events with clock times.
- **Controlling thread (trial mode)**: the thread that runs `trial_main`. It pins itself to the CPU of `--ctl-cpu`, starts the one worker of the trial mode and waits for its end.
- **S, W, B, E, X, TR, M, K rows (trial mode)**: row kinds that only the trial mode prints: S (the plan line of a trial), W (one window), B (one bin), E (the summary of a trial), X (a problem), TR (one trace event), M (one setting or one fact of the process) and K (the address of one kernel).
- **Context switch**: Linux stops running a thread on its CPU. It is voluntary when the thread waits by itself, and involuntary when Linux takes the CPU away.
- **Minor page fault**: a page fault that Linux serves without disk access. The first touch of a page is one.

## Main flow

1. Start. `main` reads the clock once for the process start time `t_base_ns`, reads the page size and sets the default buffer size of 1 MiB. Then `restrict_cpus` removes every CPU above 119 from the allowed CPU set of the process ({L2061-2068}).
2. Mode choice. `main` compares every argument with the word `--trial`. When one is equal, it calls `trial_main` and returns its result. Otherwise it goes on in the interval mode, which is the rest of `main` ({L2069-2071}).
3. Argument parsing. One loop over the arguments fills the settings structure `cfg`: threads, CPU list, bytes per thread, interval length, rounds, the `--seq` list, the stop rule, the start rule and the counter settings. `--selftest` and `--list` end the program in this loop ({L2073-2125}).
4. Checks of the settings. A failed check prints the option summary and ends the program with exit status 2. Each `--seq` entry without `@SIZE` gets the size of `--bytes`, and a copy kernel in the list gives each thread a second buffer ({L2126-2157}).
5. Threads. `main` creates a barrier for all workers plus itself and starts one thread per worker. Thread `i` gets entry `i` of the CPU list ({L2159-2173}).
6. Each worker pins itself to its CPU, opens its counters when `--count` is given, maps its buffer with `alloc_buf` and writes every word of the `--bytes` range of it once with `k_write`. This write is the first touch ({L988-997}).
7. Header. `main` prints the header lines: the settings and the column names of the I, T, P and C rows ({L2175-2194}).
8. Only in a process with more than one thread: when all buffers exist, `main` reads the page state of all buffers and prints P rows with the position -1 ({L2198-2206}, {L2262-2276}).
9. Loops. The workers and `main` run the same two loops: the rounds, and inside a round the positions of the `--seq` list. One pair of round and position is one interval ({L1003-1004}, {L2196-2197}).
10. Warm-up pass. Each worker calls the kernel of the position once over the whole range of the entry. This call is not timed ({L1016}).
11. Common start, only with `--stop common`. When all workers wait at the barrier, `main` reads the clock, sets the start time to that value plus 2 ms and the deadline to the start time plus the `--min-ms` value, and then adds 1 to `gen` ({L2214-2219}). Each worker waits for the new `gen` and then reads the clock in a loop until the start time ({L1023-1030}).
12. Start of the timed interval. With `--count` the worker first reads its counter group and its thread CPU time. Then it reads the clock: `t0` ({L1031-1035}).
13. Timed loop with `--stop common`. The worker calls the kernel on one chunk of 2 MiB, adds the size of the chunk to its byte count and reads the clock: `t1`. It repeats this with the next chunk until `t1` is at or after the deadline ({L1037-1048}).
14. Timed loop with `--stop pass`. The worker runs whole passes over the range of the entry. It reads the clock after each group of passes: 8 MiB divided by the size of the range, rounded down, and at least 1 pass. It repeats this until the `--min-ms` time has passed after `t0` ({L1049-1063}).
15. End of the interval, worker. The worker reads its thread CPU time and its counter group again. It stores the byte count, `t0`, the last `t1`, the common start time and the late flag, and it waits at the barrier ({L1064-1078}).
16. I row. `main` adds the bytes of all threads and takes the longest elapsed time `t1 - t0` of one thread. The last column of the I row is the total divided by that time, in GB/s ({L2223-2235}).
17. T rows and C rows. `main` prints one T row per thread with its bytes and its times, and with `--count` one C row per thread with the change of its counters over the interval ({L2236-2260}).
18. Page state, in a process with more than one thread. While the workers wait at the barrier, `main` reads the page state of all buffers. Then it releases the workers and prints the P rows and one `# page_read` line ({L2262-2276}). In a process with one thread the worker reads the page state itself before each interval, and `main` prints its P rows before the I row ({L1017-1021}, {L2229-2233}).
19. End. After the last interval `main` waits for the end of all threads and returns 0 ({L2280-2282}).
20. Trial mode, the other path of step 2. `trial_main` reads its arguments. It checks that `--cpus` names exactly one CPU, that `--bytes` is given and is a multiple of 256, and that `--plan` is given. It also checks that the CPU of the controlling thread is another CPU and that both CPUs are in the allowed CPU set ({L1994-2030}).
21. `read_plan` reads and checks the whole plan file. A defect ends the process with exit status 2. A plan with a counter state `open` or `read` also needs the counter settings ({L2031-2045}).
22. The controlling thread pins itself to the CPU of `--ctl-cpu`, starts the one worker and waits for its end ({L2049-2055}).
23. The worker pins itself to the CPU of `--cpus`, maps the buffer with `alloc_buf` and writes every word of the `--bytes` range once with `k_write`. This write is the first touch. Then `alloc_records` allocates the record block and writes one byte to every page of it ({L1682-1694}).
24. The worker prints the header lines, the M rows and the K rows ({L1697-1738}).
25. For each trial, in the order of the plan: the worker prints the S row. `run_trial` opens or closes the counter group as the plan line asks. It reads the page state, the context switches and the thread CPU time, runs the timed sequence and takes the three readings again. Then `emit_trial` prints the rows of the trial ({L1740-1748}, {L1459-1486}).
26. The timed sequence, function `timed_sequence`. For each window it reads the clock: `t0`. Then it calls the kernel on the first `size` bytes of the buffer, in groups of whole passes, and reads the clock after each group: `t1`. The window ends at the first `t1` at or after its requested duration ({L1340-1370}).
27. After the last trial the worker closes the counter group when it is open, and the thread ends. `trial_main` returns 0 ({L1749-1754}, {L2056}).

## Behavior a reader must know

- Difference to `bwx.c`. The command `diff` shows five changed places in three parts of the file. The header comment has other text in {L2-4}, {L6-15} and {L18-20}. In the place where `bwx.c` includes the file `bwx_selftest.c`, this file holds the whole trial mode and the include of `bwx8_selftest.c` ({L1142-2059}). `main` has three more lines, the mode choice ({L2069-2071}). Every other line of this file stands in `bwx.c`, in the same order.
- So the interval mode is the code of `bwx.c`: the text from {L22} to the end of `parse_events` ({L1140}) and the rest of `main`. A process without the argument `--trial` runs only this code, the three lines of the mode choice and, with `--selftest`, the self-test of the included file.
- Difference to the next version: `bwx10.c` is this file plus 282 added lines in eleven blocks, for five more read kernels and two options of the trial mode. One more line differs: the include of the self-test file.
- The trial mode follows the design of the investigation: one pinned worker, and trials of prefix, predecessor and target windows [Ref7]. Between two windows lie only the store of the results of the window, the clock reads and, before a target window of a trial with the counter state `read`, one reading of the counter group and of the thread CPU time ({L1366-1369}, {L1346-1348}). With `--trace` these clock reads and this reading also store events in the trace. The file `DECISIONS-bwx8.md` fixes the format of the plan file and of the output rows [Ref9].
- What is timed in the trial mode: a window is the time from its start clock read `t0` to its last clock read `t1` ({L1348}, {L1355}). Between them lie the kernel calls, the byte count, the clock reads and, for a target window with bins, the bin records. With `--trace` each clock read and the first kernel call of a window also add an event to the log ({L1283}, {L1302}). A window ends at its first clock read at or after its requested duration, at the end of a whole pass ({L1365}).
- Not timed in the trial mode: the time between two windows belongs to no window. With the counter state `read` the reading of the counter group lies there, before the start clock read of a target window ({L1346-1347}). `run_trial` reads the page state, the context switches and the thread CPU time before and after the timed sequence, and it opens or closes the counter group before it ({L1459-1486}). The S row of a trial is printed before `run_trial` starts, and all other rows after it has returned ({L1744-1747}).
- The trial mode prints no rate. A W row holds the byte count and the two clock times of one window ({L1596-1598}).
- The plan of the trial mode accepts read kernels only ({L1825}). The whole plan is read and checked before the process pins a thread or maps a buffer, and a defect ends the process with exit status 2 ({L2031}).
- After the checks of `trial_main` ({L2019-2045}) the process can still end with exit status 2: when a pinning call fails (`pin_cpu`), when the worker thread cannot be created ({L2051-2053}), when the worker does not run on the CPU of `--cpus` after the pinning ({L1683-1686}), when `mmap` fails in `alloc_buf`, or when the record block cannot be allocated. A problem during a trial gives an X row, and the process still ends with exit status 0.
- CRB build of `bwx8`. The source of this page has the sha256 that the build record gives for `bwx8.c` [Ref2]. The listing holds the 21 kernels [Ref1]. The build record lists the branch targets of `timed_sequence`: indirect calls, `clock_gettime`, `tcount` and `__stack_chk_fail` [Ref2].
- What is timed in the interval mode: only {L1035-1047} or {L1035-1061} of `worker`. The interval starts at the clock read `t0` and ends at the last clock read `t1`. Between them lie the kernel calls through `call`, the byte count and the clock reads. Not timed: allocation, first touch, warm-up pass, barrier waits, the wait for the common start, counter readings, page-state readings and all output.
- Stop rule `--stop common`: all threads get the same deadline. A thread stops at its first clock read at or after the deadline. So it finishes the chunk that it is in, and the bytes and the time of this last chunk are counted ({L1048}).
- Rate. The program prints one rate: the last column of the I row, the bytes of all threads divided by the longest elapsed time of one thread, in GB/s with GB = 1e9 bytes ({L2235}). A T row holds the bytes and the elapsed time of one thread and no rate ({L2239}).
- Kernel calls. With `--stop common` the kernel function is entered once per chunk. A kernel that saves `d8` to `d15` does so once per call, outside its loop. One clock read follows each call ({L1042-1047}).
- Thread placement: thread `i` pins itself to entry `i` of the CPU list before it opens its counters and before it maps its buffer ({L988-992}, {L2168}). The main thread is not pinned in the interval mode.
- Buffers: each buffer is a private mapping of its own, and no two threads share a buffer. A thread has one buffer, or two with `--two-buffers` or with a copy kernel in `--seq`. A buffer starts at a 2 MiB boundary, and `alloc_buf` asks Linux for 2 MiB pages for it unless `--no-thp` is given. The pinned thread writes the `--bytes` range of the buffer once before any read. The read kernels never change it ({L350-367}, {L992-993}).
- Order inside a process: the kernels run in the order of `--seq`, and the rounds follow one another directly. The file holds no call of a sleep function. Before each timed interval the worker runs the warm-up pass with the kernel of that interval ({L1016}).
- Counters in the interval mode: each thread opens its group once and never resets it. A C row holds the change between a reading directly before `t0` and a reading directly after the last `t1`. An event that does not open is printed as `NA` ({L947}, {L2254-2255}).
- What ends a process of the interval mode with exit status 2: a bad argument, a failed `mmap`, a failed call that reads or sets the allowed CPU set, an allowed CPU set without a CPU from 0 to 119, a failed read of the counter group, and a failed setup in `main`. A failed `mprotect` or `madvise` in `alloc_buf` only writes a message, and the run continues ({L361}, {L365}). The trial mode also ends with exit status 2 on a defect of its plan file.
- The code of this file does not look at the marker file and opens files only for reading. Its output is the csv text on the standard output and the messages on stderr.
