## The prefetchers: where they were turned off, and the readbacks

- **Where:** this boot's BL31 is TF-A 0.35.0-pfoff.1 (`5a9e2a8`, debug), boot B's and boot D's BL31 (the snapshot's `tfa/` equals boot B's, `diff -r`; debug `bl31.bin` sha256 `6c7483e2bff8296c91d29b25b238c8c1c84cf7f79e87d934887e08307a6aa79f`): TF-A 0.35.0 (`3b3df18`) rebuilt by this box with one added hook, never pushed (its banner, `uart_1.log` line 2: `NOTICE:  version: 5a9e2a8 (0.35.0-pfoff.1)  (debug)`). The hook runs at EL3 at the end of every power-on of CPUs 2-9 (each PSCI CPU_ON, CPU 3's return included), before BL31 returns to Linux; CPUs 0-1 are left alone. In order it sets IMP_CPUECTLR_EL1 (S3_0_C15_C1_4) bit 48, ALLPFDIS, if clear; writes IMP_CMESELR_EL1 (S3_0_C15_C11_1) with 0, which selects the cluster's one CME for the CME register accesses that follow (a write the snapshot's `MANIFEST.md` leaves out of its description of the hook); sets IMP_CMECFG_EL1 (S3_0_C15_C11_4) bit 28, PF_DISABLE, if clear; reads the registers back and prints one line on the AP console (`evidence/firmware/tfa-v0.35.0-pfoff.1.txt`).
- **Readbacks** (the AP console, `evidence/runs/membench-jibin-012/a01/evidence/run-evidence/uartout/uart_1.log`, lines 104-111 at boot and line 304 for CPU 3's one return). In all nine lines the `ectlr`, `cmpx`, `cmecfg` and `clusterpwrctlr` values are the ones boots B and D printed, and the `ectlr`, `cmpx` and `cmecfg` values are what the RTL predicted before boot B (`evidence/firmware/tfa-v0.35.0-pfoff.1.txt` step 12); only `clusterpwrstat` differs. CPU 2's line reads the CME of DSU 1 and CPU 8's that of DSU 4:
  - CPU 2 (line 104): `pfoff cpu2 ectlr 0x900000->0x1000000900000 cmpx 0x340000009400 cmecfg 0x2a9f11115->0x2b9f11115 clusterpwrctlr 0xb40170 clusterpwrstat 0x70`
  - CPU 8 (line 110): `pfoff cpu8 ectlr 0x900000->0x1000000900000 cmpx 0x340000009400 cmecfg 0x2a9f11115->0x2b9f11115 clusterpwrctlr 0xb40170 clusterpwrstat 0x70`
  - CPU 3 (line 304), back online at the end of the script, after the CME rows: `pfoff cpu3 ectlr 0x900000->0x1000000900000 cmpx 0x340000009400 cmecfg 0x2b9f11115->0x2b9f11115 clusterpwrctlr 0xb40170 clusterpwrstat 0x70`
- **IMP_CPUECTLR_EL1 bit 48** went from 0 to 1 on every CPU at every power-on (`0x900000` is the reset value).
- **IMP_CMPXECTLR_EL1** (S3_1_C15_C1_4) reads `0x340000009400` on every CPU: bits 26 and 25, the translation-prefetch disables, are clear. The boot leaves this register alone.
- **IMP_CMECFG_EL1 bit 28** was set in each cluster's CMECFG at its first core's power-on (CPUs 2, 4, 6, 8: `0x2a9f11115->0x2b9f11115`) and was already set at its second core's (CPUs 3, 5, 7, 9: `0x2b9f11115->0x2b9f11115`). Until a cluster's CME first powers up, the cluster's CPU bridge answers CMECFG from its own copy, which the CME loads at its first power-up and saves back at each power-down, so the boot-time values are that copy (`evidence/firmware/tfa-v0.35.0-pfoff.1.txt` step 12). The reading that shows the CME ran with bit 28 set is CPU 3's before-value at its return after the CME rows, read from the copy the CME's last power-down saved back, `0x2b9f11115`: bit 28 held through the CME rows.
- **IMP_CLUSTERPWRCTLR_EL1** (S3_0_C15_C3_5) reads `0xb40170` in all nine lines, as on boots B and D: the register's reset value, which TF-A 0.35.0's DSU driver writes back at every power-on just before the hook reads it, so it does not show what the cluster's power controller asked for (`evidence/jibin/l3-power-rtl.md` part 7). Its SLCRQ [7:6] = 01 and PRTNRQ [5:4] = 11 match this boot's 0x70 status bit for bit, but with AUTOSLC [17:15] and AUTOPRTN [14:12] at 0 they only feed hints to that controller, which runs in static mode and ignores them (the same file, parts 4 and 7), and boots B and D read the same 0xb40170 beside a status of 0x0.
- **IMP_CLUSTERPWRSTAT_EL1** (S3_0_C15_C3_7) reads `0x70` in all nine lines, where boots B and D read `0x0` in all nine of theirs. By the DSU RTL's field names (Arm's TRM was not consulted; `evidence/jibin/l3-power-rtl.md` parts 2-4 and 6), 0x70 is the slice field [7:6] = 01, ALL_SLICE, and the L3 RAM field [5:4] = 11, FULL_ON, with bits [3:0] at 0: cluster operating mode 7, the mode the SCP staged, in which the L3 slice looks up and allocates in both halves of its RAM. This DSU has one slice, so 01 does not mean a second slice. Bits [1:0] are the ORs of the cores' power-down and retention requests, which BL31 writes as 0 at every power-on, not a measured state. The 0x0 of boots B and D is ONE_SLICE with SFONLY, the snoop-filter-only state in which the L3 holds no data.
- **Linux runs at EL2:** `dmesg.txt` line 47 reads `CPU features: detected: Virtualization Host Extensions` and line 118 `CPU: All CPU(s) started at EL2`, as on every boot of this kernel. That is the state the proof that the `clusterpwrstat` read cannot trap assumes (`evidence/jibin/pwrstat-read-verdict.txt`).
- **The check that the prefetchers were off** (`python3 -I evidence/jibin/fcheck.py evidence/runs/membench-jibin-012 a01`, `evidence/runs/membench-jibin-012/fcheck.txt`; `docs/PLAN.md` section 8). For this boot it printed `FCHECK F2 staging=PASS box=PASS prefetchers_off=PASS hooks=9:0x70`. Its `prefetchers_off` row: `cme_l1d_refill_hwprf_per_load` in `cme-latency-dram-small.csv` reads 0.0000 in all six 8 and 16 KiB reps, under the check's own ceiling of 0.01 per load, where boot F1 read 3.9868-4.0583 at 8 KiB and 9.5630-9.9390 at 16 KiB (boot E 3.7922-3.8522 and 9.8067-10.0261; boot B 0.0000). Over the whole boot the column reads 0.0000 in all 104 chase rows of the 10 CME latency files that carry it (DRAM and OCM), where boot F1's 104 read 0.0553-16.1819. This boot runs no core row, so the core prefetchers' setting shows only in the hook's `ectlr` readbacks.
