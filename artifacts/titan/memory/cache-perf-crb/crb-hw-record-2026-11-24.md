What existing result files show (script `clock_from_counts.py`, output in the evidence folder): 29 csv files of three tests of 2026-11-13 to 2026-11-15 hold per-thread cycle counts; core clock 2.7881 to 2.7991 GHz in all 98,072 values (user-mode counts, a lower bound); mesh clock 1.99959 to 2.00001 GHz in six root runs of 2026-11-15, for old and load-only kernels alike. So a lower clock is not observed in those runs. Power and temperature were never measured. The 7200 MT/s rerun holds no cycle counter.

Open, all need CRB and the user's authorization: a no-root probe (`hwwatch.py check`, `probe`, `ls -l /dev/scmi`), the root step of atx (approved later the same day, see the second update below), a calibration run (about 2,800,000 kHz expected), the effect of the sampler on CPU 119, the layout of atx files. Not delivered: mesh power (no rail known), mesh frequency (accepted by the user as a stand-in, but atx has no name for the entry), power per process (atx summary is per result folder).
