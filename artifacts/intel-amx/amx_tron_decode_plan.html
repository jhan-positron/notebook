Outcome first

Use AMX surgically—and batch work before you tile it.

For gpt-oss decode, AMX is promising for stacked BF16 matrix work, but a single decoded token produces skinny shapes that often cannot amortize tile setup and packing. The first production target is paged software attention only when several GQA rows or jobs can be combined. Under Attention on FPGA, keep attention on Archer and redirect CPU-AMX experiments toward work that overlaps FPGA stalls—only after tracing proves the overlap is real.

Fact
8 × 1 KiB tile registers per core

AMX is an instruction-set extension inside each enabled CPU core: a tile register file plus tile matrix-multiply instructions. It is not a free-standing device or an automatic BLAS switch.

Fact
M = 8 gpt-oss rows / KV head / job

gpt-oss uses 64 query heads and 8 KV heads. That natural GQA grouping is useful, but still only half of AMX’s 16-row tile; cross-job batching is the route to full rows.

Misconception to remove: “Q/K/V are matrices, therefore AMX will speed them up” is incomplete. Decode may be bandwidth-bound, FPGA-bound, or too skinny; conversions, a second KV layout, tile state, synchronization, and idle lanes can cost more than the multiply saves.
AMX 101

What happens in one core

A compact mental model: configure shapes → load small matrix tiles → perform dot-products → accumulate FP32 → store/reformat. Software must create profitable shapes and legal state.

Tile register file

Fact Eight TMM registers hold 8 KiB total; each tile is at most 16 rows × 64 bytes. A tile configuration describes each tile’s row count and bytes per row.

TMM0..TMM7 ← LDTILECFG + TILELOADD
TMM(dst) += TMM(A) · TMM(B) via TDPBF16PS
memory ← TILESTORED; release with TILERELEASE

BF16 dot-product geometry

Fact TDPBF16PS consumes paired BF16 values and accumulates FP32. B must be in the instruction’s pair/VNNI-friendly arrangement. This is why an AMX path commonly needs prepacked weights or a write-through KV mirror.

Implication Packing once at model load or KV write can be acceptable; repacking on every page read usually is not.

Enablement

Check CPUID for AMX-TILE and AMX-BF16, OS XSAVE support, and per-thread tile-data permission. Linux applications request XTILEDATA access with arch_prctl. Every worker that executes AMX must be enabled.

Dispatch

Compile-time -march=graniterapids is not enough. Use runtime capability checks and shape dispatch: scalar/dotter for tiny M, AVX-512 BF16 for medium M, AMX for sufficiently large/padded M.

Topology

Bind compute, packed weights, and KV pages to the same NUMA domain. Measure per-socket and dual-socket. SMT siblings share core execution resources, so begin with one AMX worker per physical core. More AMX threads do not erase remote-memory traffic, power limits, or memory-channel saturation.

Xeon 6 6962P context. Intel’s SKU table lists 72 cores, 432 MB cache, 500 W TDP, two-socket scalability, and 12 memory channels. That is substantial matrix and bandwidth capacity—but the scheduler and page placement determine whether tron can use it locally.
gpt-oss MXFP4 caution. AMX on this generation has BF16/INT8 (and Granite Rapids FP16), but no native MXFP4 dot-product. For MoE, choose explicitly among: keep MXFP4 and dequantize panels on demand; cache a bounded BF16/INT8 packed working set; or pre-expand everything (usually a bandwidth loss at batch 1). Dequantization cost and accuracy are separate gates.

Plan A

Software attention + AMX

S0 · Baseline

Lock the measurement contract

  • Record exact commit, BIOS/firmware, kernel, compiler, frequency policy, SNC/NUMA, DIMM population, TP, instances, users, prompt/gen lengths, and model checksum.
  • Trace wall time by FPGA wait, ready attention, pending attention, joins, KV wait, page count, M bucket, head dimension, and sliding/full layer.
  • Acceptance: repeatable confidence intervals and per-phase time sums that reconcile with wall time.
S1 · Dispatch

Build a safe three-way router

  • Runtime CPUID + OS permission + per-thread enablement; never rely only on compile flags.
  • M≤3: existing dotter; M=4..7: blocked AVX-512 BF16; M≥8: AMX, with thresholds autotuned by head dimension and page size.
  • Keep one obvious reference path and an environment/flag kill switch.
S2 · Layout

Pay packing once

  • Write K simultaneously to canonical and VNNI mirror; use the existing pair-interleaved V layout where compatible.
  • Update every KV lifecycle operation: append, clone, defrag, page migration, eviction, prefix reuse, serialization, and zero/padding rules.
  • Quantify memory overhead, write amplification, and NUMA placement.
S3 · Kernels

Stack jobs, not just heads

  • Implement QK and PV for head-dim 64 first; pad physical M to 16 but pass logical M explicitly.
  • Collect visible jobs per (layer, KV head, page); preserve per-query masks, attention sinks/bias, sliding windows, EAGLE exceptions, online-softmax state, and deterministic reductions.
  • Amortize tile configuration per worker or compatible work run; release tiles at safe scheduling boundaries.
S4 · Scale

Prove end-to-end value

  • Sweep users 1/2/4/8/16/32; batch, TP, page occupancy, prefix sharing, 128 sliding and full attention, 2K→128K context.
  • Run one socket, two sockets, local/remote allocations, SMT on/off, and coexistence with FPGA threads.
  • Ship only buckets with statistically significant TPS/latency gain and no tail-latency or correctness regression.
Plan B

Attention on FPGA (AoF)

Ownership contract

FPGA owns QK, masking (causal, sliding, visibility, sink/bias), stable/online softmax, PV, and possibly output projection. CPU owns scheduling, page metadata, fallback, and validation. Define tensor formats, sequence positions, valid lengths, accumulation precision, and completion semantics in a versioned ABI.

AMX’s new job

Do not build a competing CPU attention fast path as the primary investment. Keep it as fallback/reference. Profile CPU slack during FPGA attention and test independent AMX work: expert-batched MoE, projection panels, LM head shards, or speculative work. Cancel any experiment that extends the critical path or contends with DMA/DRAM.

A0 · Golden model

Bit/ULP-tolerant CPU reference for every mask combination, odd page length, shared prefix, sink bias, and long-context online-softmax merge.

A1 · Descriptor ring

Batch page descriptors and KV head work. Use pinned, NUMA-local buffers; avoid per-page interrupts. Add sequence IDs and idempotent completion.

A2 · Pipeline

Double-buffer Q/K/V and results. Make DMA, compute, and next-batch preparation overlap visible in traces.

A3 · Fallback

CPU path must handle unsupported shapes, FPGA reset/timeout, partial batches, and canary comparison without corrupting KV state.

A4 · AMX overlap

Prototype one stage at a time. Pin AMX workers away from driver/IRQ threads; cap memory bandwidth and observe FPGA queue depth.

A5 · Rollout

Shadow → canary → per-model enablement. Gate on accuracy, p50/p99 latency, throughput, recovery time, power, and thermal stability.

KV capacity (bytes) = layers × live_tokens × KV_heads × head_dim × 2(K,V) × bytes_per_element
gpt-oss adjustment: alternating sliding layers retain only their active window; dense layers retain full context.
AoF success metric: end-to-end token latency and sustained TPS under realistic concurrency. FPGA kernel latency without DMA, queueing, page gathering, and fallback is not a product metric.

Verification contract

Tests that decide whether it ships

Correctness

  • QK/PV kernel differential tests for head 64/128, logical M 1..16, page count 0..64, NaN/Inf/denormal inputs, misalignment, and padded rows.
  • End-to-end logits/token parity over sliding and full layers, attention bias/sink, prefix sharing, EAGLE exception, sparse visibility, cancellation, and long contexts.
  • KV property tests: write, append, copy, defrag, fork, prefix reuse, eviction/reload, cross-page boundary; canonical vs unpacked mirror byte-equivalence.
  • AoF: randomized descriptor streams, reset/timeout/retry, duplicate completion, partial DMA, and CPU shadow comparison.

Performance

  • Micro: cycles, instructions, AMX utilization, load/store bytes, pack cost, tile-config frequency for every M/head/page bucket.
  • Component: ready/pending attention, joins, queue wait, FPGA wait, KV wait; normalize by pages, keys, and logical rows.
  • System: TPS, TTFT, ITL, p50/p95/p99, wall time, energy/token, socket power, frequency, thermal throttling, memory bandwidth, UPI/remote NUMA.
  • Workloads: gpt-oss-20b/120b; users 1..32; prompt 128/2K/8K/32K/128K; generation 128/1K; TP and instance sweeps.

How to read confidence

Fact directly supported by documents, model config, diagram, or PR code. Hypothesis an engineering candidate requiring measurement. Measure a requested experiment or reported point estimate. Risk a correctness, rollout, or evidence blocker.

Consensus notes from Codex + PAL Claude Fable 5
  • AMX is profitable only after shape aggregation and packing economics are included.
  • Software attention is a valid first bounded target for gpt-oss because GQA supplies M=8 and two visible jobs can fill M=16.
  • The reported FPGA wait creates an Amdahl floor; further attention-kernel tuning needs critical-path evidence.
  • AoF changes the optimization boundary: CPU AMX should serve fallback/reference or proven overlap work, not duplicate the primary FPGA path.
  • Correctness and lifecycle gaps outrank adding more kernels.
