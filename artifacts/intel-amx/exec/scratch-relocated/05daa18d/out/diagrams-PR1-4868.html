Short version

PR-1 (#4868) stores the saved key vectors (K) of 128-dimension attention heads in the VNNI-packed layout, behind a typed owner and typed views, and adds no AMX instruction. The page introduces four data models (the plane geometry with its index map, the typed owner with its views and one access route, the typed K plane inside the kv_block, and the transfer rows), three algorithms (the per-token store and load, the AVX-512 reader, and the per-token save_k store), and the policies and protocols around them (the layout gate, the page accessors, the FPGA staging gather, the temporary scoring gate and the kill switch). Six core diagrams carry them (KV_CACHE-B1, K_VNNI-B1, K_VNNI-B1A, K_VNNI-B2, K_VNNI-B3 and KV_CACHE-B3), and the nine context diagrams and one uninvolved diagram mostly mark what lands in PR-2, PR-3 and PR-4.

Words used here

Aligned, Dma flags / DMA
DMA is direct memory access, the engine that moves a staging buffer to the FPGA card. A row view carries two compile-time flags, Aligned (the row starts at a 64-byte boundary) and Dma (the row lives in DMA memory), and the K row operations do not require Aligned because they use unaligned vector instructions [h/tron/tensor/k_vnni.hpp:219-228].
AMX
Advanced Matrix Extensions, the tile instruction set of the CPU, whose tile multiply TDPBF16PS reads its right operand (the B operand) in the VNNI layout. This PR adds no AMX instruction.
AMX dispatch (TRON_AMX_DISPATCH)
The CMake option that compiles the AMX kernels. This PR does not require it: the option-on build passes its tests with AMX dispatch off [PR body, Builds and tests].
apply_page_tok
The per-page scoring function of h/tron/models/self_attention.hpp, which picks the dense AMX kernel or the software reader for one (query, page) pair. In this PR every page of a VNNI slot takes the software reader qk_group [h/tron/models/self_attention.hpp:1833-2019; the reader call at 1972-1981].
attention workers
The threads that run the attention kernels of a layer, and that run the staging gather through help_drain_gof when idle. They read a page only after every minibatch that writes it counted its latch (upstream_kvs_ready) down.
AVX-512
Advanced Vector Extensions, the CPU's 512-bit vector instruction set: one register holds 16 lanes of 32 bits, and VDPBF16PS is its instruction that multiplies bf16 pairs and adds them in fp32. The reader qk_group, store_row and load_row are AVX-512 code.
bf16 / fp32 / fp16
bf16 is the 16-bit brain floating-point format of the stored K and V values, fp32 is the 32-bit float format in which the score kernels add (a bf16 shifted up by 16 bits is the exact fp32), and fp16 is the 16-bit IEEE half format. An fp16 query is widened to fp32 once by the reader [h/tron/kernels/k_vnni.hpp:10-12, 71-77].
block (16-token block, token block c)
16 consecutive page offsets of a page (BLOCK_TOKENS_16), page offsets 16 c .. 16 c + 15, of which a page has TOKEN_BLOCKS_4 = 4. A block's bytes are its 4 panels, 4 KiB in all [h/tron/tensor/k_vnni.hpp:63-64, 74-75].
block_to_vnni / block_to_rows
The in-place conversions of one 16-token block between its row-major form and its VNNI form. They land in PR-4 (#4901), not in this PR.
book
The unit of memory allocation of the KV cache. It owns the memory for a requested number of pages and hands out references to them [h/tron/models/kv_cache.hpp:833].
cached_operation_uses_hw
model.hpp's per-operation answer, decided once per model, whether the FPGA scores the operation's K. PR-4 uses it in save_k to keep such blocks row-major, and this PR does not read it in save_k.
CI lane
The CMake job of .github/workflows/cmake-single-platform.yml. This PR adds -DTRON_K_VNNI=ON to its configure line, so the whole test suite runs on the VNNI layout there [.github/workflows/cmake-single-platform.yml:356].
conv (on-stack bf16 conversion)
In save_k, a K buffer row whose activation type is not bf16 is converted to a 64-byte-aligned bf16 row on the stack (named row) before set_k_row stores it [h/tron/models/model.hpp:3116-3119]. PR-3 (#4898) moves that conversion into store_k_block, where the stack array is conv[k_store_block][head_size], one row per token of a run.
copy_from / book::append
book::append copies one book's tokens after another's, page by page through page::copy_from, which calls copy_storage_slot per storage slot. Both exist in main and are unchanged by this PR [h/tron/models/kv_cache.hpp:1247, 2322].
copy_storage_slot / copy_token
page::copy_storage_slot copies count tokens of one storage slot from another page. For a VNNI slot this PR copies a whole page as one owner assignment (dst_block.k = src_block.k) and every other range token by token with copy_token (load_row then store_row through a local row) [h/tron/models/kv_cache.hpp:2286-2302; h/tron/tensor/k_vnni.hpp:331-339].
decode / prefill
Prefill is prompt processing (many tokens per user per pass), and decode is generation (one token per user per step). PR-3's Note [Shared block save] measures the per-token store of this PR at 0.86 ms per layer in a prefill layer, and PR-3 (#4898) replaces it for runs of 16 tokens.
dense page / dense AMX path
A full 64-token page that the query sees whole, which main's AMX page kernel qk_rowmajor_128x4 processes in one call (apply_dense_amx_page). In this PR that path is compiled out for VNNI slots by the temporary gate.
dimension pair (dp) / dword
Dimensions 2 dp and 2 dp + 1 of one token, stored together in one 32-bit lane (a dword, DWORD_BYTES_4) [h/tron/tensor/k_vnni.hpp:58-60]. The even value is in the low half of the dword and the odd value in the high half [h/tron/tensor/k_vnni.hpp:80-81; h/tron/kernels/k_vnni.hpp:107-108].
dimension step (s)
32 dimensions = 16 dimension pairs (STEP_DIMS_32, STEP_PAIRS_16). A 128-dimension head has DIM_STEPS_4 = 4 steps [h/tron/tensor/k_vnni.hpp:67-69].
dotter
main's per-token dot-product routine for a row-major K row (struct dotter in h/tron/kernels/dotter.hpp), driven by the per-token loop of apply_page_tok. In this PR it is compiled only for row-major slots.
EAGLE
A speculation model whose KV storage is one extra physical slot of the book (eagle_storage_offset). This PR does not change it, and PR-4 (#4901) adds a K layout state entry for it.
fill_storage_slot / fill_random
book::fill_random is a test-only fill of every kv_block with random bf16 values, and fill_storage_slot is its body per storage slot. It is the one documented exception to the typed access rule: for a VNNI slot it takes the plane address through detail::k_vnni_access [h/tron/models/kv_cache.hpp:1291, 1716-1726].
forward end
The end of one forward pass on the main thread, after the plugin's run() (the forward function of the generated model code) returned and wait_for_coop_gof drained the staging gather. PR-4 converts completed blocks there, and this PR converts nothing.
FPGA
Field-programmable gate array, the card that runs hardware attention and receives K and V rows by DMA.
GOF
A group of four consecutive tokens. The staging gather (gof::populate) copies their K and V rows into a buffer that DMA moves to the FPGA card.
hardware attention
Attention scored on the FPGA for an operation. PR-4 adds a policy that keeps short-run blocks row-major under it, and this PR has no such policy.
index map (k_vnni::index)
The constexpr function that gives the element index of K[token][dim] inside the plane: (((s * 4 + c) * 16 + dp) * 16 + t) * 2 + j [h/tron/tensor/k_vnni.hpp:105-112]. The worked example (token 37, dimension 70) gives element 5226.
k_head_fn / page_info / scratch
page_info is the per-token record the scheduler builds for the staging gather, and its k_head_fn callback returns a pointer to the token's K row for one slot and KV head. This PR adds a scratch argument: for a VNNI slot the callback gathers the row into the caller's 64-byte-aligned scratch (256 bytes per head) and returns the scratch [h/tron/gof.hpp:61-78; h/tron/scheduler/full.hpp:2747-2762].
k_packed
page::k_packed, called with a slot and a KV head: the read-only typed view (k_vnni_view<const bf16, 64, 128>) of one page's K plane, VNNI slots only. It is the argument of the reader qk_group [h/tron/models/kv_cache.hpp:1993-2001].
k_rows_saved_ / k_vnni_blocks_
The page's two atomic bit arrays per storage slot, one bit per page offset (saved rows) and one bit per 16-token block (converted blocks), which land in PR-4 (#4901). In this PR the page keeps no K layout state.
k_source_row / k_destination_row
Helpers that build a read-only row view from a bf16 pointer or from a rank-1 bf16 view that keeps its own flags (k_source_row), and a writable row view from a bf16 pointer (k_destination_row). They neither check alignment nor copy data [h/tron/tensor/k_vnni.hpp:232-253].
k_storage / native_k_storage
Inside detail::kv_block, k_storage is a std::conditional_t that names k_vnni_tensor<page_size, head_size> when k_vnni::layout_on<head_size> holds and the bf16 array native_k_storage otherwise, and the member k has that type. Both hold page_size * head_size bf16 values [h/tron/models/kv_cache.hpp:2526-2536].
k_vnni_access (detail::k_vnni_access::plane)
A friend helper with one static function, plane(view), that returns the view's raw pointer to the plane's first element. It is the only route from a view to a plane address, for the typed operations, the reader qk_group and the test-only fill [h/tron/tensor/k_vnni.hpp:209-216].
kill switch (TRON_AMX_DISABLE)
TRON_AMX_DISABLE=1 in the environment prevents use of the AMX kernels at run time (AMX-on names a run without the switch, AMX-off a run with it). With the option on, the switch keeps the layout and the reader, so it changes no score and no visit path for 128-dimension heads in this PR [h/tron/models/kv_cache.hpp:707-713].
KV head / kv_mul
One key/value head of grouped-query attention (GQA: several query heads share one key/value head), and kv_mul is the number of query heads per KV head: 4 for the models qwen3-4b and llama-3.1-8b, 3 for llama-3.2-3b, and 8 for qwen-3-30b-a3b. The reader scores a group of more than 16 heads in passes of 16.
KV page / page
A KV page is 64 consecutive tokens of KV storage allocated by the cache (page_size = 64). The page struct is a lightweight reference into a book [h/tron/models/kv_cache.hpp:1826-1828].
kv_block
The struct that holds the K plane and the V plane of one (storage slot, KV head, page). This PR types its K plane [h/tron/models/kv_cache.hpp:2519-2536].
kv_slot_id / slot / storage slot
kv_slot_id selects one persistent K/V storage region of the book, usually one per layer [h/tron/attention_ids.hpp:23]. A storage slot (kv_storage_offset) is the absolute physical slot offset in the book's allocation [h/tron/models/common.hpp:240].
layer
One transformer layer of the model. Each layer stores its K and V into its own slot of the KV cache.
layout gate (k_vnni::layout_on)
k_vnni::layout_on<head_size> is true only for 128-dimension heads and only when the option TRON_K_VNNI is defined. It depends only on the storage geometry, so every reader and writer of a slot selects the same layout [h/tron/tensor/k_vnni.hpp:95-101].
live mask
A 64-bit word with one bit per page offset. apply_page_tok sets the bit of every relevant token during its loop and hands the word to qk_group, which reads only those tokens [h/tron/models/self_attention.hpp:1933, 1962-1963, 1976-1979].
main thread / main helpers
The main thread runs the generated run() of a plugin (the generated model code), including save_k, and the main helpers are its helper threads (run_main_help). In this PR save_k runs on main alone, and PR-3 (#4898) shares its K store with the helpers.
mark_k_complete / upstream_kvs_ready
mark_k_complete records in the page that a token's K is saved, and upstream_kvs_ready is the per-slot latch (a countdown object) that downstream minibatches wait on and that save_k counts down after its stores. Both exist in main and are unchanged here [h/tron/models/model.hpp:3126, 3134-3135].
marks loop
The per-token loop of save_k_impl over the minibatch's items. For each token it stores the K rows of every KV head and then calls mark_k_complete (the mark) [h/tron/models/model.hpp:3091-3132].
minibatch
One chunk of a forward pass's token jobs that the forward runs together. save_k stores the K rows of one minibatch, and downstream minibatches wait on its latch [h/tron/models/model.hpp:3133-3135].
mutation check
A deliberate code change that a test must catch. The PR body reports one: removing the per-head scratch offset in gof::populate makes the populate case of t_phase1_integration fail.
Note [K VNNI storage]
The design comment in h/tron/models/kv_cache.hpp that says what the layout is, who writes it, who reads it, how each of the six consumers of a VNNI slot changes, and that the kill switch keeps the layout [h/tron/models/kv_cache.hpp:651-713].
Note [Row-major tail block] / row-major tail block
A 16-token block of a VNNI plane whose rows stay row-major until all 16 rows are saved and are then converted in place, which lands in PR-4 (#4901). In this PR every row goes straight into the VNNI column.
Note [Shared block save] / shared block save / window
PR-3's design: a run of 16 tokens is stored as one whole block, the main helpers claim work units of the store through a window of counters, and main waits for every helper to finish its claims (the join) before it marks the tokens. None of it is in this PR.
note_k_row_saved / note_k_block_saved
The page functions that publish the saved-row bits and the block bit. They land in PR-4 (#4901).
owner / view (k_vnni_tensor / k_vnni_view)
k_vnni_tensor<64, 128> owns one K plane as a 64-byte-aligned bf16 array, trivial to construct, copy and destroy, and k_vnni_view<T, 64, 128> refers to that plane, computes element addresses and reads one element through at(token, dim) without writing it. Views come only from an owner's as_view(), and a writable view converts to a read-only one, never back [h/tron/tensor/k_vnni.hpp:135-201].
page offset
A token's position inside its 64-token page, 0 to 63. In the VNNI plane the offset decides the token's block (offset / 16) and its column (offset % 16).
page::k / k_view / k_at (the row views)
The row-major K views: kv_block::k_view() is the plane as a [token][element] view, k_at(i_page) is one token's row, page::k(slot, kv_head) returns the kv_block's k_view, and page::k(slot, kv_head, j).set(row) writes one token's row. In this PR all of them exist only when layout_on is false [h/tron/models/kv_cache.hpp:1924-1986, 2554-2572].
pair row
One 64-byte line of a panel: one dimension pair for 16 consecutive tokens, 32 bf16 = 16 dwords (ROW_ELEMS_32, ROW_DWORDS_16) [h/tron/tensor/k_vnni.hpp:61-62, 70-72]. The 16 pair rows of a panel are 64 bytes apart [h/tron/tensor/k_vnni.hpp:258-259, 272].
pair_base / pair_row_offsets
The address arithmetic of store_row and load_row: pair_base gives the byte address of dimension pair 0 of step s for a token (its column in panel (s, c)), and pair_row_offsets lists the 16 pair rows of a panel, 16 dwords apart, as the index vector of the scatter and the gather [h/tron/tensor/k_vnni.hpp:261-280].
panel
One (dimension step s, token block c) cell of the plane: 16 pair rows of 64 bytes = 1 KiB (PANEL_BYTES_1024). A plane has N_PANELS_16 = 16 panels, and a panel is exactly one AMX B tile [h/tron/tensor/k_vnni.hpp:26-27, 74-77].
pending_k_blocks_ / convert_pending_k_blocks
The deferred conversion list of save_k and the forward-end function that drains it. They land in PR-4 (#4901).
plane
K for one KV head of one page: 64 tokens x 128 dimensions of bf16 = 16 KiB, the same bytes as the row-major plane [h/tron/tensor/k_vnni.hpp:21-30].
PR / PR 4424 / the stack
PR is a GitHub pull request of the tron repository. PR 4424 (branch jhan-amx-vnniK) is the original change that the four PRs of the stack replace: PR-1 #4868, PR-2 #4887, PR-3 #4898 and PR-4 #4901, each based on the previous one.
prompt 1024
A run with a prompt length of 1024 tokens (the --prompt-length flag of runtron, tron's command-line tool). The performance cells of the PR body use prompt 1024 and prompt 8192.
qk_group (the reader)
k_vnni::qk_group in h/tron/kernels/k_vnni.hpp: the AVX-512 routine that scores a query group against the live tokens of one VNNI-packed page, one token per vector lane. One 64-byte load supplies one dimension pair of 16 tokens, the query's pair is broadcast, and VDPBF16PS accumulates 16 scores at once with no per-token gather [h/tron/kernels/k_vnni.hpp:57-127].
qk_rowmajor_128x4 / qk_vnni_128x4
qk_rowmajor_128x4 is main's AMX QK kernel for a row-major K page: it puts the K page on the left and transposes the score matrix after the multiply. qk_vnni_128x4 is the AMX kernel that reads the VNNI plane as its B operand and lands in PR-2 (#4887).
query pack
The step that rearranges a token's query rows into the AMX operand format (pack_q_group_128x4 in main), which in this PR still runs once per token for a VNNI slot although no kernel consumes it. The kill switch skips it [h/tron/models/self_attention.hpp:1632-1634, 1688-1701].
row view (const_k_row_view / k_row_view)
A typed view of one token's 128 K values in dimension order, read-only (const_k_row_view) or writable (k_row_view), carrying the caller's Aligned and Dma flags. It is the argument type of set_k_row, get_k_row, store_row and load_row [h/tron/tensor/k_vnni.hpp:224-228].
row-major (native K)
One row of head_size bf16 values per token, indexed [token * head_size + dimension]. Every head size other than 128 keeps this layout, and so does a 128-dimension head when the option is off.
save_k / save_k_impl
The function of h/tron/models/model.hpp that stores the K rows of one minibatch into the KV cache, through two save_k overloads that forward to save_k_impl. In this PR save_k_impl stores each token's row with page::set_k_row for a VNNI slot and with page::k().set for a row-major slot [h/tron/models/model.hpp:3077-3152].
scatter / gather
_mm512_i32scatter_epi32 writes the 16 dwords of one register to a base plus 16 offsets, and _mm512_i32gather_epi32 reads 16 dwords from such addresses. store_row issues 4 scatters per token (one per dimension step), and load_row is the inverse with 4 gathers.
scheduler (h/tron/scheduler/full.hpp)
The component that runs on its own thread between forward passes: it does the token-tree work (clears, appends, the book defrag) and defines the page_info callbacks of the staging gather, which other threads run.
set_k_block / store_block
The whole-block store of a run of 16 tokens: 16 rows transposed in registers and written as whole lines. Both land in PR-3 (#4898).
set_k_row / get_k_row
The layout-agnostic page accessors that this PR adds: set_k_row writes one token's row (a const_k_row_view) into whichever layout the slot uses, store_row for a VNNI slot and memcpy for a row-major one. get_k_row is the inverse with load_row [h/tron/models/kv_cache.hpp:2010-2062].
staging gather (gof::populate)
The copy of K and V rows of one GOF into the buffer that DMA moves to the FPGA, run on an idle attention worker (help_drain_gof) or on main (wait_for_coop_gof). This PR gives it a K scratch array beside the V scratch, with one row per KV head [src/tron/gof.cpp:203-213].
store_row / load_row
store_row scatters one token's 128-dimension row into its column of the plane (4 scatters of 16 dwords, one per dimension step, touching only that token's 64 pair slots), and load_row gathers the row back. Both check the token index [h/tron/tensor/k_vnni.hpp:291-322].
t_k_vnni_layout, t_llama_unit, t_phase1_integration, t_amx_dispatch_dtype
The four tests of this PR with new or changed cases: t_k_vnni_layout is new with four cases (the index anchors, the exact scrambled store and load, the reader against the dotter, and page rows through store, load and append), t_llama_unit gains the compile checks of the type model, a 32-head compile case and a save_k case, t_phase1_integration's populate case stages K rows through the scratch, and t_amx_dispatch_dtype expects no dense kernel call under the option. Two more test files, t_gof_dma and t_gof_staging_leaks, only give their k_head_fn lambdas the new scratch argument.
temporary gate
The term && !k_vnni::layout_on<operation_head_size> that this PR adds to the dense-page AMX predicate of apply_page_tok. It keeps the dense AMX path out of VNNI slots until PR-2 adds the AMX kernel, so every VNNI-packed page takes the reader [h/tron/models/self_attention.hpp:1885-1887].
the option (TRON_K_VNNI)
The CMake option, default OFF, that selects VNNI-packed K storage for every 128-dimension head, off in every build preset until PR-4 [CMakeLists.txt:47]. Its compile definition is PUBLIC on the tron target and on the generated model objects, so every translation unit that touches a KV page sees the same layout [src/tron/CMakeLists.txt:232-234, 336-342].
TPS
Decode throughput in tokens per second per user. The PR body measures a decode TPS loss of 6.4 % at prompt 1024 and 11.6 % at prompt 8192 against main, and attributes it to the temporary gate (the dense pages that main's AMX kernel serves go to the reader instead).
transpose_16x16_epi32
The in-register 16 x 16 transpose that store_block uses. It lands in PR-3 (#4898).
tree lock
The lock on the scheduler's token tree, held for the tree work between forward passes (clear_kv_complete_at, copy_from).
tron
The inference program under test (the positron-ai/tron repository). Its C++ code lives in namespace tron.
VDPBF16PS / TDPBF16PS
VDPBF16PS is the AVX-512 instruction that multiplies bf16 pairs and adds them in fp32, and the reader uses it. TDPBF16PS is the AMX tile multiply that reads the same pair layout as its B operand, and no PR-1 code uses it.
VNNI layout / VNNI-packed
Vector Neural Network Instructions layout: two consecutive dimensions of one token are adjacent in memory, one 64-byte line holds that dimension pair for 16 consecutive tokens, and it is the B-operand format of the AMX tile multiply. VNNI-packed means stored in this layout.
wait_for_coop_gof / help_drain_gof
The two ends of the cooperative staging gather: idle attention workers run queued GOFs through help_drain_gof, and main drains the rest at the forward end through wait_for_coop_gof. Both exist in main and are unchanged here [h/tron/models/model.hpp:3239, 3252].
WK roped
tron's record label for the K rows after rope (the rotary position embedding), logged by save_k_impl through log_intermediate [h/tron/models/model.hpp:3094].
worked example
The example the three source pages trace through every diagram: the K plane of storage slot 5, KV head 0, page 7, and inside it token 37, dimension 70, which the index map places at element 5226 (panel #10, pair row 3, dword 5).
