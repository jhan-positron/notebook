Typed KV-cache tensors for VNNI packed V and native K (issue 4525)

The KV cache hands its planes to the attention kernels and the model as
typed views instead of bare bf16 pointers. The VNNI packed V plane gets an
owner (v_vnni_tensor) and a view (v_vnni_view) with the address formula and
no public pointer constructor. The row operations that lived in page::set_v
and page::get_v move to h/tron/tensor/v_vnni.hpp with their bodies
unchanged (append_v_row, load_row, copy_token). The native row-major K plane
reaches the QK kernel as native_k_view, an alias of the existing row-major
view that names the layout at the kernel signature but does not enforce it.
Stored bytes, conversions and cache behaviour stay unchanged.

The kv_block objects of an arena or chunk come into existence in the
allocation call: try_make_unique_dma_for_overwrite gets its memory through
a tagged operator new[], which implicitly creates the trivially
constructible blocks (N4950 intro.object/13). The accessors reach them
through std::launder. No placement new and no second pass over the arena
remain (Note [DMA allocation creates objects], Note [KV block lifetime]).

Tests pin the contracts: the kernels reject a bare pointer and the other
plane's view, packed views come only from an owner, rows of every source
type round-trip bit for bit on values exact in bf16, the even-destination
copy zeroes its odd partner, and append_v_row matches the packed layout
formula written out by hand.

This is the squash of the branch jhan-kv-typed-tensors as reviewed up to
2026-10-06 (kept on jhan-kv-typed-tensors-pre-squash-20261006), including
the maintainer's PR 4697 (shared KV row view helpers) and PR 4698 (KV cache
