# Reader report: the T patch's reader side and its tests, with the probe's t_llama_unit resolution reviewed

## Short version

The T patch adds a third gate to the dense AMX path (the whole page must hold the VNNI layout), splits the software loop of a VNNI page into VNNI blocks (scored by the AVX-512 reader) and row-major tail rows (scored by the row-major dotters), and adds 5 test cases, 2 sections and 1 setup block. The probe's resolution of the three-thread section is correct by reading: every saved-row bit, converted-block bit and completion count is per KV slot, the pending list is cleared by convert_pending_k_blocks, and the probe's 38-cell syntax matrix passed, so the second window's checks hold and nothing from the first window leaks. Two things the author must put in PR4-handoff.md: the PR-3 branch has moved locally to dfafd13dce (a test fix inside the very section resolve.py matches verbatim, unpushed when split-status.md was last written), and the `#include <cstring>` move of the T patch did not take effect in the probe (both headers keep the include, which is right because both use std::memcpy).

## Words used here

- Probe: the worktree ~/workspace/ai-runs/tron-split-probe-pr4 (PR-3 head 80bce9a08d with the T and B patches applied and staged). "probe N" below means line N of that file in the probe.
- T diff: handoff-material/ref/T-4737-merge.diff. "T N" means line N of that file.
- VNNI block: one of the 4 blocks of 16 tokens of a 64-token page whose K rows are stored in the AMX VNNI layout. Row-major tail block: a block whose rows are stored one 256-byte row per token inside the block's own 4 KiB (Note [Row-major tail block], probe h/tron/tensor/k_vnni.hpp:446-466).
- Saved-row bits: k_rows_saved_, one bit per page offset and storage slot. Converted-block bits: k_vnni_blocks_, one bit per block and storage slot (probe h/tron/models/kv_cache.hpp:2486-2491).
- Dense AMX path: apply_dense_amx_page, the AMX kernel over one whole page. Software loop: the per-token loop of apply_page_tok that fills s_pages.
- VNNI build / row-major build: TRON_K_VNNI on / off. k_vnni::layout_on<128> is true only in the VNNI build (probe h/tron/tensor/k_vnni.hpp:124-129).

## 1. h/tron/models/self_attention.hpp (+68/-17)

### 1.1 The dense gate k_layout_dense (probe 1906-1935)

- The dense AMX path had two gates: a packed Q must exist (`amx_q_packed != nullptr`: AMX available and a bf16 query buffer) and the page must be dense (is_dense_amx_page) [probe 1896-1904, 1932-1934].
- T adds a third gate, `k_layout_dense()`, evaluated last in the `&&` chain [probe 1935]. The comment says why it is last: a page with nothing relevant for the query is never asked for its slot state, because a book may have no active KV slot [probe 1922-1923].
- In the VNNI build the lambda returns `page.k_vnni_blocks<geometry.kv>(slot) == k_vnni::BLOCKS_PER_PAGE_MASK_0XF` [probe 1924-1927]. In the row-major build it returns true [probe 1928-1930].
- page::k_vnni_blocks returns the converted-block bits of the slot, one acquire load [probe kv_cache.hpp:2128-2137]. Bit c set means block c (page offsets 16 c to 16 c + 15) holds the VNNI layout.
- BLOCKS_PER_PAGE_MASK_0XF is 0xF, binary 1111: all 4 blocks of a page [probe h/tron/tensor/k_vnni.hpp:94-96]. A static_assert pins it to `block_bit(TOKEN_BLOCKS_4) - 1` [probe tensor/k_vnni.hpp:112]. block_bit(c) is `1 << c` [probe tensor/k_vnni.hpp:98-100]; offset_bit(offset) is `uint64_t{1} << offset` [probe tensor/k_vnni.hpp:103-105].
- is_dense_amx_page is unchanged by T: `begin == 0 && end == page_size && query_visible && pg.at_offset(63) < range.tok_hi && q_position - k_position < sliding_window_size` [probe 1725-1737].
- The comment lists the three ways a bit is clear: a block completed this pass through a run shorter than 16 tokens (converted at the forward end), a block that stays row-major under hardware attention (Note [Row-major blocks under hardware attention]), and a page filled by another writer than save_k [probe 1913-1920].

### 1.2 The software loop's split (probe 1953-2049)

- The comment now says the VNNI layout records the relevant tokens of its VNNI blocks in `live`, and the tokens of a row-major tail block are scored with the dotters through their typed row, row_major_row [probe 1953-1961].
- dot_q: before T, under the VNNI layout the lambda returned the placeholder `0` ("No dotters. The VNNI reader takes q directly.") [T 1939-1947, removed]. After T, dot_q is a `std::array<dotter<scalar_t, head_size>, kv_mul>` built by pack expansion in every build [probe 1968-1974]. The VNNI build needs the dotters now for the tail rows.
- `live` (uint64_t, one bit per token of the page) keeps its role [probe 1975]. A static_assert pins page_size to 64 for it [probe 2043-2044].
- New: `vnni_blocks` (uint8_t, the page's converted-block bits) and `plane` [probe 1982-1990]. In the VNNI build `plane` is a `std::optional<decltype(page.k_packed<geometry.kv>(slot, kv_head))>`, empty at first; in the row-major build it is the placeholder `0`. Both are fetched at the first relevant token [probe 2020-2023], for the same reason as the row view `keys` of the row-major build (a page nothing is relevant for is never asked) [probe 1976-1981].
- Per relevant token i in the VNNI build [probe 2019-2033]: if `vnni_blocks & block_bit(i / 16)` is set, `live |= offset_bit(i)`; else `k = row_major_row(*plane, i)` and every one of the kv_mul dotters writes `s_pages[offset][i] = dot_q[offset](k)`. row_major_row returns a typed row view of the 256 contiguous bytes of token i inside panel (t / 4, c) [probe tensor/k_vnni.hpp:467-479].
- After the loop: `if (live != 0)` calls `k_vnni::qk_group<kv_mul>(*plane, q + ..., live, &s_pages[0][0], page_size)` [probe 2045-2049]. Before T the condition was `if (relevant_k_tokens > 0)` and the call fetched `page.k_packed(...)` itself [T 2045-2050]. Two consequences: a page whose relevant tokens all lie in row-major blocks skips the reader, and `*plane` is valid whenever live != 0, because a live bit is set only after plane is fetched [probe 2020-2025].
- The reader's contract matches: every token block with a live bit must hold the VNNI layout, and the caller keeps the bits of row-major tokens clear [probe h/tron/kernels/k_vnni.hpp:43-46].

### 4.1 Are the bits per slot?

Yes.
- k_rows_saved_ and k_vnni_blocks_ are indexed by k_state_ix(slot), which is slot.i unless the EAGLE view is active and slot is 0 [probe kv_cache.hpp:2486-2491, 2502-2507]. The test has no EAGLE view.
- note_k_row_saved reads and sets k_rows_saved_[ix] and reads k_vnni_blocks_[ix] for ix = k_state_ix(slot) [probe kv_cache.hpp:2169-2185]. note_k_block_saved sets both for the slot [probe 2197-2202]. k_block_to_vnni_at converts the storage slot named in the pending entry and sets its bit [probe 2216-2238]; save_k takes that reference at the save (`pg.k_storage_of(slot)`) [probe model.hpp:3432-3434, kv_cache.hpp:2147-2157].
- The completion counts kv_saves_[offset][slot.i] used by mark_k_complete and is_kv_complete are per slot too [probe kv_cache.hpp:2452-2456, 2466-2470].
- operation_1's slot differs from operation 0's (REQUIRE at probe 4221); the book has n_layers = 2 slots [probe 3886].

### 4.2 Does check_blocks(true) == 0x9 hold for the second window?

Yes, by reading. On slot 1 nothing has been noted before pre_save (fill_random writes bytes only [probe kv_cache.hpp:1407-1414]). pre_save notes rows 0..4 and 8; none completes block 0, so 6 REQUIRE_FALSE pass. shared_save(operation_1) stores the same 46 KV rows into slot 1: tokens 48..63 are one run of 16 and get the whole-block save plus note_k_block_saved (0x8); the run 5..15 minus 8 (10 rows), 16..20, 64..71, 100 and 130..135 are shorter than 16 and go row-major through set_k_row [probe model.hpp:3315-3334].
