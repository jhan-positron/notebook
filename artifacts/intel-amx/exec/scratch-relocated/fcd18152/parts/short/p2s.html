TRON attention concepts: seventeen tokens, one pass

Short edition: the same mock pass and interactive figures as the full page, a third of the text. TRON is the inference engine that runs LLMs (large language models) on Positron FPGA (accelerator card) hardware plus the host CPU. Source: commit 9b11a912ba of ~/workspace/tron; file references are relative to that clone.

Short version. One TRON forward pass (one call of full_scheduler::forward(), which runs every model layer once for the tokens that are due) serves two requests that share a 9-token prompt, and 17 tokens take part, 6 of them queries (tokens whose K/V, the key and value vectors of attention, or logits, the next-token scores, must be computed this pass).

The traversal of the token tree (the prefix tree that stores every request's tokens, the shared prompt once) numbers the tokens, lists the 5 KV cache pages, and builds one ranged mask (this page's reading of "visible range of K/V") before the 6 queries are cut into 2 minibatches.

Attention then runs once per layer per minibatch and reads each page through two filters in order: the mask (tree causality, measured in token_ids, this pass's traversal numbering) and, on the windowed layer only, the sliding window (recency, measured in positions, each token's depth in its sequence).

Concept table

Lifetimes: persistent survives across passes, per pass lives inside one forward pass, per layer or per minibatch is rebuilt inside the pass. Mock names (edges S, B, A, books X, Y, pages P0..P2, Q0..Q1, minibatches MB0, MB1) are introduced in section 1.

attention One softmax-attention computation for one attention operation (one attention step of the model) and one minibatch, over that minibatch's page list. attention operation → layer → plugin layer loop (the layer loop in the model-architecture code, such as the llama plugin) → run_forward per (operation, minibatch) call 4 kernel runs (kernel: the routine that computes attention for one minibatch) (6, 7)
KV cache page A fixed-size block of KV entries inside a book (a block of KV memory holding pages; an edge lives in one book, and a book can hold several edges): 4 entries in the mock, 64 in code. Its bytes persist. lo (token_id of entry 0) and count() (live entries) are rewritten every traversal. book → edge → node → token tree persistent storage.

sliding window An optional integer W (positions) on one attention operation's config. A query keeps an entry only when q_position − k_position < W. A missing value is INT_MAX: nothing is dropped, the layer is full causal. attention operation config → attention operation (descriptor in model state, the per-model object that outlives passes) persistent value. Test runs per minibatch and per layer layer 1, W = 6: each query keeps 6 entries (7)
visible range of K/V This page's reading of the phrase: the ranged mask, a list of token_id spans, each with two bitmasks over the queries (SW_REQUIRED: software must compute; HW_AVAILABLE: the FPGA could). visible(job) tests their union. token_range → ranged mask → traversal → forward pass per pass: final before minibatches exist 7 ranges over token_ids 0..16, 6 bits each (4)
minibatch A subset of this pass's queries that moves through the layers together, so CPU attention of one minibatch overlaps FPGA matrix multiplications of another. Not a request, not a training batch. run_forward → forward pass → full_scheduler (the per-model scheduler) per pass: cut after the mask is final MB0 = (b2, a0, a1), MB1 = (a2, a3, a4) (5)
