Agreed on the facts. The setup at t_llama_unit.cpp:1943 and the VNNI (Vector Neural Network Instructions, the pair-interleaved K layout) branches of `check_blocks` compile only with `TRON_K_VNNI` (the K-layout build option). The default CI (continuous integration) lane is the gcp-nix.yml workflow, which runs on every pull request. It builds the test runtime through nix/cmake-tron-test-build.nix. That configure line sets neither `TRON_AMX_DISPATCH` (the option that compiles the AMX kernels; AMX = Intel Advanced Matrix Extensions) nor `TRON_K_VNNI`. Both default to OFF (CMakeLists.txt:48-49). The only lane with both options on is the legacy workflow cmake-single-platform.yml (lines 333-334). It runs on manual dispatch, or from publish-deb.yml (the Debian package workflow) for tag and feature-branch publishes. No pull request runs it.

The gap predates this PR. PR #3879 added `TRON_AMX_DISPATCH` to the legacy lane (f4889f8072) and PR #4424 added `TRON_K_VNNI` (929fa94e42). By then the CI cutover (the move of the default CI to the nix lane, 2f1ee29982, 2026-09-11) had already made the legacy lane manual. The PR #4424 body records that the default CI builds its benchmark binary with neither option, and the test runtime comes from the same build. This PR adds 627 test lines in three files with the same gap: 81 lines compile only under `#ifdef TRON_K_VNNI`, and the rest pick their VNNI branch through `k_vnni::layout_on`, which is false without the option.

What a fix needs. The mixed-layout coverage needs no AMX hardware. The dense AMX path is gated on `amx_q_packed` and on every block of the page holding the VNNI layout (`k_vnni_blocks` equal to `k_vnni::ALL_BLOCKS_0XF`). The VNNI reader `k_vnni::qk_group` is AVX-512 BF16 code (512-bit vector instructions, no AMX tiles). Every CI runner with the labels `[self-hosted, fpga, test, avx512]` executes that code. So adding `-DTRON_AMX_DISPATCH=ON -DTRON_K_VNNI=ON` to nix/cmake-tron-test-build.nix would make the Test host job (a required check on every pull request) run these tests. The cost is a policy choice. `TRON_K_VNNI` is a PUBLIC compile definition (a CMake term: every target that links tron inherits it) [src/tron/CMakeLists.txt:209-213]. So every test in the default lane would then run the VNNI layout. The per-commit benchmark runtime, built from the same compilation (nix/tron-build.nix), would run it too. The shipped package uses the row-major layout. The row-major branches of the tests that have a VNNI branch would no longer run in the required suite. One configuration cannot run both branches. Running both needs a second test runtime. That touches the handoff scripts (bin/ci/tron-build/prepare_handoff.py, which passes the built runtime to the test jobs) and the required check names.
