- (a) "positions 64..126 are scored by the CPU on every decode step, in converted VNNI blocks (engagement-prefix page)": REFUTED. The engagement point gates query position, hw_plan entry end and the first shard's DMA prefix end, never K positions; keys 0..dma_last are hw-only for a query >= 127. The CPU scores only the tail above dma_last (measured mean 2.49 tokens per job at prompt 1024), mostly in the row-major tail block (dotter, 4 lines per token) in FIX; qk_group runs on a converted block only when the tail lies in a block converted at an earlier forward end.
- (b) "the AMX dense kernel never runs in FPGA decode": HOLDS for steady-state decode at prompt 1024 (code: no dense page inside [dma_last+1, P] unless DMA lags by a whole page; measured ready_amx = pending_amx = 0 at prompts 1024 and 8192). Exceptions in the same binary: queries at positions 64..126 of prompts shorter than 127 (measured 147,456 visits at prompt 64), DMA lag by whole pages (measured in prompt-8192 prefill), degraded (no-HBM) shards, whole-context SW before shard 0 has 32 DMA'd GOFs (timing-dependent), sliding-window layers. Prefill of a fresh prompt under FPGA attention at prompt 1024 gives 0 dense visits (pages holding this pass's query tokens are never dense; earlier chunks are HW-covered). LDTILECFG/TILERELEASE do execute once per non-empty section per layer per step in both builds; whether they count in EXE.AMX_BUSY is unmeasured.
- (c) "gof::populate gathers K rows once per GOF (4 tokens) per user": CORRECTED to "once per (GOF, KV slot = layer) per staging lifetime, on whichever of gof_rodeo_impl / backfill_shard runs first, and again after staging eviction; per user only in the sense that GOFs are per tree edge". "Gathers" (64-line gather_row) applies only to converted blocks: FIX decode GOFs normally read the row-major tail block by memcpy (256 B, 4 lines) when GOF/block boundaries align (unverified); FIX prefill GOFs and re-populates always gather; PRHEAD always gathers; BASE returns a pointer with no copy.
