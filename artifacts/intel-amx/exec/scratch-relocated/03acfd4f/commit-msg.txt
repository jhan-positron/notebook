Packed V: assert the row preconditions, drop the unused width rule and element write

Third-review follow-up on PR #4557 (review 5432936425). The comments of
h/tron/tensor/v_vnni.hpp claimed more than the code checked. This commit
makes the two row preconditions real checks and removes two things that
had no consumer.

- detail::v_vnni_access::pair_base asserts token < Rows. The bulk row
  operations (append_v_row, load_row, copy_token) reach the plane only
  through it. One compare-and-branch per call; TRON_ASSERT is active in
  release builds. The comment names who satisfies the precondition
  instead of implying an upstream check.
- v_source_row and v_destination_row assert that the row pointer is
  aligned to chunk_alignment (64 bytes). They are the one place where a
  raw pointer acquires the `aligned` view flag that selects the aligned
  vector loads and stores. One compare-and-branch per call.
- The `Cols % 32 == 0` clauses of append_v_row and load_row go, with the
  comment that called them unneeded. The loops step one chunk of 16
  dimensions. The static_assert `Cols % chunk_size == 0` of the view and
  the owner carries the width rule. page::set_v and page::get_v keep
  their own head_size % 32 clauses from main, so no accepted page width
  changes.
- The writable at() overload goes. Nothing wrote through it. at() is a
  bounds-checked read; rows enter through append_v_row and copy_token,
  which keep the even/odd partner rule. The test probe pins that no
  view writes an element.
- Comment fixes: Note [VNNI Packed V layout] and Note [Zero-Initialized
  V Slots] no longer say direct writes "serve fixtures"; the
  scaled_v_expr comment names book::append and the book::fill_random
  exception instead of "book"; the append_v_row comment describes the
  conversion without reference to the old page::set_v.
