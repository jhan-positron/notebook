

Issue 4444 root cause
Issue #4444: the root cause of the token divergence, measured

Campaign td-20261016 on delphi-3bda, 2026-10-16. Written by Claude Code for jhan. Every measured number on this page comes from a file named in the section "Records". The generator is exec/td-20261016/report/gen_report.py. Code line numbers refer to the PR 4959 head 6b081187e1 unless a commit is named.

Short version

The tokens diverge for three reasons: the three attention engines add the same products in three different fp32 orders, the AVX-512 path truncates the softmax weights while the AMX path rounds them to nearest, and at the PR 4959 head one decode step in 64 scores one page on the software path where main uses AMX. Causes 1 and 2 were each isolated with a proof-of-concept binary and measured record for record, and cause 3 is the residual of the first one, verified in the code: a stack binary with the reader's add order removed matches main over all 1,024 prompt tokens and the first 63 generated tokens, and over the whole run under the kill switch. No kernel defect was found, and the one pre-existing accuracy problem is the AVX-512 truncation of the weights, which biases the attention output low by 0.08 % on average and raises its error against an exact reference by 1.13 to 1.8 times, depending on where it is measured.

1. What was asked and what was run

Issue #4444 asks for the cause of the token differences between the AMX/VNNI binaries and the row-major binary, with a measurement, and for a decision on the kill-switch contract. The earlier forced runs (2026-10-11, 2026-10-13) had shown that every flip sits at a near tie. They had not shown which operation makes the scores differ, nor by how much, nor whether any of it is a defect.

Method: one cell (qwen3-4b, tp2, 1 user, prompt 1,024 tokens, 256 generated tokens, CPU attention, greedy, --pay-for-determinism). Eight binaries or settings ("arms") ran as forced runs with the full per-layer record kept (20.6 GB per run). The records were compared key for key and the logits step for step. Two proof-of-concept binaries remove one cause each. Predictions were written before the runs (token-divergence-4444/predictions.md) and are scored in section 8. Kernel-level facts come from a standalone program that drives the real kernels on the machine. An offline replay on the real logged Q, K, V values gives the accuracy against an exact reference. Run-to-run noise is excluded by the bit-identity of three different binaries (clean, baseoff, pocoff: 0 of 416,443 record keys differ) and by the A/A control of 2026-10-13 (the same binary run twice, 256 of 256 steps identical) [exec/td-20261016/tiestats/tie_stats.md, section 1].

3. Cause 1: three fp32 add orders

[SVG]
How each engine sums the 128 products of one score. The products are identical (bf16 times bf16 is exact in fp32). Only the grouping of the fp32 adds differs. The two AVX-512 orders were confirmed bit for bit against scalar models (512,000 scores each). The AMX order was found by experiment and confirmed bit for bit on both AMX kernels. Source: exec/td-20261016/ktest/results.txt, lines T0, T3, T4, T5m, T6d.

Kernel level (random data, 2,000 query groups x 64 tokens). The AMX kernel and the VNNI reader disagree on 49.5 % of the scores, by a median of one fp32 ulp and at most 2 bf16 ulps where the sum cancels. The dotter and the AMX kernel disagree on 50.1 %. The two AMX QK kernels (row-major K and VNNI K) agree bit for bit. The AMX PV kernel and the AVX-512 PV loop differ in 72.8 % of outputs even when both see the same bf16 weights. So the PV path has an order difference of its own. [ktest T1, T1b, T2, T6a, T6c]

Model level. The stack binary (reader on partial pages) and main (dotter on partial pages) first differ at prompt token 1 (token 1, WO layer 16: 3.6 % of its values, relative change 2.57e-4). A median one-ulp score difference moves one or two bf16 output elements at a quarter to a half of the tokens. The layer-0 WO record differs at 352 of 1279 tokens (first at token 26), with a median relative change of 1.06e-4. The same first record appears in the kill-switch pair baseoff vs newoff, where the reader serves every VNNI block (the rows of the decode tail block still go through the dotter, section 5).

Proof by removal. The PoC binary poc unpacks every VNNI token row and scores it with the row-major dotter. The reader never runs in it. Under the kill switch, pocoff equals baseoff in all 416,443 record keys and all 256 logit vectors. So the VNNI layout itself changes no number, and the add order of the reader is the whole difference between the two kill-switch arms. With AMX on, poc equals base for every record of the 1,024 prompt tokens and of decode tokens 1,024 to 1,086, and first differs at token 1087 (cause 3 below). Prediction P1 held for the add order. The residual is a separate, smaller cause.

The clean binary and main under the kill switch are bit-identical (0 differing record keys, 256 of 256 logit vectors identical). So the kill-switch contract of Note [AMX attention dispatch] holds exactly on row-major K. With VNNI K it does not: newoff differs from baseoff from prompt token 1 on. The issue predicted this (the kill switch runs the VNNI reader, not the dotter). This run measures where it starts.

4. Cause 2: the rounding of the softmax weights

The AVX-512 PV path truncates P to bf16 (interleave_bf16_ps keeps the high 16 bits of each fp32 weight, kv_cache.hpp:2996-3001). The AMX PV kernel rounds to nearest even (_mm512_cvtne2ps_pbh, amx_attn.cpp, weights_times_v_128x4). Truncation always rounds toward zero. So the truncated weights sum to less than the exact ones while the divisor (the fp32 sum of the unrounded weights) does not shrink, and the output is scaled down. The difference itself is documented: Note [AMX attention dispatch] names the rounding of P as one of the two admissible reasons for AVX-against-AMX differences, and t_amx_numerics tests inside that envelope. What was not known is its size and sign, measured here. The truncation dates from 2024 (commit 5d94957ac8), and no comment states a reason for it.

Model level. With AMX on, the first dense page is seen by prompt token 128, the first query of the second prefill pass. A pass's own pages are never dense, because the query mask holds one range per key of the pass (ranged_mask.cpp:43-49, 131-138). There new and newoff first differ (token 128, WO layer 0: 36.2 % of its values, relative change 1.94e-3). From there the layer-0 WO differs at 1151 of 1279 tokens (every token from 128 on), median relative change 2.17e-3: about 20 times the add-order median of 1.06e-4. main under its own kill switch shows the same first record and the same size (baseoff vs base). So this is the PR 3879 difference, not a stack difference.

Separating rounding from order. The PoC binary trunc truncates P inside the AMX kernel. new vs trunc (rounding only, same AMX order) reproduces the token-128 record exactly (token 128, WO layer 0: 36.2 % of its values, relative change 1.94e-3). newoff vs trunc (order only: AMX order against AVX order, both truncated) first differs at token 128, WO layer 2: 1.2 % of its values, relative change 2.31e-4. Layers 0 and 1 of token 128 are bit-identical in that pair. The layer-0 WO of the order-only pair differs at 484 tokens with a median relative change of 7.26e-5. Nothing else differs between the two paths: the scale, page max, exp, sum and the running-state update are the same code for the AMX page and the software page [self_attention.hpp:1789-1826 and 2047-2075], the Q packing is a copy [amx_attn.cpp:230-234], and both kernels read the same stored bf16 K and V. So at the first differing record the rounding mode is the dominant mechanism and the AMX-against-AVX add order is a minor one.

[SVG]
Which path is closer to the exact result. Offline replay of layer-0 attention on the real logged Q, K, V of 201 tokens (replay results.md, M3) and the kernel test on random 64-token pages (ktest T7a, mass-weighted bias). The truncating AVX path is biased low by 0.08 % of the output on average over the 201 sampled tokens, rising from 0.07 % at 16 attended tokens to 0.15 % at 1,088, and up to 0.18 % at single tokens. The rounding-to-nearest path's mean bias is -0.002 %, 50 times smaller, and changes sign from token to token. The error against the exact output is 1.25 times larger with truncation on the fp32 attention output (2.00e-3 against 1.60e-3), 1.13 times on the bf16 output the next layer sees (2.57e-3 against 2.28e-3, because the bf16 store of the running state is common to both paths), and 1.8 times in the kernel test, which measures the rounding step alone on one page. The AMX arms sit in between because their partial pages still go through the truncating path.

The truncation removes 0.16 % of the softmax weight mass on average on real data (0.14 % on random pages). For a weight whose mantissa is uniformly placed the expected loss is 0.27 % (2^-8 x ln 2). The measured loss is smaller because the weights that carry most of the mass are the large ones, and the weight of the running-maximum token is exactly 1 and survives truncation (a hypothesis, not measured separately; in the binary the page max is taken against the running max, self_attention.hpp:1793-1794 and 2052-2053, so only the page holding the running max has a weight of exactly 1). [replay M3; ktest T7a]

5. Cause 3: one page per 64 decode steps takes a different path (PR 4959 only)

With the reader's order removed, poc and base still differ from decode token 1087 on. At layer 0 their WO records differ only at tokens 1087, 1151, 1215: the decode steps whose new token is the 64th of its page. The size of that difference (1.72e-3 median) is that of the rounding mechanism, not of an add order. Code reading attributes it to the path choice (citations in the records section): in that step main sees a complete, fully visible page and scores it on AMX (AMX order, rounded weights). The PR 4959 head stores the new row row-major into the page's last block and converts the block to VNNI only at the end of the forward pass, after attention ran. So the page fails the layout gate and goes through the software loop (reader + dotter, truncated weights) for that one step. From the next step on both score the page on AMX. The mechanism is documented in the code (self_attention.hpp:1905-1907, kv_cache.hpp:815-818). Its consequence, one page scored differently from main at every 64th decode step, is stated nowhere. By code reading (not measured at record level), PR 4957 and PR 4958 write every new row into the VNNI column at once (set_k_row scatters the row, kv_cache.hpp of the PR 4958 head b39765ec29:718), so the page is VNNI-complete at the page-end step and they should behave like main there. With the kill switch no arm uses AMX, so the asymmetry is absent there. The direct measurement of the path counters at decode steps 63 and 64 is in section 7.1.

6. From a one-ulp difference to a different token

Every difference spreads over the vocabulary quickly. At the logits of a later step a median 74.1 % to 81.6 % of the 151,936 vocabulary scores differ by at least one bf16 ulp between any two non-identical arms (never fewer than 0.0 %; 63.6 % at the first logged step of base vs new). The pair base vs poc shows that the spread needs no more than one forward pass: its first differing record is the layer-0 WO of token 1087, and 55.6 % of that same token's logits differ. The median mean |delta| over the vocabulary is 0.030 to 0.039 logit units for the add-order pairs and the rounding pairs alike, while single logits move by up to 5 to 12 logit units at a few steps. The rounding pairs move the logits somewhat more at the tail (p95 of the pair movement 0.5 to 0.625 logit units against 0.375 for the add-order pairs), but their flip counts are the same. So the logits carry no information about which cause produced them. Only the record-level first difference does.

7.3 Near-tie flip prediction

The flip rule "the top token changes when the margin plus the pair movement crosses zero" (ties to the lower token id) matches every observed flip by construction, since it uses the measured margin and movement of each step. It also confirms that the winning token is always one of the first arm's top two. The test of the model is its predictive form, which draws the movement independently of the margin from the pair's own measured movements (in ulps) and sums the flip probability over the 256 steps. On the earlier records (2026-10-13, 2026-08-30) it expected 0.76 to 1.54 flips per 256 steps per pair against 0 to 3 observed. On this campaign's eight non-identical pairs it reproduces every flip and expects 0.9 to 2.1 flips per pair, 12.4 in all. 9 were observed, and the probability of that many or fewer under the model is 0.18. The eight pairs share arms and the same three near-tie steps, so the sum counts correlated events. The independent evidence is three distinct near-tie steps (20, 84, 248) over one prompt, plus the 2026-08-30 prompt-2048 pair (3 flips at margins 0, 0 and 3 ulps). Source: exec/td-20261016/tiestats/tie_stats.md, section 2.

9. Verdict

Root cause (measured on one cell: qwen3-4b, tp2, prompt 1,024, CPU attention). The divergence has three mechanical causes, each isolated and measured:

three fp32 add orders (dotter, reader, AMX tile), which move a score by a median of one fp32 ulp (up to 2 bf16 ulps) and a bf16 output element at a quarter to a half of the tokens;

the truncation of the softmax weights in the AVX-512 PV path against round-to-nearest in the AMX PV kernel, which moves 20 to 30 % of the attention output elements (replay) and a third of the values of the logged WO record by one bf16 notch at every token that sees a dense page, and carries a systematic bias;

at the PR 4959 head only, a difference confined to the page-completing decode steps (layer-0 WO differs at tokens 1087, 1151, 1215 and nowhere else), which the code reading attributes to that step scoring its page in the software loop where main uses AMX.

Each of them changes about half of the logits in the forward pass of the first difference and about 80 % of them at the median later step. The greedy choice changes only at a near tie. This prompt has an exact tie at 0 to 4 of its 256 steps and a margin of at most 2 ulps at 10 to 11 of them, about one step in 25, and every observed flip sits at one of those steps.

Which causes a cell can have: the AMX kernels serve head size 128 with 4 query heads per KV head only. So on qwen-3-30b-a3b (8 query heads per KV head) only cause 1 exists, on gpt-oss-120b (64-dimension heads) none exists (the issue reports it identical), and on llama-3.1-8b (128 x 4) all three can.

Is it a real problem?

The add orders: no. All three are correct fp32 summations. The VNNI layout changes no number (pocoff equals baseoff bit for bit), and the same flips occur between any two orders.

The page-end path choice: not a defect. It is an asymmetry whose mechanism the code documents but whose consequence no comment states, and it prevents the stack from matching main bit for bit even after the reader order is matched.

The weight truncation: a pre-existing, systematic error of the AVX-512 path, measured here in the clean binary and under the kill switch, and by the code also the path taken on AMD hosts (the AMD fallback test of 2026-09-11; not run in this campaign). It costs a -0.08 % bias and a 1.13 to 1.8 times larger error than rounding to nearest. At the logits its effect is the same ulp-level spread as an add order, and no quality regression has been attributed to it. The cost of rounding to nearest in the AVX loop was not measured.

The kill-switch contract of Note [AMX attention dispatch]: broken exactly as the issue says. On VNNI K the switch gives an AMX-off run of the same binary, not the clean binary's numerics.

No kernel defect was found: every kernel this cell exercises (dotter, VNNI reader, the two AMX QK kernels, the AMX PV kernel) matches an exact-arithmetic model bit for bit on 512,000 scores and 102,400 to 1,024,000 outputs of random data on one Xeon 6962P. Sliding-window and softcap operation were not exercised. The design note token-divergence-issue4444-fix-design.html proposes what to change.

What would refute this: a record that differs between baseoff and pocoff or between clean and baseoff; a base-vs-poc difference at a token that is not the 64th of its page; a trunc-vs-newoff or new-vs-trunc difference before the first dense page; a flip whose margin exceeds the pair's largest movement. None occurred in this cell. The same checks apply to any other model or to the FPGA path.

Limits

One model (qwen3-4b), one prompt, one tensor-parallel setting, CPU attention. The FPGA attention path was not measured at record level. The forced run of 2026-10-13 under FPGA attention (the PR 4959 probe commit against main, prompt 1,024) shows the same picture at the logits as the CPU pairs: 0 of 256 steps identical, a median 80.1 % of the logits changed per step, flips at none [exec/results/p83-20261013/steps-fnew-vs-fbase.json]. The token identity in the issue's table for PR 4959 under FPGA attention is a token-level fact only. Under FPGA attention the PR 4959 head never converts a decode-completed block, so cause 3 cannot occur there.

The AMX add order was found by experiment on one Xeon 6962P. Intel's manual does not promise it across implementations.

The replay models the AMX kernels' internal order. Its numbers for the AMX arms are model numbers, validated against the logged WO records at the o_proj's own rounding floor.

The other observations in the issue (llama-3.1-8b token 46, qwen-3-30b-a3b token 5, the September cells) have no record-level data. The three-cause model names which causes each of those cells can have (section 9), but was not run on them.
