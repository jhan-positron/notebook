
Issue 4444 root cause
Issue #4444: the root cause of the token divergence, measured
Campaign td-20261016 on delphi-3bda, 2026-10-16. Written by Claude Code for jhan. Every number on this page comes from a file named in the section "Records"; the generator is exec/td-20261016/report/gen_report.py.
Short version
The tokens diverge because the three attention engines (the row-major AVX-512 dotter, the VNNI-K AVX-512 reader and the AMX tile kernels) add the same bf16 products in three different fp32 orders, and because the AVX-512 PV path truncates the softmax weights to bf16 while the AMX path rounds them to nearest; a greedy run then picks a different token only at a step where the two best candidates are within one or two bf16 ulps of each other. Each cause was isolated with a proof-of-concept binary and measured record for record: a stack binary with the reader's add order removed matches main bit for bit over all 1,024 prompt tokens and 63 decode steps, and exactly over the whole run under the kill switch; the one remaining difference is a path choice at every 64th decode step, verified in the code. No kernel defect was found; the one pre-existing accuracy problem is the AVX-512 truncation of the weights, which biases every attention output low by about 0.08 % and raises its error against an exact reference by 1.25 to 1.8 times.

1. What was asked and what was run
Issue #4444 asks for the cause of the token differences between the AMX/VNNI binaries and the row-major binary, with a measurement, and for a decision on the kill-switch contract. The earlier forced runs (2026-10-11, 2026-10-13) had shown that every flip sits at a near tie, but not which operation makes the scores differ, nor by how much, nor whether any of it is a defect.
Method: one cell (qwen3-4b, tp2, 1 user, prompt 1,024 tokens, 256 generated tokens, CPU attention, greedy, --pay-for-determinism), eight binaries or settings ("arms") run as forced runs with the full per-layer record kept (20.6 GB per run), then compared record for record and step for step. Two proof-of-concept binaries remove one cause each. Predictions were written before the runs (token-divergence-4444/predictions.md) and are scored in section 8. Kernel-level facts come from a standalone program that drives the real kernels on the machine; an offline replay on the real logged Q, K, V values gives the accuracy against an exact reference.

3. Cause 1: three fp32 add orders
[SVG]
How each engine sums the 128 products of one score. The products are identical (bf16 times bf16 is exact in fp32); only the grouping of the fp32 adds differs. The two AVX-512 orders were confirmed bit for bit against scalar models (512,000 scores each); the AMX order was found by experiment and confirmed bit for bit on both AMX kernels. Source: exec/td-20261016/ktest/results.txt, lines T0, T3, T4, T5m, T6d.
Kernel level (random data, 2,000 query groups x 64 tokens): the AMX kernel and the VNNI reader disagree on 253188 (49.451%) of the scores, by at most 2 bf16 ulps; the dotter and the AMX kernel on 50.1 %; the two AMX QK kernels (row-major K and VNNI K) agree bit for bit. The AMX PV kernel and the AVX-512 PV loop differ in 72.8 % of outputs even when both see the same bf16 weights, so the PV path has an order difference of its own. [ktest T1, T1b, T2, T6a, T6c]
Model level: the stack binary (reader on partial pages) and main (dotter on partial pages) first differ at prompt token 1 (token 1, WO layer 16), with a relative change of 2.57e-4: one fp32 ulp in a score moves one bf16 output element now and then. The layer-0 WO record differs at 352 of 1279 tokens (first at token 26), with a median relative change of 1.06e-4. The same seam appears in the kill-switch pair baseoff vs newoff, where the reader serves every page.
Proof by removal. The PoC binary poc unpacks every VNNI token row and scores it with the row-major dotter, so the reader never runs. Under the kill switch, pocoff equals baseoff in all 416,443 records and all 256 logit vectors: the VNNI layout itself changes nothing, and the add order of the reader is the whole difference between the two kill-switch arms. With AMX on, poc equals base for every record of the 1,024 prompt tokens and of decode tokens 1,024 to 1,086, and first differs at token 1087 (cause 3 below). Prediction P1 held for the add order; the residual is a separate, smaller cause.
The clean binary and main under the kill switch are bit-identical (0 differing records; 256 of 256 logit vectors identical), so the kill-switch contract of Note [AMX attention dispatch] holds exactly on row-major K. With VNNI K it does not: newoff differs from baseoff from prompt token 1 on, as the issue states.
4. Cause 2: the rounding of the softmax weights
The AVX-512 PV path truncates P to bf16 (interleave_bf16_ps keeps the high 16 bits of each fp32 weight); the AMX PV kernel rounds to nearest even (_mm512_cvtne2ps_pbh). Truncation always rounds toward zero, so the truncated weights sum to less than the exact ones while the divisor (the fp32 sum of the unrounded weights) does not shrink: the output is scaled down.
Model level: with AMX on, the first dense page is seen by prompt token 128 (the first query of the second prefill pass; a pass's own pages are never dense because the query mask holds one range per key of the pass). There new and newoff first differ (token 128, WO layer 0): 36.2 % of the record's values change, relative change 1.94e-3. From there the layer-0 WO differs at 1151 of 1279 tokens (every token from 128 on), median relative change 2.17e-3: about ten to twenty times the add-order seam. main under its own kill switch shows the same picture (baseoff vs base: same first record, same size), so this is the PR 3879 difference, not a stack difference.
Separating rounding from order. The PoC binary trunc truncates P inside the AMX kernel. new vs trunc (rounding only, same AMX order) reproduces the token-128 seam exactly (token 128, WO layer 0, 36.2 % of values). newoff vs trunc (order only: AMX order against AVX order, both truncated) first differs at token 128, WO layer 2 with a relative change of 2.31e-4; layers 0 and 1 of token 128 are bit-identical in that pair. The layer-0 WO of the order-only pair differs at 484 tokens with a median relative change of 7.26e-5. So at the seam the rounding mode is the dominant mechanism and the AMX-vs-AVX add order is a minor one.
[SVG]
Which path is closer to the truth. Offline replay of layer-0 attention on the real logged Q, K, V of 201 tokens (replay results.md, M3) and the kernel test on random 64-token pages (ktest T7a). The truncating AVX path is biased low by 0.08 % of the output on average (up to 0.18 % at single tokens) and its RMS error is 1.25 times (replay) to 1.8 times (kernel test) that of the rounding-to-nearest path, whose bias is zero within noise. The AMX arms sit in between because their partial pages still go through the truncating path.
The truncation removes 0.16 % of the softmax weight mass on average on real data (0.14 % on random pages; the theoretical mean for uniformly placed mantissas is 0.28 %, halved because the largest weight of every page is exactly 1 and survives truncation). [replay M3; ktest T7a]
5. Cause 3: one page per 64 decode steps takes a different path (PR 4959 only)
With the reader's order removed, poc and base still differ from decode token 1087 on. At layer 0 their WO records differ only at tokens 1087, 1151, 1215: the decode steps whose new token is the 64th of its page. Code reading (verified, citations in the records section): in that step main sees a complete, fully visible page and scores it on AMX (AMX order, rounded weights); the PR 4959 head stores the new row row-major into the page's last block and converts the block to VNNI only at the end of the forward pass, after attention ran, so the page fails the layout gate and goes through the software loop (reader + dotter, truncated weights) for that one step. From the next step on both score the page on AMX. PR 4957 and PR 4958 write every row into the VNNI column at once and behave like main here. With the kill switch no arm uses AMX, so the asymmetry is absent there. The direct measurement of the path counters at decode steps 63 and 64 is in section 7.
6. From a one-ulp seam to a different token
Whatever its size at the seam, every difference saturates within the forward pass: at the logits of every later step about 80 % of the 151,936 vocabulary scores differ by at least one bf16 ulp between any two non-identical arms, and the median mean |delta| over the vocabulary is the same 0.03 to 0.04 logit units for the add-order pairs and the rounding pairs alike. So the logits carry no information about which cause produced them; only the record-level seam does.

9. Verdict
Root cause. The divergence has three mechanical causes, each isolated and measured: (1) three fp32 add orders (dotter, reader, AMX tile), which move a score by one fp32 ulp and a bf16 output element now and then; (2) the truncation of the softmax weights in the AVX-512 PV path against round-to-nearest in the AMX PV kernel, which moves a third of the attention output elements by one bf16 notch at every dense page and carries a systematic bias; (3) at the PR 4959 head only, the page-completing decode step scores one page in the software loop where main uses AMX. Any of them saturates to ulp-level noise on 80 % of the logits within one forward pass, and the greedy choice changes only at a near tie, which this prompt offers at roughly one step in a hundred.
Is it a real problem? The add orders are not: all three are correct fp32 summations, the VNNI layout is numerically inert (pocoff equals baseoff bit for bit), and the same flips occur between any two orders. The page-end path choice is not a defect either, but it is a documented-nowhere asymmetry that costs the stack bit-identity with main even after the reader order is matched. The weight truncation is a real, pre-existing accuracy problem of the AVX-512 path (present in the clean binary, on AMD hosts and under the kill switch): a -0.08 % bias and a 1.25 to 1.8 times larger error than rounding to nearest, for no benefit. The kill-switch contract of Note [AMX attention dispatch] is broken exactly as the issue says: on VNNI K the switch gives an AMX-off run of the same binary, not the clean binary's numerics. The design note token-divergence-issue4444-fix-design.html proposes what to change.

Limits
One model (qwen3-4b), one prompt, one tensor-parallel setting, CPU attention. The FPGA attention path was not measured here (the issue's table shows PR 4959 identical to main under FPGA attention, which the row-major tail block explains).
The AMX add order was found by experiment on one Xeon 6962P; Intel's manual does not promise it across implementations.
The replay models the AMX kernels' internal order; its numbers for the AMX arms are model numbers, validated against the logged WO records at the o_proj's own rounding floor.
