Short version

PR 5015 turns the three AMX attention kernels of amx_attn.cpp (the query packer pack_q_group_128x4, the QK kernel qk_rowmajor_128x4 and the PV kernel weights_times_v_128x4) into function templates on group_heads, the number of query heads per KV head, and instantiates them for 4 and 16 heads. The one new piece of arithmetic is the transposing store of the QK kernel: a new helper store_transposed_rows writes the 4 score rows of one 128-bit lane, and the 16-head kernel calls it for lanes 1..3 as well as lane 0, so all 16 query rows reach the caller's s buffer. This page draws the buffers (B1), the functions (B2), the per-page instruction sequence (B3) and the transpose (B4) once, then each of the five logical changes of the file beside its diagram (section 2).

Words used here

AMX, tile
Intel Advanced Matrix Extensions: 8 tile registers, each configured here as 16 rows x 64 bytes (begin_region, amx_attn.cpp:116-124). _tile_loadd / _tile_stored move a tile from / to memory with a row stride in bytes; _tile_dpbf16ps (TDPBF16PS) adds the product of two bf16 tiles into an fp32 accumulator tile; _tile_zero clears one.
bf16, fp32
bfloat16, the 2-byte floating-point format of K, V and Q; fp32 = 32-bit float, the type of the scores, the exp rows and the output.
GQA, kv_mul, group_heads
Grouped-query attention: several query heads share one KV head. kv_mul is the model's ratio (the caller's geometry.kv_mul() / operation_kv_mul); group_heads is the kernels' template parameter that receives it. The PR serves 4 (llama-8b) and 16 (Muse Glimmer).
KV page
64 tokens of K and V for one layer (PAGE_TOKENS_64). The QK kernel reads the page's K plane, 64 rows of 128 bf16 (one row per token, 256 bytes); the PV kernel reads its packed V plane.
A operand, B operand
The two inputs of _tile_dpbf16ps. A is read row-major; B must be in the VNNI pair-interleaved layout (two consecutive values of a row stored next to each other). In QK, K is A and the packed Q is B (Note [QK orientation]); in PV, P is A and the packed V plane is B.
VNNI layout
Vector Neural Network Instructions layout: pairs of adjacent elements interleaved so that one 32-bit lane holds one pair. The packed Q (pack_q_group_128x4) and the V plane (Note [VNNI Packed V layout], v_vnni.hpp:31-46) use it.
panel, dim pair, step
The packed Q is 4 panels, one per 32-dim step of the 128-dim head (HEAD_SIZE_128 / DIM_STEP_32); a panel is 16 dim-pair rows x 16 columns x 2 values (amx_attn_iface.hpp:197-201). One tile load reads one panel.
S^T, s_transposed, s
The tiles produce the scores transposed, s_transposed[token][query] (64 x 16 fp32, inside the kernel); the transpose writes s[query][token] (group_heads rows of s_stride_floats, 64 token columns) into the caller's s_pages.
P, exp_rows, o
exp_rows = the caller's exp(s - max) rows (fp32); P = their bf16 bit patterns in a 16 x 64 thread_local scratch (the A operand of PV); o = the PV output, 16 rows x 128 fp32 (8192 bytes), of which rows 0..group_heads-1 are real (Note [Tile stores write 16 rows]).
512-bit register, 128-bit lane
An AVX-512 register (__m512) holds 16 fp32 values in four 128-bit lanes of 4 values each. The unpack intrinsics work inside each lane; _mm512_shuffle_f32x4 picks whole lanes from its two inputs with an 8-bit immediate selector (0x88 = lanes 0 and 2 of each input, 0xdd = lanes 1 and 3).
unpack stages 1 and 2
_mm512_unpacklo_ps / _mm512_unpackhi_ps interleave the 32-bit values of two rows; _mm512_unpacklo_pd / _mm512_unpackhi_pd interleave 64-bit pairs. Together they turn 4 tile rows into 4 registers u[row_group][0..3] (amx_attn.cpp:236-253).
function template, explicit instantiation, requires
template <size_t group_heads> makes one function body serve several compile-time group sizes; `requires(group_heads_ok(group_heads))` rejects any other size at compile time; `template void f<GROUP_HEADS_4>(...)` at the end of amx_attn.cpp compiles the body for that size so that other translation units can link to it.
thread_local static of a template
A function template's static locals exist once per specialization (amx_attn.cpp:279-283): the 4-head and the 16-head weights_times_v_128x4 each own a P scratch per thread.
Muse Glimmer, llama-8b
Muse Glimmer 30B: head size 128, 2 KV heads, 32 query heads, kv_mul 16 (the model the PR serves). llama-8b: head size 128, kv_mul 4 (the shape the kernels served before).
worked example
Muse Glimmer (16 heads), one dense page, KV head 0, the element query head 9, token 37: s_transposed[37][9] -> tile r = 2, row_group 1, u[1][1] lane 2 position 1 -> store_transposed_rows<2>, k = 1 -> s[9][37]; then P[9][37] and o[9][0..127].

The ordered steps for one page, each citing the line that does it: the pack (once per token, reused for every page), the 16 QK tile products, the 4 tile stores, the transpose (4 tiles x 4 row groups, then 1 or 4 lane stores), the caller's scale / max / exp step, the conversion of the group_heads exp rows into P, the 16 PV tile products and the 8 tile stores into o. AMX_ATTN-B4. Interaction model: the 16 x 16 transpose, from tile rows to 128-bit lanes to s rows

The heart of the change. One stored tile r holds 16 tokens x 16 columns (one column per query head). Stage 1 and 2 (the unpack loop) turn each 4-row group into four registers u[row_group][k] whose 128-bit lane L holds column 4L+k of the group's 4 tokens. Stages 3 and 4 (store_transposed_rows<lane>) gather lane `lane` of u[0..3][k] into one 16-token row and store it as s row 4*lane+k. The worked example follows query head 9, token 37 through the stages; transpose_sim.py computed and checked every mapping shown.
