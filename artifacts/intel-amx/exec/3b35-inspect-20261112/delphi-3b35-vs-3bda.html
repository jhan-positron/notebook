delphi-3b35 vs delphi-3bda

Read-only inspection, 2026-11-13 05:26 to 05:46 UTC. Both servers were under other users' load during the reads. No benchmark was run.

Short version. The two servers have the same CPUs, memory and AMX features, and SYSTEM_CONFIG="--instance 1,2" is the correct setting for the second half of delphi-3b35. Three settings differ and can lower tron speed on 3b35: TSX is off, the flat-frequency service is missing, and the deep idle states are on. All three need root to change, and the jhan account has no root rights on 3b35.

Words used here

  • tron: the inference program under test. runtron: its command-line tool. rinzler: the production server.
  • AMX: the Intel matrix instruction set that our attention kernels use.
  • TSX / RTM: Intel transactional memory instructions. tron uses them when a worker waits for work.
  • Flat-frequency service: the July 2026 fix on 3bda. It uses Intel Speed Select (SST) to let the tron cores run above 2700 MHz.
  • C6 / C6P: deep CPU idle states. A core needs 170 to 210 us to leave them.
  • Slice: one eighth of the machine in tron's resource map (1 FPGA card, 14 application CPUs, 1 driver CPU).
  • Instance "i,n": part i of n equal parts of the machine. "1,2" is the second of two halves.
  • Hugepage: a 1 GiB memory page. tron keeps model and KV data in files under /dev/hugepages.
  • NUMA node: one CPU socket with its own memory.

1. Is "--instance 1,2" correct?

Yes. It selects the four second-half cards, the socket-1 CPUs and hugepage files slice-4 to slice-7, the same as on 3bda.
  • tron reads the instance from SYSTEM_CONFIG and looks it up in resource-map.yaml [R1].
  • Both servers match the same map entry, granite_rapids_6962p [R1].
  • The map lists cards and CPUs per slice as fixed values. It does not scan the PCI bus, so a different card layout cannot move the mapping [R1].
  • A non-interactive ssh delphi-3b35 'echo $SYSTEM_CONFIG' already prints --instance 1,2 [R2].
  • The jhan account can open the four cards without root (device group positron) [R2].

State of delphi-3b35 at 05:45 UTC [R2][R3]. Box sizes are schematic.

  • 3b35 shows 7 FPGA cards, not 8. Card 3b:00.0 in the first half is absent [R2]. Hypothesis: a whole-machine run (--instance 0,1) fails on 3b35. One start attempt would confirm it.
  • Brian's server runs under the account disagg. Its allowed CPU list is 27-34,75-82, and CPUs 75-78 are our driver CPUs [R2]. Those threads used 0.0 % CPU in the sample.
  • The hugepage files of our half already exist under Brian's name. No running process maps them [R4]. tron would open, lock and resize them (read from source, not run). Ask Brian before the first run.

4. Working on 3b35: what changes for us

  • No root. sudo -n fails for jhan on 3b35. So perf counters, turbostat, intel-speed-select, the memory-lock raise and package installs do not work there. About 100 of our 462 campaign scripts call sudo [R8].
  • Not a CI machine, confirmed. No rinzler@N unit, no CI runner, no nightly timer, no lease file [R2].
  • Installed tron package is from 2026-08-17. It has no AMX kernels. Use our own builds only.
  • Missing tools: numactl, cpuid, rdmsr, intel-speed-select.
  • Launch guard (exec/lib-guard.sh, the script that refuses to start a campaign on a busy machine): it skips accounts with uid below 1000, so it cannot see Brian's server (uid 992). The load snapshot is the record of his activity.
  • Worktree trap. 98 tron worktrees are registered at 3bda-local paths. From 3b35 they look deletable. Never run git worktree prune. Create 3b35 worktrees under new names.

6. Requests for an administrator of 3b35

  • Add tsx=on to the boot arguments and reboot. The reboot also brings kernel 6.8.0-138.
  • Install and enable the flat-frequency service (intel-speed-select plus the state unit), as on 3bda.
  • Decide on C6/C6P: disable to match 3bda, or keep.
  • Grant jhan the read-only root commands we use: perf, turbostat, intel-speed-select, prlimit. Install numactl.

Insufficient data

  • Speed Select class per CPU on 3b35. Resolved by sudo intel-speed-select --cpu 0-287 core-power get-assoc.
  • Real frequency and power under an AMX run on 3b35. Resolved by sudo turbostat during a run.
  • Memory bandwidth on either server. Resolved by a STREAM-type run on an idle node.
  • Effect of BIOS 1.18 and microcode 0x1000423. Resolved by the same binary on both servers at equal load.
  • Speed of 7 of the 12 memory modules on socket 1 of 3b35. Resolved by sudo dmidecode -t memory.
