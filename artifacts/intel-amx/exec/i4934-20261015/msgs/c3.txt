attention: read the page's K block mask once per apply_page_range call

apply_page_range reads page::k_vnni_blocks once per page, before its
query loop, and passes the mask to apply_page_tok. The dense AMX gate
compares that mask instead of loading the page's state on every dense
visit, and the post-loop split of the live mask uses it too. The mask
is page state, not slot storage, so the read needs no relevant token,
and the bits cannot change during the call: save_k sets them before the
pending sections start, and the forward-end conversion runs after the
plugin joined every worker.

Why: with the AMX kernels off every (query, page) visit loaded the mask,
once per visit. A prefill visits every page once per query, so the read
ran about 1.2e9 times for an 8-user 8192-token prompt; now it runs once
per page per call. The dense gate loses the same per-visit load.

The two direct callers of apply_page_tok in t_llama_unit pass a mask of
zero: no token of their page is relevant, so it is never read. The
dispatch-dtype test records 48 rows in a new section, so a page with
three VNNI blocks and one row-major block must still take the software
loop.
