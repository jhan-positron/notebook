kv_cache: note_k_row_saved reports a block's completion once

note_k_row_saved returns true only for the call that sets the last of a
block's 16 row bits (with the block not converted yet). A row saved again
into a block that waits for its conversion returns false; it returned true
before. So the conversion queue of save_k holds every completed block
once, by construction.

Why: the forward end is about to convert the queued blocks in parallel,
one block per task. Two tasks on the same block would both pass the
"complete and not converted" check and transpose the block twice. A queue
without duplicates needs no sort at the forward end.

The page-state case records a block without converting it, saves one of
its rows again, and checks that the completion is reported once and the
block converts once.
