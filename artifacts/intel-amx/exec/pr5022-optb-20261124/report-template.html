Option B A/B test

tron PR 5022, rebased head 187da02163. Run on delphi-3b35 on 2026-11-25, 00:33 to 01:04 UTC.

Short version

Option B changes one declaration in tron's attention code. On delphi-3b35, a build with the change and a build without it produced the same tokens on two models, and all unit tests pass in both builds. Throughput differs by 0.16% at most, which is inside the run-to-run spread.

Words used here
  • tron: the inference program under test. runtron: its command-line tool.
  • AMX, AVX: CPU instruction sets. tron's AMX kernels score full 64-token blocks of the context. The AVX loop scores the other blocks.
  • kv_mul: the number of query heads per KV head. Muse Glimmer has 16, llama-3.1-8b has 4.
  • s_pages: the buffer that holds one block of attention scores, one row per query head.
  • The uninitialized tag: a constructor argument that skips the zero fill of a tensor.
  • Arm a: the head of PR 5022 unchanged. Arm b: the same commit with the option B declaration.
  • Cell: one model with one setting. Repetition: one run of a cell with one arm.
  • Decode speed: generated tokens per second per user, the mean over the 8 users of one run.
  • Prefill time: the time to read the prompt, in seconds, for the slowest of the 8 users.
  • sd: standard deviation over the 4 repetitions of one arm.
  • Band: twice the larger sd of the two arms. A difference inside the band is not told apart from the run-to-run spread.
  • K token: one context token scored for one query head. The exit report of a run counts K tokens per path (AMX, AVX).
  • tp4: one model instance on four FPGA cards. Fake device: a software stand-in for the cards, used by the unit tests.
  • delphi-3b35: the shared test machine with AMX. We use its second half: CPUs 96-143 and 223-230, and 4 FPGA cards.
  • Bugbot: the automated reviewer that flagged the current declaration.

What was compared

Both arms come from one commit and one build recipe. Arm b differs from arm a in 3 source lines [Ref1]:

-      tensor<operation_kv_mul, page::page_size> s_pages{uninitialized};
+      auto s_pages =
+          make_array_of<tensor<page::page_size>, operation_kv_mul>(uninitialized);

Arm a applies the tag to a two-dimensional tensor, which main's rule calls undefined [Ref7]. Arm b applies the tag to each one-dimensional row, which the rule allows.

Machine load

delphi-3b35 is shared. Other users run servers on the first half (socket 0). A load snapshot of 10 seconds was taken before every run, and a run starts only when our 4 FPGA cards are closed and our CPUs are at most 5% busy [Ref5].

Measure before the 16 throughput runsLowestHighestMeaning

In the snapshot before the first Glimmer throughput run, 3 rinzler servers (tron's production server program) of the user disagg had 61 busy threads, all on the first half. Our 4 cards were closed before every run, and all 256 huge pages of 1 GiB on our memory node were free.

What this test does not cover

  • Option A. The default-constructed s_pages with its zero fill was not an arm. Both arms skip the fill, so this test does not measure the cost of the fill.
  • Other sizes. One prompt length (1024 tokens) ran, with 8 users for throughput and 1 user for identity.
  • Comparison with the PR description. The PR's published numbers come from another machine, delphi-3bda. The numbers here compare the two arms with each other.
  • Log level. Both arms ran with debug logging on, as the earlier runs on this machine did.
  • CI. Arm b is not committed or pushed. Its binary reports the version 2026.11.25-187da021-dirty.
