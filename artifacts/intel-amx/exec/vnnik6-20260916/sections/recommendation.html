7.1 Why the 2026-09-15 run showed a loss

The one-run cell of 2026-09-15 compared runtron.p0perf13 (commit 544ca05c7a, the PR's base at that time) with runtron.vnnik4 (commit dc950be5f2, the PR head of that time). It measured 36.28 TPS per user for the base and 34.31 TPS per user for the VNNI binary [exec/results/vnnik4-models-20260915/results.txt, cell=qwen30b]. Today's main binary (c7844ca2ce) measures 34.26 TPS per user with a sample standard deviation of 0.66 TPS over 6 repetitions at the same cell. Today's VNNI binary measures 34.79 TPS per user with a sample standard deviation of 0.86 TPS over the same 6 repetitions. So the VNNI binary runs at the same speed as on 2026-09-15. The base moved from 36.28 to 34.26 TPS per user (-2.0 TPS, -5.6%).

Two explanations were open before the extra cell of section 7.3 ran:

  • The code between 544ca05c7a and c7844ca2ce changed the decode speed of this model. That range holds 149 commits from 26 merged pull requests. Two of them change the KV cache. PR #3054 introduces per-layer KV arenas (an arena = one memory region reserved once, from which the cache takes its KV pages). PR #3067 reclaims out-of-window sliding KV under memory pressure (sliding-window attention lets a query see only the most recent tokens, and this change frees the KV pages of tokens that have left that window when memory runs short).
  • The 2026-09-15 base run was a favourable single sample.

The extra cell measured both binaries interleaved, 6 repetitions each, at the same cell (section 7.3). The old base runs at 34.96 TPS per user (standard deviation 1.35) and main at 33.92 (standard deviation 0.69). Main is slower by 1.04 TPS (paired t -1.6, not resolved with 6 repetitions). So the 36.28 TPS of the 2026-09-15 run sits about one standard deviation above the old base's own mean: it was a high single sample. A small slowdown of main (about 1 TPS, 3%) may add to it. The measurement that would resolve the second part: the same two binaries with 12 or more repetitions.

The PR's open item was based on a comparison of two different code heads, one run each, under different background load (1-minute load average 12.5 against 16.2 at run start). The interleaved repetitions of this campaign against the exact merge base remove all three differences: the code difference (every binary is compared with its exact merge base), the load difference (the binaries run one after another inside each repetition), and the single run (every cell is repeated, section 3.2).
