Ordering rules the patch must keep

  • forward_scope is declared before with_latch_arena [model.hpp:1658]. Its destructor therefore runs after the arena release [threading.hpp:262-266].
  • begin_forward (stores the class, resets the scratch) runs before assemble_attention_plan_impl. Two hooks depend on that order. note_attn_workers files under the current class, and note_fpga_query writes fpga_bits sized by begin_forward [attn_stats.hpp:357-365, :467-472; llama.hpp:596].
  • The fold in the destructor reads final bits. No stats hook runs after the plugin's run returns. The hook calls are model.hpp :1745, :1750, :2730-2735 and self_attention.hpp :629-636, :855, :1315, :1649-1653 (plus full.hpp:2100 for T1, which the patch deletes); llama.hpp has none. run_logits waits for every listener callback [model.hpp:3303].
  • begin_forward resets the split to "unknown". A forward without attention work makes no assemble_attention_plan call [model.hpp:1714-1716]. Such a forward, and every unit test, therefore folds all rows.
  • The W1 stretch never opens when join_hw is true. The !join_hw && short-circuit at :1258 prevents it. So the software poll and stream_hw_joins add to one accumulator without double counting. When join_hw is true, the if (poll_waiting) test still runs once per head iteration: one test of a stack bool that is always false.
  • The off-state value of stats_worker never reaches a hook. It is read only under stats_enabled [self_attention.hpp:1451-1456, :1649-1653]. The W4 asserts in pool_worker replace the guards the W5 sketch relied on.

What does not interact

  • W1 and W3-E touch no common line.
  • W1 and W5 touch run_joins at different lines (:1256-1259 and :1315).
  • W2 and W4 meet only in the test fixture.
  • W3-E and W5-D both add keys to the forwards leaf, and both parsers ignore added keys.

The one true conflict is the W3 per-job split against the W5 row layout and the parsers. That is why the split is the follow-up. The W5 layout keeps the FPGA counters in their own struct, so the follow-up only changes the class index of the visit rows and the FPGA counters.

One verification pass for the whole set

  1. claude-box (the build container): nix build of t_llama_unit, t_amx_dispatch_dtype and t_heterogeneous_scheduler. Run each with TRON_ATTN_STATS unset and set to 1. Run exec/attnstats-20260924/objdump-check.sh on the off-state binary (apply_page_range size and lock-prefix count).
  2. 3bda, our half (socket 1 and its cards): one CPU-attention run of the 2026-09-24 cell (qwen-3-4b tp2, 8 users, prompt 1024, USE_HW_ATTN=0, switch on) and one FPGA cell. These two runs do three things. They regenerate every PR-body sample that the patch makes stale: T5 at 0, the worker leaves and _w0 keys, T1 without the fold, and the new forwards keys. They check forwards and token_jobs against attnstats-20260924b. They give the first software-join-wait number.
  3. 3bda: one A/A at the final head (switch unset and set, prompt 1024 and 8192, 3 repetitions). It covers the on-state cost of all five changes at once. There is no per-change A/A.
  4. Docs pass as listed above, then the replies on the five threads.
