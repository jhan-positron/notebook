ingest: the main helpers call save_k at the attention statement

The code generator (ingest/src/TronCpp.hs, the Haskell program that
emits the generated model plugins) makes the main helpers (the threads
of a generated plugin that run the per-token kernels) take part in the
K store (K = the attention keys, KV = keys and values). For an attention
statement whose operation writes KV, runHelperStatement (the function
that emits the helpers' statements) emits a save_k call. The call passes
the helper's worker_ix and the worker count n_workers of run_main_help
(the generated helper function). It sits at the position of the
statement list at which main calls save_k. submitAttentionOperation
passes worker index 0 and n_workers for main's call. An operation
without a KV write emits nothing on the helper side. So the N-th window
(one shared store) a helper enters in a pass (one forward computation of
the model) is the N-th window main opens in that pass (Note [Shared
block save] in h/tron/models/model.hpp). Both calls spell worker_ix and
n_workers as variables (Var), as the kernel calls do.

LoopyTronSpec (ingest/test/LoopyTronSpec.hs, the code generator's test
suite) has two specs that count the attention calls. Both check that a
KV-writing operation emits two save_k calls. Both check that the call
texts end in ",0,n_workers);" on the main side and
",worker_ix,n_workers);" on the helper side.
