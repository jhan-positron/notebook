tensor: the 16-token block store of the VNNI K plane

store_block (h/tron/tensor/k_vnni.hpp) stores the K rows (K = the
attention keys, one row per token) of up to 16 tokens of one 16-token
block of a packed K plane (K stored in the VNNI layout, VNNI = Vector
Neural Network Instructions, the pair-interleaved layout of
h/tron/tensor/k_vnni.hpp) with whole-line stores. For each of the 4
dimension steps (32 dimensions each) it loads one 64-byte line per
present row. It transposes the 16 registers in place
(transpose_16x16_epi32: four stages of two-register shuffles, 64
shuffles in all). It writes each of the panel's 16 dimension-pair rows
as one 64-byte store (a panel is 16 pair rows x 16 tokens, 1 KiB). A
16-bit mask `present` says which tokens of the block have a row. A
partial block uses masked stores. The slots of absent tokens are not
written. The result equals store_row (the per-token scatter store) per
present token bit for bit. Only the write pattern differs: a full block
issues 64 whole-line stores instead of 64 scatters that each write 4
bytes into 16 lines. The block index is checked against the plane's
block count, as store_row checks its token index. Two constants name
the full mask (FULL_BLOCK_0XFFFF) and the 32-bit lane count of one
512-bit register (LANES_16). One static_assert ties the block size and
the step size to the lane count. The static_assert that checks every
constant's name against its value gains LANES_16.

A page is a 64-token unit of the K and V caches (KV = key and value).
page::set_k_block (h/tron/models/kv_cache.hpp) is the page accessor for
VNNI slots (KV slots whose K planes hold the VNNI layout). It checks the
block index against the page size and calls store_block on the typed
view. Note [K VNNI storage] item 1 describes the two store paths of
save_k (the function of model.hpp that stores the K rows of a pass, one
forward computation of the model): the block save for a run of 2 to 16
consecutive tokens of one block, and the per-token scatter
(page::set_k_row) for a run of one token, as in every decode step. It
also says that a pass of more than 16 tokens may share the store with
the idle main helper threads (Note [Shared block save] in model.hpp).
The main helpers are the threads of a generated plugin that run the
per-token kernels. A generated plugin is the model code that the code
generator emits. The typed-operations lists name store_block.

t_k_vnni_layout gains the case "VNNI K block save equals the per-token
row store, bit for bit". For each of the 4 blocks and 38 masks (14 fixed
masks: full, empty, single tokens, halves, alternating lanes, mixed
patterns, plus 24 random masks) it stores the same rows with store_row
and with store_block into two planes filled with a poison pattern, and
compares the planes bit for bit. The poison outside the block proves
that the block save touches no other block.
