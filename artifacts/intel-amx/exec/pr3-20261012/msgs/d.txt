tests: the save_k case reads the helpers' finished count as the main
call returns

The three-thread section of the t_llama_unit case "save_k stores every
token's K row once, grouped by page block, alone or with helper
threads" joined its helper threads before it checked the window
counters. A production join (the main thread's wait in save_k_impl for
every helper to finish the window) that returned early would therefore
have gone unnoticed: the test's own joins completed the stores before
the checks ran.

Now the section reads the window's finished count as the main thread's
save_k call returns, before it joins its threads, and requires that
count to be n_workers - 1 under the option TRON_K_VNNI (0 with the
option off, where no window opens). The last helper starts 20 ms late,
so the main thread's join has to wait for it. A removed production join
then returns with one helper unfinished, and the check fails.
