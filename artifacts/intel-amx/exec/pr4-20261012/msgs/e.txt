tests: the forward converts the block its decode step completes

Words used here. The forward is model::state::forward (h/tron/models/
model.hpp), one pass of the model. A K block is a 16-token block of the
attention-key cache (Note [K VNNI storage] in h/tron/models/
kv_cache.hpp). The VNNI layout is the packed layout the AMX kernel
reads. save_k is the K store of one pass. t_heterogeneous_scheduler is
the test binary of t/heterogeneous_scheduler_compile.cpp, whose fixture
runs the forward on a fake device with a plugin that stores no K.

The forward calls convert_pending_k_blocks after its run joined the
workers and the staging drained. The save_k cases of t_llama_unit call
that conversion themselves, so no test reached the call through the
forward (codex's review of PR #4901, tron-code-review).

The fixture's plugin gains an optional K store of its middle operation
(the 128-dimension slot, the one VNNI slot of the fixture) through
save_k, at the point of the schedule where a generated plugin's run
stores K. The row of token job j holds the value j + 1 in every
dimension.

The new case runs two forwards on one page. The first stores rows 0 to
14 of block 0 as fifteen token jobs: a run shorter than a block, stored
row-major. The second stores row 15 as one token job. The fixture's
plugin forces hardware attention. The case's first section uses a
variant that does not, so with USE_HW_ATTN unset the operation is
software-scored (the variable is read once per process, so a case
cannot set it). The second forward then returns with block 0 converted
(option on) and every row readable with its stored value. With the
hardware-scored default the block stays row-major. Removing the
forward's conversion call fails the first section's block check. With
the option off, no block converts and the rows read back the same.
