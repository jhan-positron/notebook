Short version

Mirror adds a prepared copy of K when K is stored. That removes the baseline’s score transpose during attention. Both paths normalize the output after combining the partial results. [1] [2] [6]

Exact running-state equations and model options

All equations apply separately to each query head. U is the running weighted-value vector. Z is the running weight sum. m is the largest score seen by that worker. A “head” is one attention group within the model.

Process one page

x = αS
mnew = max(m, max(x))
P = exp(x − mnew)
Zpage = ΣP
Opage = bf16(P) · V
r = exp(m − mnew)
U ← rU + Opage
Z ← rZ + Zpage
m ← mnew

For the first page, initialize U = Opage, Z = Zpage, and m = max(x). The code uses this initialization directly. [3] [5]

Combine valid worker states

M = maxi(mi)
U = Σi exp(mi − M) Ui
Z = Σi exp(mi − M) Zi
output = U / Z

i indexes the workers’ valid partial states. M is their common largest score. These formulas describe the rescaling used by the pairwise merge. [6]

If the model has an attention sink, apply it before the final division as described below.

  • Scale and softcap. α is the configured attention scale. Its default is 1/√d, where d is the key vector length. With a configured softcap c, use x = c · tanh(αS/c). This smoothly limits the score magnitude. [3]
  • Precision. The kernel rounds P to bf16 using round-to-nearest-even, a rule that chooses the nearest representable value and breaks ties toward an even last bit. It accumulates the matrix products in fp32 (32-bit floating point). Zpage comes from the fp32 weights before their conversion. [3] [4]
  • Optional attention sink. This is an extra softmax score with a zero value vector. For sink score b, set M′ = max(M, b). Replace U with exp(M − M′)U. Replace Z with exp(M − M′)Z + exp(b − M′). Then divide U by Z. [6]
  • Other K writes. Moving a stored cache page also rebuilds its K* copy. The “when generating K” note shows the usual write, rather than every maintenance path. [1]
Words used here
AMX
Intel Advanced Matrix Extensions, a CPU instruction set for matrix multiplication.
Baseline
The compared AMX implementation that reads the original K layout and transposes its score result.
Mirror / K*
An additional transposed and interleaved copy of K, prepared for the right-hand AMX input. The original K remains stored.
Interleaved
Adjacent key components are placed together in memory in the order required by the matrix instruction.
Softmax
A calculation that turns scores into weights whose total is one. This implementation defers the division until the final weighted output.
KV page
A 64-token block of stored keys and values.
Worker
A CPU worker processing an assigned range of cache pages.
Cache hot
The freshly stored source K row is already in the CPU cache. This note does not establish that every K* destination is cached.
Softcap / attention sink
Optional model settings. A softcap limits score magnitudes. An attention sink adds an extra score with a zero value vector.
bf16 / fp32
The 16-bit input format and 32-bit accumulation format used here.
tron
The inference program under test. The source snapshot below contains both compared AMX implementations.
