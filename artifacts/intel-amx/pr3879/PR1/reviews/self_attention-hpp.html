self_attention.hpp: the moved position block and lines 1601-1619 do not depend on each other

PR #3879, file h/tron/models/self_attention.hpp. Base = merge base with main, commit a80b102c18. Head = origin/jhan-amx-p0 at 69031c201d (2026-09-09). "L" numbers are base-side lines, "R" numbers are head-side lines, as in the GitHub diff view.

Short version

The moved block (L1386-1408, now R1559-1580) computes five values from the function's parameters and reads nothing else. Lines R1601-1619 set up the score array and the four dot-product objects from the query and reads nothing else. A script that intersects the identifiers of the two blocks finds no shared variable, and both blocks are free of side effects, so running them in either order gives the same values to the loop that consumes both.

3. Why the order cannot matter: no shared variables

Two adjacent blocks can be swapped without changing any value when (a) neither reads a variable the other writes, and (b) neither has a side effect the other observes. The table lists what each block reads and writes, from the code [head R1559-1580 and R1601-1619].

5. The AMX gate between them changes control flow, not values

In the head, the gate sits between A and B [R1581-1600]. Two cases:

  • Gate takes the AMX path (packed Q present, page dense). The function returns before B. B's outputs are then not needed by anyone: the dotter loop and the epilogue that consumed them are skipped too. B has no side effects to miss.
  • Gate falls through (the only case when TRON_AMX_DISPATCH is off, when the executor is not eligible, when AMX is unavailable or disabled, or when the page is not dense). B then runs with the same inputs as in the base (q, kv_head), the loop runs with the same begin, end, q_position, k_position, query_visible, and the rest of the function is textually identical to the base [head R1620-1679 vs base L1409-1469].

The gate reads A's five values [R1593-1594]; that is the reason for the move. Had A stayed below B, the gate would have had no begin/end/query_visible to test, and B's dotter construction would have run for pages that then take the AMX path and never use a dotter.

6. Scoping check

Block A's five variables moved from the inner brace scope to function scope. That widens their visibility to the AMX gate (intended) and to the epilogue after the loop. The epilogue [R1643-1679] does not name any of them, and no other declaration of begin, end, q_position, k_position or query_visible exists in the function, so nothing is shadowed or captured differently. query_visible is reassigned inside the loop [R1625] exactly as in the base [L1414].
