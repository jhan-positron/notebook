The page-share counters (instrumentation that counts how many query tokens visit each KV page; default off) are PR 0 (separate, based on `main`); the K mirror is a stacked reference draft (PR 2); a one-line fix Ben found in passing is PR 0b. ## Short version

(Terms are defined in the next section.) An optional AMX fast path for software attention. For a dense 64-token KV page of a model with head size 128 and 4 query heads per KV head, on an executor that stores activations as bf16, the query-key scores and the weights-times-values product are computed with tile multiplies when AMX is available at run time. Every other page, model shape or activation type runs the existing AVX-512 loop. That loop's arithmetic is unchanged. The per-page setup both paths need now runs once, before the dispatch. K and V stay in their existing storage; the change adds no persistent copy of either. Build option `TRON_AMX_DISPATCH`, default OFF; runtime switch `TRON_AMX_DISABLE=1` (contract: AMX off, same layout, same AVX dotter, the numerics of a build without the option; `doc/amx_software_attention.md`).

## Words used here

- **tron / rinzler / runtron**: tron is the inference program; rinzler is its server, built from tron; runtron is its command-line tool.
- **AMX**: Intel Advanced Matrix Extensions, the tile-matrix instruction set of Sapphire Rapids and later Xeons. The measurement host is a Granite Rapids Xeon 6962P; the continuous-integration (CI) runners with AMX are Granite Rapids 6960P and 6962P machines.
- **AVX-512, the dotter**: the vector instruction set and the existing attention loop that uses it.
- **canonical**: the AMX path that reads K as it is stored (this PR). The K mirror variant, which keeps a second copy of K in the layout the tile multiply consumes, is PR 2.
- **Q, K, V; QK; PV**: query, key and value tensors; the query-key score product; the product of the softmax weights with V.
- **bf16, fp16, fp32**: bf16 (bfloat16) is the 2-byte floating-point format K, V and (for eligible executors) Q are stored in; fp16 is the 2-byte IEEE half-precision format; fp32 is the 4-byte format the sums are accumulated in. An **executor** is the model's storage and arithmetic type set (host = float, host_bf16, host_fp16).
- **KV page**: 64 tokens of K and V. **kv_mul**: query heads per KV head (grouped-query attention); the kernels serve kv_mul 4 with head size 128, hence the namespace `amx_attn_h128g4` and the `_128x4` suffix.
- **dense page**: a page whose 64 tokens are all active, visible to the query in one range, and inside the query's sliding window. Only dense pages take the AMX path.
- **tp2 / tp4**: tensor parallelism over two or four FPGA (field-programmable gate array) cards. **MMLU Pro**: a multiple-choice accuracy benchmark. **TTFT**: time to first token.

## What changed, by commit

1. **Kernels + interface + contract document** (`src/tron/kernels/amx_attn.cpp`, `h/tron/kernels/amx_attn_iface.hpp`, `doc/amx_software_attention.md`): the query packer, the row-major QK kernel `qk_rowmajor_128x4` (K as stored is the A operand, packed Q the B operand, the result transposed on the way out: Note [QK orientation]) and `weights_times_v_128x4`; a typed `tron::bf16` interface; the kernel bodies live in one translation unit (one .cpp file compiled on its own; the build rule that gives it the AMX flags is commit 3); the runtime switch and its contract documented.
2. **Dispatch integration** (`h/tron/models/self_attention.hpp`, `h/tron/models/kv_cache.hpp`): `is_dense_amx_page` (the predicate), `try_apply_dense_amx_page` (QK, the same scale/max/exp step as the dotter's epilogue (the step after its dot products), PV, the accumulator update, in one function that returns whether it ran) and `packed_amx_query` (at most one pack per token per call, done after the outer visibility and window checks and before the dense predicate); the raw V accessors `page::v_data` / `kv_block::v_base`. The dotter loop and its arithmetic are unchanged; the begin/end/position/visibility prologue it used moved above the dispatch so both paths share it.
3. **Build option + CI flag** (`CMakeLists.txt`, `src/tron/CMakeLists.txt`, `.github/workflows/cmake-single-platform.yml`, `README.ci.md`): `option(TRON_AMX_DISPATCH)` in the top-level `CMakeLists.txt`; when ON, `src/tron/CMakeLists.txt` adds the kernel source with the AMX compiler flags on that one file only. The CMake CI lane configures with the option ON, so the kernels and the dispatch compile whenever that lane's build step runs (a cached build artifact can skip it). The kernel cases of `t_amx_numerics` execute tile instructions only when the runtime check `available()` passes (an AMX CPU with OS tile support, in practice a Granite Rapids runner); elsewhere they print a warning and return. The workflow does not require a real-AMX execution for every candidate tip; that remains open (issue #3997).
4. **Tests** (`t/CMakeLists.txt`, `t/t_amx_numerics.cpp`, `t/t_amx_dispatch_dtype.cpp`, `t/t_llama_unit.cpp`, `config/test-benchmarks.json`): `t_amx_numerics` (the compile-time eligibility gate over the executors' activation scalars and the shape; packer layout compared bit for bit; QK against the AVX dotter within the fp32 add-order envelope; PV within the round-to-nearest versus truncation envelope), `t_amx_dispatch_dtype` (the production dispatch with CPU fakes, stand-in definitions of every kernel entry point that record their calls and run no AMX instruction: a bf16 executor packs once and calls QK and PV once for a full page; a 63-token page packs but calls neither kernel; float and fp16 executors never reach the fakes). `t/t_llama_unit.cpp` only swaps a literal 2 for the new named constant `kv_block_planes`; the eligibility case the original PR added there was dropped, because the first case of `t_amx_numerics` checks the same predicate.

Why these tests: the numerics test fails at compile time if the eligibility gate admits a float or fp16 activation scalar or a shape other than head 128 with 4 query heads per KV head, and at run time if the packer misplaces a value or if a kernel's result leaves the error envelope its inputs allow (fp32 add order for QK, the weight rounding mode for PV), which is the contract the dispatch relies on. The dispatch test fails if the type gate lets a float or fp16 executor reach the packer or if the dense predicate lets its 63-token page reach the kernels; it checks call counts and the captured query values, not attention outputs. The two tests protect different boundaries; both are cheap host tests, and the kernel cases need an AMX host.

## Verification of this tip

Built and tested on 2026-09-07 on delphi-3bda (Intel Xeon 6962P, a Granite Rapids CPU) from commit 9723d56f62 in a clean worktree (this PR's tip fcc78573b0 differs from it only in the cost-data file `config/test-benchmarks.json`, which no test reads), CMake preset `cross-avx512` (with `-DBUILD_INGEST_MODELS=OFF`, which only skips the ingest models), once with `-DTRON_AMX_DISPATCH=ON` and once with `-DTRON_AMX_DISPATCH=OFF` (the option's default value). In both configurations the three test targets and the `tron` library they link compiled. The whole pre-split tree rebased onto the same base (the reference the split is checked against) passed the same three tests with the option ON on 2026-09-06. clang-format-19 (the repository's formatter) leaves the files of this PR unchanged. The cost-data entries for `t_amx_numerics` and `t_amx_dispatch_dtype`, which CI's "Check slice cost data" step requires, were measured on the same host with `bin/slice bench --update` (0.737 / 0.758 / 0.788 s and 8 MB, and 0.778 / 0.775 / 0.873 s and 9 / 9 / 11 MB, at the 1-, 2- and 4-slot placements) and are part of commit 4.
