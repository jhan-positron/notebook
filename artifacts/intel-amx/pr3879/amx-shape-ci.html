delphi-3bda nightly CI · attention geometry check · 2026-09-18

Which nightly-CI models have the 128 × 4 attention shape that the AMX kernel serves?

Words used here: AMX is Intel Advanced Matrix Extensions, the tile-matrix instruction set on the Granite Rapids CPU in delphi-3bda. tron is the inference program under test. Head size is the number of values in one attention head (128 here). kv_mul is the number of query heads that share one KV (key/value) head, also called the GQA ratio. The full glossary is at the end.

Short version

The nightly CI on delphi-3bda runs 12 performance configurations that cover 9 distinct base models. Three of those base models have head size 128 and kv_mul 4, the only shape tron's AMX attention kernel serves: llama-3.1-8b-instruct-good, mixtral-8x7b-instruct-v0.1, and ingested-qwen-3-4b-instruct-2507. Because qwen-3-4b runs at both tp2 and tp4, those three models account for 4 of the 12 CI runs.

Reading of the question: "KV head size = 12" is taken as head size 128, which is the kernel's constant HEAD_SIZE_128. No CI model has a head size of 12.

What "fits the shape" does and does not mean

  • It means the geometry gate passes. The gate is shape_ok(head_size, kv_mul) = head_size == 128 && kv_mul == 4, evaluated per attention kernel geometry [h/tron/kernels/amx_attn_iface.hpp:148-150; h/tron/models/self_attention.hpp, the eligible<…>(geometry.kv.head_size, geometry.kv_mul()) call].
  • It does not mean the nightly CI exercises the AMX path today. The dispatch is behind the CMake option TRON_AMX_DISPATCH, default OFF [tron origin/main CMakeLists.txt:48]. The AMX branch (PR #3879) merged into tron main on 2026-09-15 (commit 3fd5edaa66) and the installed package commit 3faba6d0 contains it, but the deb preset that builds the package does not set the option [GNUmakefile:510; CMakePresets.json presets deb and base-ninja]. Only the unit-test workflow turns it on [.github/workflows/cmake-single-platform.yml:355]. Measured on delphi-3bda on 2026-09-18: the installed package tron 2026.09.18-3faba6d0 has 0 occurrences of the string TRON_AMX_DISABLE and 0 of amx_attn in /opt/positron/bin/rinzler, while the sibling kill switch TRON_NO_RTM appears 2 times (the control that shows the probe works). So the CI binary has the AMX kernel compiled out.
  • Executor type also matters, and all 12 runs pass it. The AMX query packer reads Q as bf16, so only executors that store activations as bf16 are eligible. tp2, tp4, perm_tp2, and perm_tp4 all do [amx_attn_iface.hpp:152-159; h/tron/models/common.hpp:92-96].
  • Even when on, AMX handles only dense pages. A page is a 64-token block of the KV cache. A (query, page) pair goes to AMX only if the whole page is visible to the query and inside the sliding window. The partial tail page of every query still runs the AVX-512 dotter [amx_attn_iface.hpp:19-31].
  • Hardware attention takes work away from the AMX path for one of the three fitting models. tron can run attention on the FPGA instead of in software, and the AMX gate lives only in the software path. The generated plugins for qwen-3-4b, gpt-oss-120b, and gemma-4-31b set force_hw_attn = true, so hardware attention is on for them by default unless the launch sets USE_HW_ATTN=0; KV positions from index 127 onward go to the FPGA and only the software-computed remainder could use AMX [gen/src/tron/h/tron/plugins/qwen_3_4b_instruct_2507.hpp:41; h/tron/models/model.hpp model_forces_hw_attn; src/tron/models/hw_attn_config.cpp; h/libpos.hpp:90]. The hand-written llama-3.1-8b and mixtral-8x7b plugins do not set it, so their attention stays in software unless USE_HW_ATTN is set on the DUT. Insufficient data on what platformd sets on delphi-3bda: the launch environment of the rinzler process would resolve it.
  • gemma-4-31b is out on both geometries. Its sliding-window layers are head 256 with kv_mul 2, and its global layers are head 512 with kv_mul 8 [gen/src/tron/h/tron/plugins/gemma_4_31b_it.hpp attention_kernels].
  • Why "12" and not "11". scripts/perf.py has 12 configs and the Granite Rapids goal.tps table in scripts/system_ci.py has 12 keys. The YAML threshold file thresholds/system_ci_perf.yaml lists only 11 for this platform; gemma-4-31b has no threshold row there yet.

Words used here

AMX
Intel Advanced Matrix Extensions, the tile-matrix instruction set on Granite Rapids CPUs. tron's AMX kernel multiplies 16-row × 64-byte tiles of bf16 values.
bf16
bfloat16, the 2-byte floating-point format tron stores K, V, and (on eligible executors) Q in.
head size
The number of values in one attention head. tron calls it head_size; HuggingFace configs call it head_dim.
KV head
One key/value head of the attention cache. Several query heads can share one KV head.
kv_mul, GQA
Query heads per KV head (grouped-query attention ratio). tron computes it as n_heads / n_kv_heads.
128 × 4
Head size 128 and kv_mul 4. One query group is then 4 heads × 128 values = 512 bf16 = 1024 bytes, the operand shape the kernel amx_attn_h128g4 is written for.
tron
The inference program under test. It compiles one plugin per model with fixed geometry constants.
plugin
tron's compile-time description of one model: hand-written lines in h/tron/plugins/llama.hpp (the TRON_LLAMA_CONFIG macro) or a generated header under gen/src/tron/h/tron/plugins/.
ingested model
A model whose plugin was generated by tron's ingest pipeline from a traced HuggingFace model (gpt-oss-120b, qwen-3-4b, gemma-4-31b here).
executor: tp2, tp4, perm_tp2, perm_tp4
How tron spreads a model over accelerator devices. tpN uses N devices. The perm_ variants consume GPTQ weights with desc_act=true (permuted columns). All four store activations as bf16.
nightly CI
GitHub workflow "System CI (Rinzler 72-core Intel system OCI version)", cron 03:30 UTC daily, DUT delphi-3bda, platform type granite_rapids_72_rinzler.
rinzler
The production inference server that the CI drives.
KV page
A 64-token block of the key/value cache. "Dense" means the whole page is visible to the query.
AVX-512 dotter
The existing vector-instruction attention loop that every non-AMX case uses.

How this was checked

The numbers were read twice: once directly from the tron sources and HuggingFace configs, and once by 9 independent agents, one per base model, each followed by a skeptic agent instructed to refute the verdict, then by a completeness critic. 8 of the 9 skeptic checks confirmed the table above. The llama-3.3-70b pair recorded 64 query heads and 8 KV heads correctly but wrote kv_mul 4 instead of 8. The critic recomputed 64 / 8 = 8 and rejected that verdict, which matches the source line and the table. The critic also confirmed the 12-run list and that the functional, soak, and MMLU-Pro phases use the same 9 base models and add none.

Colour check: the chart uses the documented emphasis pair (accent blue #2a78d6 for "fits", muted gray #898781 for "does not fit"). The palette validator script could not run on this host (no JavaScript runtime installed), so the pair is taken from the validated reference palette rather than re-validated here.
