Short version. When the AMX K mirror is compiled in and the host can use AMX, each mirror-eligible KV-cache book allocates an extra buffer of ordinary RAM equal to half its KV bytes, and before this commit no log, gauge, or accessor reported that buffer anywhere. This commit adds three read-only reporting channels (a per-book accessor, a second number on the KV-footprint log line, and a FUSE gauge) without letting any eviction or cache-sizing decision see the new number, because evicting KV frees hugepage-pool bytes, which is not the memory the arena uses. A rewritten leak test forces the allocation path to run on any machine and pins two of the three channels — the accessor and the gauge's counter — to the bytes the allocator really handed out.
Lineage note: “mirror” names the formulation S = Q·KT read from a second, VNNI-interleaved copy of K, which originates from Bill’s PR #2934; the arena and the accounting discussed here are our implementation of that idea in PR #3879.

2. Background

Deep background (skip if you know tron's KV cache)

tron answers chat requests by running a language model. For every conversation it keeps a KV cache: the attention Keys and Values of all tokens seen so far, so each new token only has to attend over stored data instead of recomputing it. That cache is organized into books. A book owns a fixed number of KV pages, each page holding 64 tokens, and the book's pages live in DMA memory — memory taken from a pool of 1 GiB hugepages that the FPGA accelerator card can read directly. The pool is finite (512 hugepages on the test machine delphi-3bda), so tron has a memory-pressure governor: it watches hugepage-pool usage, and when usage crosses a target it evicts cached KV, which returns whole hugepages to the pool.

PR #3879 adds a CPU attention path that uses AMX, Intel's tiled matrix-multiply instruction set. AMX multiplies tiles fastest when the right-hand operand is stored in an interleaved layout called VNNI. K as stored in the KV pages is not in that layout, so the PR keeps a second, derived copy of K — the K mirror — already interleaved. All mirror planes of one book live in one buffer called the arena. Three properties of the arena matter here (Note [K mirror parallel arena], kv_cache.hpp:555-591): it is ordinary RAM, not DMA (only the CPU reads it); it is sized at exactly half the book's KV bytes (a KV block has two planes, K and V, and only K gets a mirror); and it is allocated at book construction only when the model is AMX-eligible and the host can run AMX (amx_attn::available()).

rinzler publishes its live metrics as FUSE stats: a tree of virtual files (for example /rinzler/stats/dma_heap/*) served by the process itself. A fleet agent called platformd scans an /exported subtree of that mount and forwards selected metrics to Prometheus, the fleet's time-series database. A manifest array in the source lists every static metric file with its Prometheus type, unit, and description; a test, t_tronstats_convention, walks the manifest and checks the published files against it.

Narrow background: the gap this commit fills

Before this commit, every byte-accounting channel in the system measured something the arena is not:

  • book::dma_size_bytes() reports DMA memory by contract (kv_cache.hpp:859-866) — the arena is not DMA, so it is rightly excluded;
  • the memory-pressure governor measures committed hugepages and per-device accelerator memory (doc/memory_pressure_governor.md, “Usage measurement”) — the arena consumes neither;
  • the “KV cache footprint” log line printed only the DMA total.

So a mirror-eligible book silently held kv_bytes/2 of ordinary RAM that no operator-facing number acknowledged. On a host serving 400 GiB of KV that is up to 200 GiB of unreported RAM. codex's review flagged this as its finding #4. The commit's fix is visibility only: count the bytes once at allocation, and report the count through three read-only channels.

3. Intuition: a third memory that nobody was watching

Think of the process as holding three kinds of memory. The hugepage pool is watched by the governor, which can act on it: evicting KV returns hugepages. Device memory on the accelerator cards is watched the same way. The arena is a third memory in the governor document's sense: it needs its own usage counter, and it gets no target, because there is no admissible action — evicting KV frees pool bytes, and pool bytes are not what the arena consumes.

A toy walkthrough with those numbers. A mirror-eligible book with 4 GiB of KV pages is constructed. The arena allocation succeeds, so the book records 2 GiB (half of 4 GiB) in a new member and adds 2 GiB to a new process-wide atomic counter. The construction then reports (+4 GiB DMA, +2 GiB mirror, +1 book) to the footprint logger, whose own running totals moved by 6 GiB — more than the 1 GiB print threshold — so it prints KV cache footprint: 4.00 GB DMA + 2.00 GB K mirror in 1 books. Any read of the FUSE gauge file now returns 2147483648 (2 GiB in bytes). When the book is destroyed, the destructor reports the same three quantities negated and subtracts 2 GiB from the atomic counter; the gauge reads 0 again.

Takeaway. The commit changes no allocation, no eviction, and no kernel behavior. It takes one number that already existed at allocation time (bytes = kv_bytes/2), stores it, and wires it to three read-only outputs.

4. What the commit deliberately does not do

The commit message spends a paragraph on the fix it rejects: folding the arena into dma_size_bytes() or into the governor's usage measure. The reasoning, restated:

  • Units differ. The governor's usage is committed hugepages, and its one action — evicting KV — frees hugepages. The arena is ordinary RAM; evicting KV because the arena is large would relieve pressure that does not exist in the pool. (It would also shrink the arena as a side effect, but the trigger would still be measuring the wrong memory.)
  • dma_size_bytes() is DMA by contract. Its callers use it to reason about pool consumption; the EAGLE embedding store counts there because it really is DMA (kv_cache.hpp:859-866). Adding non-DMA bytes would corrupt that meaning.
  • The bound is structural. Books are carved from the hugepage pool, and each arena is half its book's KV bytes, so all arenas together can never exceed half the pool. A host that enables the mirror must simply be provisioned with pool/2 of ordinary RAM to spare — a provisioning rule, not a runtime control loop.
  • The nothrow allocation is not a safety net. The arena is allocated with a form of new that returns null instead of raising an error when memory is short. Under Linux overcommit that answer is not final: the kernel grants virtual address space optimistically, and physical pages are committed only when first written (here, at the first mirror write). So a successful allocation can still end in the kernel's out-of-memory killer terminating the process later. Visibility plus provisioning is the protection; the null-check is only a fallback for the case where the failure is visible at allocation time.

5.5 Prove it: the tests (t/CMakeLists.txt, t/t_amx_arena_leak.cpp)

t_amx_arena_leak already existed: it globally replaces the alignment-taking array forms of operator new[]/delete[] (the overloads with a std::align_val_t parameter, at any alignment; the arena passes 64) with counting wrappers, which is a faithful proxy for the arena because the arena is allocated with exactly such a form and almost nothing else uses them (the standard library's std::allocator uses the non-array forms). But the arena allocates only when amx_attn::available() is true, so on a machine without AMX the interesting assertions were skipped. The commit removes that host dependency with a linker trick, then adds a byte-exact accounting test.

8. Glossary

tron / rinzler / runtron
The inference program this repository builds / the production server binary / the command-line tool for running the model directly.
book
One allocation of KV-cache pages: K and V tensors for stored tokens, in DMA memory the FPGA can read (struct book, kv_cache.hpp). Every production model's cache is a book instantiation.
KV page
A 64-token block of the KV cache; books are sized in pages.
DMA memory / hugepage pool
Memory carved from a boot-time pool of 1 GiB hugepages, mapped so the FPGA accelerator card can read it directly (DMA = direct memory access). The pool is the scarce resource KV eviction protects.
AMX
Intel Advanced Matrix Extensions: CPU instructions that multiply small tiles of matrices; PR #3879's new CPU attention path uses them.
VNNI layout
The interleaved element order AMX wants for the right-hand matrix operand; the reason K needs a second, re-arranged copy.
K mirror / arena
The second, VNNI-interleaved copy of K / the single ordinary-RAM buffer holding all mirror planes of one book, sized kv_bytes/2. See Note [K mirror parallel arena], kv_cache.hpp:555-591.
TRON_AMX_K_MIRROR
The CMake build flag that compiles the mirror (and thus the arena) in. Off: none of the counted code exists and every new accessor/counter reads 0.
amx_attn::available()
Run-time answer to “may this process use AMX now”: CPU support, OS permission, and the TRON_AMX_DISABLE kill switch. One of the two gates on arena allocation (the other is the model's eligibility flag).
amx_mirror_eligible
The per-model flag saying an attention kernel of the AMX shape (bf16 activations, head size 128, and 4 query heads per KV head) exists, carried into the book constructors. The write-through gate mirror_write_ok, by contrast, deliberately ignores the query-head ratio.
bf16
16-bit brain floating point, the activation type of the models this path serves; 2 bytes per value in the size arithmetic.
EAGLE
Speculative decoding with a small draft model; books can carry extra per-token embedding storage for it (the x_bytes template argument / support_eagle flag). That storage is DMA and counts in dma_size_bytes().
memory-pressure governor
The component (doc/memory_pressure_governor.md) that compares hugepage-pool usage and per-device accelerator-memory usage against targets and evicts cached KV when over.
FUSE stats / gauge
Live metrics served by the process as virtual files through FUSE (filesystem in userspace). A gauge is a metric that can rise and fall.
platformd / Prometheus
The fleet's node agent that scans the exported stats / the time-series database it forwards them to. A manifest entry's .yaml descriptor tells platformd each metric's type and unit.
t_tronstats_convention
The test that round-trips every manifest entry against the published FUSE files; it creates its own mount in a temporary directory, so it needs FUSE support but no running server.
spdlog
The logging library tron uses; spdlog::info prints one log line.
std::atomic / fetch_add / memory_order_relaxed
A variable safe to update from many threads / its atomic add-and-return-old-value operation / the weakest ordering setting: the operation is atomic but promises nothing about the order of surrounding memory operations — fine for statistics.
inline variable
C++17 feature: a variable defined in a header that every including file may define, with the linker merging all definitions into one object — one process-wide instance without a .cpp file.
nothrow new / overcommit
A form of new returning null instead of raising an error on failure / the Linux policy of granting virtual memory optimistically and committing physical pages at first write — which is why a non-null nothrow result is not a guarantee.
Catch2 / REQUIRE / WARN / SUCCEED
The C++ test framework used here / hard assertion that fails the test / message that never fails anything / an explicit pass marker.
--wrap (linker)
GNU linker feature: --wrap=SYMBOL resolves calls to SYMBOL to __wrap_SYMBOL, letting a test substitute one function without touching the library.
codex
An automated code reviewer run on PR #3879; its finding #4 (arena RAM reported nowhere) prompted this commit, and its suggested link-wrap technique is used in the test.
P1 / P2
Priority labels on review findings (P1 more urgent). codex filed the visibility gap as P1; the commit message re-triages it to P2 because the missing bytes are bounded and provisioned, leaving only visibility to fix.
