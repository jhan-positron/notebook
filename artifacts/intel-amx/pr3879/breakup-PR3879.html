Short version

Split the PR in Ben's order, but change what the third piece is. Land the page-share counters (PR 0, about 150 lines) and the canonical AMX path (PR 1, the retitled #3879, about 1,050 lines): PR 1 is the part with the measured decode gain (+17.5% at qwen, 8 users, prompt 8192) and it depends on nothing else.

Do not merge the K mirror arena. The systems tests that finished overnight show the mirror arm 17 to 24% slower to first token than the canonical arm, and its arena holds half the KV cache (about 45 GB per engine) in ungoverned host RAM. Keep it as a reference draft; 449 of its 1,170 lines are deleted and 519 rewritten if Bill's single-K design goes ahead.

Bill is right that single-K is viable, and wrong that it is nearly free. It turns the AVX fallback into the production reader for every non-dense page and changes the FPGA staging input, with no measurement yet on Granite Rapids or inside tron. Measure the VNNI store cost and the GOF staging cost next week; a dated gate on 2026-09-16 decides whether single-K or the mirror gets review time.

Words used here

Project names and abbreviations that this page uses. A general dictionary does not give these meanings.

tron / rinzler
tron is the inference program under test; rinzler is its production server, built from tron.
PR 3879
Pull request "AMX software attention (default-off): QK/PV tile kernels + K-mirror arena", branch jhan-amx-p0, head 60d66d9c04, 35 commits, 18 files, +2,538 / -52 lines against main at 1407f48ddb. main has moved 1,031 commits since that base.
AMX / AVX
AMX (Intel Advanced Matrix Extensions) is the tile-matrix instruction set the change uses. AVX (Advanced Vector Extensions) is the older vector instruction set the existing attention code uses. The bf16 dot instruction VDPBF16PS needs the AVX-512 BF16 feature, not generic AVX.
bf16
bfloat16, the 2-byte floating-point format in which K and V are stored. Scores accumulate in fp32.
K, V, QK, PV
K (keys) and V (values) are the cached tensors attention reads. QK computes query-key scores; PV multiplies the softmax weights by V.
page / book / slot
A page holds 64 tokens of K and V. A book owns the allocation that holds pages. A slot identifies one persistent K/V storage layer independent of who reads or writes it.
kv_mul / GQA
GQA (grouped-query attention) lets several query heads share one K/V head; kv_mul is that ratio. The AMX kernels in this PR handle head size 128 with kv_mul 4 ("128x4").
kernel / dispatch
The kernel is the AMX tile code in src/tron/kernels/amx_attn.cpp and its intrinsics-free header h/tron/kernels/amx_attn_iface.hpp. The dispatch is the code in h/tron/models/self_attention.hpp that decides per page whether to call the kernel or the AVX path, plus the gate predicates and the PV epilogue. Build option TRON_AMX_DISPATCH, default off; runtime kill switch TRON_AMX_DISABLE=1.
canonical K
K kept in today's original single-copy, row-major storage and read as stored. The supported default arm of the PR ("canonical arm").
VNNI layout
Vector Neural Network Instructions layout: a permutation of a page's K in which one 64-byte row holds one dimension pair for 16 consecutive tokens, so it is directly the B operand of the AMX bf16 tile multiply and of VDPBF16PS. In PR 3879 the shape is [4 dimension blocks][4 token blocks][16 pairs][16 tokens][2] (kv_cache.hpp:640-664).
K mirror / mirror arena
A second copy of K in the VNNI layout, written through on every K store into a parallel arena of ordinary RAM (not the hugepage pool the FPGA sees). Opt-in via TRON_AMX_K_MIRROR. The mirror formulation originates from Bill's PR #2934; the implementation and every number on this page are ours (branch jhan-amx-p0).
single-K
Bill's proposal: store K once, in the VNNI layout, inside the existing K plane; delete the mirror; teach the AVX fallback and the FPGA staging to read the VNNI layout. "Single K" means one durable CPU representation; FPGA staging and device memory remain.
GOF
Group of four: the FPGA hardware-attention staging unit, 4 tokens of K (8 KB) and V (8 KB), filled from the CPU pages by gof::populate and then transferred by DMA (direct memory access). Hardware attention reads the staging copy, not the book's K bytes.
EAGLE
The speculative-decoding arrangement in which a draft model and the validating model share a cache through distinct physical storage views (an extra physical slot).
page-share counters
h/tron/kernels/page_share_counters.hpp plus five guarded blocks in self_attention.hpp: instrumentation that counts how many query tokens visit the same KV page in one pass. Compiled only with -DTRON_PAGE_SHARE_COUNTERS.
TTFT / TPS
TTFT is time to first token (mostly the prefill of the prompt). TPS is generated tokens per second per user.
PR stack
A chain of PRs each based on the previous one. tron's AGENTS.md rule: only the PR based on main may be marked ready for review; descendants stay draft until the parent merges.
est.
An estimate, not a measurement.

2.3 What the single-K investigation established verified

The investigation (PR3879-codex/single-K.html and its layout notes) was checked line by line against the PR head by an independent agent. Its central code claims hold:

  • The FPGA does not read the book's K bytes directly. page_info::k_head_fn hands one contiguous row to gof::populate (full.hpp:2289-2292), which shuffles it element by element into the staging block (gof.cpp:155-160, hwattention.hpp:727-738); the DMA descriptors source the staging block, not the page (gof.cpp:108-113, hwattention.hpp:455-456). So the PR's Note [Why not replace canonical K] barrier 1 ("the FPGA reads the K page bytes exactly as stored", kv_cache.hpp:598-600) is wrong as written.
  • The layout formula is a bijection over all 8,192 (token, dimension) pairs of a page, and one 64-byte row is one AVX-512 load holding one dimension pair for 16 tokens, so an AVX reader with a broadcast Q pair and VDPBF16PS needs no gather and no transpose. The Note's "32 B apart" (kv_cache.hpp:602-603) should read "64 B between successive pair rows"; no stride in the layout is 32 B.
  • Bill's note says k_at() has zero callers and can be deleted. That is false for PR 3879: six callers in kv_cache.hpp (the row accessors at 1574, 1580, 1588, 1597 and copy_storage_slot at 1961, 1964), through which save_k, the AVX dotter, the canonical AMX kernel and the GOF callback all read K.
  • Bill's format has the outer axes swapped relative to ours ([token block][dimension block] vs our [dimension block][token block]); 6,144 of 8,192 elements sit at different offsets. His token-tile-base source-stride expression must not be pasted into our shuffle.
  • The local AVX prototype (AMD Zen 5 under KVM, one query, full page) was correct on 98,905 scores but not faster: 80.08 ns per page swizzled vs 77.14 ns canonical. 67,462 of 98,905 scores differ bitwise from the dotter because the reduction order changes.

So single-K is technically viable, and the PR's own stated reasons for not doing it are partly wrong. What the investigation did not do is measure anything on Granite Rapids or inside tron.

5.1 The fact that reorders the measurements

The round-1 TTFT penalty is the first serving-path signal about the cost of the VNNI scatter store. In the mirror arm that store is added to the contiguous store on every K row during prefill; under single-K it replaces the contiguous store, so the net work is smaller, but each token still lands in 64 cache lines instead of 4, and eight RX workers writing adjacent tokens of one page share those lines. Nobody has measured that latency. So the store-cost measurement (G1) comes first, before the AVX benchmark and long before any accessor migration; it also settles the round-1 open item about the mirror.

A second fact frames the whole question. Ingested plugins are generated with force_hw_attn = true (ingest/src/TronCpp.hs:233, read at model.hpp:795-796), so on FPGA hosts qwen-class models run hardware attention by default and AMX engages only with USE_HW_ATTN=0, for EAGLE, for software-required ranges, and (on main) for the new HBM-exhaustion fallback. verified Every AMX gain in the PR and in round 1 was measured with USE_HW_ATTN=0. Single-K puts its one new cost, the strided GOF source read, on the path ingested head-128 models use by default, while its saving lands on the software path. Whether production will run these models with software attention at all is a question for Jeremy (decision 10); the answer sets how much the whole K-storage question is worth.

5.3 Opt-in and rollback contract for single-K

  1. Default-off build, default row-major storage. Admit only validated head-128 slots whose whole consumer set is supported; every other slot stays row-major.
  2. Encoding is a storage property. Chosen per physical slot before the first write, immutable for the book's lifetime, carried across copies, never decided by a runtime AMX availability check (available() probes once and caches, amx_attn.cpp:72-81).
  3. Dispatch by encoding first. A VNNI slot must never reach a contiguous-row reader, including when the dense AMX gate declines.
  4. Keep the old-behaviour rollback. In the single-K configuration, TRON_AMX_DISABLE=1 selects row-major storage and the old dotter at process start, so the same-binary A/B methodology survives. A separate development control forces AVX on VNNI storage for testing the new fallback.
  5. Full rollback is a restart. Populated books are never converted in place.
  6. Determinism stays separate. Worker planning under pay_for_determinism is unchanged; whether any golden-output comparison must reproduce the old reduction tree is a written decision before SK-B, not an accident.
