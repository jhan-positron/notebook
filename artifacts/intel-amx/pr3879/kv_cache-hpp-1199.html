Lineage note: “mirror” names the formulation S = Q·KT read from a second, VNNI-interleaved copy of K. The formulation originates from Bill's PR #2934; the implementation discussed here (the mirror arena, scatter_k_mirror, qk_mirror_128x4) and all line references are ours (jhan-amx-p0).

1. In one paragraph

The KV book keeps two copies of every K row: the canonical K (the original single-copy storage in the DMA arena) and the mirror (a VNNI-layout copy in a parallel arena, read only by the AMX kernel qk_mirror_128x4). With EAGLE, the book has one extra physical slot L for the draft model, and the scheduler “shifts the view” (moves the pointer kv_blocks_alias) while the draft runs, so the draft's logical slot 0 lands on physical slot L. Every canonical-K accessor goes through the shifted pointer; book::mirror() does not — it always maps logical slot 0 to mirror plane M(0). Result: the draft's write-through overwrites the validator's slot-0 mirror plane with the draft's K, and the validator's next full-page AMX decode scores its queries against the draft's K. Nothing asserts; the scores are silently wrong for the validator layer on slot 0.

3. What EAGLE is, and how tron runs it

3.1 The idea

Speculative decoding: a cheap draft model proposes the next few tokens; the exact model (the validator) scores all of them in one forward pass; the longest prefix the validator agrees with is kept and the rest is thrown away. The output distribution stays that of the exact model; the speed-up comes from the validator handling several tokens per pass instead of one.

EAGLE (Li, Wei, Zhang, Zhang, ICML 2024) is one such draft design. Its draft is a single transformer layer plus a small linear layer. Instead of predicting from tokens alone, it predicts from the validator's own hidden features: the input for drafting token t+1 is the pair (embedding of token t, validator's final hidden state after token t-1). It reuses the validator's embedding table and LM head, so the draft is tiny and tracks the big model closely. The weights tron loads are third-party EAGLE heads (leptonai/EAGLE-Llama-3.1-8B-Instruct, leptonai/EAGLE-Llama-3.3-70B-Instruct, config/models.yaml:254–300), re-keyed by bin/fix_eagle_safetensors.py.

4. Background: two arenas, two kinds of slot, one movable pointer

  • Logical slot (kv_slot_id): one per model layer. save_k, attention, and every page accessor take a logical slot.
  • Physical slot (kv_storage_offset): an index into the DMA arena arena_data. Without EAGLE, logical slot i = physical slot i.
  • EAGLE extra slot: a book built with support_eagle has storage_slot_count = logical_slot_count + 1; the extra physical slot L (eagle_storage_offset()) has no logical descriptor (kv_cache.hpp:845–848 at cc8a86bb3).
  • Storage view: set_storage_view(eagle_storage_offset()) sets kv_blocks_alias = arena_data.get() + n_pages * offsets[L]; reset_storage_view() sets it back to arena_data.get() (kv_cache.hpp:829–842). book::kv_block(slot, head, pg) reinterpret-casts kv_blocks_alias (kv_cache.hpp:1160–1166), so while the view is active, logical slot 0 resolves to physical slot L.
  • Who sets the view: h/tron/scheduler/full.hpp:1729–1740 (cc8a86bb3; 1717–1727 at bbb55ae5f): if (is_eagle) for (auto* b : kv_books) b->set_storage_view(b->eagle_storage_offset()); then state.forward(...) then reset_storage_view(). is_eagle is true only for the EAGLE child scheduler (the draft), which runs with max_layers = 1 (full.hpp:1401–1403).
  • Mirror arena (TRON_AMX_K_MIRROR): mirror_arena_, plain RAM, one VNNI K plane per (physical slot, kv head, page), sized kv_bytes/2. Addressed only by mirror_at_storage<geometry>(kv_storage_offset, head, pg) = mirror_arena_ + n_pages*offsets[offset]/2 + (head*n_pages+pg)*plane_bytes (kv_cache.hpp:1215–1231). It has no equivalent of kv_blocks_alias.

4.1 A neighbouring review comment: the arena is sized for every slot (kv_cache.hpp:182, R2-05)

Any eligible kernel makes the whole arena: for a model with one eligible and one ineligible attention kernel the ineligible slots' planes are allocated (kv_bytes/2 covers every slot), never written by save_k, and rebuilt on every page move by copy_storage_slot. No in-tree plugin is mixed today, so fine — but say so here (“any kernel; sized for all slots; only eligible geometries are written through”), and a two-kernel array in t_amx_arena_leak would record the intended answer.

What it says in plain words. “Eligible” is decided once per model, not per KV slot: amx_mirror_eligible(plugin_t::attention_kernels) returns true as soon as any attention kernel of the plugin has the AMX shape (head 128, 4 query heads per KV head) (kv_cache.hpp:181–190; the scheduler evaluates it at full.hpp:1456 and stores the one bool on node_base, full.hpp:305–321). The arena is then sized as kv_bytes/2 (kv_cache.hpp:1053–1062), and kv_bytes is the sum over all storage slots — every slot's n_kv_heads × 2 planes × 64 × head_size × 2 B, plus the EAGLE slot (calculate_allocation_sizes :1097–1105, make_kv_slot_offsets :636–650). So a model whose kernels differ in geometry gets one mirror plane per (slot, head, page) for slots that can never use one. Three code paths then treat those planes differently:

Is it a bug? No — a cost. The planes of ineligible slots always equal scatter(canonical K) after a rebuild and are never read, so results cannot change; what a mixed model would pay is RAM for planes nobody reads (that slot's share of kv_bytes/2: n_pages × n_kv_heads × 64 × head_size × 2 B) and scatter work on every page move. The comment's reading of kv_bytes/2, save_k and copy_storage_slot is confirmed against the code (Table 7); its “no in-tree plugin is mixed today” holds, with one refinement: the only multi-kernel plugins in the build tree, the generated gemma-4 ones, have two ineligible kernels each, so they get no arena at all (the multi-kernel arrays in t/heterogeneous_scheduler_compile.cpp and t/t_llama_unit.cpp are all-ineligible as well).

Option 1 — say so, and pin the semantics with a test (what the comment asks; recommended now). Option 2 — per-slot eligibility (only if a mixed plugin lands). The book cannot decide this alone: its layout knows each slot's kv_geometry (n_kv_heads, head_size) but not the query-head ratio, which lives in attention_geometry. The scheduler has both: from plugin_t::attention_operations (each descriptor carries binding.kv_slot and kernel, kv_cache.hpp:226–231) and attention_kernels it can build a per-slot mask — slot s is eligible iff some operation bound to s uses a kernel that passes shape_ok — and pass it along the path the bool takes today (node_base, try_create, the 4-argument constructor). Two levels of tightening:

  • Skip the wasted work only: mirror_at_storage returns nullptr for masked-out slots. copy_storage_slot's existing null check then skips the rebuild with no other change; the EAGLE plane follows slot 0's bit (EAGLE requires a uniform-geometry cache, eagle_compatible at :728, so with EAGLE a mixed mask can only come from kernels that differ in query-head count over one KV geometry). RAM stays kv_bytes/2.
  • Also shrink the arena: size it as the sum over eligible slots and give mirror_at_storage its own prefix offsets over that subset instead of layout offsets / 2 (:1240–1246). More plumbing (a second offsets table, and t_amx_arena_leak would assert the smaller size) for RAM that no in-tree model spends today.

4.2 What src/amx_fused_bench.cpp does (the whole-path benchmark; R1-51 to R1-56)

The name. “Fused” here only means that the three steps of attention for one 64-token page — scores (Q·KT), softmax, and the weighted sum with V — run back-to-back inside one timed loop, the way the real kernel runs them, instead of each step being timed alone. This page calls it the whole-path benchmark (our own results page, rampup/fused-sweep.html, already uses that name).

What it is. A 732-line stand-alone program: no tron headers, compiled by hand (g++ -O3 … -mavx512bf16 -mamx-tile -mamx-bf16 src/amx_fused_bench.cpp, exec/p0-fused-sweep.sh:12–14); no CMake target builds it. No step reads kv_blocks_alias or any view flag; set_storage_view/reset_storage_view (kv_cache.hpp:829–842) touch only kv_blocks_alias. So kv_storage_offset(slot.i) = physical slot 0 → plane M(0), view or not. The same chain is used by the reader page::k_mirror_data (kv_cache.hpp:1506–1510).

So the slot is 0 and the mismatch is: canonical row → physical slot L, mirror row → M(0), the validator's plane.

8. What the comment asks for (S7, S8)

S7 — make mirror() follow the view, or forbid the combination

kv_block() follows the view because set_storage_view rewrites the base pointer it dereferences. mirror() has no such pointer: it recomputes the address from slot.i every time. Two ways to close the gap, both named by the comment:

Option A — honour the view. Record the active view and let mirror() map logical slot 0 to the EAGLE physical offset while it is active.

// sketch only - not compiled, not tested
// book members
uint8_t* kv_blocks_alias;                        // existing
#ifdef TRON_AMX_K_MIRROR
std::optional<kv_storage_offset> view_offset_;   // new
#endif

void set_storage_view(kv_storage_offset offset) noexcept {
  ... existing asserts and kv_blocks_alias shift ...
#ifdef TRON_AMX_K_MIRROR
  view_offset_ = offset;
#endif
}
void reset_storage_view() noexcept {
  kv_blocks_alias = arena_data.get();
#ifdef TRON_AMX_K_MIRROR
  view_offset_.reset();
#endif
}

template <kv_geometry geometry>
bf16* mirror(kv_slot_id slot, size_t kv_head, size_t pg) noexcept {
  // Same rule as kv_block(): under the EAGLE view, logical
  // slot 0 is the extra physical slot.
  if (view_offset_) {
    TRON_ASSERT_EQ(slot.i, 0);
    return mirror_at_storage<geometry>(*view_offset_, kv_head, pg);
  }
  return mirror_at_storage<geometry>(kv_storage_offset(slot.i), kv_head, pg);
}

Equivalent alternative: keep a second shifted base pointer for the mirror arena (a literal copy of the kv_blocks_alias mechanism, shifted by byte_base / 2). In either form, give mirror_at_storage the same offset-range assert that kv_block_at_storage has (kv_cache.hpp:1192–1193), so a future caller with a bad offset fails loudly instead of aliasing a neighbour's plane.

Option B — assert the combination away. Refuse a view while a mirror arena exists (or do not allocate the arena for EAGLE books). This keeps the code smaller but makes EAGLE and the mirror mutually exclusive.

// sketch only - not compiled, not tested
void set_storage_view(kv_storage_offset offset) noexcept {
#ifdef TRON_AMX_K_MIRROR
  TRON_ASSERT(!mirror_arena_,
      "EAGLE storage view is not supported with the K mirror arena");
#endif
  ... existing ...
}

Option A is what the comment prefers (“the same way kv_block() does”); Option B is offered as the fallback in parentheses. Option B makes EAGLE and the mirror mutually exclusive — section 3.4 weighs how likely that combination is, and what each Option-B variant would do at run time.

9. Why previous testing did not catch it, and which tests to add

8.1 Four conditions, never all true at once

The wrong read happens only when all four columns below hold. Every test and campaign we have satisfies at most three. Sources: exec/*.sh, exec/logs, rampup/, the PR description and doc/intel-amx.md contain no EAGLE or speculative-decoding run (the only “speculat” hits are the compiler building speculate.cpp and a KV-sharing remark in the rampup doc); test contents from git show cc8a86bb3:t/....

8.2 The structural reason

  • One function carries the seam. Both production users of the mirror — the writer page::set_k_mirror and the reader page::k_mirror_data — resolve through book::mirror(kv_slot_id). No test calls either of them while a view is active. The writers the tests do exercise (copy_storage_slot, fill_storage_slot) take a physical kv_storage_offset and are correct by construction, so “mirror == scatter(canonical K)” held in every test that checked it.
  • The view and the mirror were tested as two features, never as one. The EAGLE-view test predates the mirror and was not extended when the mirror arena was added; the mirror tests were written for a validator-only world.
  • The symptom is silent. No assertion, no NaN, no crash: the validator's slot-0 layer scores against K_d instead of K_v. A throughput campaign cannot see that even with EAGLE on; only an output comparison (logits or EAGLE acceptance rate, AMX vs. TRON_AMX_DISABLE=1) can.
  • Our on-machine work never enabled EAGLE (sources listed above), so the path did not execute once.

8.3 Tests to add

Integration-level check (not a unit test): with EAGLE enabled on a 128/4-shape model, the TRON_AMX_K_MIRROR build must produce the same logits as the canonical build, or equivalently the same EAGLE acceptance rate with TRON_AMX_DISABLE=1 and unset. Whether an EAGLE-capable model config exists in our ingest set on delphi-3bda: Insufficient data — check config/models.yaml for an EAGLE head before planning that run.

12. Glossary

canonical K
Project shorthand: K kept in today's original single-copy storage (the K plane of a kv_block in the DMA arena), read as stored by the FPGA, the AVX fallback and qk_canonical_128x4.
mirror, mirror plane, M(i)
A second copy of K per (physical slot, kv head, page), stored in the VNNI layout that the AMX tile B operand needs, in the separate mirror_arena_. Read only by qk_mirror_128x4. M(i) is the comment's name for the plane of physical slot i. Formulation from Bill's PR #2934; implementation ours.
VNNI layout
Pair-interleaved element order required by the AMX TDPBF16PS B operand: for each token, consecutive dimension pairs sit 32 bytes apart across 16×16×2 panels. scatter_k_mirror writes one token's 128-value K row into that order.
EAGLE; draft; validator
Speculative decoding: a small one-layer draft model (the EAGLE child, is_eagle = true) proposes tokens; the full validator (exact model, the parent) checks them. In tron both share one KV book and one token tree; the draft gets one extra physical slot.
logical slot / physical slot
kv_slot_id = one per model layer, what callers pass. kv_storage_offset = position in the arena. Equal except for the EAGLE extra slot L, which is physical only.
storage view; kv_blocks_alias
The mechanism that lets the draft reuse slot-0 code: set_storage_view shifts the base pointer kv_blocks_alias so logical slot 0 resolves to physical slot L; reset_storage_view undoes it. Active only during the draft's state.forward.
save_k; write-through
The per-layer routine that stores freshly computed K rows into the page (model.hpp save_k_impl). “Write-through” = its immediate update of the mirror right after the canonical store.
page; book; page move
A book is one KV cache of n_pages pages; a page holds 64 tokens. A page move is book::append (the defrag path) copying tokens between pages through copy_from → copy_storage_slot, which rebuilds mirror planes from the copied canonical K.
dense fast path
The branch in self_attention.hpp that hands a whole 64-token page to one AMX kernel call instead of the per-token dotter loop.
K_v, K_d
The validator's and the draft's K row for the same token; different models, different values.
