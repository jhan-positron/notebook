Baseline vs Mirror AMX

What the hand drawing on the Notion "Scratch" page says, step by step, next to what tron's two AMX attention kernels actually do.

code read: tron pre-split tree 60d66d9c04 (branch jhan-amx-p0-pre-split, holds both kernels) · sketch fetched 2026-09-13 · page written 2026-09-13
Short version

The sketch gets the one real difference right. Baseline computes the scores transposed and transposes them back, and mirror instead reads a second, pre-interleaved copy of K that is written at the moment K is generated.

The softmax tail in both columns does not match the code. P is never normalized before P·V, the multiply by the attention scale is missing, and the only division by the running sum happens once at the very end.

Measured at prompt 8192, the transpose is 0.37 us of the QK phase and the whole attention unit gains 0.22 us (2.89 to 2.66 us), while the mirror pays for it with a second copy of K (half the KV bytes, in ordinary RAM) and a slower time to first token (+18% to +24% at 8 users).

Words used here

tron
the inference program under test. The code cited below is its software attention path, which runs on CPU cores.
AMX
Intel Advanced Matrix Extensions. A CPU instruction set with 8 tile registers, each 16 rows × 64 bytes. One instruction (TDPBF16PS) multiplies a tile A by a tile B and adds into a tile C in fp32.
A operand, B operand
the two inputs of a tile multiply. A is plain row-major. B must be in the "VNNI" layout: pairs of consecutive rows interleaved element by element, so the pair sits together in memory.
K*, "interleaved & transposed"
the sketch's name for K stored in that VNNI B layout: dimension pairs become rows, tokens become columns. The code calls it the K mirror plane.
baseline / canonical-K
K kept in today's original single-copy storage (one 128-value row per token) and read as stored. Kernel qk_canonical_128x4. This is what PR #3879 ships.
mirror
the second-copy formulation, kernel qk_mirror_128x4, built with TRON_AMX_K_MIRROR. Lineage: the mirror formulation originates from Bill's PR #2934. The implementation and all numbers on this page are ours (branch jhan-amx-p0 and its pre-split tree).
KV page
a block of 64 tokens' K and V for one layer and one KV head. The unit both AMX kernels process in one call.
GQA group, kv_mul
the 4 query heads that share one KV head. 4 heads × 128 dims × bf16 = 1024 bytes = one full tile operand, which is why the kernels serve exactly this shape.
bf16
16-bit brain float. K, V, Q and P are bf16 inside the tile multiply. Products are added in fp32.
v*, s*, m*
the running softmax state per query head: weighted sum of V, sum of exp, and running maximum. Pages update it. Workers' partial states are merged ("joined") at the end.
attention unit
one query token × one KV page × one KV head, as measured on 2026-09-01. Its time does not depend on the number of users or the prompt length.
TTFT
time to first token, in ms. The prefill cost the serving path shows the user.

4. What the sketch leaves out

  • Both builds pack Q, differently. Baseline packs Q into the VNNI B layout. Mirror copies Q into zero-padded rows. Both do it at most once per (query token, KV head, section), that is once per apply_page_range call, and reuse it across that section's pages. When the planner splits one KV head's pages across workers, each section packs the same Q again. The cost is small in both builds. self_attention.hpp:1419-1449
  • K* is a second copy, not a replacement. Canonical K must stay: the FPGA offload path reads canonical K rows on the CPU for its 4-token GOF swizzle before the DMA (gof.cpp:108-162), the AVX fallback reads contiguous rows, and the kill switch TRON_AMX_DISABLE needs the unchanged layout. The K* arena is ordinary RAM sized to half the KV bytes (a KV block is K plus V, the mirror is K only). One imprecision in the code comment itself: kv_cache.hpp:598-600 says the FPGA reads the page bytes as stored, but the DMA reads the swizzled staging buffer, and it is the CPU swizzle that reads the canonical rows. kv_cache.hpp:555-611 (the arena note runs 555-591)
  • V needs no V*. V is already stored with even/odd token pairs interleaved (for the AVX path), and that is exactly the tile B layout. So the P·V step is identical in both builds and needs no second copy. kv_cache.hpp:2231-2259
  • The scores are bit-identical. A unit test requires the mirror kernel's 4 × 64 scores to equal the baseline kernel's exactly. Both reduce the 128 dims in the same four 32-dim steps with the same pairing. So the contrast is layout and cost only, not numerics. t/t_amx_numerics.cpp:185-224
  • Equal tile work, one step fewer. Both kernels issue 20 tile loads, 16 tile multiplies and 4 tile stores per page. The baseline then reads the 4 KB of stored tiles back and transposes them. The mirror stores the tiles straight into a 16-row scratch and copies 1 KB out. amx_attn.cpp:127-180, 249-267; self_attention.hpp:1581-1586
  • K* has a second write site. Every page move (defrag, append) goes through copy_storage_slot, which rebuilds the mirror from the destination's freshly copied canonical K. save_k is not the only writer. kv_cache.hpp:614-638, 1966-1977
  • Only dense pages benefit. The AMX predicate is per (query, page): a full 64-token page, fully visible, inside the sliding window. Partial or tail pages run the AVX loop in both builds, so the mirror's saving applies to dense pages only. self_attention.hpp:1562-1571
  • The mirror has a fallback the baseline lacks. If a page's K* plane is absent (arena not allocated, or allocation failed), that page runs the AVX loop. The arena is allocated with a no-throw new, and its pages commit at the first scatter, so a host that enables the mirror must keep half the KV pool free in ordinary RAM. self_attention.hpp:1579-1589; kv_cache.hpp:577-591
  • Where the cost moves. Baseline pays the transpose at read time, once per page per query token per KV head, on every decode step. Mirror pays a scalar scatter at write time, once per token per layer per KV head, plus the RAM. That trade is what the measurements below quantify.
  • The two are compile-time alternatives. Both kernels are compiled into every AMX build. TRON_AMX_K_MIRROR selects the mirror kernel, the arena, and the write-through. amx_attn_iface.hpp:245-247

6. A corrected redraw, in the sketch's own style

Same bullet form as the drawing. Blue background = the step only the baseline has. Orange background = the step only the mirror has. Grey text = shared.

Baseline AMX:
  • pack Q → VNNI (once per token × KV head × section)
  • ST = K · QT (K as stored is operand A)
  • S = (ST)T (AVX-512 transpose, 0.37 us of QK at prompt 8192)
  • s = S · scale; m = max(s, m*)
  • P = exp(s − m); ΣP (P not normalized)
  • O = P · V (V as stored)
  • v* = v*·c + O; s* = s*·c + ΣP; m* = m
  • … next page …
  • after all pages + join: out = v* / s*
Mirror AMX:
  • when generating K: store K, then scatter K* (VNNI) while L1-hot
  • pack Q → zero-padded rows (once per token × KV head × section)
  • S = Q · K* (K* is operand B, stored straight, no transpose)
  • s = S · scale; m = max(s, m*)
  • P = exp(s − m); ΣP (P not normalized)
  • O = P · V (V as stored)
  • v* = v*·c + O; s* = s*·c + ΣP; m* = m
  • … next page …
  • after all pages + join: out = v* / s*

7. Verification status

Every code claim on this page was read directly from the pre-split tree and then checked by independent refuters (two lenses per claim: literal reading of the cited lines, and a search of the rest of the tree for contradictions). Each measured number was re-read from its result file. Result: 14 of the 16 code verdicts held as written. Two refuters corrected wording, both now applied: Q is packed once per (token, KV head, section), not per (token, KV head), and the "FPGA reads the page bytes" reason is imprecise (it is the CPU swizzle that reads them). Of the three number checks, the TTFT figures held exactly, the 0.37 us gap was the QK phase only (the whole-unit gap is 0.22 us, corrected above), and the arena figures were GiB not GB with a one-sample band (corrected above). A final critic agent, given the sketch transcription and the full kernel sources, listed 11 sketch-versus-code mismatches and 11 points the claims had missed. All mismatches are covered in section 3. The missed points that matter for the contrast (bit-identical scores, equal tile work, the second write site, the dense-page limit, the read-side meaning of "cache hot") are now in sections 3 and 4. The independent transcription of the sketch agreed with the one in section 1 in every step; it flagged the stylized ampersand and a stray stroke before Q as the only uncertain glyphs.
