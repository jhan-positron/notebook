Short version

h/tron/tensor/k_vnni.hpp is a new file of PR 4956 (tron pull request 4956, the first of four PRs that split PR 4424). With the build option TRON_K_VNNI on, the PR stores the K cache (the saved keys of attention) of 128-dimension heads in the VNNI layout, the pair-interleaved value order that the AMX tile multiply reads as its B operand. The file defines the typed K plane (the keys of one KV head for one 64-token page) as an owner (k_vnni_tensor) and a view (k_vnni_view), the index map and its constants, the transfer rows, and the operations that move one token's row in and out (store_row, load_row, copy_token). No raw plane pointer leaves the file except through detail::k_vnni_access, which only the typed operations, the AVX-512 score reader k_vnni::qk_group and the test-only fill may use. The file holds no AMX instruction, no 16-token block operation and no page state: those parts of PR 4424 land in PR 4957, PR 4958 and PR 4959. This page draws the plane geometry, the hierarchy from a page down to one pair, the type model, the function model, one token's row through the operations and the callers once (section 1), then shows each of the seven logical parts of the file (K0 to K6) beside its diagram (section 2).

K_VNNI-B1. Data model: one K plane, its panels, pair rows and the index map

A plane is K for one KV head of one page: 64 tokens x 128 dimensions of bf16 = 16 KiB, the same bytes as the row-major plane. It is 16 panels of 1 KiB, indexed by dimension step s and token block c. A panel is 16 pair rows of 64 bytes. A pair row holds one dimension pair of 16 tokens. Every arrow says how many. The worked example (token 37, dimension 70) is traced through the index formula.

K_VNNI-B1A. The hierarchy travel: the K of one page -> plane -> token block and dimension step -> panel -> pair row -> pair

One chain of carve-outs, each level drawn from the one above: the K of one KV page for one storage slot is one plane per KV head; a plane is the 64 x 128 grid; a dimension step cuts its columns and a token block cuts its rows, so a panel is one cell of the 4 x 4 cut; inside a panel the 32 dimensions are 16 pairs; the VNNI form stores the panel as 16 pair rows; a dword of a pair row is one pair of one token. The worked example (token 37, dimension 70) is followed down every level and through the index formula. B1 above stays as the reference drawing.

K_VNNI-B2. Type model: owner, views, the one access route, and the transfer rows
