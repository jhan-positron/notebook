## Short version

PR-4 is the last of four stacked pull requests (PRs) that replace PR 4424 of tron (the inference program): it keeps a 16-token block of the K cache (the stored keys) in plain row order until the block's 16th row is saved, converts the block to the VNNI layout (the packed layout of PR-1) at the end of that forward pass, leaves the blocks the FPGA scores row-major, and turns the layout on in the released Debian package. The expected effect is that the FPGA-attention decode loss of issue #4500 is gone within the measurement band (the cells and the whole-machine campaign of section 4 decide) and that the generated tokens equal main's under CPU attention in the measured cells. Your job: build the branch jhan-vnnik-4-tail-block on jhan-vnnik-3-shared-save from the two prepared patches, run the checks of section 4 on claude-box (this container) and on delphi-3bda (the test machine), write the body (section 6), and open PR-4 as a draft on jhan-vnnik-3-shared-save.

- K cache: the stored key vectors of past tokens. KV page (also "page"): a 64-token block of the K and V caches. Plane: the packed K storage of one page and one KV head (16 KiB; KiB = 1024 bytes). kv_mul: the number of query heads that share one KV head. bf16: the 16-bit brain floating-point format. fp32: the 32-bit float format. dword: a 4-byte unit. Line: a 64-byte CPU cache line.
- Slot (KV slot): one persistent K/V storage region (Note [KV slot retention] in h/tron/models/kv_cache.hpp). VNNI slot: a slot whose K planes hold the VNNI layout; with the option on that is every slot of 128-dimension heads (the layout gate k_vnni::layout_on<head_size>, a compile-time constant). Row-major slot: a slot that stores K as one row per token.
- Book: struct book of h/tron/models/kv_cache.hpp, the KV cache object that owns the memory of a group of pages and hands out page references. The scheduler creates one or more books per sequence. A book may have no active KV slot (logical_slot_count() == 0); some unit tests build one that way.
- Owner (k_vnni_tensor, h/tron/tensor/k_vnni.hpp): the typed object that holds the bytes of one plane and nothing else (16 KiB, 64-byte aligned). View (k_vnni_view): the typed accessor taken from an owner by as_view(). Every row store and load of a plane goes through a view. A test case that works on an owner directly uses no page, no slot and no `#ifdef TRON_K_VNNI`. So it runs the same in every build, with the option on or off.
- AMX: Intel Advanced Matrix Extensions, the tile instruction set. AVX-512: the 512-bit vector instruction set. VNNI layout: the pair-interleaved operand layout (two consecutive dimensions of one token adjacent; one 64-byte line holds that pair for 16 tokens). Panel: one 1 KiB block of the plane, 16 dimension-pair rows x 16 tokens. Token block (also "block"): 16 consecutive tokens of a page (4 per page; block c holds the page offsets c * 16 to c * 16 + 15). Dimension step: 32 dimensions (4 per 128-dimension head). The plane holds 4 steps x 4 token blocks = 16 panels.
- The option: the CMake switch TRON_K_VNNI (off in every preset until PR-4; PR-4 turns it on in the deb preset only). CMake: the build-configuration tool tron uses. AMX dispatch: the CMake switch TRON_AMX_DISPATCH that compiles the AMX attention kernels (on main since PR 3879; on in the deb preset since PR 4505). Kill switch: the environment variable TRON_AMX_DISABLE=1, which makes amx_attn_h128g4::available() false at run time, so no AMX kernel runs.
- deb preset: the CMake preset named "deb" in CMakePresets.json that builds the released Debian package (`make deb`, outside nix). Preset: a named CMake build configuration. The released package: the deb that the nightly installs and that production serving runs.
- The kernel: qk_vnni_128x4 (PR-2), the AMX QK (query-key score) kernel that reads a whole page's plane as its B operand; it runs only on a dense page (a full 64-token page that the query attends to in whole). The reader: k_vnni::qk_group (PR-1), the AVX-512 loop that scores the VNNI blocks of a page, one token per vector lane. Dotter: the row-major QK loop of main, one dot product per token; with PR-4 it also scores the rows of a row-major tail block of a VNNI slot. Relevant token: a cached K token that a query token attends to; "the first relevant token" of a page is where the software loop fetches the page's blocks mask and plane.
- save_k: the function of h/tron/models/model.hpp that stores one pass's K rows into the cache, once per (layer, pass). Pass: one forward computation of the model over its current input. Prefill: the pass that processes the prompt tokens, many tokens per pass. Decode: the passes that follow, one generated token per user per pass. Minibatch (also "the batch"): one group of a pass's items; a generated plugin has one minibatch per pass. Operation: one attention operation of the model (attention_op_id, common.hpp); a layer's attention is one operation; cached_operation_uses_hw(operation) says, once per model, whether the FPGA scores that operation's K. Logits: the per-word scores of a pass; the logit delivery is the step that computes them and notifies the listeners that wait for them. Forward end: the point of a pass, after the plugin's run() joined its workers and the cooperative FPGA staging drained (wait_for_coop_gof), at which PR-4 converts the completed blocks.
- GOF (group of four): the hardware KV cache's unit of 4 consecutive tokens of K and V. The staging (gof::populate) copies a GOF's rows into a buffer that DMA (direct memory access) moves to the FPGA card. Cooperative staging: that staging work done by the pass's worker threads next to the compute; wait_for_coop_gof waits until it has finished. Shard: a 1024-token range of one sequence's K and V on one FPGA card, with its HBM allocation. HBM: the FPGA card's high-bandwidth memory, which holds the K and V of the shards the card scores. "HBM bypass space exhausted" and "lose HW attention" are the warnings a run prints when a shard gets no HBM and its tokens are scored on the CPU instead; campaign.sh counts both per run and summarize.py shows the first per arm row. Engagement point: the first sequence position the FPGA scores (hw_attn_engagement_point, 127 by default; USE_HW_ATTN=N raises it, rounded up to a page boundary). The CPU scores every position below it.
- Block save (PR-3): store_block (h/tron/tensor/k_vnni.hpp) writes the K rows of one 16-token block as whole 64-byte lines after a register transpose; page::set_k_block is the page accessor. Shared block save (PR-3): save_k cuts a pass of more than 16 items into work units that the idle main helpers store too (Note [Shared block save] in model.hpp). Masked partial-block path (PR-3): the branch of save_k that stores a run of 2 to 15 tokens with masked line stores (set_k_block's `present` parameter, k_scatter_run_len, the else branch of store_k_block's `n == k_scatter_run_len` test). PR-4 removes that path from save_k; store_block keeps its mask parameter for the block-save test, and set_k_block passes the full mask.
- Window (K store window, PR-3): one shared save_k call of a pass that the main helpers join; window W of a pass is the W-th shared save_k of that pass (Note [Shared block save] in h/tron/models/model.hpp; the fields are batch::k_store_window in h/tron/models/common.hpp). The join: the main thread's wait at the end of a window for the helpers' finished count. The join watchdog: that wait's time limit (120 s), with the assert message "save_k: the K store window did not close". The three-thread section of the save_k test runs two windows on two operations and two KV slots.
- The save_k case's helpers (t/t_llama_unit.cpp, the test case "save_k stores every token's K row once, grouped by page block, alone or with helper threads"): pre_save marks rows 0 to 4 and row 8 of page 0 as saved before the pass (note_k_row_saved only; it writes no row data), so the pass's run of rows 5 to 15 completes block 0 of page 0 and queues it for the forward-end conversion. check_marks requires, for every job, that its token is not yet KV-complete, then marks K complete once more and requires that second mark to complete the token exactly for the jobs with KV work (save_k made the first mark, once per job). check_blocks(converted) requires page 0's converted-block bits to equal 0x8 (block 3 only) when converted is false and 0x9 (blocks 0 and 3) when true, and 0 on pages 1 and 2; with the option off it checks nothing (its body is under #ifdef TRON_K_VNNI). - Row-major tail block (PR-4): a 16-token block of a VNNI slot whose rows are stored row-major (one contiguous 128-value row per token, 4 lines, inside the block's own 4 KiB) until all 16 rows are saved. Note [Row-major tail block] in h/tron/tensor/k_vnni.hpp describes it. Run: consecutive items of a pass that fall into one block of one page. PR-4's store_k_block rule: a run of 16 tokens that fills its block takes the block save (set_k_block, VNNI at once); a shorter run is stored row by row (set_k_row) into the block's row-major form.
- Saved-row bits and converted-block bits (PR-4): per storage slot and page, one bit per token row that says the row was saved (k_rows_saved_), and one bit per block that says the block holds the VNNI layout (page::k_vnni_blocks). note_k_row_saved sets a row bit and returns true when the block's 16 rows are saved and the block is not converted yet (a row saved again into a complete, unconverted block returns true again; a row of a converted block returns false). note_k_block_saved sets all 16 row bits and the block bit after a whole-block save. Pending block: a block whose 16th row a pass saved row-major; save_k queues it (pending_k_blocks_, main thread only) and convert_pending_k_blocks converts it at the forward end (its Perfetto trace event is named convert_k_blocks). block_to_vnni and block_to_rows (tensor/k_vnni.hpp): the in-place conversions of one block between its row-major and its VNNI form, bit-identical to store_row per token. row_major_row: the typed row view of one token of a row-major block, 4 lines. k_row_if_row_major: the page accessor that returns a token's row-major row when its block is row-major (the FPGA staging reads it directly). k_forget_row: called when a new token takes a page offset (clear_kv_complete_at). It drops the saved-row bits of that offset and of every offset above it, and the converted-block bits of those blocks, in every storage slot (the EAGLE entry included). The offset's own block is converted back to row-major first (block_to_rows) when it was converted, keeps rows below the offset (offset % 16 != 0) and the storage is readable. Blocks above only lose their bits; their bytes are left alone.
- Storage ref (PR-4): page::k_storage_ref, the pair of a slot's storage and its layout-state entry. It is taken at the save (page::k_storage_of). A later storage-view change then cannot redirect a pending conversion. EAGLE view: the separate storage view of EAGLE speculative decoding (a draft-model technique), which keeps its own K layout state.
- Dense gate (PR-4): the third condition of the dense AMX path in h/tron/models/self_attention.hpp, after amx_q_packed and is_dense_amx_page (the dense predicate): every block of the page must hold the VNNI layout (page::k_vnni_blocks == k_vnni::BLOCKS_PER_PAGE_MASK_0XF, binary 1111).   5. Page copies, token appends and forgets carry the layout state with the rows. The EAGLE view keeps its own state. The masked partial-block path of PR-3 is removed.
