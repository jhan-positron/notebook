Short version

PR 4959 (tron pull request 4959, the last of the four PRs that split PR 4424) makes save_k in model.hpp keep short K writes row-major until their block is complete, and adds the conversion of those blocks at the end of the forward pass. save_k is the function that stores the K rows (the keys of one attention layer) of one minibatch into the KV cache (the paged store of keys and values); PR 4958 gave it the block save and the shared window this PR builds on. A run of 16 consecutive tokens that fills one 16-token block is still stored as one VNNI block (the pair-interleaved layout the AMX tile multiply reads); any shorter run is now stored row by row into the block's own row-major form, and the block is converted in place at the end of the forward pass that saves its 16th row, unless the hardware attention scores the operation (then it stays row-major). This page draws the data model, the call graph, the life of one block, the threads over one pass and the store decision once (section 1), then shows each of the four logical changes of the file beside the diagram it alters (section 2).

The four PRs of the split, one line each (a run = the consecutive tokens of one pass that land in the same 16-token block of a page)

  • PR 4956 changes how one K row is stored (scattered into the VNNI plane instead of written as a row) and how the CPU reads it (the AVX-512 reader instead of the row-major dotter).
  • PR 4957 changes who scores a full page (the AMX tile kernel reads the VNNI plane as its B operand) and how the queries are packed for it.
  • PR 4958 changes how a run of tokens is written (a 16-token block at once, transposed in registers) and which threads write it (the idle helpers share the store).
  • PR 4959 changes what a run shorter than a block saves (row-major rows) and when that block turns VNNI (at the end of the pass that completes it, or never under hardware attention). It also turns the option on in the deb package. (this PR)

KV cache / book / page / block / offset
The paged store of keys (K) and values (V). A book owns the pages of one request; a page holds 64 token offsets of K and V per storage slot and KV head (kv_cache.hpp:1994); a block is 16 consecutive offsets of a page (block c = offsets 16 c .. 16 c + 15, 4 blocks per page); the offset of a token inside its page is offset_in_page (kv_cache.hpp:2085).
storage slot / kv_slot_id / state entry
A kv_slot_id selects the persistent KV storage of one attention operation (binding.kv_slot). The page keeps its K layout state per storage slot plus one entry for the EAGLE storage (index layout_t::n_slots); k_state_ix maps a logical slot to its entry (kv_cache.hpp:2534).
KV head / head_size / kv_mul
One key/value head. A token has geometry.kv.n_kv_heads of them; each K row holds head_size bf16 values (128 for the VNNI layout). kv_mul is the number of query heads that share one KV head.
VNNI layout / VNNI block / plane
The pair-interleaved K layout (VNNI = Vector Neural Network Instructions): two consecutive dimensions of one token are adjacent, and one 64-byte line holds that dimension pair for 16 consecutive tokens. The plane is the K of one KV head of one page (16 KiB); a VNNI block is a 16-token block that holds this layout (its converted-block bit is set).
row-major rows / row-major tail block / row_major_row
The pre-conversion form of a block: token t of block c owns 256 contiguous bytes (its 128 bf16 in dimension order) inside the block's own 4 KiB, at row_major_row (tensor/k_vnni.hpp:431, Note [Row-major tail block] at 403). A row is stored there with store_row_major (4 whole 64-byte lines, tensor/k_vnni.hpp:445).
complete, may wait / converted block
Note [K VNNI storage] (kv_cache.hpp:685): a block whose 16 row bits are set is complete; it may wait for its conversion until the forward end. A converted block has its k_vnni_blocks_ bit set and holds the VNNI layout.
k_rows_saved_ / k_vnni_blocks_
Two atomic bit sets per state entry of a page: the saved rows (uint64_t, one bit per page offset, kv_cache.hpp:2648) and the converted blocks (uint8_t, one bit per block, kv_cache.hpp:2653). Every reader and writer of a row of a VNNI slot takes the layout from the block bit.
note_k_row_saved / note_k_block_saved
The page's bit publishers (kv_cache.hpp:2215, 2242). note_k_row_saved(slot, offset) sets one row bit and returns true when the row's block now has all 16 rows and is not converted yet. note_k_block_saved(slot, c) sets the 16 row bits and the block bit of a whole-block save.

One run_forward call (model.hpp:1780) runs every layer for this step's tokens. The forward end is what follows the plugin's run() (model.hpp:1834): wait_for_coop_gof (model.hpp:3577) drains the cooperative GOF staging, then convert_pending_k_blocks runs (1842), then the logits are delivered.

set_k_row / set_k_block / store_block / store_row
The page's two K store entry points. set_k_row (kv_cache.hpp:2291) stores one token's row in the layout of its block: store_row_major into a row-major block, store_row (the 4-scatter write into the token's VNNI column, tensor/k_vnni.hpp:316) into a converted block. set_k_block (kv_cache.hpp:2321) stores the 16 rows of one whole block at once through store_block (tensor/k_vnni.hpp:363: a register transpose, then whole-line stores).

PR 4958's protocol (Note [Shared block save], model.hpp:3079): when a VNNI pass holds more than 16 items and 2..128 workers, main cuts the items into work units (runs inside one block), opens a window, every worker claims units, and main joins the helpers before it records rows and marks tokens. main thread / main helpers / attention workers / worker_ix
The threads of a generated plugin: main (worker_ix 0) runs the schedule, the main helpers (worker_ix 1 .. n_workers - 1) run the per-token kernels and join the K store window, the attention workers run the attention plan and drain the FPGA staging in their idle time.
hardware attention / cached_operation_uses_hw / engagement point
Attention scored on the FPGA. cached_operation_uses_hw(operation) (model.hpp:1529) reads attention_operation_uses_hw, decided once per model. Past the engagement point (hw_attn_engagement_point, 127 by default) the FPGA holds the K/V of every DMA-complete GOF and the CPU scores only the tail. GOF / staging / gof::populate / help_drain_gof
A group of four consecutive tokens whose K and V rows the staging (gof::populate) copies into a buffer that DMA moves to the FPGA card. help_drain_gof (model.hpp:3564) is that work done by idle attention workers; it reads a block's rows row-major, which is why the conversion waits for the forward end.
mark_k_complete / credit_gof_save / upstream_kvs_ready
The marks loop after the stores (model.hpp:3433-3449): the per-token completion mark, the per-GOF dispatch credit under hardware attention, and the latch the downstream minibatches wait on.
the reader (k_vnni::qk_group) / the dotter / the AMX kernel (qk_vnni_128x4) / k_layout_dense
The three ways a page is scored (self_attention.hpp): the AMX kernel scores a dense page whose 4 blocks are all VNNI (k_layout_dense, self_attention.hpp:1915); the AVX-512 reader k_vnni::qk_group scores the tokens of VNNI blocks; the dotter (the per-token dot product) scores the rows of a row-major block through row_major_row (self_attention.hpp:2013).
AMX / AVX-512 / bf16
AMX (Advanced Matrix Extensions) is the tile instruction set of the CPU; AVX-512 the 512-bit vector instruction set; bf16 the 16-bit brain floating-point format of the stored K values (a 128-dimension row is 256 bytes).
TRON_K_VNNI / k_vnni::layout_on / TRON_AMX_DISABLE
TRON_K_VNNI is the CMake option that selects the VNNI K storage for 128-dimension heads; k_vnni::layout_on<head_size> is its compile-time gate. TRON_AMX_DISABLE=1 (the kill switch) stops the AMX kernels at run time and keeps the layout.
EAGLE
A speculative-decoding scheme whose KV storage has its own state entry (index layout_t::n_slots) in the page's bit sets; with the EAGLE view active, slot 0 maps to that entry (kv_cache.hpp:2534-2537).
TRACE_EVENT / Perfetto
A named time span in the run's Perfetto trace (tron's timing trace). convert_pending_k_blocks records 'convert_k_blocks' with the entry count (model.hpp:3172).
memory orders (acquire, release)
The C++ std::memory_order values: a release write publishes every earlier write of its thread to a thread whose acquire read sees it. The block bit is set with release and read with acquire.

M3. The row-recording loop after the join, and the hardware-attention policytop

new head lines 3411-3433 +20 / -0 lines

Commits that last touched these lines (hover for the subject): 88b81bf2f7

  • After every store is done (the join of a shared window, or the single store_k_block call), main records this pass's rows (3413-3432). For every item with KV work: page_of, offset_in_page, then note_k_row_saved(slot, j) (3426); when it returns true, the block j / k_store_block is queued as {&pg, pg.k_storage_of(slot), block} (3427-3428).
  • note_k_row_saved returns true only when the row's block now has all 16 rows saved and is not converted yet (kv_cache.hpp:2207-2231). A row of a whole-block-saved or converted block returns false, so a block is queued once per completion; a row saved again into a block that waits returns true again, and the conversion is idempotent.
  • The policy: when cached_operation_uses_hw(binding.operation) is true (3419) the loop is skipped. No row bit is recorded and no block is queued; a block that decode completes stays row-major, as Note [Row-major blocks under hardware attention] (kv_cache.hpp:763-799) explains. Whole-block saves are not affected: note_k_block_saved runs inside store_k_block (M2).
  • The loop runs only for a VNNI slot (if constexpr k_vnni::layout_on, 3413); a row-major slot keeps no bits. Worked example: the prefill records bits 0..40 and queues nothing; the decode step that saves offset 47 queues block 2 of page 7.
