Two checks on PRs 4824, 4868 and 4887

positron-ai/tron, 2026-10-15. Review comments posted by the checks described below; nothing in the code was changed.

Short version. Two checks ran over every C++ line the three PRs add: the named-bool rule and the simplify-cpp-comments skill in Check mode. They produced 326 comment findings and 43 named-bool findings, each one checked by two or three independent refuter agents before it was posted. The findings are posted as inline review comments on the PRs; the tables below link every review.

Words used here

named-bool rule
jhan's rule of 2026-10-15: use a named constexpr bool only where a bool is passed as an argument in a function call, constructor call or template argument, because a bare true or false at a call site does not say what it means. Default arguments and initializers take the bare literal (precedent: PR #4901 commit d0e6f816dd).
simplify-cpp-comments, Check mode
the skill that lists every added or changed comment a rule would cut, shorten or move, with the rule number and the proposed text. Rule 1: the name carries it. Rule 2: do not restate identifiers. Rule 3: one line for the one fact the code does not say. Rule 4: every comment line maps to a code line. Rule 5: a call-site comment says only why the call sits here. Rule 6: no comment on a language idiom. Rule 0: only comments the diff adds or changes.
refuter
an independent agent given one finding and told to refute it, through one lens: the rule as written, the code at the PR head, or diff scope and line anchoring. A comment finding is posted when at least two of three refuters did not refute it; a named-bool finding when neither of two did.

Method and limits

  • Inputs: the three PR diffs, split per file with new-file line numbers; the full files at each head for context. Only added lines were checked.
  • Finders: per changed C++ file, two comment finders with different framings (rule by rule, and the cover test) and one named-bool finder where the file has a bool candidate. Findings from the two comment finders were merged by overlapping line range; 244 of the 285 first-run comment findings were found by both.
  • Run 1 (workflow wf_a5efbc70-452) reached the 1000-agent cap before two files of PR 4868 (t_k_vnni_layout.cpp, t_llama_unit.cpp) were checked; run 2 (wf_a84b3a54-b45, 239 agents) covered them and re-ran the named-bool check under the rule wording of 2026-10-15 (template arguments in, default arguments out). Named-bool findings from run 1 were discarded.
  • Refuted: 2 comment finding(s) were dropped by the refuters (listed in findings/dropped.json): one cut a clause that exists before the PR (Rule 0), one cut a step heading that states a placement reason.
  • Not flagged under the named-bool rule: bare literals in returns, assignments, initializers, comparisons, designated initializers and default arguments; Catch2 macros; computed constexpr bools. On main the parameter-name comment form /*name=*/true appears 454 times and no *_TRUE/*_FALSE constant exists outside numeric_limits traits.
  • Not flagged under the comment rules: Note [..] blocks as a whole; inside a Note only a sentence that restates an identifier.
  • Every proposed comment line fits the 88-column limit of the project's clang-format. No code was built or run.
  • Posting: GitHub returned a 502 and then a secondary rate limit on the first large review; the rest went out in parts of at most 25 comments, 90 seconds apart. Review ids are in the table above.
  • Record: split-4424/checks-20261015/ holds the tools, the findings with every refuter vote (merged-with-votes.json.gz), the review bodies and the annotated diffs.
