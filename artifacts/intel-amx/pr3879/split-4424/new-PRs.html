The four PRs proposed from PR 4424

What each proposed PR is, and how the four relate to PR 4424. Written 2026-10-10 from split-plan.md and split-handoff.md; no execution steps here.

Short version. PR 4424 is four features in one: the VNNI K layout with its readers, the AMX kernel that reads it, the shared block save, and the row-major tail block with the hardware-attention policy.

The proposal cuts it into four stacked PRs in that order, each building on the one before: PR-1 the layout and its readers, PR-2 the AMX kernel, PR-3 the shared block save, PR-4 the tail block, the policy and the deb preset.

Together the four reproduce today's PR 4424 head; PR-3 and PR-4 are the content of the former PRs 4774 and 4737, and PR-1 and PR-2 are the rest, split along the AMX seam.

Words used here

PR 4424
positron-ai/tron pull request "VNNI K: store the K cache of 128-dimension heads in the AMX VNNI layout, with a shared block save". Draft, branch jhan-amx-vnniK, base main, head 0a5334ccb6, 29 files, +4,054 / -198 lines.
K cache, KV page, plane
The K cache holds the key vectors of past tokens. A KV page is a 64-token block of the K and V caches. The plane is the packed K storage of one page and one KV head (16 KiB).
VNNI layout
The pair-interleaved operand layout that the AMX tile multiply reads as its right operand (B operand). Storing K that way lets the kernel compute S = Q K^T without a register transpose.
AMX, AVX-512
AMX: Intel Advanced Matrix Extensions, the tile instruction set. AVX-512: the 512-bit vector instruction set, present on every host tron runs on.
The option, the kill switch
The option is the CMake switch TRON_K_VNNI (off in every preset until PR-4 puts it into the deb preset, the preset that builds the released package). The kill switch is TRON_AMX_DISABLE=1, which turns the AMX kernels off at run time.
Dotter, reader
The dotter is the row-major dot-product loop that scores K on the CPU today. The reader is PR-1's AVX-512 loop that scores K stored in the VNNI layout.
save_k, shared block save
save_k stores one pass's K rows into the cache. The shared block save writes one whole 16-token block at a time and shares the work with the idle helper threads of the main loop.
Row-major tail block
The last, partly filled 16-token block of a page, kept in plain row order until its 16th row is saved, then converted to the VNNI layout at the end of that forward pass.
Hardware attention, FPGA
Attention scores computed on the FPGA (the accelerator card) instead of the CPU. Production runs qwen3-4b that way.
Stack
A chain of PRs, each based on the previous one. Repo rule: only the PR based on main is ready for review; the others stay drafts until their parent merges.
Concern letters L, R, G, A, S, T, B
The seven parts of PR 4424 used in the plan: L layout and storage, R AVX-512 reader, G FPGA staging, A AMX kernel, S shared block save, T tail block + policy, B build and CI files.
TPS, TTFT, tp2 / tp4
TPS: decode tokens per second per user. TTFT: time to first token. tp2 / tp4: tensor parallelism over 2 or 4 engines.
Issues #4444 and #4500
#4444: the VNNI reader adds scores in a different order than the dotter, so a token can flip at a near tie against the row-major binary. #4500: the FPGA-attention decode loss caused by the per-token 64-line column access of the VNNI layout.

1. What PR 4424 contains

Every hunk of the PR was labeled by concern. Four of the seven concerns go to PR-1 (the layout cannot ship without its software reader: a build with the option on does not compile otherwise). The other three become one PR each.

2. The four PRs

PR-1

VNNI K: the layout, its AVX-512 reader and the FPGA staging path

base: main · opens as: ready for review · size: +1,846 / -160 lines (965 added lines are tests)

What it changes

  • Stores the K cache of 128-dimension heads in the VNNI layout instead of row-major rows. A new typed owner (k_vnni_tensor) and read-only or writable views replace raw pointers, which is what Ben asked for on 2026-09-21.
  • Writes every token's K row into that layout one row at a time (4 scatters per row).
  • Scores the stored K with a new AVX-512 reader (k_vnni::qk_group) wherever the software path runs: partial pages, hosts without AMX, the kill switch. Until PR-2, every page of a VNNI slot takes this reader, even on an AMX host. The reader is permanent: after PR-2 the AMX kernel takes full pages and the reader keeps the partial ones; after PR-4 the rows of a row-major tail block go to the row-major dotter, and the reader keeps the converted blocks of partial pages.
  • Teaches the FPGA staging gather to read K rows out of the layout.
  • Adds the CMake option TRON_K_VNNI (off in every preset) and turns it on in the manual CMake CI lane. The packed V layout has no such option (it is unconditional on main); the K option exists so that a row-major K build stays available as the rollback and comparison binary (issue #4444) and so that main's default build does not change until PR-4.

Why it exists

Everything else in the stack builds on the layout and on the typed views. Keeping the AMX kernel out of this PR lets reviewers without AMX background review the storage design on its own: the PR has no AMX instruction.

What you get after it merges

With the option off (every preset): no change. With the option on and no AMX: about +4 to +5 % decode throughput over the row-major reader. With the option on and AMX: about 7 to 11 % below main's AMX kernel until PR-2 (figure 5, first panel).

Temporary code

One clause that keeps the dense AMX path off for VNNI slots, and five comment sentences. PR-2 removes them.

Where its tree comes from

Built as a real tree (76a0160b72 = the tested ba69cb513e minus the AMX kernel minus the shared save). It passes a 22-cell syntax check; it has not been built or run on delphi-3bda yet.

Also carries

The open items of PR 4424 that belong to the layout and the reader. Addressed later in the stack: issue #4444 only in part (PR-4 makes the tokens identical to main in the measured CPU-attention cells; the FPGA-attention difference and the kill-switch rollback contract stay open). Not addressed by any of the four: the kv_mul 3/8 reader slowdown (the AMX kernel is eligible for kv_mul 4 only, so those models stay on the reader), the widened test tolerance, the genoa96 cost row, the benchmark-binary mismatch of the legacy lane.

PR-2

VNNI K: the AMX QK kernel reads the plane as its B operand

base: PR-1 · opens as: draft · size: +277 / -61 lines

What it changes

  • Adds the kernel qk_vnni_128x4 and its query packer pack_q_rows_128x4. The kernel takes the 4 query rows as the A operand and the page's 16 K panels as the B operand, so the scores come out as S = Q K^T with no register transpose.
  • Dispatches to it for full pages of VNNI slots and removes PR-1's temporary gate.
  • Tests: bit identity against the row-major kernel on real AMX (t_amx_numerics), the dispatch fakes (t_amx_dispatch_dtype), a typed-boundary probe.

Why it exists

This is the reason the layout exists: the transpose that the row-major kernel pays on every page is gone.

What you get after it merges

About +6 to +10 % decode throughput over main's AMX kernel at prompt 1024 to 8192 (figure 5). Prefill at short prompts is a little slower at tp4 (the per-row store) until PR-3.

Temporary code

None of its own.

Where its tree comes from

Built as a real tree (4d3a042225 = the PR-1 tree plus the AMX diff, two comment repairs). 22-cell syntax check passes; not built on delphi-3bda yet.

Also carries

The reviewers of the AMX code (Ben, Bill) review this PR; it is the smallest of the four.

PR-3

VNNI K: shared block save

base: PR-2 · opens as: draft · size: +678 / -75 lines

What it changes

  • When a pass saves 16 consecutive tokens of one page block, the 16 rows are transposed in registers and written as whole 64-byte lines (store_block, page::set_k_block) instead of 64 scatters per row.
  • The main thread shares that store with its idle helper threads: save_k takes a worker index, the code generator (TronCpp.hs) emits the helper-side call, and a window protocol hands out work units. This is the form Ben asked for in the only open review thread (the save_k_helper fold, PR 4774).
  • Tests: the block save bit for bit against the per-row store, and a three-thread save_k case.

Why it exists

The per-row store of PR-1 costs 105 ns per (token, KV head) row in prefill, 0.86 ms per layer at 8 users. That shows up as a slower first token at short prompts.

What you get after it merges

Time to first token at prompt 1024 drops below main's AMX base: about -45 ms at tp2 and -88 ms at tp4 (figure 5, second panel). Decode throughput is unchanged within 0.4 %.

Temporary code

About 15 lines of masked partial-block store logic that PR-4 replaces with the row-major tail block (decision D10 keeps the tested form).

Where its tree comes from

Its tree equals ba69cb513e, built and tested on delphi-3bda on 2026-10-08, apart from comment wording.

Also carries

Main changed the code generator by 442 lines since the merge base, so this PR's two Haskell hunks are the likeliest merge conflict of the stack.

PR-4

VNNI K: keep short K-cache writes row-major, convert at the forward end; deb preset turns the layout on

base: PR-3 · opens as: draft · size: +1,466 / -115 lines

What it changes

  • A 16-token block whose rows arrive one at a time (every decode step) is kept in plain row order inside its own bytes until its 16th row is saved; the main thread converts it to the VNNI layout at the end of that forward pass. Two bit sets per page record which rows are saved and which blocks are converted; the converted-block bit selects the layout for every reader and writer.
  • Under hardware (FPGA) attention the blocks are never converted: the FPGA reads rows, so the layout would only cost.
  • The dense AMX path takes a page only when all 4 blocks are converted; the software loop scores tail rows with the row-major dotter.
  • Turns the layout on in the deb preset (the released package), so this PR is the one that changes production.

Why it exists

Issue #4500: with the per-token column access of the VNNI layout, FPGA-attention decode on qwen3-4b lost 4 to 12 %. The tail block removes the 64-line access for decode rows and makes CPU-attention tokens identical to main again in the measured cells.

What you get after it merges

FPGA-attention decode back to the base within noise (figure 5, third panel). Whole machine, 14 nightly configs, 2026-10-09: llama-8b 32 users at 4096 +4.8 % TPS, qwen 8k software attention +7.6 %, llama-3.2-3b -1.4 % (the kv_mul 3 item), memory within 0.3 %.

Temporary code

None.

Where its tree comes from

Its content is the PR 4737 merge diff (byte-identical) plus the preset commit: the tree of 9d5c7a389b, built, tested and measured on the whole machine on 2026-10-09.

Also carries

The cost rows refresh, and the whole-machine campaign that backs the production claim.

3. How they relate to PR 4424

PR 4424's own history already holds three of the four trees. PR 4774 (the save_k worker fold) and PR 4737 (the tail block) were separate stacked PRs until 2026-10-08, when they were merged into 4424. PR-3 and PR-4 give them back their own PRs; PR-1 and PR-2 are the remaining content, cut along the AMX seam, which the history never had as separate states. The sum of the four, merged with the same main, equals today's head except for the CMake line that required AMX dispatch (dropped in PR-1, decision D2) and comment wording that the earlier PRs carry and the later ones restore.

4. How big each PR is

PR-1 is still at the repository's 95th percentile of merged-PR size. Half of it is tests. Cutting it further would mean adding the tensor type without its store and reader, which the reviewer declined on PR 4557.

5. What each step buys

7. What stays open about this picture

  • Every number above is from an older base (2026-09-14, 2026-09-15, 2026-09-30) or from the whole head (2026-10-09). The four new heads have not been measured against the latest main yet; the handoff schedules those runs.
  • PR-1 and PR-2 exist as real trees that pass a syntax check only; PR-3 and PR-4 reuse trees that were built and tested on delphi-3bda. Full builds and tests of the reduced trees are part of the handoff.
  • Whether a four-PR stack or a three-PR variant (AMX kernel folded into PR-1) suits the reviewers is decision D1 in split-handoff.md; the other open decisions (CI coverage, build host, protected sections) are listed there.
