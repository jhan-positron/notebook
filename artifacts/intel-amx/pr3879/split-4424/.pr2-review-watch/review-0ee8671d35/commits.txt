    tests: bit identity and the typed-boundary probe for the VNNI kernel
    
    t_amx_numerics gains the case "AMX QK from the VNNI K plane is
    bit-identical to AMX QK from row-major K". It stores the same K values
    twice: row-major, and through store_row in scrambled token order into a
    k_vnni_tensor. It packs the same queries with both packers. It runs
    qk_rowmajor_128x4 and qk_vnni_128x4 on them. It compares the 4 x 64
    fp32 scores (4 query rows x 64 tokens) bit for bit, for 2 seeds. Both
    kernels add the same four 32-dimension partial dot products in the same
    order inside TDPBF16PS (the AMX tile multiply instruction). So the
    scores must match bit for bit. The case needs AMX hardware. Without
    it, a WARN marks the case skipped. The packer case gains a section for
    pack_q_rows_128x4: rows 0 to 3 hold the query rows bit for bit, and the
    padding rows keep their previous bytes.
    
    The t_llama_unit case "attention operations resolve to typed KV slots"
    gains six STATIC_REQUIREs (compile-time checks): qk_vnni_128x4 accepts
    the packed K view, read-only or writable, and rejects raw pointers, the
    native K view and the V view. The alignment comment names the AMX tile
    rows.
    
    README.ci.md names the kernel case among the tests of the VNNI layout.
    It says that the case compiles in every TRON_AMX_DISPATCH build and
    executes AMX only on a Granite Rapids (the Intel CPU family with AMX)
    runner.

    amx: the QK kernel on the VNNI plane
    
    qk_vnni_128x4 (src/tron/kernels/amx_attn.cpp) is the AMX (Advanced
    Matrix Extensions, the tile instruction set) QK (query-key score)
    kernel for one dense page whose K is stored in the VNNI (Vector Neural
    Network Instructions) layout of h/tron/tensor/k_vnni.hpp. The 4 query
    rows, padded to 16, are the A operand (the left matrix) of the tile
    multiply. The page's 16 K panels (a panel is 16 dimension-pair rows x
    16 tokens, one B tile) are the B operand (the right matrix). The tiles
    come out as S[query][token]. No transpose is needed. The four
    accumulator tiles hold the four 16-token blocks. The 16-row tile stores
    go to a buffer inside the kernel, and only the 4 query rows are copied
    out. The plane address is taken once through detail::k_vnni_access.
    static_asserts tie the plane constants to the kernel constants.
    pack_q_rows_128x4 copies the 4 query rows as stored. Rows 4 to 15 stay
    the zero padding the caller keeps.
    
    amx_attn_iface.hpp declares both entry points with their typed-view
    contracts. Note [QK orientation] describes the flipped orientation, and
    the dispatch diagram names the kernel.
    
    self_attention.hpp chooses the packer at the pack site and the kernel
    at the dense-page site by k_vnni::layout_on<head_size>. A dense page of
    a VNNI slot (a KV slot stored in the VNNI layout) takes the AMX page
    path. Partial pages, the kill switch (TRON_AMX_DISABLE=1), hosts
    without AMX and kv_mul (query heads per KV head) other than 4 keep the
    AVX-512 (512-bit vector) reader k_vnni::qk_group.
    
    The comments of kv_cache.hpp, tensor/k_vnni.hpp and kernels/k_vnni.hpp
    name the two layout-specific score kernels that may take the plane
    address. With TRON_AMX_DISABLE=1 a VNNI binary runs the reader: an
    AMX-off run of the same layout.
    
    t_amx_dispatch_dtype.cpp defines fakes for both entry points. The fakes
    of both packers and both kernels count into the same probe, and the
    fake of the VNNI packer counts a second time. So a full page expects
    one pack, one QK and one PV call under either layout, and the VNNI
    packer count checks that the dispatch picks the packer of the build's K
    layout.
