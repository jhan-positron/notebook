Short version

PR 4958 (tron pull request 4958, the third of four PRs that split PR 4424) adds the block save to h/tron/tensor/k_vnni.hpp: store_block writes the K rows (the saved keys of attention) of up to 16 tokens of one 16-token block into the VNNI plane (the pair-interleaved layout that the AMX tile multiply reads as its B operand) as whole 64-byte lines, after a 16 x 16 register transpose (transpose_16x16_epi32), instead of one 4-byte scatter per (token, dimension pair, line). The file gains two constants (FULL_BLOCK_0XFFFF, LANES_16), two static_asserts, the transpose, store_block, and one sentence in the comment of store_row: several threads may store different tokens of one plane at the same time, which is what the shared save_k window of model.hpp relies on. The bytes a block save leaves in the plane are bit-identical to the per-token store (the test compares 4 blocks x 38 present masks). This page draws the plane and the present mask, the registers of one dimension step, the function model, the bytes of one block through the three store paths and the threads of one shared window once (section 1), then shows each of the four logical changes of the file beside the diagram it alters (section 2).

The four PRs of the split, one line each (a run = the consecutive tokens of one pass that land in the same 16-token block of a page)

  • PR 4956 changes how one K row is stored (scattered into the VNNI plane instead of written as a row) and how the CPU reads it (the AVX-512 reader instead of the row-major dotter).
  • PR 4957 changes who scores a full page (the AMX tile kernel reads the VNNI plane as its B operand) and how the queries are packed for it.
  • PR 4958 changes how a run of tokens is written (a 16-token block at once, transposed in registers) and which threads write it (the idle helpers share the store). (this PR)
  • PR 4959 changes what a run shorter than a block saves (row-major rows) and when that block turns VNNI (at the end of the pass that completes it, or never under hardware attention). It also turns the option on in the deb package.

K_VNNI-B1. Data model: one K plane, its panels, pair rows, lanes and the present mask

A plane is K for one KV head of one page: 64 tokens x 128 dimensions of bf16 = 16 KiB. It is 16 panels of 1 KiB, indexed by dimension step s and token block c. A panel is 16 pair rows of 64 bytes. A pair row holds one dimension pair of 16 token lanes. New in this PR is the present mask: bit t set means that lane t of the block is stored by the block save. Every arrow says how many. The worked example (unit 2 of the shared window: block 2, present 0x01ff; token 37, dimension 70) is traced through the index formula.

K_VNNI-B2. Register model: the 16 x 16 dwords of one dimension step before and after the transpose

store_block handles one dimension step at a time with 16 zmm registers of 16 dword lanes. After the loads, register t holds the row of token c * 16 + t and lane dp its dimension pair dp. After transpose_16x16_epi32, register dp holds pair row dp of the panel and lane t the token. The diagram shows both grids on the worked example, the zero registers of the absent lanes, and a table of what a lane means before and after.
