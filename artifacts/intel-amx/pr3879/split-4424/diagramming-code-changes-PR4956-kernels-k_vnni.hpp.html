Short version

h/tron/kernels/k_vnni.hpp is a new file of PR 4956 (tron PR 4956, the first of the four PRs that split PR 4424). It holds one function, k_vnni::qk_group: the AVX-512 reader that scores one query group against the live tokens of one KV page whose K plane is stored in the VNNI layout (the pair-interleaved order in which one 64-byte line holds one dimension pair of 16 tokens). The reader keeps one token per vector lane and one accumulator register per query head, reads only the tokens whose bit is set in the live mask, and adds the same products as the row-major dotter in a different order; it runs no AMX instruction, so any translation unit may include it. This page draws the data model, the function model, the loop nest, the numerics contract and the threads once (section 1), then shows each of the five logical parts of the file (Q0 to Q4) beside its diagram (section 2).

KERNELS-B1. Data model: the inputs and the output of qk_group

qk_group takes the read-only VNNI plane of one page (k_page, 16 panels of 16 pair rows), the query rows q (kv_mul rows of 128 values), the live mask (one bit per token) and the output pointer s with its row stride. One accumulator register per head holds the 16 running scores of one token block. Every arrow says how many. The worked example (kv_mul = 4, live = offsets 0..40) is traced through the masks and into s.

KERNELS-B2. Function model: callers, the three branches of qk_group, callees, and the other readers of K

apply_page_tok calls qk_group once per (page, KV head) after its loop marked the live tokens; the layout test calls it with bf16, float and fp16 queries. The function has three if-constexpr branches: the split above 16 heads, the fp16 widening, and the masked block loop. The bottom band shows the row-major dotter loop (row-major slots only), the dense AMX page path (excluded by the layout gate) and the VNNI AMX kernel of a later PR.

KERNELS-B3. Sequencing model: the loop nest of qk_group on the worked example

The block loop visits the 3 blocks whose mask is not zero and skips block 3. For one block: zero the accumulators, then for each of 4 dimension steps and 16 pair rows one masked 64-byte load and one product per head (a VDPBF16PS for a bf16 query, two FMAs for a float query), then one masked store per head. The yellow box counts the instructions of the worked example.

KERNELS-B4. Numerics model: the same products as the row-major dotter, a different order of the fp32 adds

The comment at lines 28-31 states the contract. The row-major dotter scores one token with 4 VDPBF16PS into two accumulators and a horizontal reduce_sum over 16 lanes; qk_group keeps one lane per token and adds 64 dimension-pair products into that lane in (step, dp) order. The products are the same; the order of the fp32 adds is not. The test bounds the difference with a relative envelope of 1e-4 of the absolute-product mass plus 1e-6.

KERNELS-B5. Interaction model: who runs qk_group, what it reads, what it never touches

An attention worker builds the live mask in its loop, takes the read-only view page::k_packed, calls qk_group and keeps the scores in its own s_pages. save_k writes one token's column with store_row; the reader never reads a token whose live bit is clear, so unwritten tokens cannot change the result. The test poisons dead tokens with NaN and checks that no poison reaches a live score. Threads are lanes.
