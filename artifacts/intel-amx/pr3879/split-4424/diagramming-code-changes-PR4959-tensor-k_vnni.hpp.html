Short version

PR 4959 (tron pull request 4959, the last of four PRs that split PR 4424) lets a 16-token block of the VNNI K plane (the saved keys of one KV head for one 64-token page, in the pair-interleaved order the AMX tile multiply reads) hold its rows row-major until all 16 rows are saved. In h/tron/tensor/k_vnni.hpp this is Note [Row-major tail block]: token t of block c owns 256 contiguous bytes inside the block's own 4 KiB, at panel (t / 4, c), row t % 4. The file gains the typed row view of that form (row_major_row), the two row operations on it (store_row_major, load_row_major: one memcpy of 4 whole 64-byte lines), the in-place conversion of a complete block to the VNNI layout and back (block_to_vnni, block_to_rows: a 4 KiB stack copy, then store_block or 16 row stores), and the bit helpers that name the page's layout state (block_bit, offset_bit, BLOCKS_PER_PAGE_MASK_0XF, PANEL_ROWS_4). Which form a block holds is recorded by the page in kv_cache.hpp; the operations here take the layout from the caller. This page draws the plane with one block in both forms, the bit model, the function model, the life of one block's bytes and the thread model once (section 1), then shows each of the five logical changes of the file (K0 to K4) beside its diagram (section 2).

The four PRs of the split, one line each (a run = the consecutive tokens of one pass that land in the same 16-token block of a page)

  • PR 4956 changes how one K row is stored (scattered into the VNNI plane instead of written as a row) and how the CPU reads it (the AVX-512 reader instead of the row-major dotter).
  • PR 4957 changes who scores a full page (the AMX tile kernel reads the VNNI plane as its B operand) and how the queries are packed for it.
  • PR 4958 changes how a run of tokens is written (a 16-token block at once, transposed in registers) and which threads write it (the idle helpers share the store).
  • PR 4959 changes what a run shorter than a block saves (row-major rows) and when that block turns VNNI (at the end of the pass that completes it, or never under hardware attention). It also turns the option on in the deb package. (this PR)

K_VNNI-B1. Data model: one K plane and the two forms of one 16-token block

A plane is K for one KV head of one page: 16 panels of 1 KiB, one per (dimension step s, token block c). A block owns the 4 panels of its column, 4 KiB. In the row-major form a panel holds 4 token rows of 256 bytes (PANEL_ROWS_4); in the VNNI form it holds 16 pair rows of 64 bytes. The worked example (page 7, slot 5, KV head 0) has blocks 0 and 1 converted, block 2 row-major with 14 rows, block 3 empty; token 37 and dimension 70 are followed to their element in both forms.

K_VNNI-B2. The bit model: the saved-row bits, the converted-block bits and the helpers that name them

The page (kv_cache.hpp) keeps two words per storage slot: k_rows_saved_ (one bit per page offset) and k_vnni_blocks_ (one bit per 16-token block). This file names the bits: offset_bit, block_bit and BLOCKS_PER_PAGE_MASK_0XF. The diagram shows the worked example's words, the block states they encode, and the readers of the bits.

K_VNNI-B3. Function model: every operation the PR adds, its callers and what it calls

The operations are grouped by purpose: the bit helpers, the row-major form of a block, the in-place conversion, and the unchanged operations of PR 4956 and PR 4958 that the new ones call. Every cell says in one line what the function does and cites its definition. Callers in other files sit at the left with their call-site lines.

K_VNNI-B4. Sequencing model: the bytes of one block from its first row-major row to the VNNI form and back
