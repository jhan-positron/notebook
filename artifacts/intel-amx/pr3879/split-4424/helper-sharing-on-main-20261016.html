Can PR 3's helper sharing and PR 4's tail block boost tron without the VNNI layout?

Short version. PR 3's sharing of the K store with the idle helpers is layout-independent and could be applied to main's K and V stores in an independent PR. It would shorten prefill only: est. 1.4 to 2.6 % of time to first token at tp2 and about 6 % at tp4 (qwen3-4b, 8 users, prompt 1,024 tokens), and nothing in decode. PR 4 has no technique that helps without the layout, and the stack's decode gains come from the layout-bound scoring paths of PR 1 and PR 2.

main thread, main helpers, attention workersA generated plugin runs the schedule on one main thread. The main helpers run the per-token kernels (rmsnorm, rope, swish). Ready, PendingAttention sections over pages complete before this pass (Ready) and over pages written in this pass (Pending). A Pending section cannot start before Save V ends.
tp2, tp4The model split over 2 or 4 FPGA cards. TTFT = time to first token (the batched prefill). TPS = decode tokens per second per user.
VNNI layoutThe K storage of PR 1 (#4956): one 64-byte line holds one dimension pair of 16 tokens. Main's K is row-major (one 256-byte row per token). Main's V is already VNNI-packed with even and odd tokens merged in one line.
est.An estimate, not a measurement.

PR 4

Every mechanism (row bits, forward-end conversion, hardware-attention policy, dotter over tail rows, page-reuse and copy bookkeeping) either restores a property main already has or manages the state a two-layout page needs. Its FPGA-attention gains against its parent (+2.5 % at tp2, +12.1 % at tp4) return the stack to main (+0.6 % and -0.3 % against main, inside the band). Ported alone to main, the only effect would be cost (two extra atomic loads per new token, a conversion with no consumer).
