Words used here

tron, rinzler, runtron
tron is the inference program under test; rinzler is its production server (what the serving tests drive); runtron is its command-line tool (what the prompt-8192 point uses).
AMX, AVX
Intel Advanced Matrix Extensions (tile matrix instructions the new attention kernels use) and the older vector instructions the existing code uses.
K, V, KV cache, page
The stored attention keys and values of served tokens; a page holds 64 tokens. For every prefill token the server writes one K row (128 bf16 values, 256 bytes) per layer and KV head.
canonical, mirror, VNNI
canonical = the AMX kernel reads K exactly as stored (PR 1, #3879). mirror = PR 2 keeps a second copy of K in ordinary RAM in the VNNI layout (the order the AMX tile multiply consumes: each token's values are spread over 64 cache lines instead of 4). single-K = Bill's proposal to store K once, in the VNNI layout, inside the existing K plane.
PR 0, PR 0b, PR 1, PR 2, SK-A/B/C
PR 0 (#4267) = page-share counters; PR 0b (#4265) = one-line memory-order fix plus, today, a regression test; PR 1 (#3879) = canonical AMX path; PR 2 = the mirror, a local branch only; SK-A/B/C = the three single-K pull requests planned after the gate (accessors; readers and FPGA staging adapter; primary VNNI store).
G1, G2, G3, gate 2026-09-16
The measurements that decide single-K (breakup plan section 5.2): G1 = cost of the VNNI store, G2 = cost of the FPGA staging transform (GOF) from the VNNI plane, G3 = the AVX fallback reader on Granite Rapids. The gate meeting reads them on 2026-09-16.
TTFT, TPS, arm, run
TTFT = time to first token in ms (the prefill latency a client sees); TPS = decode tokens per second per user. An arm = one binary plus its switches; a run = one rinzler process serving one model for one perf measurement (10 rounds of the systems_test harness, prompt about 1000 tokens, 1536 generated).
probe binary, sonly, inplace
rinzler.g1 / runtron.g1 = round 1's head 60d66d9c04 plus a 56-line debug commit (fceeddc529 on branch jhan-dd-g1-store). The environment variable TRON_DD_G1 changes how K is stored: sonly = no canonical store, scatter into the arena only; inplace = no canonical store, scatter into the page's own K plane, and the AMX kernel reads that plane. Both give wrong numerics on purpose (canonical readers see permuted or stale K); only timing is meaningful. Unset = the mirror arm unchanged.
half split, the monitor, the guard, cost data
Bill has cards 10/13/38/3b and socket 0; we have cards 90/93/b9/bc and socket 1. Whole-machine work only when Bill has no work process. The monitor (exec/bill-watch.sh) writes CLEAR or STOP every 30 s; the guard (exec/lib-guard.sh) refuses launches while the CI lease, another person or serving is active. Cost data = the per-test timing entries CI requires in config/test-benchmarks.json, produced by a whole-machine bench.

4. Do we have enough data to call the single-K series over PR 2?

Update 14:00 UTC: the campaign ran; the first G1 numbers are in Tuesday-morning-status.html (same folder). On qwen at 8 users the in-place VNNI store is +11.7% slower to first token than canonical, far above the 2% kill line; the text below is the state before those numbers.

Not yet. The question splits into three propositions. The first is settled by measurement; the second and third have no measurement at all, and today's G1 run is the first number for the second. The gate date stays 2026-09-16.

A fourth fact frames the value of the whole question: ingested models (qwen, gpt-oss) run hardware attention by default, so every AMX gain measured so far needed USE_HW_ATTN=0. Whether production will run qwen-class models with software attention at all is the open question to Jeremy (decision 10). If the answer is no, the AMX path's value is confined to EAGLE, software-required ranges and the HBM-exhaustion fallback, which lowers the stakes of both PR 2 and single-K.

What today settles and what it cannot

  • Settles: whether the VNNI store pattern, by itself and in the hugepage K plane, costs first-token time at 8 concurrent prefills (proposition b, the G1 kill criterion); the root cause class of PR 2's penalty (arena vs pattern vs double store); whether the penalty scales with concurrency.
  • Cannot settle: the gate's second clause (save_k time per row more than twice today's 70 ns: the probe has no per-row timer; a store microbenchmark with 1 and 8 writers on adjacent tokens would, about 90 minutes of code, half machine); G2 and G3 (no harness, no port yet; the standalone probe on one Granite Rapids core gives an indicative G3 number in minutes); decode speed of a real single-K build (the probe reuses the mirror kernel but the AVX fallback still reads canonical K, so its TPS column is not a single-K decode number); anything on the current base (the probe is the old head); page capacity (unchanged by design); anything about numerics (the probe's are wrong on purpose); whether PR 2's penalty is fixable (today names the component, not a fix).

7. Rules and traps for the day

  • Half split stands. Whole-machine work only while the monitor says CLEAR. The campaign holds the campaign lock only while it runs cells; while it waits for Bill it releases the lock and kills nothing, so half-machine work of ours can proceed beside a dormant campaign. To stop it for good: pkill -f 'g1-20260908/g1-campaign[.]sh'; its exit trap stops its own rinzler and writes summary.md.
  • The monitor's own kill matches a process named exactly rinzler; the campaign's processes are rinzler.canon, rinzler.mirror, rinzler.g1, so the campaign runs its own 10-second watcher, which kills only its own processes (binaries by absolute path, the harness by its result path). Do not rely on the monitor alone for other rinzler scripts.
  • SYSTEM_CONFIG="--instance 1,2" is exported by the login environment and tron applies it after the command line; every tron process in the campaign runs under env -u SYSTEM_CONFIG. The placement proof lines ("Configured instance", "App CPU list") are kept per run.
  • Never edit g1-campaign.sh after the lease clears: bash reads a running script incrementally from NFS. Until then edits are safe because only the small waiter is running. Versions 1 and 2 are kept as g1-campaign.sh.v1-20260908 and .v2-20260908.
  • The probe arms' outputs are numerically wrong by design. Never quote their tokens, accuracy or the TPS column as single-K decode numbers. Every K-mirror build (mirror, g1mirror, sonly, inplace) reads K through the mirror kernel; only off, canon and canon2 use the canonical kernel, so probe-vs-canon deltas include the kernel difference (the mirror kernel was about 8% faster per attention unit on 2026-09-01).
  • The campaign does not measure the gate's second clause (save_k time per row more than twice 70 ns); that needs the store microbenchmark listed in section 6. G1 cannot be closed from the campaign alone.
  • Idle production serving is stopped only after 10 quiet minutes (journal and connection checks, round 1's recipe); the 02:45 UTC timer brings it back.
  • No new run between 01:30 and 11:00 UTC (pre-CI hold, CI prep 02:45, lease about 03:37).
