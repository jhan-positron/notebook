## Short version

PR #4267 adds page-share counters (counts of how many query tokens use each visit to a KV page in the software attention loop; a visit is "shared" when two or more do) behind a compile-time option, and prints their totals to stderr once, at process exit. The approving reviewer asked whether the counters could instead be published as files in tron's FUSE stats tree, with collection opt-in at run time (the review suggested an environment variable), so that they can be read while the process runs and measured over an interval. This issue tracks that follow-up, with one prerequisite: an A/A control benchmark (two builds that should run at the same speed) showing that the counting code, compiled into every build but switched off by the environment variable, costs nothing measurable.

## Words used here

- tron: the inference program this repository builds. runtron: its command-line tool. rinzler: its production HTTP server. Both binaries would publish the counters.
- batch runtron run: a runtron invocation that processes fixed prompts and exits, as opposed to serving requests.
- software attention: attention computed on the CPU rather than on the FPGA. KV page: a 64-token block of the key/value cache. KV head: one key/value head of the model; several query heads share it. query token: a token whose attention is computed in the current step; it reads the KV pages of earlier tokens.
- `apply_page_range` (`h/tron/models/self_attention.hpp`): the software attention function that visits a range of KV pages for one KV head. page visit: one pass of that function over one page. hooks: the five short `#ifdef` code blocks that #4267 adds to that function.
- FUSE (Filesystem in Userspace): a Linux interface that lets a process serve a directory tree which other programs read with ordinary file operations (for example `cat` on a file in the tree).
- FUSE stats tree: the directory tree tron serves (`README.stats.md`; API in `h/system/fuse_stats.hpp`). platformd: the host agent that reads the `/exported/` part of each rinzler mount and serves the values to Prometheus (a metrics database that polls an HTTP endpoint). tronstats: the naming convention the tree follows, and platformd's collector library that reads it.
- leaf: one file in that tree, created with `stats::make_file`; an optional read callback computes the value on every read.
- casual leaf: a leaf outside `/exported/`, readable by hand, with no convention obligations. exported leaf: a leaf created with `exported=true` and mirrored under `/exported/`; it must have a descriptor (a small YAML entry giving description, unit and Prometheus type, declared in `src/system/fuse_tronstats_manifest.cpp`).
- A/A control: two runs, or two builds, that are expected to give the same result.
- gated-off build: this change, built normally and run with the environment variable unset. current main (option OFF): today's build, with no hooks compiled in.

## What #4267 contains (head ef13273ba9)

`h/tron/kernels/page_share_counters.hpp` holds five process-wide totals and a 7-slot histogram of query tokens per visit (1, 2, 3, 4, 5-8, 9-16, more than 16); all 12 are `std::atomic<uint64_t>` (counters that several threads can add to without a lock). A `page_visit_counts` struct collects one `apply_page_range` call's counts as plain integers (`record_page_visit`) and adds them to the totals (`flush`). A static object `report_at_exit` prints the totals to stderr at normal exit (the "exit summary" below). The whole header is inside `#ifdef TRON_PAGE_SHARE_COUNTERS`. The five hooks in `apply_page_range` are: (1) declare `visit_counts` once per call, (2) declare `n_relevant_query_tokens` once per page, (3) increment it for each (page, query token) pair whose query token had relevant keys on that page, (4) call `record_page_visit` once per page, (5) call `flush` once per call. The CMake option `TRON_PAGE_SHARE_COUNTERS` defaults OFF and is ON only in the `coverage` CMake preset (a named build configuration in `CMakePresets.json`), so production and benchmark binaries carry no hooks and no atomics today. `t/t_page_share_counters.cpp` has four test cases (Catch2, the C++ test framework this repository uses) that call `record_page_visit` and `flush` directly.

## Proposed design

1. Keep the data path unchanged: `page_visit_counts`, `record_page_visit` and `flush` stay as they are. Remove the header's outer `#ifdef` so the atomics and the struct compile in every build.
2. Gate at run time at the hook sites, not inside the struct. Add a non-template inline function `page_share::enabled()` to the header that reads the environment variable `TRON_PAGE_SHARE_COUNTERS` (same name as the CMake option it replaces) once per process through a function-local static (a variable initialized on the first call and kept for the life of the process; pattern: `init_logits_chunk_size` in `h/tron/models/model.hpp`). Collection is on when the variable is set to `1`; unset or any other value means off. Copy the value into one `const bool` local next to hook 1 (`apply_page_range` is a template; a static inside it would be one object per instantiation, not one per process) and gate only the increment in hook 3. `record_page_visit` already returns when the count is 0. `flush` already returns when no visit was recorded. So with the environment variable unset no atomic is written. The four test cases pass with no code change.
3. Publish casual leaves under `/rinzler/stats/page_share/` (the process-level prefix; runtron uses it too): one read-only `uint64_t` leaf per total (`page_visits`, `relevant_query_tokens`, `shared_visits`, `shared_tokens`, `pending_visits`) whose read callback returns the atomic's current value, and one `std::string` leaf `histogram` with the seven slots as a JSON array. Pattern: `h/tron/models/expert_stats.hpp`. Leaf layout is Decision 4 below.
4. Register the leaves from both `main()` functions before `stats::start()` (the call that mounts the tree), next to `pos_heap_register_fuse_stats`, with the `fuse::stats::is_initialized()` early return that `expert_stats.hpp` uses. `register_memory_pressure_fuse_stats` in `src/rinzler.cpp` is the same pattern.
5. Keep the exit summary. On their normal exit paths both binaries unmount the tree before static destructors run (`stats::unmount()` in rinzler's shutdown handling, the `unmount_guard` in runtron), so a leaf cannot deliver an end-of-run total for a batch runtron run. The summary already prints nothing when no visit was counted.
6. Remove the build-system parts of the compile-time gate: the CMake option, the compile definition (`target_compile_definitions(tron PUBLIC ...)`) in `src/tron/CMakeLists.txt`, the `coverage` preset entry, the `README.ci.md` paragraph (replace it with one sentence on the environment variable and the leaf path), and the `DEFINES` clause of the test in `t/CMakeLists.txt`. Rewrite the four comments that describe the compile-time gate: in the header, in the test file, above the test's `add_catch_test` line in `t/CMakeLists.txt`, and on the include line in `self_attention.hpp`. The `config/test-benchmarks.json` entry for the test stays.
7. Add one test case that registers the leaves on the process-wide stats object after `stats::initialize()` and without `stats::start()` (the way the `StatsEnvironment` test setup in `t/t_tronstats_convention.cpp` does), flushes a known `page_visit_counts`, and checks through `file_handle::get_value()` how much each leaf value rose. Check the rise, not the absolute value, because the existing flush case also adds to the totals.

Size estimate: about 10 files, roughly +60/-40 lines. If Decision 1 picks exported leaves, add one descriptor per leaf in `src/system/fuse_tronstats_manifest.cpp`, a registration helper, a `.skip` marker for the new directory (the convention test `t/t_tronstats_convention.cpp` fails when a new grouping directory, one that only groups leaves and is not a label, has no marker; `README.stats.md`, "Mark new grouping directories"), and edits to that test. Commit 2e8de30219 (leaves for the temperature registers of each FPGA's HBM, high-bandwidth memory: 7 files, +250/-5 lines) shows that size.

## Prerequisite: A/A control of the gated-off build

Today current main (option OFF) has no hooks in `apply_page_range`. After this change every binary, including the production rinzler package, carries the hooks even with the environment variable unset: one conditional test (a branch) per (page, query token) pair that reaches the attention kernel, one per page visit (the early return in `record_page_visit`), one per `apply_page_range` call (the early return in `flush`), plus two local variables (`visit_counts` and `n_relevant_query_tokens`) that must stay in a register or on the stack for the whole inner loop. The cost of that with the environment variable `TRON_PAGE_SHARE_COUNTERS` unset has not been measured.

Before opening the PR: run the CI benchmark tool `bin/ci/benchmark_save.py` (the tool that the CI script `bin/ci/ci-run-benchmark.sh` runs) once at current main and once at a commit with the gated-off build, and compare the two with `bin/ci/benchmark_info.py -c <gated-off commit> -r <main commit>`. Configure `gen/` with the CI `native` preset first and pass `--grid --paranoid` with `--cpus-per-machine` set to the host's core count (the form `ci-run-benchmark.sh` uses when no build artifact exists; the tool refuses a host whose core and card counts differ from the flags, so use a whole host). The tool writes into `/scratch/tron-benchmark/`, the CI record store, and `benchmark_info.py` reads only that directory, so the two hand runs leave two extra records there. Acceptance: the comparison reports no change on every workload. The run-to-run spread (how much the timing of identical code differs between two runs) is not in the existing records: the store keeps one record per commit and host. So measure a same-code pair first (main against main plus an empty commit). Without that spread, it is unknown whether a "no change" verdict can detect a slowdown of the size this change could cause. If acceptance is not met, the compile-time option stays, and the FUSE leaves are compiled only when that option is ON.

## Decisions to take before the PR

1. Casual leaves (readable with `cat`, no descriptor) or exported leaves (collected by platformd for Prometheus, needs descriptors)? The reviewer who asked for FUSE decides.
2. "Measured over random chosen intervals": the proposal interprets this as subtracting two reads of the cumulative counters (value at the end of the interval minus value at the start), which needs no new code. A reset leaf (a writable file that sets the counters back to 0) would break the `prometheus_type: counter` rule (a counter only ever increases since process start; `README.stats.md`, "Declare the descriptor") if the leaves are exported; casual leaves carry no such rule. Confirm with that reviewer.
3. Keep the exit summary? It is the only end-of-run record for a batch runtron run, and no script consumes it today.
4. One leaf per value (step 3), or one `summary` JSON leaf with all 12 values? One callback reads the 12 atomics a few nanoseconds apart instead of in 12 separate `cat` calls, but the values can still differ by one in-flight `flush`, which adds to the 12 atomics one at a time. Default: one leaf per value.

## Done when

- [ ] A/A control result recorded in the PR: gated-off build vs current main (option OFF), "no change" on every workload, with the same-code spread measured first.
- [ ] With `TRON_PAGE_SHARE_COUNTERS=1` in the environment, `cat` on `page_visits` and `relevant_query_tokens` under `/rinzler/stats/page_share/` returns rising counts while runtron or rinzler runs (the `shared_*` leaves rise only when a visit served two or more query tokens, and `pending_visits` only in the second attention pass of a step); two reads subtracted give the count for the interval between them.
- [ ] With the environment variable unset or set to `0`, while runtron or rinzler runs after some attention work, each of the five total leaves reads 0, `histogram` reads seven zeros, and the exit summary prints nothing.
- [ ] Either (a) acceptance met (no change on every workload): CMake option, compile definition, preset entry and test `DEFINES` removed; or (b) acceptance not met: option kept and the leaves compiled only when it is ON. `README.ci.md` and `README.stats.md` updated in both cases.
- [ ] The four existing `t_page_share_counters` cases pass with no code change (the four comments listed in design step 6 are rewritten), plus the new leaf case.
- [ ] Decisions 1 to 4 above recorded in this issue.
