## 1. Short version

Wade's FUSE idea fits tron's existing stats tree, because the PR's counters are already process-wide atomics and the tree already has a read-callback precedent for exactly this shape [h/tron/models/expert_stats.hpp:156-161]. The real change is not the FUSE part but the gate: the compile-time option would become an environment variable, which compiles a disabled branch into the attention page loop of every binary, including production, and that cost is unmeasured. My call is to merge #4267 as Wade approved it and do the FUSE version as a follow-up, after an A/A benchmark of the gated-off build shows the difference is inside noise.

**Words used here**

- tron: the inference program under test. rinzler: its production HTTP server. runtron: its command-line tool.
- FUSE (Filesystem in Userspace): a Linux interface that lets an ordinary process serve a directory tree that other programs read with normal file calls such as `cat`.
- tronstats: tron's FUSE stats tree, served by a thread inside rinzler or runtron and mounted at startup [src/system/fuse_sysfs.cpp:301-320].
- leaf: one file in that tree, created with `make_file`; an optional read callback computes its value on each read.
- casual stat: a leaf created without `exported=true`; readable by hand, outside `/exported/`, no descriptor needed. exported stat: a leaf created with `exported=true`, mirrored by a symlink under `/exported/`, and required to carry a descriptor [README.stats.md:224-237].
- platformd: the external host agent whose tronstats collector scans `/exported/` in each instance's mount and serves the values on a Prometheus endpoint at `:9100/metrics` [README.stats.md:61-62; src/system/fuse_tronstats.cpp:208-209]. Its source is not in the tron repo.
- Prometheus: a metrics database that scrapes HTTP endpoints; a Prometheus "counter" only rises and resets only on process restart [README.stats.md:405-409].
- KV page: a 64-token block of the key/value cache. `apply_page_range`: the software attention function that walks a range of KV pages for one KV head; it is called once per section of a worker's plan [ef13273ba9:h/tron/models/self_attention.hpp:1254-1359, :982-987].
- page visit: one `apply_page_range` pass over one KV page; the PR counts a visit only when at least one query token was relevant to that page [ef13273ba9:h/tron/kernels/page_share_counters.hpp:78-80].
- static destructor: the destructor of a process-lifetime object; it runs on return from main or `exit()`, not on `abort()`, a crash, or SIGKILL [ef13273ba9:h/tron/kernels/page_share_counters.hpp:115-118].
- A/A control: two runs expected to give the same result, used to bound noise or to show a change has no effect.
- Revisions: unprefixed citations are the tron checkout at main 9b11a912ba; "ef13273ba9:" is the PR #4267 head; "26a0338c3b:" is the AMX PR #3879 head.

## 2. What Wade is asking

Wade approved #4267 at head ef13273ba9 (review 5156698046, 2026-09-09) and added: "I'm wondering if you looked at the possibility of using FUSE for this? Collection could still be opt-in (via env-var maybe), then they could be inspected live and measured over random chosen intervals instead." ## 3. What already exists in tron

- **The FUSE stats tree is default-on and mounted by both binaries.** `option(ENABLE_FUSE_STATS ... ON)` [CMakeLists.txt:45]. runtron initializes and starts it unconditionally in main() [src/runtron.cpp:494, :506]; rinzler does the same [src/rinzler.cpp:4220, :4435]. With the option OFF, `make_file` and read callbacks still work in memory; only `mount()` and the FUSE thread are skipped [src/system/fuse_sysfs.cpp:301-320; README.stats.md:503-505]. CI mounts the tree in the test-host, test-fpga, benchmark and coverage jobs and unmounts it in cleanup steps [.github/workflows/cmake-single-platform.yml:53-56, 474-476, 594-596, 752-754, 770-773; cpp-coverage.yml:20-22, 51-54, 98-101].
- **The API.** `stats::make_file(path, value, read_only=false, exported=false)` aborts through TRON_ASSERT if `stats::initialize()` never ran [h/system/fuse_stats.hpp:101-106]. A value is a variant of bool, int, double, int64_t, uint32_t, uint64_t, std::string [h/system/fuse_sysfs.hpp:28-29]. `set_read_callback` may be installed after `stats::start()` [h/system/fuse_stats.hpp:161-164]. The callback runs on libfuse worker threads (up to 10 at once), from `op_read` and also from `op_getattr`, so one `cat` fires it about three times [src/system/fuse_sysfs.cpp:305-313, 627-638, 729-741; libfuse lib/fuse_loop_mt.c:37, 176-178]. `op_read` has no try/catch around the callback [src/system/fuse_sysfs.cpp:734-736]. Read-only leaves report mode 0444 and reject writes with EACCES [src/system/fuse_sysfs.cpp:636, 764-766].
- **expert_stats.hpp is the model-layer precedent for a counter plus a histogram.** It returns early when stats are not initialized [h/tron/models/expert_stats.hpp:145]. `total_passes` is a uint64 leaf created with `read_only=true, exported=true` whose callback returns a relaxed atomic load [:156-161], with a descriptor registered right after [:162]. The per-router `counts` and `active_histogram` are JSON string leaves ("[v0,...,vN-1]"), not exported, and intentionally without a Prometheus descriptor [:181-196, :68-70]. Those rows are plain uint64 arrays; writer and reader both take a per-router mutex, which is what makes each row read consistent [:102, :108, :116, :123]. Collection itself has no runtime gate [:105-112]. Registration runs from `model<>::load_safetensors` [h/tron/models/model.hpp:1065-1067], which in both binaries runs after `stats::start()` [src/rinzler.cpp:4435, :4441; src/runtron.cpp:506, :519]; that is the documented "dynamic file" exception [h/system/fuse_stats.hpp:144-150]. The comment at model.hpp:1062-1063 claiming it registers "before stats::start()" is wrong.
- **Wade's own HBM thermal stat (commit 2e8de30219, 2026-09-04, 7 files, +250/-5).** `pos_hbm_thermal_regs_fuse_stats()` creates, per device, six exported gauge leaves under `/rinzler/stats/hbm_thermal/<bdf>/` with `make_file(uint64_t{0}, read_only=true, exported=true)` and a callback that performs one MMIO register read per firing [src/pos/device.cpp:774-845, :801-834], plus one casual `idx` leaf [device.cpp:838-840]. It needed a new descriptor family `kHbmThermalMetrics` [src/system/fuse_tronstats_manifest.cpp:712-737], a helper `register_tronstats_hbm_thermal_metrics` [src/system/fuse_tronstats.cpp:286-294], a `.descriptor.yaml` marker with a new `name` field [manifest.cpp:67-69], and convention-test edits [t/t_tronstats_convention.cpp:53, 389, 477-489]. Its body sits under `#ifdef TRON_FUSE_STATS_ENABLED` [device.cpp:775, 844], and it is called lazily from `get_devices()` [src/pos/driver.cpp:817]. Wade's own comment records that one `cat` samples the register about three times [device.cpp:758-764].
- **Registration sites.** There is no "register everything" helper; each family is called by name before `stats::start()` [src/runtron.cpp:501-506; src/rinzler.cpp:4407-4435]. Process-wide library counters already reach FUSE by the pattern "library holds the atomics, application registers the files": token_cache counters published at `/rinzler/stats/memory_pressure/*` from rinzler main [src/rinzler.cpp:3962-4035, called :4413], and dma_heap counters published from the system library and called from both mains [ef13273ba9:src/system/memory.cpp:498; src/runtron.cpp:501; src/rinzler.cpp:4407]. `/rinzler/stats/` is the process-level prefix; `/model/<id>/` is the per-model prefix [README.stats.md:282-289].
- **Writable leaves and reset.** `/rinzler/config/*` knobs use `make_file(read_only=false)` plus `set_validation_callback` storing into an atomic [src/rinzler.cpp:4309-4335; README.stats.md:281]. The only write-triggered action leaf is the opt-in `HBM_ALLOC_SHADOW` dump trigger [src/pos/alloc.cpp:414-460]. No reset-on-read exists, and counters are documented as monotonic since process start [README.stats.md:407-409].
- **Runtime opt-in precedents.** Tron reads process-wide flags once through a function-local static from `getenv` [h/tron/models/model.hpp:79-85; h/tron/models/kv_cache.hpp:446-449; 26a0338c3b:src/tron/kernels/amx_attn.cpp:84]. The closest precedents for env-gated collection are `TRON_HW_SAMPLER` [src/pos/hwperf.cpp:126-129] and the heap shadow map `TRON_HEAP_SHADOW`, which is always compiled and has no CMake option [src/system/CMakeLists.txt:37-41; src/system/memory.cpp:105-108].

## 4. What the FUSE design would look like

The PR today: six named `inline std::atomic<uint64_t>` totals (12 atomics, 96 bytes), a per-call `page_visit_counts` struct, `record_page_visit`, `flush`, and an `exit_reporter` static destructor, all inside `#ifdef TRON_PAGE_SHARE_COUNTERS` [ef13273ba9:h/tron/kernels/page_share_counters.hpp:18-153]; five `#ifdef` hook blocks in `apply_page_range` [ef13273ba9:h/tron/models/self_attention.hpp:1290-1292, 1300-1302, 1333-1335, 1352-1354, 1356-1358]; the option and its wiring [ef13273ba9:CMakeLists.txt:47; src/tron/CMakeLists.txt:231-237; CMakePresets.json:118; README.ci.md:513-522]; the test with its own define [ef13273ba9:t/CMakeLists.txt:268-271].

The sketch:

1. **Keep the data path as it is.** `page_visit_counts`, `record_page_visit` and `flush` stay unchanged [ef13273ba9:page_share_counters.hpp:67-112]. Remove the header's outer `#ifdef` (lines 18 and 153) so the atomics and the struct compile in every build.
2. **Runtime gate at the hook sites, not inside the struct.** Keep the `visit_counts` declaration unconditional [self_attention.hpp:1291]. Next to it add `static const bool counting = page_share::enabled();`, where `enabled()` reads `getenv("TRON_PAGE_SHARE_COUNTERS")` once in the existing idiom [h/tron/models/model.hpp:79-85]. `apply_page_range` is a member function template, so the static is one object per instantiation and `getenv` runs once per instantiation. Change block 3 to `if (counting && relevant_k_tokens > 0) n_relevant_query_tokens++;` [self_attention.hpp:1334]. Blocks 4 and 5 need no gate: `record_page_visit` returns when the token count is 0 [page_share_counters.hpp:79] and `flush` returns when `page_visits` is 0 [page_share_counters.hpp:100]. With counting off, no atomic is ever touched.
3. **Publish leaves.** Add a free function `page_share::register_fuse_files()` that returns early unless `fuse::stats::is_initialized()` [pattern: h/tron/models/expert_stats.hpp:145]. Under a casual path such as `/rinzler/stats/page_share/` (process-level prefix, same as dma_heap and memory_pressure) create one `uint64_t` leaf per total (`page_visits`, `relevant_query_tokens`, `shared_visits`, `shared_tokens`, `pending_visits`) with `read_only=true` and a callback returning a relaxed load [pattern: expert_stats.hpp:156-161], plus one `std::string` leaf `histogram` rendering the seven slots as `[h1,h2,h3,h4,h5_8,h9_16,h17plus]` [pattern: expert_stats.hpp:164-175, 189-196]. Alternative: one `summary` JSON leaf holding all 12 values, which narrows the read-skew window to one callback. A casual leaf under a new directory needs no `.skip` marker because the convention lint walks only `/exported/` [src/system/fuse_tronstats_lint.cpp:164-227; t/t_rinzler.cpp:4595]. Callbacks must be thread-safe because several libfuse workers can run them at once; relaxed loads and a local string buffer are.
4. **One registration call in each main, before `stats::start()`.** runtron: between lines 505 and 506 [src/runtron.cpp:505-506]. rinzler: between lines 4433 and 4435 [src/rinzler.cpp:4433-4435]. This matches `pos_heap_register_fuse_stats` [h/system/memory.hpp:136; runtron.cpp:501; rinzler.cpp:4407] and gives static files, so no scraper rescan is needed.
5. **Exit summary: keep it.** rinzler unmounts the tree before static destructors run [src/rinzler.cpp:4622-4639], and runtron's `unmount_guard` unmounts on any return from main [src/runtron.cpp:483-485], so a FUSE leaf cannot give an end-of-run total for a batch runtron campaign. The reporter already prints nothing when no visit was counted [page_share_counters.hpp:125-127], so with counting off it is silent. Dropping it is possible but removes the only end-of-run record.
6. **Remove the build plumbing.** Delete the option [ef13273ba9:CMakeLists.txt:47], the PUBLIC compile definition block [src/tron/CMakeLists.txt:231-237], the coverage-preset cache variable and its trailing comma [CMakePresets.json:117-118], and replace the README.ci.md paragraph [README.ci.md:513-522] with one sentence on the env var and the FUSE path. The test's `DEFINES TRON_PAGE_SHARE_COUNTERS` clause and its three-line comment become a no-op and should go [ef13273ba9:t/CMakeLists.txt:268-271]; the test file's header comment needs the same edit [ef13273ba9:t/t_page_share_counters.cpp:6-11].
7. **Tests.** The four Catch2 cases pass unchanged because they include only the header and call `record_page_visit` and `flush` directly [ef13273ba9:t/t_page_share_counters.cpp:21, 43-117]; that holds only if the gate is at the hook sites, not inside those two functions. An optional fifth case can create the leaves in memory and read them through `file_handle::get_value()` without mounting [src/system/fuse_sysfs.cpp:933-949], or use the `StatsEnvironment` fixture [ef13273ba9:t/t_tronstats_convention.cpp:164-172].

**Size (est.):** about 10 files touched: page_share_counters.hpp (+~40 lines: `enabled()`, `register_fuse_files()`, drop the `#ifdef`), self_attention.hpp (3 hook edits), runtron.cpp (+1), rinzler.cpp (+1), CMakeLists.txt (-1), src/tron/CMakeLists.txt (-7), CMakePresets.json (-1), README.ci.md (paragraph rewrite), t/CMakeLists.txt (-3, edit 1), t/t_page_share_counters.cpp (comment). Net roughly +60/-40 lines (est.). If the leaves are exported instead of casual, add the manifest descriptor family, a register helper, a `.skip` marker in MARKERS (the aggregate-scan lint fails a new unskipped grouping directory [src/system/fuse_tronstats_lint.cpp:241-256, 199-200]), and convention-test edits; Wade's thermal commit is the calibration for that shape at 7 files, +250/-5.

## 6. Open items

Measure or decide before switching:

1. **A/A control of the gated-off binary vs the current OFF build.** Run the same `bin/ci/benchmark_save.py` invocation on the same host against two committed revisions; CI's invocation is `--grid --cpus-per-machine 192 --prebuilt` over the five STANDARD_JOBS [bin/ci/ci-run-benchmark.sh:70, 94; bin/ci/benchmark_lib.py:158-210]. The script refuses a dirty tree, keys results by commit and hostname, and skips a config that already has enough samples [bin/ci/benchmark_save.py:88-90, 112-114, 128, 175]; on delphi-3bda pass `-c 144` (2 x 72 cores) or the core check raises. Whether the repeat-to-repeat spread resolves a sub-percent difference: Insufficient data (needs the spread from an existing `/scratch/tron-benchmark/*.json` record). `bin/slice bench` measures test wall-clock only and is the wrong tool [doc/slice-benchmark-lifecycle.md:3-4].
2. **Register allocation.** Compare `objdump -d` of `apply_page_range` for both builds, because the runtime gate keeps two locals live across the inner loop that the OFF build deletes. Insufficient data until done.
3. **Mounts in CI and claude-box.** CI already mounts the tree in every job that runs tron [cmake-single-platform.yml:474-476, 594-596, 752-754]. claude-box (the rootless podman container): Insufficient data on whether `/dev/fuse` is available there; running `t_fuse_sysfs` inside it would resolve it. A leaf unit test does not need a mount, because `make_file` and `get_value` work in memory [fuse_sysfs.cpp:301-320, 933-949].
4. **Prometheus export wanted?** Exported leaves need `exported=true`, a descriptor (manifest entry or `register_tronstats_metric_descriptor`), and a `.skip` marker for the new grouping directory, or the aggregate-scan lint fails [README.stats.md:234-237, 354-361; fuse_tronstats_lint.cpp:241-256]. The JSON histogram leaf would stay casual, as expert_stats's do [expert_stats.hpp:68-70]. This is Wade's call.
5. **Path and scope.** `/rinzler/stats/page_share/` follows the process-wide precedents; `/model/<id>/` would need per-model counters, which the PR does not have (one rinzler can load several models [src/rinzler.cpp:3729-3730, 2319-2337]).
6. **Interval semantics.** Wade's "random chosen intervals" can mean differencing two reads (no code) or a reset control leaf (a writable leaf; would break the monotonic-counter contract [README.stats.md:407-409]). Not established; ask.
7. **Exit summary.** No script today consumes the `[page-share]` text (the campaign script greps the old `[P1]` label [exec/p1-counters.sh:24-28]); keeping the reporter needs a stated consumer, and dropping it removes the only end-of-run record for batch runtron.
8. **Callback concurrency.** Read callbacks can run on several libfuse worker threads at once [libfuse lib/fuse_loop_mt.c:176-178]; the JSON renderer must use local buffers only.

## 7. Recommendation

Option (a): merge #4267 as it stands and do FUSE in a follow-up. Wade approved this exact head (review 5156698046 on ef13273ba9), so a rework now reopens a reviewed diff for a change that is a replacement of the gate, not an addition to it: it removes the option, the PUBLIC define, the preset entry and the README paragraph, and edits the header and all five hooks. The counters' data path, the four test cases and the cost-data entry carry over unchanged into the FUSE version [ef13273ba9:page_share_counters.hpp:67-112; t/t_page_share_counters.cpp:43-117; config/test-benchmarks.json:472], so nothing in PR0 is wasted. The one property the follow-up changes for everyone is that a disabled branch enters the attention page loop of every binary, including the .deb rinzler, and no measurement of that cost exists in the PR texts or the repo; the A/A control in item 1 should come before that decision, not after. Option (c), declining, is not warranted: the FUSE version is about ten files (est.), matches two in-tree precedents (expert_stats and memory_pressure), and buys live reads, interval measurement and production visibility that the exit summary cannot give. Option (b), reworking now, trades an approved PR for an unmeasured hot-path change; I would not.
