A second copy of the attention keys (K) in the tile-friendly VNNI layout, kept in a separate heap allocation (the arena) beside the KV pages. PR 2 only.
single-K
Bill's own proposal ("Single-Format VNNI KV", 2026-09-04): store K once, in the VNNI layout, instead of keeping a mirror. A dated gate (2026-09-16) decides between single-K and the mirror.

SUCCEED() stub
A Catch2 test case that passes unconditionally because the code under test is compiled out.
ODR
The One Definition Rule of C++: one definition of each non-inline function in a program.
seam
A place where one implementation can be substituted for another without editing the caller; Bill's companion document proposes a template parameter as that seam.
FUSE gauge
A value tron exposes as a file in its stats file system (FUSE) and, when exported, as a Prometheus metric.
TTFT
Time to first token, the latency of a request's prefill.
est.
An estimate, not a measurement.
VNNI
Intel's interleaved bf16-pair layout, the B-operand layout the AMX tile multiply reads.
GOF
Group of four: the 4-token staging block the FPGA hardware-attention path builds from K and V (the shuffle into it is the G2 gate measurement).
dotter, dotter epilogue
The existing AVX-512 attention loop (one query-key dot product per token) and the per-page softmax step that follows it.
Catch2, slice
Catch2 is the C++ test framework; bin/slice is tron's test runner, which schedules test binaries by their recorded cost data and reports pass or fail from the exit code.
lld, ThinLTO
lld is the linker the build uses; ThinLTO is link-time optimization applied per target by the lto CMake macro.
TILERELEASE, tile region
The instruction that clears a thread's AMX tile configuration; the region is the span between begin_region() (load) and end_region() (release).
tron::finally
The repository's generic scope guard (h/common/util.hpp:73): an object whose destructor runs the stored callable.
book, page, kv_block
book is the per-model KV cache object; a page holds 64 tokens; kv_block is the storage struct for one page of one (slot, kv_head): its K and V arrays hold that page's keys and values.
EAGLE
Speculative decoding with a draft model; the draft scheduler shares the validator's root node.
G1, G2
The two gate measurements due 2026-09-16: G1 = cost of storing K in the VNNI layout; G2 = cost of the GOF shuffle from that layout.

What the problem is, in plain words

  • One file, two shapes. A default build (the option OFF, which is what a developer builds locally) compiles apply_page_range, apply_page_tok and attn_accum without these blocks; the CI lane and the AMX hosts compile them with the blocks. A rename or a signature change made while working in the OFF shape can break the ON shape without the author noticing until the CI lane runs. Finding 1 closed that gap for CI; it is still open for local builds.
  • Reading the hot loop means holding three conditions in mind. At blocks 4 and 6 a reader must combine the preprocessor condition, the per-geometry compile-time condition and the per-process run-time condition to know whether a line executes, and the set-up those lines rely on is 70 lines earlier (block 3) while the guard is 1,300 lines earlier.
  • The nesting is three deep. At the head Bill reviewed it was four to five deep, because the K-mirror choice added a further #ifdef inside the dispatch blocks; that layer left with the mirror.

What is done. The dense-page computation is one function (block 5c), called from one place (block 6); the pack is one helper (block 5a); the region bracket is a scope guard (block 3), which removed the seventh block that used to close the region after the loop. Bill's "single call" half is met.

What remains, and why it is not a mechanical edit. Bill's fix asks for "one call and no preprocessor". The statements can lose their #ifdef: blocks 3, 4 and 6 sit inside member function templates, so an if constexpr on a constexpr flag exported by the interface header (true only when the kernel translation unit is compiled) would discard the AMX branch in OFF builds without instantiating it, and the OFF build would then not reference any kernel symbol; the one trap is amx_on = amx_eligible && available(), which must sit inside the discarded branch rather than behind &&, or an unoptimised OFF build would still need the missing available(). Block 5 could also lose its guard, because member functions of a class template are compiled only when something calls them (not verified by a build). Blocks 1 and 2 cannot: if constexpr is a statement, and a type and a data member are declarations. Facts. The paragraph and the arena are not in #3879: the file is untouched by the PR, and the arena exists only in the parked draft. The arena was ordinary RAM by design (Note [K mirror parallel arena]: only the CPU reads it, and keeping it outside the hugepage budget keeps the KV page count identical with and without the mirror). That same choice hid it from the memory-pressure governor, which measures committed hugepages, and produced the round-1 soak result: the arena reached 43.8 GB at 30 minutes and a 46.5 GB peak (server-log figures, 10^9 bytes) on one tp2 engine, host used memory grew by up to 42.3 GiB, and the soak monitor raised its 5 GiB growth alert while the AMX-off arm stayed flat with 56 GB of KV in hugepages; Wade's evaluation listed "ungoverned RAM sized at pool/2" as blocking. The KV pages themselves come from a pool of 1 GiB hugepages mapped with MAP_POPULATE at startup, so a pool-backed copy is committed up front and counted by the governor with no new code. The same round measured the mirror arm 17 % (llama-3.1-8b tp2) and 24 % (qwen-3-4b tp4) slower to first token than the canonical arm, at parity on mixtral; the cause is unmeasured (leading hypothesis: the K write-through during prefill), so that number says nothing about page size, and Bill's TLB claim is likewise unmeasured.

Two forms of "hugepage alloc". Form A: a third plane inside kv_block, which is what Bill's own bill-amx branch does (member array k_vnni, written through from save_k); the book's DMA buffer grows by half, no new allocation code, the governor counts it because the book is bigger; kv_block is not templated on kv_mul, so ineligible models would carry the plane unless that is fixed. Form B: a separate allocation from the pool through the helper the book already uses (try_make_unique_dma_for_overwrite); keeps the arena plumbing; traps: the helper's "callers must propagate failure" rule, the fault-injection seam's assumption that the helper's "only callers are book::try_create" (h/system/memory.hpp:263-264), the dma_size_bytes() contract and the section-5 accounting cross-check. In both forms the pool grows by half the KV bytes (Bill's "add more huge pages") and the "third memory" paragraph is deleted. Note that bill-amx is not single-K: it keeps row-major k and adds k_vnni as a third plane; single-K (his 2026-09-04 document) drops the second copy entirely.

How the gate changes the question. Under single-K the one K copy lives inside the hugepage-backed KV block and the arena and the hugepage question disappear.
