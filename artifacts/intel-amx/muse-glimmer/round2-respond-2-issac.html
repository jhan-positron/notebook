A token is one unit of text that the model reads or generates. Attention is the model step in which each token reads from earlier tokens.
Query head, KV head
Parallel parts of one attention step. A KV head holds keys and values, and a group of query heads shares one KV head.

Query heads per KV head. The model llama-3.1-8b has 4, and the model Muse Glimmer has 16.

Kernel, pack, QK kernel, PV kernel
A kernel here is an optimized function for one step of attention. The pack copies one group of a token's query heads into the layout that the QK kernel reads. The QK kernel scores queries against keys, and the PV kernel multiplies the attention weights with the values.
KV page, partial page
A KV page is a 64-token block of stored keys and values. A partial page holds fewer than 64 tokens.
Mask, visible range
The mask splits the tokens into ranges and marks the ranges that a query may read. A marked range is a visible range of that query.
Dense page
A full page, inside the query's sliding window, that the query sees completely through one visible range. Only a dense page takes the AMX path.

The build option of CMake (a C++ build tool) that compiles the AMX kernels and their call sites. Its default is OFF.

The define makes no second copy of the dispatch template in this program

The test's own source file is compiled with the define, and the library tron is compiled without it. Two different versions of one function in one program are an error. The compiler and the linker are not required to report it.

  • All seven guarded blocks sit inside the class template self_attention [R12]. The compiler emits a copy of it only for a model type that a source file uses.
  • The test builds 5 model types from a configuration that no other source file has [R11].
  • The test's object file holds 68 symbols of that template. The other 356 object files in the link command hold 0 [R6].
  • Three library files do include self_attention.hpp without the define. The linker takes no code or data from their object files for this test program.

Isaac's commit message says the option changes only code inside the self_attention template [R2]. That is true. One guarded block adds a data member, so the changed code includes a class layout and not only function bodies.

That is harmless here for the same reason: no other object file uses these model types. No tool checks this condition. If a later edit shares a model type with the library, the one-definition rule is broken without an error message.

His example, t_page_share_counters, proves the CMake mechanism only. That test never compiles self_attention.hpp. So the proof of safety is the measurement above.

8. Found during the tests

Fault m04 is not caught, and the cause is older than PR 5022.

  • The dense-page condition of self_attention.hpp has five clauses [R12]. One asks for a full page of 64 active tokens. Another asks that one visible range of the query covers slot 63, the last token slot of the page.

  • PR 5022 adds a 16-head partial-page section that builds its page the same way. So that section has the same gap.

A fix would separate the two clauses in the test. One new section could use a 63-token page inside a visible range that is one token longer. A second could use a full page whose last token lies in a second visible range.

The first needs one more parameter of the test helper. The second also needs a second visible range, because the mask allows no token without a range [R12]. A smaller change of one line covers fault m04 alone: the helper's visible range ends at the page size.
