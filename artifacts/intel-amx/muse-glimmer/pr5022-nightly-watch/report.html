Short version

1 nightly run on the Intel machine and 1 on the AMD machine used a tron build with PR 5022. Muse Glimmer on the Intel machine: decode 82.71 TPS (+6.9 %), time to first token 3687 ms (−1.0 %); on the AMD machine: decode 78.49 TPS (−1.6 %), time to first token 3735 ms (−0.1 %). Other models: 2 of the 44 compared series are slower than normal or failed: gpt-oss-120b tp4, 8 users; llama-3.1-8b tp2, 32 users.

How the normal is calculated

  • Source: every scheduled nightly session of the two machines since October 1, 2026, read from Talos [Ref1]. Reruns started by hand are left out.
  • A night counts as a night with PR 5022 when the merge commit of the PR is an ancestor of the commit of its tron build [Ref4].
  • Baseline nights: start at the newest night before the PR. Keep the nights with the same platformd version, the same FPGA image and the same test settings. Then walk back night by night. Two nights in a row that sit more than 3 spreads from the median are a level shift, and the baseline stops there.
  • Normal: the median of the baseline nights.
  • Spread: 1.4826 times the median distance of the baseline nights from their median. For bell-shaped data this equals the standard deviation. One odd night does not change it.
  • Band: the normal plus or minus the largest of three values: 4 spreads; 0.75 % of the normal for the decode rate or 1 % for the time to first token; 3 ms for the time to first token.
  • A night outside the band counts as faster or slower. Inside the band it counts as normal.
  • False alarms: each baseline night was tested against a band built from the other baseline nights of its series. 5 of 590 nights fell outside (0.8 %).
  • Not covered: the rate of the slowest user, which the Slack report prints [Ref3]. The numbers here are the mean over all users.
  • The nightly package build turns AMX on [Ref5]. Without it PR 5022 could not change the nightly numbers.
Words used here
  • tron: the inference program under test. rinzler: the production server built from it, which the nightly runs.
  • PR 5022: the tron pull request that lets the AMX attention code serve Muse Glimmer [Ref2].
  • AMX, AVX: CPU instruction sets for matrix and vector math. Only the Intel machine has AMX. Before the PR, Glimmer used AVX on both machines.
  • Muse Glimmer 30B: a 30-billion-parameter language model. It has 16 query heads per KV head (kv_mul 16), a shape the AMX code did not accept before the PR.
  • Nightly: the System CI run of the systems_test repository. Each night it runs functional, performance, accuracy and soak tests on a whole machine.
  • delphi-3bda: the Intel machine of the nightly. andoria-b1a3: the AMD machine of the nightly.
  • Talos: the internal test-results service that stores every nightly session.
  • Decode: producing output tokens one by one. TPS: tokens per second for one user during decode, as a mean over all users.
  • Prefill: reading the prompt before the first output token. TTFT (time to first token): how long that takes, in milliseconds. The nightly prompt has 1024 tokens.
  • tp2, tp4: the model is split over 2 or 4 FPGA cards. 8 users: 8 requests run at the same time on the machine.
  • Series: one model at one user count on one machine, for one metric.
  • Median: the middle value of a sorted list. Level shift: a lasting step of a series to a new level.
  • platformd: the control service on the machine that starts the servers. FPGA image: the bitfile loaded on the accelerator cards.
  • tron build name, for example v2026.11.25-73ab1891: the build date and the first 8 digits of the commit.
  • est.: an estimate, not a measurement of the nightly.
