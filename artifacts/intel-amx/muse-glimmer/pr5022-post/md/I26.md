You are right. Done: `t_amx_numerics` is registered with `SKIP_RETURN_CODE 4` and carries the label `skip_return_code_4`. Both registry rows of `t_amx_numerics` carry `"skip_return_codes":[4]` (your comment at line 311).

The cause is exactly what you describe. The QK and PV cases `SKIP` when AMX is absent [t/t_amx_numerics.cpp:317-319, :330-332]. Catch2 3.7.1 returns 4 when every selected case was skipped and the process was not started with `--allow-running-no-tests` [catch_session.cpp:350-353]; our registered command never passes that flag. `add_catch_test` registers the whole binary with plain `add_test`, so Catch2's own `catch_discover_tests` default of `SKIP_RETURN_CODE 4` never applies; only the PROPERTIES we pass do [t/CMakeLists.txt:212-219]. Slice reads the skip code from the `skip_return_code_N` label alone [bin/slice:1508-1510], so both halves are needed, as doc/slice.md:296-305 says.

The registration:

```
# The QK and PV cases SKIP without AMX; a run that selects only them exits
# Catch2's code 4. SKIP_RETURN_CODE + the skip_return_code_4 label report
# that as skipped (ctest and Slice) rather than failed.
add_catch_test(NAME t_amx_numerics LIBRARIES tron pos_fake
  PROPERTIES SKIP_RETURN_CODE 4 LABELS fake)
set_property(TEST t_amx_numerics APPEND PROPERTY LABELS skip_return_code_4)
```

The second label is appended with `set_property`, the way `t_mwaitx_cliff` appends its label. One call cannot carry both labels. `add_catch_test` forwards its arguments unquoted, so a list such as `"fake;skip_return_code_4"` splits into two items. `set_tests_properties` then gets an odd number of values and stops the configure.

Verification, measured on a Granite Rapids host. The kill switch stands in for a host without AMX. With it, `TRON_AMX_DISABLE=1 gen/t_amx_numerics "[kv_data]"` exits 4: 2 cases, both skipped. `ctest --show-only=json-v1` lists `SKIP_RETURN_CODE 4` and the label `skip_return_code_4`. The unfiltered kill-switch run exits 0, with 3 cases passed and 2 skipped. The unfiltered run with AMX exits 0.
