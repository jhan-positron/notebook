The facts are right: no workflow that a pull request triggers builds with `TRON_AMX_DISPATCH`. The thread at src/tron/CMakeLists.txt:216 has the same point, and my reason for keeping the flag out of this PR. With it ON, every eligible model test of the required lane would run the AMX kernels on an Intel runner and the AVX path on an AMD runner. That changes CI for every pull request.

The test file was behind the guard before this PR. The new sections are the ones the review asked for (threads at t/t_amx_dispatch_dtype.cpp:143, :209 and :305). They run in the CMake workflow (`cmake-single-platform.yml`), which builds with the option ON. README.ci.md describes its manual run on the final commit of a PR.

What ran at this head:

- That workflow: run [44777748892](https://github.com/positron-ai/tron/actions/runs/44777748892). Its test-host job passes all 106 host tests on an AMD runner (attempt 1) and on a Granite Rapids runner (attempt 2). `t_amx_dispatch_dtype` is one of them.
