AMX attention: build the score rows as 1-D tensors

apply_dense_amx_page declared its score buffer s_pages as a two-dimensional
tensor with the uninitialized tag. Note [Uninitialized Weight Tensors] says
that the tag is well-defined for a one-dimensional tensor only. A tensor of
two or more dimensions keeps its rows in a union member that the tag
constructor never constructs, so access to the rows is undefined.

s_pages is now a std::array of one-dimensional tensors, one per query head,
each built with the tag through make_array_of. The buffer is still not
zero-filled, and the QK kernel still writes every element before any read.
The rows stay consecutive: the static_assert on sizeof(s_pages) holds.

Tests on delphi-3b35 (Xeon 6962P, clang 19.1.7, preset native,
RelWithDebInfo, TRON_AMX_DISPATCH=ON), 2026-11-25. Two builds were
compared: the commit before this one, and the same tree with this
declaration. The tested tree differs from this commit in comment lines only.

- Unit tests, both builds: t_amx_dispatch_dtype 30,747 assertions,
  t_amx_numerics 21,521 and t_llama_unit 265,801 pass.
- Token identity (1 user, temperature 0, seed 1, deterministic mode, prompt
  1024 tokens, 256 generated tokens): the token files of the two builds are
  byte-identical for Muse Glimmer 30B (tp4) and for
  llama-3.1-8b-instruct-good (tp4, CPU attention).
- Throughput (8 users, prompt 1024 tokens, 256 generated tokens, 4
  repetitions per build): the decode speed differs by +0.16% on Glimmer and
  by -0.01% on llama, and the prefill time by +0.08% and -0.05%. Each
  difference is inside twice the larger standard deviation of the two
  builds.
