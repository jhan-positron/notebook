Blocking findings

C1

The plan can silently replace the historical question

The August 18 binary (787342cf…) and its build flags are gone. A current build that happens to flip at generated token 30 is useful evidence about the current build, but it does not prove the old event had the same cause. If the flip moves, “adopt the flip you got” or search other prompt lengths/chapters changes the target and adds selection bias.

The nearest preserved artifact, gen/runtron.inc1b (9e5df5dd…), and its build recipe in exec/p2-inc1b.sh should be tried before a fresh build. That recipe used cross-avx512, BUILD_INGEST_MODELS=ON, dispatch on, and cleared CMAKE_CXX_FLAGS; the HTML currently proposes a different native build.

Required change: separate the terminal claims. Either reproduce the archived token-30 pair with an exact or justified runtime-equivalent artifact, or report historical root cause unresolved. Name any current-build investigation as a separate analogue; do not retarget it under the original title.

C2

A near tie explains sensitivity; it does not prove admissible numerics

H1 is circular: it calls the AMX delta admissible because it resembles other deltas produced by the implementation under test and grows “smoothly.” A systematic kernel or page-selection defect can be small, typical, and smooth. Likewise, the proposed automatic threshold is derived from the first observed AMX delta, so it cannot be a correctness oracle.

The decisive quantity for the reported pair is the change in its gap, not a generic absolute logit delta:

margin_off = Loff(" but") - Loff(" and")
delta_gap  = [Lon(" but") - Loff(" but")] - [Lon(" and") - Loff(" and")]
margin_on  = margin_off + delta_gap

This shows how the winner changed. Correctness is a separate axis. The kernel's absolute-error envelope (1e-4 × absolute product mass) also cannot be compared directly with relative L2 at WO, after normalization, projection, and bf16 conversion.

Required change: always report two independent conclusions: (1) near tie or not, and (2) bounded expected numerics, defect, or unresolved. Validate the second using identical captured runtime inputs replayed through AVX, AMX, and an independent higher-precision/reference calculation at the attention seam, with a predeclared metric and bound.

C3

H2–H5 are not mutually exclusive or fully discriminated

“PV truncation changes little” rules out only that conversion as the dominant isolated intervention; it does not establish QK/PV accumulation order. QK conversion/reduction, softmax, mixed AVX/AMX page reduction, dispatch, or an input-dependent kernel defect remain. Rounding and reduction order may both contribute. The P4 debug patch itself also needs a lane-for-lane unit test against the AVX truncation conversion before its result can be interpreted.

H4's refutation is also invalid. A consistently wrong page set can begin exactly at token 63 and affect every later layer smoothly. Aggregate page counts do not prove page IDs or visibility. Passing generic kernel tests does not refute a production-shape/input defect.

Required change: add an unresolved/mixed outcome. Use QK-vs-PV hybrid ablations or a 2×2 conversion experiment where practical, capture and replay the exact target tensors, and trace expected versus actual page IDs/reasons per token and layer. Conclude H3 or H4 only from a positive discriminator, never by elimination.

C4

The reproducibility and engagement controls are incomplete

Only OFF/OFF is repeated. An AMX-only race, arena issue, or dispatch nondeterminism would pass that gate. The plan also says engagement is indispensable while initially treating P1 as optional. The debug branch now contains P1/P3/P4 at bd68d5cb50, which is progress, but the HTML and harness do not hard-gate on ON pages_amx > 0 and OFF pages_amx = 0. The aggregate counter still cannot validate the correct pages.

  • Repeat both unforced arms: OFF/OFF and ON/ON.
  • Repeat both teacher-forced arms and require exact within-arm values.
  • Bridge uninstrumented to instrumented binaries within each arm; the global log mutex and per-line flush must not change the target prefix or own argmax.
  • Record token/query, layer, eligible page IDs, AMX page IDs, fallback page IDs/reasons, visibility bounds, and arena state—or assert these against a precomputed trace.
Required change: make all four A/A controls and engagement/page-set assertions hard gates before interpreting any A/B delta.

C5

The Qwen intermediates do not have unique keys

The generated Qwen plugin logs 32 WQ head slices and 8 WK head slices per token/layer under identical labels such as WQ layer 0 of token N and WK layer 0 of token N. That invalidates the proposed exact A/A comparison:

  • bin/compare_intermediates stores the last reference occurrence, then compares every test occurrence against that last head. A perfectly identical A/A can therefore print false Busted! blocks.
  • dd_first_divergence.py indexes the first reference occurrence and skips later test occurrences, silently checking only one head.
  • The former also materializes a tens-of-GB reference log as NumPy arrays; it is the wrong comparator for the planned ~32 GB files.
Required change: patch debug labels to include the head/slice index, or implement an occurrence-aware streaming comparator with matching cardinality and stable identity. Validate declared vector lengths, duplicate counts, malformed/truncated records, and both-direction key completeness. Do this before R3a.

C8

The companion campaign harness fails open

exec/dd/dd-campaign.sh uses only set -u, does not check most run return codes, treats control comparisons as reports rather than gates, counts R7 skip markers without failing, merely prints engagement lines, and unconditionally writes ok at the end. A timeout, CI handoff, missing model, A/A mismatch, vacuous kernel test, or zero AMX engagement can therefore end in a green marker.

The harness also runs the conditional truncation arm before reading Phase 2, and promises a later dd-phase3-hf.sh that does not exist.

Required change: do not launch this harness as-is. Add explicit fail-closed gate functions for each expected outcome, artifact size/completeness checks, a cleanup/release trap, nonzero failure markers, and a phase boundary that stops for analysis before conditional R5/R6/R8/R9 work.

Major corrections

M1

Freeze IDs and prove token/logit alignment before large captures

Prompt-ID reconstruction is deferred until Phase 3, after the expensive runs. Move it to Phase 0. Hash the source text, exact 2048 IDs, tokenizer/model revision, BOS/shared-system-prompt behavior, and the first 64 OFF IDs. Prove the token-file form reproduces the -u 1 form before treating HF or t_amx_logit_ab as aligned.

For generated token 30, HF needs the causal prefix through generated token 29; if token 30 is also supplied, the scorer must explicitly select the preceding row. The current logit script assumes a tree-index formula. Assert it by requiring the OFF sparse top-1 at every mapped row to equal the free-run/forced ID, and fail on any missing row or vocabulary-size mismatch. Prefer an HF path that accepts exact IDs instead of decode→text→encode.

Required change: publish a one-line mapping for generated step, output-row index, tree index, and HF row, then make the scripts verify it from the data.

M2

Localize the target call, not merely the first normal AMX effect

With a 2048-token prompt, WO layer 0 of token 63 is the first expected downstream sign that AMX ran. It is not the cause of the generated-token-30 flip (approximately tree index 2076 under the current mapping). By then, hidden states and cached K/V have accumulated temporal and depth differences, so a cross-process layer diff mixes current arithmetic with propagated state.

P2—the attention-output seam needed to separate the kernel from WO—is still absent for the ingested Qwen target. P3 exists but the harness does not use it, so it still schedules roughly 100 GB of logs. dd_first_divergence.py also sorts layerless Logits before layer 0, which can make its advertised “first” key wrong.

Required change: implement P2 for the generated/shared Qwen path and use P3 from the first instrumented run. Place the full-output log after the existing all-worker attention barrier (or emit explicitly head-indexed slices); logging from one run_joins worker can otherwise observe incomplete KV heads. Capture selected boundary sentinels plus the target token/layers, then shadow/replay the exact target attention inputs. Fix the semantic sort order before relying on “first divergence.”

M3

Verify tap-point precision and define quantitative outcomes

A float32 file format does not prove the logits were computed or captured before bf16 quantization; widening bf16 values to float cannot recover lost bits. Verify R9's tap point and compare it against the text log on a fixture. Also replace “small,” “typical,” “smooth,” “most,” “clear outlier,” and “orders of magnitude” with declared metrics and thresholds.

For R5, “the flip disappears” must mean the model's pre-force top-1 in Top-k Token IDs returns to the OFF winner; the output token file is forced and cannot answer that question. HF ordering should remain supporting context because the discussion already records a large engine-level Tron↔HF gap.

Required change: predeclare the gap-change, kernel error, page-trace, and rounding-dominance criteria. If no criterion is met, report mixed/undetermined, not “nothing to fix.”

Recommended corrected run order

  1. Define the claim boundary and recover provenance. Try the preserved inc-1b artifact and reconstruct its source/build recipe. Freeze exact prompt IDs, model/tokenizer revisions, environment whitelist, compiler/preset, CPU/microcode, git status, and binary hashes. If historical reproduction is impossible, stop the historical claim here.
  2. Repair and fixture-test the instruments. Make keys unique, validate record lengths/completeness, fix semantic ordering and token mapping, make every gate exit nonzero, add P2, and activate P3 filtering.
  3. Build controlled variants. Use separate build directories from one clean commit for canonical, truncation, and—only if needed—mirror. Validate the P4 conversion patch with a dedicated unit test.
  4. Run cheap tests first. Run verbose kernel/dispatch tests and prove they executed. Include the mirror-specific and truncation-specific checks in their respective builds.
  5. Establish both-arm A/A. Run OFF/OFF and ON/ON unforced, then OFF/OFF and ON/ON forced. Hard-stop on any within-arm token/value mismatch, zero/mismatched engagement, page-set discrepancy, missing key, duplicate identity, or incomplete artifact.
  6. Reproduce the exact symptom. Require repeated OFF/ON runs to share the first 29 IDs and reproduce the same token-30 candidate pair. Verify the instrumented builds preserve their uninstrumented arm.
  7. Measure the forced gap. On repeated forced runs, compute the actual " but"/" and" gap and delta_gap, with exact row alignment. Report near-tie status independently of correctness.
  8. Localize causally. Validate page IDs and capture identical production inputs at the target attention call. Replay AVX, AMX, and a high-precision/reference implementation; then use controlled QK/PV/rounding ablations if attribution remains necessary.
  9. Use secondary checks conditionally. Run same-build mirror only if implicated. Run full 36-layer HF on exact IDs as context, not as the admissibility oracle. Preserve an exact minimal regression test for any defect found.

Bottom line: keep the plan's staged recipe and teacher-forced comparison, but revise the claim boundary, controls, keying, build pairing, hard gates, and causal oracle before spending the machine window. The first successful output should be a trustworthy measurement; only then should the campaign choose a hypothesis branch.
