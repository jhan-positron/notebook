Hypotheses and the observation that decides each

The flip must have one of these causes. Each hypothesis names the measurement that confirms or refutes it; the phases below collect exactly those measurements.

IdHypothesisConfirmed byRefuted by
H0The comparison itself is not pinned (environment, or FPGA cross-process nondeterminism).A/A control (OFF twice) differs in tokens or in any Logits of token N line.A/A byte-identical for tokens and all logged lines.
H1Near-tie amplified by admissible numerics. H3Within H1: fp32 accumulation order (QK and PV) is the dominant contributor.Truncation build changes little; deltas remain and are smooth; kernel tests pass.Truncation build removes most of Δ.
H4Dispatch / page-bookkeeping bug: wrong visibility, a partial page treated as full, a page skipped or double counted, mirror-arena fallback in one arm.Per-layer deltas at tokens < 63, or concentrated at page boundaries (multiples of 64), or missing in some layers; or mirror-vs-canonical AMX runs differ.Deltas begin exactly at the first full visible page for every layer and are present at every later token.
H5Kernel numerics bug (indexing, dropped dim block, wrong accumulation precision).t_amx_numerics fails on 3bda, or the first per-layer delta is far outside the kernel envelope (1e-4 x abs product mass) at WO layer 0.Kernel tests pass and first deltas are at envelope scale.
H6The flip does not reproduce on the current code (original binary is gone; kernels changed since inc-1b).Fresh canonical build: first OFF-vs-ON difference is not at token 30 (or none in 256 tokens).Fresh build reproduces token 30.

Predeclared rules (from the review). Logits and activations on tp2 are bf16 and print exactly, so a single-pair delta is quantized to whole bf16 ulps (0.4-0.8 % of the value). Therefore: near-tie = OFF margin ≤ 1 ulp of the top-1 logit, or ≤ 2 x the p95 of |delta pair| over the non-flip steps. Typical delta uses the graded statistic mean |delta| over the whole vocabulary, compared with its p95 over non-flip steps (outlier = > 3 x). H2 vs H3: median mean |delta| of the truncation build / canonical < 1/3 = rounding-mode dominated; the flip state in the truncation build is an observation, not evidence. H5: at the first full page, Attn out layer 0 element change > max(2 ulps, the add-order control) or changed fraction > 3 x the control. The add-order control is one extra OFF run with two fewer app cores (a different attention plan, no AMX; Note [Paying for Determinism] names core count as a plan input): it gives the admissible per-layer delta scale from a path that never touches AMX.

Prior: the only teacher-forced AMX-vs-AVX logit record on this model (956 steps, three prompts) shows max TVD 0.054 and both arms at identical distance from the HF reference; on llama-3.1-8b both observed flips were near-ties (margins 0.031 and 0.000) exec/QUEUE.md:68. H1 is therefore the expected answer. The plan is built so that H1 is demonstrated, not assumed, and so that H4/H5 would be caught if present.

Risks and unknowns

  • The flip may not reproduce (original binary gone). H6 handles it: the campaign targets the first flip it sees; R4x measures deltas over 256 forced steps either way, so "no flip" is separated from "hollow".
  • Build time at the light profile is unmeasured; the campaign records it. If the ingest step fails, the marker says build-canon-failed and nothing runs.
  • Prompt ids. If the HF-tokenizer ids do not reproduce R1a, later runs keep -u 1 and the HF arbiter loses its alignment; R8 is then skipped as inconclusive.
  • Near-tie verdicts are soft by nature; the report states the numbers (ulps, p95s, control scale), not a binary "correct".
  • bf16 logging quantizes every delta to whole ulps; that is why the rules use graded statistics and a non-AMX control rather than the kernel envelope at WO.
