Definitive Decode

Can two runtron runs be made identical so that diffing their tokens and per-layer data finds AMX bugs? The direction is right and tron already has the switches. Three premises of the proposal are wrong, and the proposal omits the switch that actually pins the numbers. Every claim below is tied to a source line in tron (main 68783a17db) or tron-amx (jhan-amx-p0, PR #3879); unfamiliar terms are in the glossary.

Q1 · Is the idea sound?
Yes in direction. Wrong in three premises.

(a) There are no per-layer logits: the lm_head runs once, after the last layer. Hand-written plugins can approximate a per-layer view with --max-layers N (N = 2..n_layers, one run each); the ingested qwen-3-4b and gpt-oss plugins refuse it. (b) Exact identity is the right test only for two runs of the same arm; AMX-on vs AMX-off differ by design. (c) "Dense + seed + temperature 0" does not pin the numerics; --pay-for-determinism does. At temperature 0 the seed is not read by the sampler (it still matters only for --length-jitter, --jitter/QPS schedules and --synthesize-missing-tensors, all off by default).

Q2 · What instead?
A three-rung ladder: A/A control, teacher-forced A/B, HF arbiter.

Under the corrected recipe (flag on, same cores, one prompt, fresh process, software attention), OFF-vs-OFF must be byte-identical. OFF-vs-ON is compared with a tolerance on the same forced token stream, and only counts once AMX is proven to have run (a TRON_AMX_DISPATCH build, a bf16 executor, USE_HW_ATTN=0, no draft model). When the arms disagree, the HuggingFace reference dump says which one moved. All three rungs use flags that exist today.

Q3 · MoE such as gpt-oss?
Same recipe for run-to-run identity. gpt-oss never runs AMX attention.

gpt-oss has head size 64 and 8 query heads per KV head; the AMX path requires 128 and 4, so an AMX A/B on gpt-oss compares identical code. The MoE model that exercises AMX is Mixtral-8x7B (hand-written or ingested). Expert pinning (--forced-routing) is honored only by the hand-written Mixtral plugins (8x7B, 8x22B); on gpt-oss it loads the file and silently does nothing, and the file can only come from HuggingFace.

Corrected recipe (commands first)

Same binary, same cores, exactly one prompt, a fresh process per run, software attention forced on. Derived from the recipe that already produced byte-identical OFF-vs-OFF tokens on delphi-3bda intel-AMX/exec/t1-quick.sh:21-37,45-50, with the capture and forcing flags added and one trap removed: -u N does not mean "N users", it appends N Moby Dick prompt files to the run runtron.cpp:112, 734-742. t1-quick used -u 1 as its only prompt; combined with a token-file prompt it would batch two prompts into every pass.

    --instance 0,4 --devices 10:00.0,13:00.0 --app-cores <fixed set> --dev-cores 3,4 --numa 0 \
    --hugepage_file /dev/hugepages/dd --nr_hugepages 128 -o \

Where two runs can stop being twins

Each stage of a decode step has one way to differ between runs and one knob that removes it. The proposal covers the last stage (sampling) and none of the others.

Why "same seed" and "dense model" do not do what the proposal expects

  • Seed. At temperature 0, normalize() sets top_k=1 and the sampler returns max_element before the PRNG is drawn libtron.hpp:113-119; stats.cpp:81-97. The seed feeds only length jitter, submission-time jitter, tensor synthesis and temperature>0 sampling stream_generate.hpp:409-412, 1327, 1424. Without --seed, runtron draws one from /dev/urandom runtron.cpp:809-813, which is harmless here.
  • Dense. MoE top-k is a pure function of the router logits: strict > partial_sort on the hand-written path, topk_fixed with lowest-index tie-break on the ingested path mixture_of_experts.hpp:313-315; topk.hpp:174-195. The only RNG in routing is behind --expert-routing uniform|load, which seeds from std::random_device and ignores --seed mixture_of_experts.hpp:325-334. In-tree tests assert bit-exact logits and identical tokens for Mixtral (serial and tp2, ingested tp2) under the flag t_generate.cpp:199-234; t_generate_ingest_1_mixtral.cpp:17-44.
  • What the flag does not pin (from Note [Paying for Determinism] itself): core count, tokens per forward pass including other prompts' tokens and prompt chunking, KV pagination (a prefix shared with an earlier request starts pages elsewhere), and temperature>0 sampling stream_generate.hpp:187-212. Hence the fixed-cores, single-prompt, fresh-process rows in the table.
  • Exact ties are not a nondeterminism source: the dense argmax is std::max_element (first index) and the sparse top-k orders ties by lower token id stats.cpp:97; top_k_accum.hpp:82-86. They do happen: 1 of 192 teacher-forced steps on llama-3.1-8b was an exact top-1 tie (margin 0.000000) QUEUE.md:68.

Two comparisons need two instruments

The proposal uses one instrument, exact identity, for two different comparisons. It is correct for one of them.

What is measured so far

  • OFF-vs-OFF greedy tokens: identical across two processes, qwen tp2, ctx 2048 and 8192, 256 generated tokens each (green ANSI chunks re-extracted from exec/results/slot1/t1-quick/off{1,2}-*.log). The summary file t1-quick.txt records "OFF vs OFF DIFFER": a known false positive from line filtering (ASLR addresses, mid-line log continuation) QUEUE.md:68.
  • OFF-vs-ON greedy tokens: at ctx 2048 the first difference is the 30th generated token (chunk index 29: " but" vs " and"); at ctx 8192 all 256 tokens identical t1-quick/off1-*.log vs on1-*.log. The ctx-2048 flip has not been root-caused (near-tie vs bug); the ctx-8192 identity has not been shown to have engaged AMX (no engagement signal exists, and the binary's build flags were not recorded).
  • Teacher-forced AMX-vs-AVX logits, llama-3.1-8b (192 steps, t_amx_logit_ab): argmax agreement 190/192, both flips at near-ties (margins 0.031 and 0.000000 = exact tie; median margin 0.266), worst absolute logit delta 0.25. No HF reference for this model (GPTQ extract path blocked) QUEUE.md:68.
  • Teacher-forced AMX-vs-AVX logits, Qwen3-4B-Instruct-2507 (3 prompts, 956 aligned steps): max TVD 0.054, 1 step of 956 above 0.05; both arms at identical distance from the HF fp32 reference (max TVD 0.7139 both, argmax-vs-HF 126/148 both) QUEUE.md:68. The tron-vs-HF gap is a known engine-level issue, not introduced by AMX.

Per-layer data: what exists, what it costs, what is missing

There are no per-layer logits. The lm_head (wcls) matmul runs once per forward pass on the final normalized embedding model.hpp:1801-1812, 3103. Hand-written plugins can approximate a per-layer view with --max-layers N for N in 2..n_layers, one run per N llama.hpp:1232-1248; N = 1 trips the EAGLE heuristic (is_eagle{max_layers == 1}), which demands a one-layer HF config and otherwise skips the final RMSNorm and prefixes every label with "Draft " llama.hpp:304-309, 335, 1246; model.hpp:1271. Ingested plugins refuse truncation outright: generated code asserts max_layers == -1 || max_layers == n_layers TronCpp.hs:986-999. For qwen-3-4b and gpt-oss the only per-layer probe is --intermediates-file.

Operator facts about the intermediates log

  • One file per run. The path is std::removed then opened at model-state construction model.hpp:1362-1369. The help text says "append"; it does not append across runs.
  • Compare by key, never by diff. Lines are written by attention workers, main helpers and FFN workers under one mutex; their order changes run to run model.hpp:1263-1285. Values are identical run to run only under --pay-for-determinism model.hpp:2024-2026. bin/compare_intermediates keys on the first 50 characters of each line and parses both files with the same parser, so tron-vs-tron works bin/compare_intermediates:99-123.
  • Identity mode. With --vec-rtol 0 any key with nonzero relative L2 error prints a "Busted!" block listing every differing index (the element tolerance defaults to vec_rtol/3 = 0); keys absent from the reference print "Not found in reference". Grep for those two strings. Do not read the 7-decimal "Relative error in L2" display as proof (values below 5e-8 show as 0.0000000), and note that an all-zero reference vector yields nan and is never flagged. The script's exit status is always 0 bin/compare_intermediates:59-75, 116.
  • Token index. "of token N" is the token-tree linearization index, equal to the absolute position only for one sequence walked from the root in a fresh process common.hpp:134-137; full.hpp:2088-2100. Two prompts in one run make labels collide.
  • Precision. Values print with setprecision(8): exact for bf16 (all tp executors; logits are bf16 there), not guaranteed for float (host executor: adjacent fp32 values can print identically). A build with -DPRINT_HEX in the compiler flags (bare #ifdef, no CMake option) prints the raw 16 bits of each element, meaningful only for bf16 arrays; those files must be compared with cmp/diff after sorting by key, because compare_intermediates calls float() on every field model.hpp:1273-1281, 1186; btensor.hpp:21; bin/compare_intermediates:106-109.
  • Cost. Every value costs about 12 bytes and every line takes the global mutex plus std::endl and flush. For qwen-3-4b (36 layers, hidden 2560, intermediate 9728, vocab 151936) the ingested label set is roughly est. 15.5 MB per token across 36 layers, est. 32 GB for a 2048-token prompt, plus est. 1.8 MB per decode step for the full-vocab Logits line (computed from the print format and the HF config dims; not measured). The forward pass is serialized on the log while it runs. Use 64-192 token prompts and tens of steps, not 2048 and 256.
  • Not through rinzler. rinzler (the production server binary) hard-codes pay_for_determinism = false and log_intermediates = false rinzler.cpp:2006-2010.

Protocol: how to go from "two runs" to "which line is wrong"

  1. Kernel level first. On delphi-3bda, from a build with -DTRON_AMX_DISPATCH=ON (and -DTRON_AMX_K_MIRROR=ON for the mirror tests), with TRON_AMX_DISABLE unset: ctest -L fake -R 't_amx_(numerics|mirror|arena_leak|dispatch_dtype)'. t_amx_numerics pins the AMX QK and PV kernels to the AVX path within an input-derived envelope and fails on wrong indexing, a dropped token or dim block, or changed accumulation precision t_amx_numerics.cpp:1-12, 178, 280-287. Check the output for "AMX unavailable on this host ... skipped" or "build without TRON_AMX_... nothing to test": either means the run proved nothing t_amx_numerics.cpp:145-149, 295-298; t_amx_mirror.cpp:83-86. This is the fastest bug locator for kernel bugs; what it cannot see is page bookkeeping, visibility, mirror coherence and dispatch conditions.
  2. A/A control. Two OFF runs (and two ON runs) per the recipe. Tokens: cmp. Logits and activations: compare_intermediates --vec-rtol 0, grep "Busted" / "Not found". Expected: nothing printed. If something is, either the recipe is not pinned or the FPGA path is not reproducible across processes (open item 1); nothing downstream is interpretable until this passes.
  3. Prove engagement. Until the counter exists: the binary's CMake cache says TRON_AMX_DISPATCH=ON; the ON process was launched with TRON_AMX_DISABLE unset on an AMX-capable host (available(): CPUID 7.0 EDX bits 22/24, XCR0[18:17], arch_prctl grant) amx_attn_iface.hpp:33-38; self_attention.hpp:1362; the log shows HW attention disabled for model '<id>': USE_HW_ATTN=0 (a model that is not HW-eligible logs "HW-attention not available for this model. Will use SW-only path." instead; both mean software attention) model.hpp:1528-1539, 1613-1622; at least 64 tokens are visible to the query (first AMX step = query position 63; the 128-token prompt is the recipe's choice, not the threshold); the model is head 128 / kv_mul 4 on a bf16 executor.
  4. Teacher-forced A/B. ON run replays A's ids via --force-feed-text-token-file. Per key: relative L2 sorted by (token, layer, stage) with a threshold calibrated on the A/A control (exactly 0) and the kernel envelope (1e-4 x absolute product mass at kernel level; end-to-end must be predeclared). Per step: top-1 agreement from Top-k Token IDs for Logits[0], margin (top-1 minus top-2 logit) at every flip, TVD. Expected pattern: zero delta for tokens below 63; small delta from WO layer 0 onward for T ≥ 63. Delta at T < 63, delta only at some layers, or delta outside the envelope = bug class hint (visibility, page bookkeeping, or kernel).
  5. Arbiter. When arms disagree beyond the envelope, the HF dump says which arm moved away from the reference. extract_logits takes text (--text-file), tokenizes it, truncates to --max-tokens (default 40; set it to prompt + forced length) and needs an explicit --max-layers 36 (no "all" keyword); its --save-tokens file is what runtron's --token-file reads, so ids flow HF to tron extract_logits:104-110, 127-162; reference_logits.py:87-116; load_model.py:23-29. Only keys whose 50-character label matches are compared (the script maps "Logits of token" to "Logits for token"); the HF hooks emit labels tron's ingested plugins never do (e.g. "WQ (post QK-Norm)" for qwen3), so expect partial overlap; the exact shared set for qwen-3-4b is an open item dump_intermediates.py:235-241; bin/compare_intermediates:126-156.

Glossary

logits, lm_head (wcls)
The last hidden vector is multiplied by the vocabulary matrix (lm_head, called wcls in tron) to give one score per token: the logits. This happens once per step, after the last layer.
argmax, greedy, temperature 0
Picking the highest-scoring token instead of sampling one at random. --temperature 0 selects this.
PRNG, seed
Pseudo-random number generator and the number that starts it. Greedy decoding never asks it for a number.
arm
One configuration in a comparison. Arm A = AMX off (TRON_AMX_DISABLE=1), arm B = AMX on.
A/A control
Running the same arm twice. If the two results differ, the setup is not reproducible and no A/B result can be read.
hollow A/B
An A/B where the code path under test never executed, so the arms are identical for a trivial reason.
teacher forcing
Feeding a fixed token sequence into the model regardless of what it would have picked, so every step of two runs sees the same input. runtron: --force-feed-text-token-file.
near-tie, margin
Two candidates whose scores are within rounding noise of each other; margin = top-1 minus top-2 logit. A tiny numeric change swaps the winner and everything downstream changes.
attention plan, main helpers
tron splits its CPU worker threads into "main helpers" (FFN and glue work) and attention workers, then assigns KV pages to attention workers. This plan fixes the order in which partial sums are added; floating-point addition is not associative.
pay_for_determinism
runtron flag that makes the attention plan a function of nothing measured at runtime (fixed helper split num_workers*2/7, uniform worker weights). Costs some throughput.
rdtsc
The CPU cycle counter. Without the flag, tron times each worker with it and re-balances the plan from those timings.
bf16, ulp
16-bit float with an 8-bit significand. One unit in the last place is 0.4-0.8 % of the value, so many logits are exactly equal and "identical logits" has a coarse floor.
KV page
64 tokens of cached keys and values. The AMX kernel works only on full, fully visible pages; the first one is complete at query position 63.
kv_mul, GQA
Query heads per KV head (grouped-query attention). qwen-3-4b, llama-3.1-8b, Mixtral-8x7B: 4. gpt-oss: 8. Mixtral-8x22B: 6.
QK, PV
The two matrix products inside attention: query x key (scores) and probabilities x values (weighted sum). AMX replaces both; PV rounding differs between the AVX and AMX paths.
dotter
tron's AVX-512 dot-product kernel used for QK on the non-AMX path.
K mirror, canonical
Two AMX layouts. Canonical reads the normal K storage; the mirror build keeps a second, AMX-friendly copy of K in a separate memory arena (cmake TRON_AMX_K_MIRROR). Choosing between them needs two binaries.
software vs hardware (HW) attention
Attention computed on CPU cores vs on the FPGA card. AMX only applies to the software path; ingested models default to hardware attention unless USE_HW_ATTN=0.
DMA progress
How much of the K/V data has finished copying to the card at the moment a pass is planned. With hardware attention on, tron decides per pass which pages the card handles from this, which can vary between runs.
ingested vs hand-written plugin
Ingested = C++ generated by the ingest pipeline from HF weights (qwen-3-4b, gpt-oss, ingested-mixtral). Hand-written = llama.hpp family (llama, Mixtral). They differ in which debug hooks exist.
executor, tp2, host
How weights and activations are placed: tp2 = result dimension tiled across two FPGA cards, bf16 activations; host / host_fp16 = CPU-only with float / fp16 activations (never AMX-eligible).
rinzler
The production inference server binary. runtron is the command-line tool; the recipe works only in runtron.
intermediates log
Text file of labeled activation vectors written by log_intermediate; label format <thing> layer L of token T.
WQ / WK / WV / WO / WFF1 / WFF3 / WFF2
Label names for the q, k, v, o projections and the gate, up, down FFN projections. "roped" = after rotary position embedding (RoPE) is applied.
token-tree linearization index
tron stores all live sequences in one tree; "token T" numbers the tokens of the current pass in tree order. For one sequence it equals the position.
relative L2
compare_intermediates' metric: length of the difference vector divided by length of the reference vector. 0 = identical.
TVD
Total variation distance between two probability distributions over the vocabulary; 0 = identical, 1 = disjoint. Golden tests set a per-step cap (0.05 for ingested llama-3.1-8b, 0.10 for gpt-oss-20b).
golden logits, outlier cap
Reference logits from HuggingFace stored by hash; a test passes if per-step TVD stays under the cap except for a small allowed fraction of "outlier" steps (each under a second cap).
envelope
An input-derived bound on how far two correct implementations may differ (here: accumulation order plus rounding mode). Inside = admissible; outside = bug.
speculation, draft model
Decoding several candidate tokens per step with a small draft model. Off by default; incompatible with force feeding.
ctest -L fake
The test label for tests that run on a fake device (no FPGA needed).
green ANSI chunks
runtron prints generated text in green escape sequences; earlier token comparisons extracted those from the console log. --output-token-file replaces that.
delphi-3bda, slot1
The Xeon 6 6962P test machine with FPGA cards, and the results directory (exec/results/slot1/) of the first measurement campaign.
