Address two medium-priority findings before merging: a new restriction rejects otherwise valid attention shapes, and required continuous integration does not enable the new cache layout. One low-priority comment corrects the documented rollback behavior. This review includes source inspection and small compile probes, but no full build or hardware test.

Words used here
  • K / KV: saved key vectors / saved key and value vectors used by attention.
  • Head: one attention calculation. Several query heads can share one KV head. kv_mul is that ratio.
  • VNNI layout: the pair-interleaved storage order introduced by this pull request. Two neighboring key dimensions are stored together across tokens.
  • AMX: Intel Advanced Matrix Extensions, the processor’s matrix instructions. AVX-512: its 512-bit vector instructions.
  • CI: continuous integration. GCP Nix is the repository’s required build-and-test workflow. The legacy CMake workflow runs separately.
  • P2 / P3: medium-priority correction / low-priority correction. These are review priorities, not measured failure rates.

P2Preserve support for larger query groups

Comment on h/tron/kernels/k_vnni.hpp:254–255

Review comment: Please provide a reader path for groups larger than 16 query heads per KV head. The layout selector enables VNNI for every 128-dimension head. However, this assertion rejects a group of 32 query heads sharing one KV head. That shape passes the existing geometry validator. The software attention caller instantiates this reader without a group-size fallback. Enabling TRON_K_VNNI therefore makes such a plugin fail to compile, even when AMX would not run. Process larger groups in smaller chunks, or provide a layout-compatible fallback.

Valid shape: 32 query heads / 1 KV head→128 dimensions: layout enabled→Reader limit: 16 heads
  • The existing validator accepts this shape. [Geometry contract]
  • The layout selector checks only head size. The software caller supplies the complete query group. [Layout selector, Reader call]
  • Compile probes using the exact extracted declarations accept the geometry and reject the new reader assertion. These probes do not compile a complete plugin. [Accepted geometry, Rejected assertion]

Validation after correction: Compile and exercise a 128-dimension software attention operation with 32 query heads and one KV head under the new layout. Compare its scores with the existing row-major reader. No deployed-model failure is claimed by this review.

P2Exercise the new layout in required CI

Comment on .github/workflows/cmake-single-platform.yml:331–334

Review comment: Please enable a coherent VNNI test build in the existing required CI pipeline. This change enables the layout only in the legacy workflow. The required GCP Nix build sets neither feature option. Both default to OFF. Its three-thread save test consequently returns immediately from each helper and checks that no shared window opened. The low-level layout tests still run, but required CI cannot catch regressions in shared saving or the integration of the new page layout.

  • The legacy workflow is limited to manual dispatch and calls from another workflow. [Legacy triggers]
  • The required test build omits both options. Their defaults disable them. [Nix configuration, Defaults]
  • The shared-save test accepts a window count of zero when the option is off. [Three-thread test]

Validation after correction: Verify that a required suite compiles the feature consistently across the library and plugins, and executes the shared-save and page-copy paths with the option enabled. Preserve coverage of the default layout.

P3Correct the rollback guarantee in the dispatch note

Comment on h/tron/models/kv_cache.hpp:706–710

Review comment: Please update item 4 of “AMX attention dispatch” to match this new storage contract. It still promises the same AVX reader and clean-binary numerical behavior when TRON_AMX_DISABLE=1 is set. With VNNI storage enabled, the new reader remains active. An operator following the old note would not restore the default reader during a numerical rollback. Qualify that promise with TRON_K_VNNI=OFF and point to this layout note. [Conflicting promise]

The new layout note matches the implementation and should be authoritative. The PR description already acknowledges this conflict.
