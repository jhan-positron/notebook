Causes in the skill texts

  • The gate rules are worded for hardware. Both skills describe a runtime skip behind a hardware probe. This test has a compile-time guard and a case that passes, so nothing skips [Ref10].
  • The lane fact is context, not a finding. Check 3A records that the lane compiles the case out, and then asks only to move the assertion. The code under test is itself behind the option, so a move does not work here [Ref10].
  • A true sentence closes the claim check. Check 7 asks that a CI sentence names the lane. After round 2 every sentence said plainly that the checks are compiled out, so the check had nothing to report [Ref10].
  • No skill carries the test policy of the repository. AGENTS.md says that a required CI suite must execute every committed test, and that an agent may not decide an exception. It also says to use "the smallest appropriate existing suite" [Ref7].
  • No skill searches the registration file for a sibling. The form of the fix stood at t/CMakeLists.txt:276 since 2026-09-04, with the comment "It passes the define itself so the test runs in every CI build" [Ref7][Ref9].
  • The skill update of 2026-11-19 took the cost lessons and left the CI lessons out. The claim check "CI covers this" went into no skill, and the gate rule lost its fix sentence [Ref14].

The five rules behind the edits

  1. Read where a new test section executes. Work out each guard in the lane's build of the test program. A hand-started workflow is not a required lane.
  2. Sort by what the section needs. It needs nothing from the option, or only the macro, or code that only the option-on build holds, or hardware.
  3. Name the remedy with the smallest scope. Move the section, or give the one test program the definition, before anything that changes the whole lane. Search the registration file for a sibling that already does it.
  4. Check that the definition is safe. No other part of the test program may compile an entity that the macro changes and that the test also uses.
  5. A declined remedy does not close a finding. Write the reason for declining as a condition on the fix, search again, and do not pass the point on as settled.
