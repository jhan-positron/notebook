## Short version

PR-3 is the third of four stacked PRs that replace PR 4424. It replaces the per-row scatter store of the packed K plane with a block save (16 token rows transposed in registers and written as whole 64-byte lines) and shares that store with the idle main helper threads, which removes the prefill cost of PR-1's store. Your job: build the branch jhan-vnnik-3-shared-save on jhan-vnnik-2-amx from the prepared patch (three known conflicts, each resolved by exact text, plus one two-line edit), run the syntax checks on claude-box, build and test on delphi-3bda (including the Haskell code-generator suite and a tp4 cell), write the body, and open PR-3 as a draft on jhan-vnnik-2-amx.

- Block save: PR-3's K save for a run of 2 to 16 consecutive tokens of one block. store_block (tensor/k_vnni.hpp) loads the 16 rows' 16 dimension pairs of one step (one 64-byte load per row), transposes the 16 registers in place (transpose_16x16_epi32, 64 shuffles) and writes each of the panel's 16 pair rows as one 64-byte store (masked to the present tokens' lanes when the block is partial). page::set_k_block (kv_cache.hpp) is the page accessor. ## 1. Context

- Why a split: jhan judges PR 4424 too big for manual review (4,054 added lines). PR-1 holds the layout with no AMX instruction. PR-2 holds the kernel that gives the layout its decode benefit. PR-3 holds the K store that removes the layout's prefill cost. PR-4 holds the tail block that restores token identity under CPU attention and fixes issue #4500.
- What PR-2 measured with the per-row scatter store (PR #4887 body, 2026-10-11, qwen3-4b tp2 8 users, CPU attention, against main at 72308ec90c): decode TPS +5.4 % at prompt 1024 and +9.5 % at prompt 8192; TTFT +100 ms (+3.2 %, inside the band) at prompt 1024 and -523 ms (-1.0 %, beyond the band) at prompt 8192. The body's Open item "The per-row scatter store's cost in TTFT" says that the third PR of the stack, the shared block save, is intended to remove it, and that no pair of that run isolates the store's own cost. PR-3 is that PR and that measurement (section 5.5).
- Why the store costs: PR-1's save_k scatters each token's 64 dimension pairs into 64 different lines (4 bytes per line), where the row-major store writes 4 whole lines. In the Perfetto trace of 2026-09-14 (exec/results/vnnik2-trace-20260915/analysis.md, qwen3-4b 8 users prompt 1024, 128 tokens of each user per pass), Save K took 858 us per prefill layer at tp2 (104.7 ns per (token, KV head) row) and 863 us at tp4 with the scatter store; with the block save and the sharing it took 80 us at tp2 (9.7 ns per row) and 60 us at tp4. main's row-major store took 274 us at tp2 and 281 us at tp4 in the trace of the same days (PR 4424 body). So the shared block save is faster than both. Save V, which is unchanged, took about 290 us per layer in every arm.
