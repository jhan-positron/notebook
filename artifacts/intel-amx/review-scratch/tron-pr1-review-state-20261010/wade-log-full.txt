Subject: VNNI K: the layout needs no AMX dispatch
The layout, its typed owner and views, the per-row store, the AVX-512
reader and the FPGA staging gather contain no AMX instruction and no
TRON_AMX_DISPATCH guard. So TRON_K_VNNI no longer requires
TRON_AMX_DISPATCH: the FATAL_ERROR block of src/tron/CMakeLists.txt and
the clause in the option help go. Both PUBLIC compile definitions stay.

The comments say what the reader does in this tree: until the VNNI AMX
kernel is merged it serves every page of a VNNI slot, it is the one
layout-specific reader of the plane, and TRON_AMX_DISABLE=1 changes no
score and no visit path for 128-dimension heads. The 64-byte alignment
of the owner is stated for the pair rows alone.

Subject: kernels: the AVX-512 reader of the VNNI K layout
h/tron/kernels/k_vnni.hpp adds k_vnni::qk_group, the AVX-512 score
reader of a VNNI K plane. One 64-byte masked load supplies one dimension
pair of 16 tokens. VDPBF16PS (bf16 query) or FMA on exactly widened
values (float query; an fp16 query is widened once) accumulates 16
scores at once. A group wider than 16 heads is scored in passes of 16.
A token whose bit is clear in the live mask is never read.

The software loop of self_attention.hpp records the relevant tokens of a
VNNI slot in a live mask and scores them after the loop with qk_group
through page::k_packed. A row-major slot keeps the per-token dotters.
The dense AMX page path is gated off for VNNI slots (temporary until the
VNNI AMX kernel lands), so every page of a VNNI slot takes the software
loop. The attn_stats comment and the amx_attn_iface diagram name the
reader.

Subject: kv_cache: store K of 128-dimension heads in the VNNI layout
With TRON_K_VNNI on, kv_block::k of a 128-dimension head is the typed
owner k_vnni_tensor; every other head size keeps the bf16 row array.
Note [K VNNI storage] in kv_cache.hpp describes the layout, its writers
and its readers. The row views page::k() and kv_block::k_view / k_at are
constrained to row-major slots. page::k_packed returns the read-only
plane view of a VNNI slot. The layout-agnostic page::set_k_row /
get_k_row take one token's row as a typed view and serve both layouts.
copy_storage_slot copies a whole page as one owner assignment and every
other range token by token. fill_random fills the plane through the
access helper.

save_k (model.hpp) stores each token's K row with page::set_k_row. A
non-bf16 activation row is converted to bf16 on the stack first.

CMakeLists.txt adds the option TRON_K_VNNI (default OFF).
src/tron/CMakeLists.txt defines TRON_K_VNNI PUBLIC on the tron target
and on tron_model_compile_config, so every translation unit that touches
a KV page, the generated model objects included, sees the same layout.

store_row (4 scatters), load_row (4 gathers) and copy_token.

k_vnni_view, so intrinsics-free headers can name them.
