Concrete findings:

F1 — Coverage: exercise the packed-K staging scratch in a value assertion.
Checks: 3A, 33. Suggested priority: P2.
Location: src/tron/gof.cpp:213; nearest changed test t/t_phase1_integration.cpp:859.
The new call passes a different scratch slice to each K head. Every changed test callback ignores that argument and returns a pre-existing contiguous row instead:
  t/t_phase1_integration.cpp:859-860 and :892-895
  t/t_gof_dma.cpp:347
  t/t_gof_staging_leaks.cpp:137
The first fake-device populate case checks only the populated flag (:875-877). The concurrent test decodes V only (:918-924). The DMA test checks final K bytes (:359-368), but through the old direct-pointer callback. The heterogeneous scheduler fixture's forward method runs no attention job (t/heterogeneous_scheduler_compile.cpp:216-224); its hardware cases inject plans/results and do not check staged K bytes.
A change from k_scratch.data() + h * HW_BAKED_HEAD_SIZE to k_scratch.data() would therefore pass these tests. It would make each head pointer refer to the final gathered head when the production callback uses scratch.
Please extend the existing fake-device populate case to gather distinct token/head/dimension values from packed cache pages into the supplied scratch and verify the final staged K values. Use the real callback or a shared callback helper if feasible. The assertion should fail when the per-head scratch stride is removed.
Policy: AGENTS.md:39-45 says not to use weak proxies when the real contract is more specific. AGENTS.md:53-56 prefers the closest existing test.
This is a new integration gap. It is separate from D8's accepted option-on required-CI exception. The FPGA token smoke is useful end-to-end evidence but does not isolate this byte contract.

F2 — Coverage: preserve existing numerical limits when TRON_K_VNNI is off.
Checks: supplementary repository test-policy audit; related to 3A's observation question and 10's scope trace. This is not presented as a demonstrated Wade habit about tolerance choice.
Locations: t/t_llama_unit.cpp:2733, :2739, :2872.
The weighted-V comparison changes from absolute 0.02 to 0.05 unconditionally. The weight-sum comparison at :2733 changes from absolute 2e-6 to relative 1e-6 unconditionally. The test helper's third parameter is an absolute tolerance (t/testutil.hpp:52-66).
With TRON_K_VNNI off, production attention retains the original dotter and AMX decisions (h/tron/models/self_attention.hpp:1884 and :1964-1969). The old comparison was intended to catch split/join discrepancies on that path. A weighted-V discrepancy between 0.02 and 0.05 now passes on the unchanged path.
The PR body openly describes the change and reports that the row-major result remained inside the old limits. That disclosure clears a hidden-behavior/scope accusation; it does not establish why the off configuration needs weaker assertions.
Please retain the original row-major limits and apply any justified VNNI-specific envelope only to the option-on case.
Policy: t/AGENTS.md:21 says "Do not delete, skip, or weaken existing assertions." AGENTS.md:118-120 also says to preserve behavior and never weaken a failing test.
No run was performed to claim the narrower VNNI bound would pass. The finding is specifically the unnecessary weakening of the option-off contract.

F4 — Description: the poison test proves score isolation, not absence of reads.
Checks: 3A, 17. Suggested priority: P3.
Location: t/t_k_vnni_layout.cpp:219-220, also :232.
The comment says "A stray load would spread it into the scores." Each token occupies its own accumulator lane in qk_group. The final store uses the live mask (h/tron/kernels/k_vnni.hpp:123). Replacing the masked load at :97 with an unmasked load would keep inactive NaNs in inactive lanes, and the masked store would discard them. The assertions at t/t_k_vnni_layout.cpp:299-302 and :316-321 would still pass.
The production instruction currently is masked, so no production defect is claimed. Narrow the comment to what the test proves: inactive-token contents do not affect live scores, and inactive score slots retain their preset. A separate read-observation test would be needed to establish the stronger no-read property dynamically.
This counterexample is established by the vector dataflow, not by an executed mutation test.
