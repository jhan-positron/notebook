An interactive guide to operand B

How AMX reads
operand B.

Short version

Intel AMX (Advanced Matrix Extensions, a processor instruction set) reads B as groups of input values. For BF16 (a 16-bit floating-point format), each group contains two values from the same B column at adjacent positions in the sum. A transpose of these pair-sized cells produces the required layout when each stored row contains one full column of mathematical B.

One B group · one output column
b0b1

2 values × 16 bits = 32 bits

same column · adjacent k

Scope: TDPBF16PS (the AMX instruction for BF16 matrix multiplication with 32-bit floating-point accumulation). This guide uses BF16 pairs. Integer instructions use groups of four values. [1]

Words and symbols used here

A, B, C are the left input, right input, and output matrices. Operand means an input to an instruction.

M, N, K count output rows, output columns, and products per output. m, n, k are their indices, starting at index 0.

VNNI means Vector Neural Network Instructions. “VNNI layout” here groups values from one B column at adjacent k positions.

Tile means a matrix-shaped processor register. FP32 means the 32-bit floating-point format used for the sums.

Row-major means storing one row after another. Transpose swaps row and column positions.

Scalar means one number. Pack means rearrange values in memory. p is a pair index. P is packed B. W = Bᵀ stores one B column per row.

What does “transposed” refer to? W is a common layout for weights (stored multiplication inputs), with one row per output column: W[n,k] = B[k,n]. Group adjacent W entries first. Then transpose the grid of whole pairs. Keep the order inside each pair.

04

Why not accept the ordinary 4 × 3 B?

A processor could be designed to do that. Interleaved pairs are a hardware interface choice. Matrix multiplication itself does not require them.

The design benefit is regular delivery of inputs to many multipliers. A packed B group already contains both values needed by one output column. The multiply unit can use this fixed arrangement without also accepting a second arrangement of the same values.

Intel documents the grouped operation and a conceptual grid of multiply-and-add units. The hardware cost argument below is an engineering interpretation of that interface. These references do not provide a measured comparison with a design that accepts ordinary B. [4]

Why exactly two values?

The chosen group is 32 bits wide.

  • One 32-bit input group holds two 16-bit BF16 values. Both products contribute to the same output. [1]
  • The integer version uses four 8-bit values in the same group width. Its output is a 32-bit integer. [3]
  • This gives both formats one output column per 32-bit B group. A 64-byte B tile row therefore supplies 16 output columns.

Two is a consequence of the chosen group width and data type. It is not a rule of matrix algebra.

Why interleave those values?

Each group has one destination.

For A’s first pair [1, 2], output column n = 0 needs B values [1, 4]. Both values must reach the calculation for C[0,0].

Ordinary B puts [1, 2] next to each other instead. Those two B values belong to different output columns.

Packing puts the matching values together before the multiply. The hardware can map each group to its output column in the same way across the row. This is the useful regularity of the format.

What would accepting ordinary B require?

To keep the existing paired multiply interface, a design would need to bring matching values from two ordinary B rows together. The diagram shows one possible preparation step inside such a hypothetical processor.

  • The hardware tradeoff: supporting this preparation can require storage, selection circuits, and connecting wires. Their cost depends on the implementation. An input format fixed in advance lets the multiply unit omit support for this extra layout.
  • The software tradeoff: a separate packing pass reads and writes the values before multiplication. A program that produces B directly in packed form can avoid that pass. An unchanged B block can be packed once and reused for many A rows or later multiplications. For small or rarely reused inputs, packing can be a significant part of the total work.

These are design tradeoffs, not measured power, area, or speed results. Reading two ordinary rows does not by itself imply twice the memory traffic.

Could another multiply design avoid interleaving entirely?

Yes. It could process one k position at a time. Multiply one A value by the whole corresponding B row, then add that contribution to the output row.

k = 0:  1 × [1, 2, 3] = [1, 2, 3]
k = 1:  2 × [4, 5, 6] = [8, 10, 12]
Combined contribution:  [9, 12, 15]

This is an outer-product approach (one A column multiplied by one B row). The example shows only output row m = 0. It uses ordinary B rows directly.

AMX’s paired interface groups two k positions for each output instead. An alternative organization could produce the same mathematical result. The paired format alone does not prove that every alternative would be slower.

The arithmetic above uses the exact integer examples from this page. A different addition order can change rounded floating-point results.

How closely does this match BF16 arithmetic?

The separate even-position and odd-position sums follow Intel’s instruction definition. The sums are combined before adding old C. Real operations round in FP32. [1]

All inputs and intermediate results in this example are small integers. They are represented exactly in BF16 or FP32 where required. The browser therefore shows exact results for these examples. It is not a general BF16 emulator.

06

Pack once. Load the resulting rows.

The direct mapping needs no intermediate transpose. This example uses even K and a tightly packed output buffer.

C-style pseudocode · bf16 means an existing BF16 storage type
// B is row-major: K rows by N scalar columns.
// P is row-major: K/2 rows by 2*N scalar columns.
// K is even. All dimensions are scalar counts.
for (int p = 0; p < K / 2; ++p) {
  for (int n = 0; n < N; ++n) {
    P[p][2*n    ] = B[2*p    ][n];
    P[p][2*n + 1] = B[2*p + 1][n];
  }
}

// If the source is W[n][k] = B[k][n], use:
// P[p][2*n    ] = W[n][2*p    ];
// P[p][2*n + 1] = W[n][2*p + 1];

These assignments copy BF16 values. They do not convert the pair to FP32. This mapping is the two-value case of Intel’s B-packing example. [2]

colsb is the tile-configuration field for bytes per row. A load’s stride is the byte distance between the starts of successive memory rows. For tightly packed P here, both are 12 bytes. [2]

Dimensions and remaining values

  • For an odd K, extend K to an even length. Fill the added k position with zero in both A and B.
  • In the standard tile configuration, each tile holds at most 16 rows and 64 bytes per row. [3]
  • For BF16, those limits allow M ≤ 16 output rows, N ≤ 16 output columns, and K ≤ 32 products per output in one instruction.
  • Larger matrices use multiple tile blocks. Successive k blocks add to the existing C tile.

The pair rule has a format.

INT8 means 8-bit integer input. INT32 means 32-bit integer accumulation. The AMX integer dot-product instructions group four INT8 values per output column. [3]

BF16: 2 values × 2 bytes = 4 bytes
INT8: 4 values × 1 byte = 4 bytes

For INT8, replace the pair with P[p,n] = (B[4p,n], …, B[4p+3,n]). The packed tile has K/4 rows. [2]

This guide describes TDPBF16PS and the standard integer dot-product family. Check the specific instruction when using other AMX extensions.

Byte offsets for the packed example

A tightly packed BF16 P places B[k,n] at byte offset 4N × floor(k/2) + 4n + 2 × (k mod 2). Here floor rounds down to an integer, and mod gives the remainder.

For B[3,1], the offset is 12 + 4 + 2 = 18 bytes. Its value is 11. It is the second value of P[1,1]. The earlier k value occupies the lower-addressed 2 bytes of each pair.
