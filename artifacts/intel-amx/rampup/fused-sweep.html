Whole-Path Attention Bench

Per-page time for the complete software-attention pipeline (pack → matrix multiply → score handling → softmax → multiply-by-V → accumulate), one core (96), delphi-3bda, quiet machine, every point self-validated against a scalar reference (worst rel err 3×10⁻⁴). Harness: tron-amx/src/amx_fused_bench.cpp; raw data: fused-sweep-v2.txt. 2026-08-18.

Terms. Nq = number of queries multiplied against one KV page in a single matrix operation (the "query width"). For qwen3-4b private decode, Nq=4 is guaranteed: one decode token activates the 4 query heads that share each KV head (32 query heads ÷ 8 KV heads). Nq of 8–16 occurs only when several queries legally share the same physical page (same-sequence prompt positions, shared system prompts, speculative branches). AVX baseline = the shipping vector-instruction approach (one dot product per token per query). ours 4+4 = our orientation (Sᵀ=K·Qᵀ): K is used exactly as stored, but the score block comes out sideways and needs a transpose step; "4+4" is the output blocking of the multiply-by-V stage. mirror = the other orientation (S=Q·Kᵀ; the formulation is from Bill's PR #2934, the kernel measured here is our own harness implementation of it): scores come out row-per-query with no transpose, but it needs K in a different byte arrangement — so a second, rearranged copy of every K page (the "mirror") is kept and written whenever K is saved. The mirror's upkeep costs are excluded here by design: the extra save-time write (which runs on the RX driver thread, on the per-layer critical chain), ≈+50% K-cache memory, and keeping the copy consistent when pages are moved by defragmentation. Those are charged in the system-level runs (P2). Residency = where the KV data lives during the run: L2 (per-core cache), L3 (shared cache), or DRAM, controlled by the size of the page ring the benchmark cycles through.

Verdicts

  • Mirror orientation wins at every width and residency at the harness level — at the guaranteed decode width 4: 2.36× (L2) / 1.68× (L3) / 1.77× (DRAM) vs the AVX baseline, and 1.3–1.8× vs our transpose-based orientation. Root cause of our gap: the score round-trip through memory (the score tile round-trips through memory and is transposed; corrected 2026-08-21 - an earlier version called this a store-forwarding stall, but opt-manual 20.15 supports 64-byte tile-store-to-vector-load forwarding and a 6962P microbenchmark measured no such stall, see doc 01 §6.4).
  • Not yet a formulation decision: these numbers exclude the mirror's system costs — the extra save_k write on the per-card RX worker (per-layer critical chain), ≈+50% K+V cache capacity, and defragmentation coherence. Those get charged in system-level runs per the consensus rule.
  • Alternative that could close our gap without a mirror: pipelined score handling — process page N−1's scores while page N's tiles store (removes the store-to-load stall). Queued as a P5 experiment.
  • Width crossover vs AVX: mirror orientation already wins at Nq=2; ours at Nq≈3–4; Nq=1 stays AVX.

Method notes: 200k/800/25 iterations per point for L2/L3/DRAM rings; identical softmax code in all variants; mirror pack time excluded from the page loop (write-through model), reported separately in system runs; epilogue optimizations included in all AMX variants (rescale skipped when the running max does not move, transpose+scale as one pass, width-specialized transposes).
