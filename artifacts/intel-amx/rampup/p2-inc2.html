P2 increment 2: mirror-orientation QK via a K mirror plane

Same protocol as increments 1/1b: qwen-3-4b-tp2, software attention, means of 3 repeats. The mirror build (TRON_AMX_K_MIRROR=ON) adds a third, VNNI-interleaved K plane to every KV block (+50% KV storage), written through at save_k time on the RX worker; the QK kernel becomes S = Q·Kᵀ with no transposing store. The + QK and + PV dots are from the increment-1/1b runs (AMX-off arms of all runs agree within 0.5%). Dispersion: worst cell-level peak-to-peak spread across all 24 cells is 1.15% of the mean; per-rep values are in the raw files.

Naming: "mirror" is the formulation — S = Q·Kᵀ read from a second, VNNI-interleaved copy of K — and it originates from Bill's PR #2934. The implementation and every number on this page are ours (worktree jhan-amx-p0, binary 02b81206…); Bill's PR tree predates the qwen plugin and cannot run this model.

AVX-512 baseline+ QK on AMX (inc 1)+ PV on AMX (inc 1b)+ K mirror orientation (inc 2, this run)

Decode throughput — all four arms

Takeaway: the mirror orientation adds +3.7% / +5.2% decode on top of increment 1b at 1u/8K and 8u/2K; at 1u/2K the +0.1% delta is parity (rep ranges fully overlap). Total AMX gain: +4.5% / +16.1% / +23.0% over the AVX baseline. The gain grows with attention share, as with every increment so far.

Prefill throughput

Takeaway: prefill nets +1.0–2.0% over increment 1b including the RX-worker mirror write-through — the save_k write cost is real but smaller than the kernel gain, so the net stays positive (total: +44.4% to +105.3% over AVX).

The costs

Cost 1 — the kill switch is not a baseline rollback: with AMX disabled at runtime, the mirror build's AVX path runs -3.8% / -7.8% / -3.9% below the increment-1b build's AVX path, even though mirror writes are gated off. Decomposition (same night, layout-only control build + decode-phase perf counters; "layout" = how each KV block arranges its data planes in memory — two planes K+V today, three with the mirror plane added, see the doc 02 glossary): the 3-plane layout alone reproduces the penalty exactly (-3.7/-7.6/-4.0%); LLC-load miss rate jumps 50.8% → 84.6% while dTLB misses stay ≈0.00% in both arms — cache/prefetch locality, not TLB (the dead mirror plane between every K/V block breaks prefetch streams). The layout also cost the CANONICAL kernel -9.2/-8.1% when run on 3-plane blocks (the layout-only build); the separate-arena mirror (increment 3, measured later the same day) removed the fallback penalty entirely without changing the mirror arm's speed - the tax belonged to the canonical kernel's access pattern only. Until that lands: a mirror build should only ship where AMX is actually on, and its runtime disable must not be described as returning to baseline performance.
Cost 2 — KV capacity: exact arithmetic, not a measurement: the same KV byte budget holds one third fewer pages (48 KB vs 32 KB per block-page). Not binding at these test loads; it matters for long-context, many-user serving.
