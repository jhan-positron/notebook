Decode (token generation) throughput

Takeaway: adding PV (increment 1b) roughly doubles every decode gain vs QK alone — +4.4% → ctx 2048, +12.0% → ctx 8192, +16.9% → 8 users — and the gain grows with attention's share of the decode step, as the P0 model predicted.

Prefill (prompt parsing) throughput

Takeaway: prefill gains are larger than decode gains (+41.6% to +102.0%): during prefill every page is full and reused across many query tokens, so K/V stay in cache — the regime where the P0 grid showed the AMX kernel's largest margins. The 8192-token prompt now parses in half the time (15.7 s → 7.8 s).

Method and glossary

  • Same-binary A/B: one build (sha256 787342cf…) run twice per workload set; the only difference is the TRON_AMX_DISABLE environment variable, so compiler and code-layout effects cancel out.
  • Decode: generating 253 response tokens one at a time (256 requested; the run stopped 3 short in every case, identically in both arms). Prefill: parsing the prompt (2048 or 8192 tokens) before generation starts; with USE_HW_ATTN=0 its attention also runs on the CPU.
  • What increment 1b adds: increment 1 moved only the QK score computation (scores = query · key) to AMX tiles; increment 1b also moves PV (output = attention weights · value). The value data is stored pair-interleaved, which is exactly the AMX input format, so no repacking is needed.
  • Machine: delphi-3bda idle (production serving down, load 0.27), 2026-08-18 22:15–22:23 UTC, inside the confirmed free window (nightly CI prep starts 03:30 UTC).
  • Numerics (corrected 2026-08-19): both paths round the attention weights to bf16 for the PV multiply — the AVX-512 path truncates (16-bit shift, kv_cache.hpp:1795) while the AMX path rounds to nearest even; both accumulate in fp32. For finite, non-subnormal values the expected differences between the two arms are that rounding mode and the fp32 reduction order (full writeup: doc 02 §6b). First token-level check (same night, greedy + seeded + --pay-for-determinism; control: two AVX runs byte-identical): AMX output byte-identical at ctx 8192, one argmax flip about 20 tokens in at ctx 2048 (one prompt per context — a sample, not a verdict). The formal T1 logit-tolerance test is still the gate before any enable-by-default.
