AMX / VNNI-K decision tree when USE_HW_ATTN=1

The tree of 2026-09-16, kept in its original shape. Lines that hardware attention changes are marked. Checked against tron commit ff680c8020.

Short version. USE_HW_ATTN=1 changes no compile-time line. It turns hardware attention on for every eligible model, with the FPGA serving queries from position 127 on. Every run-time leaf of the tree now applies only to the (query, page) pairs the CPU still computes, and on a VNNI K slot the copy to the FPGA costs 4 gathers per token.

What did not change, and why

  • USE_HW_ATTN is read with getenv once, at model start. No CMake option and no #ifdef depends on it [src/tron/models/hw_attn_config.cpp:19-33].
  • The K layout is a compile-time property of the KV slot's head size. Hardware attention does not read it [h/tron/kernels/k_vnni.hpp:91-97].
  • The AMX gate has no hardware-attention term. It tests the probe, the shape, and the dense predicate, and it sees only the pairs the CPU computes [h/tron/models/self_attention.hpp:1236-1239, 1546-1556].
  • The CPU still writes K and V of every token into the cache. The FPGA copy is staged from that cache [h/tron/models/kv_cache.hpp:694-698].

Words used here

hardware attention, software attention
Hardware attention: the FPGA (the attached accelerator card) computes the attention of a (query, page) pair from K and V copied into its memory. Software attention: the CPU computes it, with the dotter, the VNNI reader, or the AMX kernels.
USE_HW_ATTN
The environment variable that selects hardware attention. Unset: on for ingested models when FPGA cards are present. 0: off for every model. A number N above 0: on for every eligible model, and N sets the engagement point [h/tron/models/hw_attn_config.hpp:9-15].
engagement point
The first sequence position the FPGA may serve. N rounds up to the end of a 128-position hardware page (k x 128 - 1), never below 127. So 1 gives 127 [src/tron/models/hw_attn_config.cpp:24-30; h/libpos.hpp:77, 90].
SW_REQUIRED, HW_AVAILABLE
The two marks the scheduler puts on each (query, token range) pair of a hardware-enabled layer. SW_REQUIRED pairs go to the CPU: queries at positions below the engagement point, and the causal tail past the K and V already copied to the FPGA. HW_AVAILABLE pairs go to the FPGA [h/tron/scheduler/full.hpp:1936-1965].
staging
The copy of K and V rows from the CPU cache into the FPGA's memory. On a VNNI K slot each token's row is rebuilt with 4 gathers first, because the row is not contiguous there [h/tron/scheduler/full.hpp:2644-2661].
dense page
A (query, page) pair that passes is_dense_amx_page: all 64 tokens live, the query sees the page through one visible range, and the page is inside the sliding window. Only dense pages run the AMX kernels [h/tron/models/self_attention.hpp:1383-1394].
dotter, VNNI reader
The two CPU readers for pages that do not take AMX. The dotter is the AVX-512 per-token dot-product loop for row-major K. The VNNI reader (k_vnni::qk_group) is AVX-512 code for a VNNI K plane, 16 tokens per vector.
pass
One forward step of the model over a minibatch of tokens: all users' new tokens for one decode step, or one chunk of a prompt in prefill. The visible ranges of a pass close above every query token of that pass, so a page whose tokens are queries of the same pass is not dense for them [src/tron/models/ranged_mask.cpp:42-49].
EAGLE model, ingested model
EAGLE: a draft model for speculative decoding, excluded from hardware attention. Ingested model: a model whose C++ plugin the ingest pipeline generated, as opposed to a hand-written plugin.

Insufficient data

  • No counter measurement shows how many pairs take the AMX path under hardware attention. A run with TRON_PAGE_SHARE_COUNTERS (the per-page visit counters) on a hardware-attention arm would give the number.
  • The staging cost of a VNNI K slot (4 gathers per token) is unmeasured. A staging-time comparison of a row-major and a VNNI binary on the same prompt would give it.
