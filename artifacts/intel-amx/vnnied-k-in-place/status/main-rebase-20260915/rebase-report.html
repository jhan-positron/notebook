VNNI-K branch rebased onto main

2026-09-15 23:30 UTC to 2026-09-16 00:30 UTC. Branch jhan-amx-vnniK, PR positron-ai/tron #4424. Written by Claude for jhan.

Short version. PR #3879 merged into main, so the 17 VNNI-K commits were moved from their old jhan-amx-p0 base onto main, and PR #4424 now targets main with an updated description. Five commits needed conflict resolution, and main's new whole-page K views plus two new tests needed small adaptations so a TRON_K_VNNI=ON build compiles. The force-push is the remaining step (yours), followed by a measurement round against a main binary.

Words used here

TermMeaning
tronThe inference program under test.
VNNI-K, TRON_K_VNNIThis branch: the K cache of 128-dimension attention heads is stored in the AMX VNNI layout (the pair-interleaved operand layout of the AMX tile multiply). TRON_K_VNNI is the CMake option that turns it on (default OFF).
row view, page::k()An accessor of the KV cache that returns one token's K values as one contiguous row. A VNNI slot has no such row, so the accessor does not exist for 128-dimension slots when TRON_K_VNNI is on.
whole-page K viewNew on main ("Reuse checked K page views"): page::k(slot, kv_head) returns all 64 rows of a page at once. Same restriction applies.

7. CI coverage on main (unchanged by the rebase, worth knowing)

  • No default CI lane compiles TRON_K_VNNI or TRON_AMX_DISPATCH. The GCP Nix build (nix/cmake-tron-test-build.nix) sets neither option. The flags live only in the legacy CMake workflow.
  • publish-deb.yml calls the legacy workflow as its test gate for tag pushes and feature-branch publishes. After this PR that gate compiles and tests tron with TRON_K_VNNI=ON. The .deb itself is built by make deb without the flag.
  • slice.yml triggers on changes to cmake-single-platform.yml, so the PR gets one extra CI job (Slice self-tests). It does not read the configure flags.
