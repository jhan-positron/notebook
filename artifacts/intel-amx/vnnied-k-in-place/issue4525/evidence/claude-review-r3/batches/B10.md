### N15 [round-2 NEW finding, severity MINOR] Aligned flag of moved set_v/get_v row views unstated
- Where in the round-2 design: 5. Interface design (One cache row-write rule)
- Relates to round-1 id(s): F01, F10
- Claim: Ambiguity that makes the implementer guess: the design says the packed append_v_row (the renamed set_v, the V row save) takes 'the existing contiguous row view with the caller's scalar type and alignment', and load_row (the renamed get_v) wraps caller scratch in an existing contiguous view. tron's row view carries an `aligned` template flag that may be true or false. Today's set_v bodies load the source with aligned instructions (_mm256_load_epi32 for bf16 and fp16, _mm512_load_ps for float) and get_v stores the destination with aligned instructions (_mm512_store_ps, _mm256_store_si256). If the new overloads accept aligned == false views, the implementer must either keep aligned loads (undefined behavior on an unaligned caller) or switch to unaligned loads (an instruction change the design's own section-8 instruction comparison would flag). The design does not say which. Today's callers do satisfy 64-byte alignment: save_v_impl passes &vs[ix][kv_head * head_size] with head_size % 32 == 0 into a chunk-aligned buffer, and the GOF (hardware cache preparation) callback passes caller-owned 64-byte scratch.
- The round-2 design text said: "Packed overloads take v_vnni_view<bf16,R,D> or v_vnni_view<const bf16,R,D>. Sources use the existing contiguous row view with the caller's scalar type and alignment. Preserve those properties at the call site. [...] load_row moves today's get_v loops. Support the existing bf16 and float destinations needed by its callers. Wrap caller-owned scratch in an existing contiguous view; add no scratch-view type."
- Evidence given in round 2: h/tron/models/kv_cache.hpp:2300, 2308@2880c3aa9b (`bf16x16 lo = _mm256_load_epi32(vout_ptr + i)`), :2339, 2349 (fp16 source, _mm256_load_epi32), :2380, 2389 (`fp32x16 lo_fp32 = _mm512_load_ps(vout_ptr + i)`), :2421, 2430 (get_v float: _mm512_store_ps), :2455, 2463 (get_v bf16: _mm256_store_si256); h/tron/models/model.hpp:2831-2832@2880c3aa9b (`pg.template set_v<geometry.kv>(slot, kv_head, j, &vs[ix][kv_head * geometry.kv.head_size])`); h/tron/scheduler/full.hpp:2652-2656@2880c3aa9b (v_head_fn passes `dest` scratch to get_v); h/tron/tensor/view.hpp:116-121@2880c3aa9b (rank-1 view template parameter `bool aligned`); design.txt:240, :242.
