## F01 [major] Model V save path: the design never names which operation save_v_impl calls

- Claim: Ambiguity: the design never says which of its two V write operations save_v_impl (the model.hpp function that stores one token's V vector into the cache) calls after the parent PR. That zeroing is the only thing that keeps the padding row zero when a page offset is reused, because clear_kv_complete_at (the function run when an offset is reassigned) resets completion counters and never touches V bytes. An implementer who follows those sentences leaves a stale odd row in place after an even write on a reused offset. scaled_v (the weighted V sum) rounds its loop bound up to a full pair, so a stale NaN in that odd row is multiplied by weight 0 and the sum becomes NaN. The existing regression test calls page::set_v directly, so it would keep passing while the model path regressed.
