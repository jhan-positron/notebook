### G27 [round-3 NEW finding, severity NOTE] Debug row: 'make BUILD_TYPE=Debug <test>' does not reconfigure an existing gen/, and 'Plain Make defaults can restore RelWithDebInfo' holds for one path only
- Where in the round-3 design: 8. Build configurations table, row 'NaN-preserving Debug check, 16 lanes' (design-r3.txt:455; worktree rule :449)
- Relates to earlier id(s): N39 N60 N02
- Kind: ambiguity | found by lenses: process-ci, disposition-checker
- Claim: The row tells the agent to run targeted conversion cases with make BUILD_TYPE=Debug and the test target. That command changes the build type only when Make re-runs the CMake configure step, and Make re-runs it only when the gen/config/test stamp is missing or one of its listed inputs changed; none of those inputs tracks BUILD_TYPE. So in a gen/ already configured as RelWithDebInfo, make BUILD_TYPE=Debug t_llama_unit keeps the cached RelWithDebInfo and TRON_IGNORE_NAN stays defined; the agent would test the macro-defined policy while believing it tested the Debug policy. Conversely, in a worktree configured by hand with the row's cmake line, the first plain make target re-runs cmake with Make's default -DCMAKE_BUILD_TYPE=RelWithDebInfo and silently undoes the Debug configuration, while in a Make-configured Debug worktree a later plain make keeps Debug. The sentence 'Plain Make defaults can restore RelWithDebInfo' is true for the first path and false for the second, and the row does not say which. The t_% Make target also builds and then runs the whole binary with no Catch2 filter. The design's separate-worktree rule (:449) and 'Confirm the macro is absent' limit the damage, so the risk is low.
- The round-3 design text said: "Run targeted conversion cases using make BUILD_TYPE=Debug with the applicable test target, or build with cmake --build gen --target t_llama_unit after Debug configuration. Plain Make defaults can restore RelWithDebInfo. Confirm the macro is absent."
