### G49 [round-3 NEW finding, severity MINOR] AMX-on row asks for 'evidence that the kernel ran' without naming a method
- Where in the round-3 design: 8. Build configurations table, row '16 lanes, AMX code on' (design-r3.txt:453; rule at :445)
- Kind: omission | found by lenses: process-ci
- Claim: The row requires 'evidence that the kernel ran' for real numerical results but names no artifact that counts. The design's own rule at :445 says hardware-unavailable early returns do not count as execution. The AMX tests print a WARN line and return when the runtime probe says AMX is unavailable, and the probe also returns false when TRON_AMX_DISABLE=1 is set. A concrete, source-backed method exists and should be named; otherwise the implementer may present a green t_amx_numerics run from a host without AMX as kernel execution.
- The round-3 design text said: "Compile real kernels and unconditional fake definitions. Execute applicable fake dispatch cases. Real numerical results require compatible AMX hardware and evidence that the kernel ran."
- Evidence given in round-3: t/t_amx_numerics.cpp@2880c3aa9b:146, :190 (WARN("AMX unavailable on this host - QK precision check skipped") and the PV counterpart before returning); t/t_amx_numerics.cpp@30c4ac82cb:199-202 (same pattern for the VNNI QK check). h/tron/kernels/amx_attn_iface.hpp@2880c3aa9b:167-170 and src/tron/kernels/amx_attn.cpp@2880c3aa9b:61 (available() true when CPU, OS and per-process permission allow AMX and TRON_AMX_DISABLE is not 1). design-r3.txt:445, :453.
- RECOMMENDATION (what the design was asked to change): After 'evidence that the kernel ran' add: 'Evidence is the Slice log of t_amx_numerics and t_amx_dispatch_dtype from delphi-3bda showing the AMX precision sections passed with no AMX unavailable on this host WARN line, plus a control run of the same binaries with TRON_AMX_DISABLE=1 whose log shows the WARN lines. Record both log paths.'
- LEAD NOTE (final grade minor): The finder graded this a note; all three verifiers grade it minor and the lead follows them. A "Catch2 passed" line proves nothing here: both AMX precision cases return before any assertion when available() is false, after a WARN line, and the listener logs passed whenever no assertion failed (testlog.cpp:21-25). Correction: drop t_amx_dispatch_dtype from the kernel-ran evidence; it links CPU fakes and a fake available() that returns true. Name the t_amx_numerics Slice log with no "AMX unavailable" WARN line plus a TRON_AMX_DISABLE=1 control run.

'Catch2 passed' alone is not enough: the tests WARN and return when available() is false, and that still passes. t_amx_dispatch_dtype uses fake kernels and is not hardware evidence."
