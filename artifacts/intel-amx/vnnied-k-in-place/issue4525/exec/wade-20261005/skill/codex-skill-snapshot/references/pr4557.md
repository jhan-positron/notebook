# PR #4557: source examples and limits

Short version: Wade's review exposed gaps between a refactor plan, its tests, and its final claims. Several facts were already known during design review. Apply the checks without treating every proposed deletion or stylistic preference as a correctness requirement.

Source: [Wade's review of Tron PR #4557](https://github.com/positron-ai/tron/pull/4557#pullrequestreview-5420005787), submitted October 5, 2026. Code references below use head `96a6220ab664f73f215c57d6ed7802bbacd4d7a2`. PR descriptions and thread resolution can change afterward.

Words used here:

- KV cache: saved key (K) and value (V) vectors used by later attention operations.
- Packed V: value vectors stored with adjacent tokens interleaved for each dimension.
- bf16: the 16-bit floating-point format used for stored values.
- Poison: an invalid value deliberately written into unused storage to reveal an incorrect read.

## Tests that froze incidental numerical behavior

A new test required a float NaN with only discarded payload bits to become bf16 infinity. Other rows required the existing truncation behavior. Preserving these operations during the refactor did not establish a lasting consumer requirement. Keep exact bf16 copying and partner-zero rules distinct from the conversion policy. Do not change the numerical implementation merely to remove an unjustified test contract. [Comment](https://github.com/positron-ai/tron/pull/4557#discussion_r4188336250)

## Independent layout comparison behind a hardware gate

The packed-storage byte comparison used an independent formula. It followed the `available()` early return in the AMX numerical test. The comparison itself did not need AMX. The ordinary `at()` reader and the append operation shared `pair_base`, so their round trip could not independently establish the storage mapping. Review oracle independence and assertion reachability together. [Comment](https://github.com/positron-ai/tron/pull/4557#discussion_r4188336256), [test at reviewed head](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/t/t_amx_numerics.cpp#L196)

The workflow compiled with `TRON_AMX_DISPATCH=ON`. This contradicts the PR description's AMX-off claim, but does not by itself prove that every runner could execute AMX. Check runner capability separately. [Workflow](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/.github/workflows/cmake-single-platform.yml#L355)

## K naming versus K enforcement

`native_k_view` aliases the generic row-major view. A matching unrelated generic view or an explicitly wrapped pointer remains accepted. However, the pointer constructor is explicit: direct unwrapped pointer calls are rejected. Wade's wording that any pointer passes needs that qualification. Correct an overclaim about layout or provenance without falsely claiming that the direct-call compile check fails. [Comment](https://github.com/positron-ai/tron/pull/4557#discussion_r4188336267), [alias](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/h/tron/tensor/kv_cache_fwd.hpp#L43), [call probes](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/t/t_llama_unit.cpp#L374)

## Structural assertions need individual assessment

Several owner traits repeated assertions in production code. Tests forbidding an unused operator also described an implementation choice. Two checks had concrete safety consumers: rejecting a view of a temporary owner prevents that dangling-view case, and owner alignment supports aligned vector accesses. Those checks do not establish all lifetime or alignment safety. Do not adopt a blanket deletion of structural assertions. [Comment](https://github.com/positron-ai/tron/pull/4557#discussion_r4188336302)

## Matching copy parities do not prove matching observations

Wade noted that two tests exercised all source/destination even/odd combinations. That observation alone does not justify removing a poison variant. The full-page bit-copy case subsequently overwrites odd partner positions. The partial-page poison case observes the final unused odd partner.

At this head, even-source/even-destination and odd-source/even-destination copies clear the partner in separate implementation branches. The two poison configurations end with those different branches. Before reducing coverage, preserve an observation of both clearing obligations. A focused case can be smaller than a full repeated matrix. [Comment](https://github.com/positron-ai/tron/pull/4557#discussion_r4188336316), [copy branches](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/h/tron/tensor/v_vnni.hpp#L357), [poison case](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/t/t_llama_unit.cpp#L3293), [bit-copy case](https://github.com/positron-ai/tron/blob/96a6220ab664f73f215c57d6ed7802bbacd4d7a2/t/t_llama_unit.cpp#L3664)

The poison section's name said preservation while its assertions required zeroing. This is a separate, straightforward description defect. [Comment](https://github.com/positron-ai/tron/pull/4557#discussion_r4188336324)
