> [!NOTE]
> **Medium Risk**
> Touches scheduler shard allocation and HW-attention indexing/buffering; mistakes here can cause incorrect attention outputs or hangs under long-context/multi-device workloads.
> 
> **Overview**
> Updates the HW-attention job API to be *explicitly device-bound* by passing a `PosDevice*` through `fill_attn_job_template` and storing it on the queued work request.
> 
> Fixes multi-device / longer-context HW attention planning and execution: shards are now allocated round-robin across available devices, partial-shard boundaries are derived from DMA progress, and `self_attention::prepare_hw_attention` computes a *relative* `tok_ix` that reflects the concatenated valid positions across (potentially non-contiguous) shards. HW attention result buffers are also changed to be per-pass (vector of `unique_ptr` rows) so split workloads don’t collide.
> 
> Tightens worker-side diagnostics by improving a ring-index assertion message and disabling some hard-fail debug checks/log spam behind `#if 0`.
