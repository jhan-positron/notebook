## PR body (as it is now; may have been edited after the review)

## Why this change exists

`pos_shutdown()` was commented out in test listeners across the codebase with the note: *"Crashes and burns due to unfreed allocations."* This caused:

1. **Every test binary leaked hugepages and DMA allocations** (tracked in #1733)
2. **Intermittent segfaults in `t_dma`** during process exit (#1535, #2400) — all 3 test cases pass, then the process segfaults during teardown because the kernel tears down VFIO BAR mappings while static destructors still reference them

The root cause: `PosDevice::init()` allocates DMA buffers and queues, but nothing freed them. `pos_shutdown()` was disabled because calling it triggered heap asserts on the outstanding allocations.

## What changed

### DMA cleanup infrastructure
| Change | Why |
|--------|-----|
| `PosDevice::destroy()` | Matching free for `init()`. Without it, heap assert fires on shutdown. |
| `hwkv_rings` destructor | Frees 128 cache block DMA allocations. |
| `delete device` + `devices.clear()` in `pos_shutdown` | Without this, device objects leak and restart appends duplicates. |
| Zero-init pointer members in `PosDevice` | `destroy()` null-checks before freeing; uninitialized pointers cause garbage `dma_deallocate`. |
| `pos_heap_active_allocations()` | DMA allocation counter (real heap + fake-mode). Enables leak detection in test listeners. |

### t_dma segfault fix (#1535, #2400)
| Change | Why |
|--------|-----|
| Enable `pos_shutdown()` in `TestDmaListener` | Without it, process exit races VFIO BAR teardown against static destructors → segfault. |
| Release DmaQueues in transfer test | Test acquired TX/RX queues per device but never called `release()`. |
| Baseline allocation tracking | Record `pos_heap_active_allocations()` after `pos_startup()`, warn only if tests leak above that baseline. The 288 device-init allocations (64 device.cpp + 64 consumed_head + 32 ring buffers + 128 hwkv_rings) are expected. |

### Restart lifecycle hardening
| Change | Why |
|--------|-----|
| `pos_startup()` idempotency guard | Prevents duplicate device scan if called twice without shutdown. |
| `vfio_groups = nullptr` after delete | Prevents double-free on second shutdown. |
| `get_group_fd` EBUSY retry | IOMMU teardown is async; rapid restart cycles hit EBUSY on group reopen. |

### Test + review feedback
| Change | Why |
|--------|-----|
| `t_pos_restart` (3 FPGA cases) | Restart produces same device count, idempotency, double-shutdown. |
| `t_pos_lifecycle_fake` (6 cases) | Shutdown with outstanding allocs, allocation tracking, reinit. |
| `INFO()` diagnostic in lifecycle test | Per mcherba review — surfaces allocation count on failure. |

## What this does NOT change

Production behavior is unaffected. `pos_shutdown()` was already called at process exit in Rinzler. The only behavioral change is in test infrastructure — listeners now clean up instead of leaking.

### Superseded by main (resolved during merge)
- Inline group init in `vfio_device_init` → main serialized into `vfio_init_groups()` (better race fix)
- `host_initialized` double-call guard → landed independently on main
