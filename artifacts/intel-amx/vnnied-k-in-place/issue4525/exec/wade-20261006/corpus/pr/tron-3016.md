## PR body (as it is now; may have been edited after the review)

First pass at opening up the APIs to enable Weight load reuse with HW attention.  Currently we end up with batches of 16, and the sooner we can get gof_rodeo out of the main thread and not blockign the better.  While a gof_rodeo only happens every 4 token positions in generation, during prompt parsing we see 32 of them per batch of 128 token positions at each layer, and it's taking about the same amount of time as the Actual attention work  and should be non-blocking.

> [!NOTE]
> **High Risk**
> Large changes to HW attention correctness, async KV DMA ordering, and multi-device synchronization; regressions could cause wrong attention results or stale HBM reads.
> 
> **Overview**
> Expands **hardware attention** toward weight-load reuse: multi-query passes are planned with **EMEM-aware** shard/query limits (`max_shards_for_emem`, `maximum_hwattn_batch_size`), per-query `last_hw_token_pos`, and multi-Q metadata via `tok_ix_per_b` instead of a single shared `tok_ix`.
> 
> **GOF KV offload** is reworked to be less blocking on the forward path. Completed GOFs are prepared with `prep_xfer` / `xfer_n_blocks`, then submitted either **locally** or through a **per-device `gof_xfer` manager queue** (`minfifo` + batch submit under `producer_mutex`). `dma_tracker` gains `push_batch`, **`await_layer` waits all devices**, and optional `await_all` for deterministic tests. Scheduler/model changes add **multi-binding `gof_jobs`** (shared-prefix sibling GOFs), prefix-based shard eligibility, async backfill task dispatch, and barriers (`wait_for_gof_xfer_submits`, cooperative drain).
> 
> **Prompt/prefill** can stay on HW for shared K/V boundaries (scheduler no longer forces multi-query edges entirely to SW); causal tails are reconciled into SW masks. HW launch ordering in ingest moves **`prepare/launch_hw_attention` before `save_k`/`save_v`** so attention overlaps persistence. **`USE_HW_ATTN` defaults on**; bitfile **WLR** capability is checked at device init.
