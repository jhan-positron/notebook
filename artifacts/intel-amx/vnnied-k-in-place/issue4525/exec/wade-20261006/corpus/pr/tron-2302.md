## PR body (as it is now; may have been edited after the review)

A new unit test, `t_clearhbm` is added (disabled for normal CI runs) which uses an approach developed by @Wado-posi to clear the HBM. This runs on all the devices in the instance in parallel for speed.

On Atlas, with the FPGAs running bitfile `archer_128col_nan_reg.rbf` , I ran the following command after cycling power on the box, waiting for the system to come back online, confirming that platformd finished successfully, then ran the following commands:

```
cd ~/code/tron
export TRON_LOG_LEVEL=info
SYSTEM_CONFIG="--instance 0,2" gen/t_clearhbm & SYSTEM_CONFIG="--instance 1,2" gen/t_clearhbm & wait
```
Within 15 seconds the command completed successfully. Afterwards, any runtron command run on any card would produce meaningful output (no gibberish, no NaNs). An example of such a command is:
```
gen/runtron --dont-stop --nr_hugepages 48 --seed 42 --model llama-3.1-8b-instruct-fast --instance 4,8 --iterations 1 --length 644 --prompt-length 380 -f /scratch/mcherba/democlient_prompts/llama_test_prompts/prompts_512/pg2349.txt
```
The `t_clearhbm` executable can potentially be used as a temporary workaround that can be run immediately after a power cycle, platformd start, to eliminate that initial "bad state" which is present in the latest bitfile.
