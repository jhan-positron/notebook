## PR body (as it is now; may have been edited after the review)

Skip per-query scans of attention pages already covered by hardware offload. Preserve software tails and partial-page visibility, and fix Pending readiness checks for pages shared by multiple writers.

**Large reductions in Ready worker time during both prompt and generation; no material overall model speedup demonstrated.** GPT-OSS-120B TP4, one user at 32K context, hardware attention enabled:

| Phase | Reduction in summed Ready worker time |
| --- | ---: |
| Prompt / prefill | **76.7%** (2.64 → 0.614 s) |
| Generation / decode | **37.3%** (29.6 → 18.6 ms) |

Within Ready sections with no estimated software work, the reductions are **99% for prompt** and **47.9% for generation**. These are overlapping worker spans, averaged across three matched trace pairs. Repeated untraced model checks at 2K and 32K, including four users at 2K, show equivalent throughput and latency (less than 1% difference).

**Potential gain:** removing these scans frees workers and may improve model performance when CPU attention becomes a bottleneck. That larger benefit has not been measured.

**Pending sections:** the increase reproduces at **2.14% more prefill worker time** across three fresh pairs (+3.05%, +2.03%, +1.35%), versus **5.2%** in the original single pair. Generation Pending averages **2.65% more worker time**, driven by one pair (+6.72%; the other two are within 1%). These are summed worker times; no corresponding full-model latency or throughput regression has been measured. Pending generally contains new pages requiring computation. The readiness fix waits for every writer of a readable physical page and deduplicates checks for consecutive tokens sharing that page.

Validation:

- `t_llama_unit`: 128,487 assertions / 30 cases; `t_ranged_mask`: 262 assertions / 25 cases. Both passed at 1, 2 and 4 slices; benchmark metadata is refreshed.
- Restoring only the old producer-token visibility predicate makes both shared-page readiness cases fail; the other 29 cases pass.
- Pinned clang-format-19, applicable Lefthook checks and `make build-test` passed.
- CI: [host tests](https://github.com/positron-ai/tron/actions/runs/34655835716/job/103452391973) **92 passed, 0 skipped, 0 failed**, including the proxy suite; [FPGA tests](https://github.com/positron-ai/tron/actions/runs/34655835716/job/103452392013) **53 passed, 0 skipped, 0 failed**. All 19 checks in that CI run passed.

Performance checks used clean, frozen Nix `cross-avx512` RelWithDebInfo builds and the same GPT-OSS-120B TP4 plugin, weights and prompt tokens. Both ran through public Distributed Dice wrappers on **andoria-cf8c, NUMA0**, with NUMA1 idle for the primary comparisons. Hardware attention was enabled at engagement 127; sliding-window layers retain software attention. No live-token or per-user prompt-chunk override was set.

One-user sweeps used three isolated iterations per version, the same 32K→2K runtime order, 32,769 / 2,049 actual input tokens, 128 generated tokens. The four-user CI-style control used 2,048 input tokens per user, 514 generated tokens. Multi-user samples average the four correlated request measurements within each fresh batch.
