## Summary

Adds the foundational hardware-attention type *declarations* — `gof.hpp` and `shard.hpp` — that the upcoming hardware-attention work will build on. Headers only, no implementation. Build-clean: nothing on main includes them yet, so they compile to nothing.

- `h/tron/gof.hpp`: GOF (group-of-four) types — `page_info`, `gof`, `gal`, `gof_job`, plus the `gof_rodeo_fn_t` typedef and `backfill_shard` declaration. The header reflects the post-redesign API: per-shard `hw_attn_params const* hw_params` rather than module-scope state.
- `h/tron/shard.hpp`: `shard` type for HW KV cache management. The ctor takes `hw_attn_params const*` (defaulted to `nullptr` for test stubs with `max_layers == 0`).

Some function declarations (e.g., `gof::populate`, `backfill_shard`) reference symbols not yet on main. As long as nothing calls those functions, the link stage is happy. Implementations land in a follow-up PR alongside the supporting infrastructure (`device_dma_tracker`, `HW_MAX_KV_HEADS` / `hwkv_max_layers` constants, the `hw_attn_params` extension).

The `POS_PER_PAGE` rename from hwattention_sync is held back to `pos_per_page` to match main's current spelling; this aligns automatically with the future PR that brings `pos/hwattention.hpp`'s broader rename.
