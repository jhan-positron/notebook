## PR body (as it is now; may have been edited after the review)

Reduce software and FPGA attention separately as each becomes ready, then combine the two results. FPGA passes merge while later passes run; each query finishes once both of its reductions are complete. The plan fixes the merge order; regrouping can change rounding relative to main.

**Long context improves both prompt and generation.** Fresh Dice measurements against main `ab13fef7b`:

| Context | Prompt: lower TTFT | Generation: higher tok/s |
| --- | ---: | ---: |
| 2K | equivalent | **2.17%** |
| 32K | **7.57%** | **15.9%** |
| 88K | **16.2%** | **29.5%** |

GPT-OSS-120B TP4, one user, hardware attention on, 128 generated tokens. Medians of three isolated requests per context/version on the same Genoa/four-FPGA partition.

Eight-user controls (four per TP4 partition, ten isolated iterations per partition):

- **GPT-OSS-120B, 2K prompt / 514 generated tokens, hardware attention on:** TTFT improves **2.07%**; generation is equivalent.
- **Llama 3.1 8B, 1,920 prompt / 130 generated tokens, hardware attention off:** prompt and generation are equivalent.

Changes under 1% are equivalent. The two-stage ordering is equivalent to the previous PR head in these workloads; no regression of 1% or more was measured against main.

Validation: `make build-test`, three focused attention suites covering both readiness orders and DMA lifetime, and refreshed 1/2/4-slice test benchmarks passed. The host suite had **88 passed, 0 skipped, 1 failed**: the unchanged proxy/Dice launch issue tracked in [#4418](https://github.com/positron-ai/tron/pull/4418).
