## Summary

Stacked on #2785. Instruments `tron::hardware::allocator` (the HBM allocator) with FUSE stats and opt-in caller-attribution shadow map, mirroring `pos_heap_v2`'s observability surface for the host DMA heap.

- `/rinzler/stats/devices/<bdf>/allocator/{capacity,free_max,free_total,free_blocks,allocations,deallocations}` — six gauge/counter endpoints per device. Byte stats are whole-device totals (scaled by `FETCHERS_PER_DEVICE` internally).
- `HBM_ALLOC_SHADOW` (compile-time CMake option on the `system` library): per-allocation caller-PC capture at the `alloc_kv_weights` / `alloc_hardware_weights` API boundary plus a `dump_profile()` diagnostic. Symbol resolution via `addr2line` against the rinzler binary.
- Write-triggered `dump_profile_trigger` FUSE control file per device — `echo 1 > .../dump_profile_trigger` fires a snapshot to `$TRON_HBM_PROFILE_PATH`. Always reads as 0.
- OOM error messages in `driver.cpp` now include caller PCs unconditionally (useful even without HBM_ALLOC_SHADOW); SHADOW build also fires `dump_profile("kv_OOM" / "weights_OOM")`.

This is the "extract to main" companion of the same work that exists on `pos_heap_v2`. Commits cherry-picked verbatim from the original development, plus one compatibility commit (`580ad39a1`) that aligns `src/pos/fake.cpp` with the structure used on hwattention_sync (drop the local minimal `struct PosDevice`, use the real one from `pos/device.hpp`, change `fake_devices` to a nullptr-initialized `PosDevice*` array, add empty `devices` global + `pos_list_devices()`) and adds explicit `#include "pos/alloc.hpp"` to `src/rinzler.cpp` / `src/runtron.cpp` so `pos_devices_register_fuse_stats()` is visible without relying on a transitive include path that doesn't exist on main.

Used in the diagnosis of MMLU heap-exhaustion crashes that motivated [STORY-425](https://www.notion.so/positron-ai/356d132d3cfd81f28995f545be1bd260). Related characterization work tracked under [STORY-446](https://www.notion.so/positron-ai/35ed132d3cfd81d48e1ee87bcc26c276) (HBM allocator fragmentation characterization).

> [!NOTE]
> **Medium Risk**
> Changes allocator layout behind a compile flag and registers live device pointers in FUSE callbacks; misconfigured `HBM_ALLOC_SHADOW` across TUs would corrupt `PosDevice`, but the PR routes the macro through `system` to prevent that.
> 
> **Overview**
> Adds **observability** to the per-device HBM `tron::hardware::allocator`, parallel to the host `pos_heap_v2` story: fragmentation gauges (`free_total`, `free_blocks`), capacity, and cumulative alloc/dealloc counters, plus optional **caller-PC shadow** when `HBM_ALLOC_SHADOW` is enabled at configure time (declared **PUBLIC on `system`** so `sizeof(allocator)` stays consistent wherever `alloc.hpp` is included).
> 
> **FUSE** exposes `/rinzler/stats/devices/<bdf>/allocator/*` (byte metrics scaled by `FETCHERS_PER_DEVICE`); shadow builds add write `dump_profile_trigger` / read `dump_profile_output`. **`rinzler` / `runtron`** call `pos_devices_register_fuse_stats()` before stats start.
> 
> **Driver** paths `alloc_kv_weights` / `alloc_hardware_weights` always record return addresses for OOM logs; shadow builds also `dump_profile` on failure. A sysfs test confirms **read callbacks** can return strings larger than stored-value limits.
