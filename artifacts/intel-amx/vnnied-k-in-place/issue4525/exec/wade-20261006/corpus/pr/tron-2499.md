> [!NOTE]
> **Medium Risk**
> Refactors core scheduler traversal logic from recursive to iterative; while intended to be logic-preserving, it touches KV/job scheduling, shard/GOF wiring, and range building, so subtle ordering/state propagation bugs could impact correctness/perf at long contexts.
> 
> **Overview**
> Replaces `full_scheduler::compute_forward_args()`’s recursive post-order DFS with an explicit heap-backed stack to prevent stack overflows on very deep token trees, while keeping the same scheduling outputs (token jobs, listener handling, shard/GOF bookkeeping, and ranged-mask range construction).
> 
> As part of the refactor, it reuses a single `token_got_kv` buffer across edges to reduce allocations and simplifies GOF wiring by replacing an `unordered_set` lookup with a linear scan over `edge.gals`.
> 
> Separately, makes `LOG_TOKEN_TIMES` configurable as a stride macro (instead of hardcoding 512) when emitting per-token timing logs in `stream_generate.hpp`.
