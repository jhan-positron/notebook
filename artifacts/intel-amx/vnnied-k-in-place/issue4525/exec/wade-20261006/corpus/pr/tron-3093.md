## PR body (as it is now; may have been edited after the review)

Flip the TRON_ARENA_ALLOCATOR_DEFAULT_ON CMake option to ON so pos_heap_v2
(the arena allocator) is selected when TRON_USE_ARENA_ALLOCATOR is unset.
The env var still overrides per launch ("0" forces legacy, "1" forces
arena), so the only behavior change is the unset default.

Validated by a 3-day system-CI soak with TRON_USE_ARENA_ALLOCATOR=1. On
this branch: a fresh build-test (857/857 targets) and the FPGA suite in a
2-card slice (41 passed / 0 failed / 0 skipped) — the default-mode
scheduler/generate/ingest-model tests now exercise pos_heap_v2, and the
pinned arena/legacy memory tests stay covered.

Note: the option is read at CMake configure time. An existing gen/
configured under the old default keeps OFF until `make distclean` (or a
-DTRON_ARENA_ALLOCATOR_DEFAULT_ON=ON reconfigure) -- option() does not
override an already-cached value.
