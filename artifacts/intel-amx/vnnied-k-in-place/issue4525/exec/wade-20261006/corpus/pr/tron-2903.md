## PR body (as it is now; may have been edited after the review)

Add minfifo, a minimal Vyukov style Multi Producer Single Consumer Fifo queue and move from  using the CKSTAILQ to it for enqueueiung to devices

---

> [!NOTE]
> **Medium Risk**
> Changes the hot path between app threads and TX workers; correctness depends on minfifo memory ordering and queue-full handling, though new tests cover MPSC behavior.
> 
> **Overview**
> Replaces the per-device **in-work** path from a **mutex-protected Concurrency Kit STAILQ** to a new **`tron::minfifo`** lock-free **multi-producer / single-consumer** ring (2048 slots via `inwork_ring_size`).
> 
> **Enqueue** (`enqueue_hardware_matmul_job_to_device`) no longer takes `inwork_mutex`; it atomically updates `enqueued_work` / `work_req_count` and pushes `wqentry*` into `inwork_queue`, **asserting** on overflow instead of an unbounded list.
> 
> The **TX worker** dequeues with `dequeue()` and blocks on **`mwaitx`** using `dequeue_wait_hint()` on the next cell’s sequence word, rather than watching the STAILQ head pointer.
> 
> Related tuning: **`max_cmd_fifo_depth`** is raised from **32 → 1024** (aligned with HW), and several device counters (`enqueued_work`, `dequeued_work`, `work_req_count`) are **`std::atomic`**. **`mwaitx`** gets a corrected minimum timeout so short waits don’t jump to multi-ms sleeps. **`t_minfifo`** adds concurrency and capacity tests; `minfifo` is linked into **`pos`** and **`pos_fake`**.
