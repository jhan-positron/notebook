## PR body (as it is now; may have been edited after the review)

Add a prep_worker thread per device and make the main thread call to prepare nonblocking and queue the prepare action to the dev specific thread.

this requires some new synchronization work as prior the serialized sequence served as the synchronization baser but now we need to make that more deliberate.

<!-- CURSOR_SUMMARY -->
---

> [!NOTE]
> **High Risk**
> Changes core FPGA driver threading, work-queue ordering, and WQE lifetime; incorrect synchronization could cause hangs, wrong launches, or reuse of in-flight work requests.
> 
> **Overview**
> Moves **`hw_prepare`** off the caller/TX path onto a **per-device PREP thread** with a **`prepwork`** queue, replacing implicit ordering from synchronous prepare with explicit **`wqentry`** gates (`prep_done`, `hw_prepared`) and **mwaitx** waits.
> 
> **Prepare → launch flow:** `prepare_hardware_*` now enqueues prep work instead of calling `hw_prepare` inline; **`hardware_job::operator()`** and **`stream_results()`** wait for **`hw_prepared`** before TX launch or reading result metadata. Completion callbacks (or the direct-launch path) set **`prep_done`** so entries can be reused.
> 
> **`prepare_and_launch_direct`:** Optional **`direct_launch`** lets the PREP worker enqueue to **`inwork`** after prepare (used by MoE **`prepare_and_launch_direct`**), reducing cross-FPGA serialization on the main prepare/launch sequence.
> 
> **Ops/tuning:** Startup barrier counts PREP per device; prep threads are **joined** on shutdown. **`--prep-cores`** / **`prep_pin_thread`** (currently aliased to helper cores) and default prep core lists in **`system_optimize`**; minor **`resource-map.yaml`** comments. TX path tweaks: larger **`max_cmd_fifo_depth`**, **`short_timeout_ns`** for slot waits, more **`mwaitx`** in **`tx_wait_for_slots`**, prefetch/trace in **`hw_prepare`**, TX waits for prep before launch.
