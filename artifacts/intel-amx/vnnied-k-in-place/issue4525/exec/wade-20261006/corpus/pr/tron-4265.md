## PR body (as it is now; may have been edited after the review)

Two commits: the one-line fix, and a regression test for it in the existing `t_llama_unit` binary.

**The fix.** `log_kv_footprint`, the function in `h/tron/models/kv_cache.hpp` that prints the throttled "KV cache footprint" log line (KV = the attention keys and values the server caches), loaded its `last_print_bytes` atomic (a counter several threads update) with `std::memory_order_release` (a memory order: the rule for how the operation is ordered against other memory operations; release is meant for stores). The C++ standard does not allow that order on a load: the precondition of `atomic<T>::load` ([atomics.types.operations]) is that the order is neither `memory_order::release` nor `memory_order::acq_rel`. The old call therefore had undefined behaviour. The loaded value only decides whether the footprint has changed enough to print the line again. The two totals in the same function (`total_bytes`, `total_books`) are already updated with relaxed operations. The load is not used to synchronise access to other data. The load therefore becomes relaxed; the store that follows keeps its release order.

Pre-existing on `main` (line 454 at a80b102c18). Ben (bgamari-positron) pointed at it while reviewing #3879 ([comment 3937077542](https://github.com/positron-ai/tron/pull/3879#discussion_r3937077542), anchored at line 487 of the head 60d66d9c04, where the same load sits inside that PR's version of the function). Separate PR so the fix does not depend on the AMX (Intel Advanced Matrix Extensions) attention change.

**The test** (first test case in `t/t_llama_unit.cpp`, a fake host test that needs no model files; placed there at the reviewer's request instead of in a binary of its own). The wrong and the right order compile to the same instructions with clang, so no check on program output can fail; the compiler, clang-tidy, ThreadSanitizer and UndefinedBehaviorSanitizer are silent too. The detector is libstdc++'s own precondition check inside `std::atomic::load`, enabled by `_GLIBCXX_ASSERTIONS` on the `t_llama_unit` target only (`add_catch_test ... DEFINES _GLIBCXX_ASSERTIONS` in `t/CMakeLists.txt`). The macro is independent of `NDEBUG` and changes no linkage names, sizes or layouts, so the checked test object links against the unchanged `libtron`. The check reaches the load because `log_kv_footprint` is always-inline (`TRON(inline)`) and is called from the constructors of the KV books (a book is one allocation of cache pages) that this translation unit already instantiates: the test file compiles its own checked copy, and a wrong order aborts (SIGABRT, the abort signal) at the first call. The new case forks a child through the file's existing `assertion_signal` helper (fork, run the callable, report the signal that killed the child, 0 for none), calls `tron::log_kv_footprint(1, 0)` there (1 byte is below the 1 GiB print granularity, so nothing is logged), and requires 0. Without the fix the case fails (`REQUIRE(... == 0)` sees 6 = SIGABRT); with the fix it passes. The case is declared first on purpose: the binary runs as one ctest test in declaration order, and with `main`'s line 13 of the 27 existing cases construct a book unisolated and abort the whole process, so the fork-isolated case reports the contract by name before that happens. The `#error` at the top of the file makes a dropped define a build failure instead of a test that can no longer fail. The bug entered `main` in 0b5bdf2c86 (2025-04-10).
