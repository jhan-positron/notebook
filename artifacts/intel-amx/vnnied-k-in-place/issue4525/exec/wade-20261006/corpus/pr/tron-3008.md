> [!NOTE]
> **High Risk**
> Touches the hot TX/RX matmul path (MMIO wcmds, descriptor chains, rxinfo geometry) and FPGA weight-reuse semantics; mis-staging would corrupt results or hangs, though behavior is mostly structural with HW-attn WLR still default-off.
> 
> **Overview**
> **Refactors `hw_prepare()`** in `worker.cpp` into phased helpers (`prepare_and_stage_legacy` / `prepare_and_stage_attn`, `write_tx_descriptors`, `compute_block_layout` + `fill_rxinfo`, `write_rx_descriptors`) so legacy vs HW-attention staging, WLR, and DMA setup are easier to follow without changing the overall prepare → launch → RX contract.
> 
> **HW-attention weight-load reuse (WLR)** is no longer compile-time `ENABLE_HWATTN_WLR`; it is **opt-in via `HWATTN_WLR` env** (default off). When enabled and the prior attention request’s full K/V wcmd set matches, the path collapses to **two reuse wcmds** (`hbm_stride=0`) for back-to-back Qs—legacy matmul WLR stays always on.
> 
> **Small correctness/typing tweaks:** result geometry out-params use **`uint64_t`**, **`act_slot_base` is snapshotted before** command prep so TX activation DMA matches the slot embedded in acmds, and padding/full block counts go through **`block_layout`** instead of inline legacy-only math.
