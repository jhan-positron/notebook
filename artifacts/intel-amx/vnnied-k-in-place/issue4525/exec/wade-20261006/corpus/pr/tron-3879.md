## Short version

This PR adds an optional AMX path to software attention. The KV page must be a full 64-token page, and the query must be allowed to use every token of it. The model must have head size 128 (128 values per head) and 4 query heads per KV head. The model must also keep its queries in bf16. For such a page, the query-key scores and the softmax-weights-times-values product are computed with AMX tile multiplies. Every other page, model shape or number format runs the existing AVX-512 loop, unchanged. 

Both paths start from the same three lookups for a page: how many tokens it holds, whether the query may use it, and the positions of the query and of the page's first token. The AVX loop made these lookups already and applies its visibility and sliding-window rules token by token, as before. The lookups now run once, before the choice between the two paths. The AMX path adds whole-page tests on them: all 64 tokens in use, one visible range, first token inside the sliding window.

The build option TRON_AMX_DISPATCH is OFF by default, and a default build compiles no AMX feature. Setting the environment variable TRON_AMX_DISABLE=1 makes the AMX build run the AVX loop on every page. That build then produces the same output values as a build without the option.

## Words used here

- **AMX**: Intel Advanced Matrix Extensions, the tile-matrix instruction set of Sapphire Rapids and later Xeons. The measurement host is a Granite Rapids Xeon 6962P.
- **KV page**: 64 tokens of K and V. **kv_mul**: query heads per KV head (grouped-query attention); the kernels serve kv_mul 4 with head size 128, hence the namespace `amx_attn_h128g4` and the `_128x4` suffix.
- **dense page**: a page whose 64 tokens are all active, visible to the query in one range, and inside the query's sliding window. Only dense pages take the AMX path.
