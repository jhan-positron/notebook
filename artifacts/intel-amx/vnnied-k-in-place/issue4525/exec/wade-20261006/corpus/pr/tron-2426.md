## PR body (as it is now; may have been edited after the review)

Implements golden-gof-shard.md design by merging the best parts of two independent implementations:

- gal struct as authoritative GOF store (unique_ptr on edges)
- Query-driven gal creation with page_info on gal
- Trailing boundary shard creation logic
- Ascent-based shards_getting_gofs propagation
- Shard push filtering with hwkv_min_gofs_for_offload threshold
- DMA tracker clear() + bounds assertions
- Comprehensive phase1-5 integration tests

> [!NOTE]
> **Medium Risk**
> Touches scheduler traversal, HW KV offload eligibility, and DMA/backfill paths, so mistakes could cause incorrect attention results or missed offloads. Changes are contained to the GOF/shard offload pipeline and are covered by expanded integration tests.
> 
> **Overview**
> Replaces per-edge GOF storage with an edge-owned **authoritative `gal` (GOF-for-all-layers) repository**, where each `gof_job` points at a `gal` holding the shared `page_info` and per-layer GOFs.
> 
> Updates the scheduler’s GOF/shard pipeline to be *query-driven*: `gal` objects are created only when a query token completes a GOF, shards needing the GOF are determined on ascent (`shards_getting_gofs`), and `gof_rodeo_impl` now DMAs only to shards whose token ranges cover the GOF position.
> 
> Reworks shard management by creating shards via **trailing-boundary logic**, adding shard offload eligibility filtering (including `hwkv_min_gofs_for_offload` and partial-shard handling), and making DMA tracking more robust via `device_dma_tracker::clear()`, bounds assertions, and reset/shutdown cleanup. Integration tests are extended to cover the new phases and edge cases.
