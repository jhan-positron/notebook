## PR body (as it is now; may have been edited after the review)

This is a follow-on PR to PR 2089, which adds GOFs and shards. Here we remove the allocation mechanism that was introduced on hwattention_sync as part of the AOF development effort, which supported only a single model and concurrent user, and switches to the GOF/shard infrastructure.

This is a work in progress, and depends upon PR 2089 merging to hwattention_sync first.

<!-- CURSOR_SUMMARY -->
---

> [!NOTE]
> **High Risk**
> High risk because it changes how HW attention finds and manages KV cache HBM addresses (moving from a global singleton to per-shard allocations) and touches scheduler/GOF save/flush paths that can affect correctness and performance across layers.
> 
> **Overview**
> **Moves HW KV cache ownership from the global `hwkv_rings` singleton to per-`shard` HBM allocations.** Shards now allocate and free per-layer K/V HBM regions (`alloc_kv_weights` + new `free_kv_weights`) and GOF DMA paths write into these shard bases.
> 
> **Wires shard bases into HW attention execution.** `gof_configure` now tracks `max_layers`, embryonic GOF keying switches to `gof_global * n_layers + layer`, and `prepare_and_launch_hw` populates `wqentry::kv_k_base/kv_v_base` via new `gof_kv_bases`, which the FPGA worker uses instead of `get_hwkv()`.
> 
> **Splits and modernizes debug/test utilities.** Large dump/debug helpers are removed from `hwattention.hpp` and reintroduced as shard-aware helpers in new `pos/hwattention_dump.hpp`; multiple tests are updated to allocate their own KV HBM regions and stop relying on deprecated `save_k_to_hardware`/`save_v_to_hardware` and `hwkv_rings` setup.
