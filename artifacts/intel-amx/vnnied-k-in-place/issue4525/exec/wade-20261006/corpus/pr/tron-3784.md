## PR body (as it is now; may have been edited after the review)

## Summary

- Value-initialize `PosDevice::rx_entries` during construction.
- Remove the startup `memset` that overwrote live `rxinfo` objects.
- Remove the now-unused C string header.

## Why

`rxinfo` contains a `std::function<void()>`, making it a non-trivial type. Byte-zeroing the array after construction is therefore undefined behavior.

The ring does not require clearing after each use: `prepare_tail` and `rx_head` govern slot ownership, and producers overwrite the active request state before RX consumes a reused slot. Value
initialization preserves the intended initial zero/empty state without violating object lifetimes.

This does not change the ring protocol or public API. Completed entries remain available for diagnostics until their slots are reused.
