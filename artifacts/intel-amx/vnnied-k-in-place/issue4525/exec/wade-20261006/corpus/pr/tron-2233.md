> [!NOTE]
> **High Risk**
> High risk because it changes the HW attention driver API and command generation logic (weight-load/activation command mapping, HBM addressing, and scheduling timing), which can directly affect correctness and device execution.
> 
> **Overview**
> **HW attention now consumes shard-based KV metadata instead of per-request single K/V bases.** A new `shard_layer_t` (K/V HBM bases + per-layer allocation size) is threaded through `fill_attn_job_template`, stored on `wqentry` as `shards[]/nshards`, and used by the TX worker to generate K/V weight-load commands per shard.
> 
> **Shard collection and timing moved later in the pipeline.** `self_attention` now defers shard discovery until after `upstream_kvs_ready` and patches the active work request using a new `gof_collect_shards()` helper; GOF/shard code and debug dump utilities were updated to use the new `kv_shard_layers` representation.
> 
> Also adds an internal doc describing the new shard-based HW-attn API and tightens/debug-logs parts of device init and driver command emission.
