Shared files keep their local constant spelling (Wade nit on #4557)

Wade's review comment (#4557, issuecomment-6021333114): value-suffixed
constants such as V_PAIR_TOKENS_2 fit the AMX kernel files, which use that
style throughout, but shared code should keep the idiom of the surrounding
file. This commit applies that to the three shared files the PR touches:

- h/tron/tensor/v_vnni.hpp: the six header constants go; the moved set_v,
  get_v and append bodies spell the pair stride, the shift count and the
  lane masks exactly as kv_cache.hpp still does, for example
  `const __m512i hi_16_of_32 = _mm512_set1_epi32(0xffff0000);`.
- t/t_llama_unit.cpp: the two new test cases use lower-case constexpr
  names (head_size, pattern_base, specials_even_token ...) like the rest of
  the file; the poison case returns to the literal 3, 4 and 7 of main.
- t/t_heap_v2.cpp: the one call reads `(1024, std::align_val_t{64})` like
  its two sibling calls.

The AMX kernel keeps the name V_PAIR_TOKENS_2; its definition moves from
the header into src/tron/kernels/amx_attn.cpp next to the other file-scope
constants there.

Spelling only. The libtron.a disassembly is identical before and after
(delphi-3bda, clang 19, RelWithDebInfo, AVX512 + TRON_AMX_DISPATCH), and
t_llama_unit, t_amx_numerics, t_heap_v2 and t_amx_dispatch_dtype pass.
