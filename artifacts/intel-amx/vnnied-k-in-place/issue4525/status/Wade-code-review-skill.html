2. Three facts that change the planned replies

The page status/PR4557-respond-Wade-comments.html (2026-10-05) proposed accepting every point. The verification contradicts three of its replies. jhan decides.

W5: the two GENERATE values are not duplicates of each other

copy_token has two partner-clearing branches for an even destination: andnot for an even source [h/tron/tensor/v_vnni.hpp:359-364] and srli for an odd source [v_vnni.hpp:378-384]. With 2 destination tokens the last copy lands on token 6 from source 4 (even from even). With 3 it lands on token 6 from source 3 (even from odd). Each value observes one branch. The bit-exact section fills all 64 tokens, so its later odd-destination copies overwrite every odd partner and it cannot observe partner clearing. Returning the poison section to one value drops the observation of one branch. The reply should concede the shared setup and keep both values, or move one clearing observation into the bit-exact section.

L4a: Wade's cited workflow does not gate the PR, and the replacement row is wrong

cmake-single-platform.yml has only workflow_dispatch and workflow_call triggers [.github/workflows/cmake-single-platform.yml:5-12 at e5fa372c19]; its caller is publish-deb.yml:68, under its tag or feature-branch gate at lines 64-67. The checks that gate the PR are the GCP Nix lane, which configures without TRON_AMX_DISPATCH (default OFF). So the reviewed sentence was true for the gating lane and wrong only in naming no lane. The row posted after the review ("CI builds AMX-on since PR #4505") is wrong twice: the gating lane builds AMX-off, and the flag entered the legacy workflow in PR #3879 (commit f4889f8072), not #4505.

3. Why we missed them

Five mechanisms cover all 13 points.

  • Wrong oracle. The author-side lenses judged the tests against the design document, and the design's bit table and check list were copied from the implementation. Nobody asked, per row, who consumes the value (W1, W4).
  • A critic that can only add. The completeness critic walked the design row by row and recommended tests per row. It created the duplicate coverage and the stale section name (W5, W6).
  • One review, too early. The only full review ran on 2026-09-22 against the diff. The PR body, the later commits (the overload, the tile constants, the alignment check, the fix commits) and the merge of main came afterwards, and nothing re-ran at the final head (M1, S1, S2, L3, L4a, L4b, L4c).
  • Known facts not carried forward. The design records already said the K alias does not enforce the layout, the formula check sits behind a hardware gate, and the maintainer must accept the allocation change. None reached the PR body or a finding (W2, W3, M1).
  • Truth and readability instead of reader need. Body passages and commits were checked for being true and plain, never for whether a reviewer who only has GitHub needs them (L4c, L3).
