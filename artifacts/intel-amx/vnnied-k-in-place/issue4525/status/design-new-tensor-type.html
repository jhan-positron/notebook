Typed cache tensors for packed V and native K

Issue #4525 · Assigned to jhan-positron · Repository: positron-ai/tron

Short version

Give packed V its own storage type and use layout-specific cache arguments at the kernel boundary. Native K keeps its existing storage and view. Add this interface on main first, then adapt PR #4424 to use a separate packed-K owner.

This revision incorporates the round-3 review and its verifier corrections. It specifies packed-storage access, fixture construction, template constraints, and the remaining verification steps. R is the stored token count. D is the stored dimension count. The packed-K formula uses groups of 32 dimensions and groups of 16 tokens. Each 16-token by 32-dimension panel is one AMX B tile. Let s = dimension / 32 and c = token / 16. Its base is (s * (R / 16) + c) * 512 bf16 elements. Inside it, use the packed-V formula on a 32-row by 16-column plane with row dimension % 32 and column token % 16. The in-panel offset is ((dimension % 32) / 2) * 32 + 2 * (token % 16) + dimension % 2 bf16 elements. Across the plane, dimension groups are outermost and token blocks are next. Swapping the two plane coordinates alone does not produce this order. [S1] [S10]

The new V storage type requires a positive even number of rows. Its column count must be positive and divisible by chunk_size, the selected SIMD width. This satisfies the sketch’s positive-dimension rule. The 16-lane packed page::set_v, the page method that writes one V row, still requires widths divisible by 32 dimensions. The packed scaled_v_expr supports 64, 128, 256, or 512 dimensions. The unchanged 8-lane path requires head_size / chunk_size % 8 == 0. There is no new 8-lane V-save wrapper. Owner and expression reads

  • v_vnni_tensor contains exactly one 64-byte-aligned bf16 array. It allocates no separate memory. Default construction leaves values uninitialized. Keep construction, copying, and destruction trivial. The owner does not inherit expr.
  • Provide as_view() & and as_view() const &. Delete both rvalue forms, including const &&. Keep same-type copy and move operations defaulted. Store no pointer to the owner's own array.
  • v_vnni_view<T,R,D> inherits expr<view_type,R,D>. v_vnni_row<T,D> inherits expr<row_type,D>. Restrict T to bf16 or const bf16. A row stores its pair address and parity by value. It outlives a temporary matrix view while the owner remains alive.
  • The packed types have no DMA template parameter or static DMA flag. No proposed consumer requires one. An arbitrary logical row is not a contiguous DMA input. The backing arena can still be DMA-safe memory. Do not inherit views<>, whose leaf rows must be contiguous.
  • The matrix supplies operator[] returning its row expression. The named host-tensor constructor reads row chunk() values. Add no dim, element, const_element, shape0(), or valid() member without a caller. No null-view state or default view constructor is proposed. Leave the rank-1 expression concept unchanged. The named V expression consumer is the ordinary host-tensor construction check in section 8. Production V paths continue to use bulk operations.   • copy_token moves the four source/destination parity branches of append_v. Preserve overlap restrictions and fresh destination ranges. Even destinations zero their partner. Odd destinations preserve it.
