Short version

PR 4737 changes kv_cache.hpp so that a 16-token K block stays row-major until all 16 of its rows are saved, and is transposed to the VNNI layout in place afterwards (or never, for operations the FPGA scores). The page gains two bit sets per storage slot that record saved rows and converted blocks, and every K reader and writer in the file now follows those bits. This page draws the data model, the call graph and the timing once (section 1), then shows each of the nine logical changes of the file next to the diagram it alters (section 2).

B1. Data model: book, page, kv_block, and the new per-page state

The two arrays this PR adds live in the page struct and have one entry per storage slot plus one for the EAGLE storage. They describe the K plane of every KV head of that slot in that page. B1 also fixes the worked example that the later diagrams reuse.

B2. One block, two layouts in the same bytes

The K plane of one (slot, KV head, page) is 16 panels of 1 KiB. A block owns four of them, 4 KiB apart. The PR lets those four panels hold either 16 row-major token rows or the VNNI form, and converts between the two in place (k_vnni.hpp, outside this file). The page's block bit says which form a block holds.
