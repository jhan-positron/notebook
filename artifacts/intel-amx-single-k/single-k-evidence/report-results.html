Compiled and executed direct swizzled-K readers

Local experiment A standalone C++20 proof implements AVX-512 BF16, AVX-512 FP32-query FMA, and AVX2 FP32-query FMA using PR #3879’s exact mirror indexing. It runs on claude-agentsrv, reporting AMD Ryzen 9 9950X under KVM, pinned to logical CPU 0, compiled with GCC 11.4.0. It does not link Tron: the installed compiler cannot compile Tron’s scalar __bf16 type. Canonical comparison kernels are intrinsic-level transcriptions of the dotter, and canonical K exists in this harness only as an oracle/baseline.

This tests QK on randomized finite inputs, not final model accuracy. Active infinities/NaNs and FP16 queries were not covered. The retained kernels use four partial accumulators per token lane; the earlier pseudocode shows the simpler single-chain derivation.

A separate subnormal probe produced zero with BF16 dot instructions and 9.18355e−41 with the FP32 FMA reader at MXCSR 0x1f80. That confirms an ISA/FP-environment difference which must not be mistaken for a storage-layout failure.

A small performance check, with narrow scope

For one query and one resident 64-token page, median of seven runs of 6,000 calls:

Kernelns / page
Canonical BF16 dotter transcription77.14
Swizzled AVX-512 BF1680.08
Canonical FP32-query dotter transcription157.65
Swizzled AVX-512 FP32-query106.64
Swizzled AVX2 FP32-query195.85

These establish a working compute path, not a production speedup. The BF16 result itself warns against assuming that compatibility means faster execution. This test does not exercise four-query K reuse, softmax/PV, writes, scheduling, FPGA packing, AMX, or cold/NUMA traffic. The canonical timing helpers scan all 64 visibility bits; the raw partial-page timings therefore are not representative of Tron’s tail traversal and are deliberately excluded here. No statistical confidence interval or Intel performance claim is made.
